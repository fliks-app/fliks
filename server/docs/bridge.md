# Bridge registry

Temporary HTTP endpoints between `fliks-server` and Nest during the strangler. Each row is added in the milestone that needs it and removed when the bridge is deleted. Planned list: phase-2 plan §6.4. A feature whose caller or callee moves later may stay broken instead of getting a bridge (plan §0 rule 2): see "Known gaps until Sn".

Auth: `Authorization: Bearer $FLIKS_BRIDGE_TOKEN` (random per boot; constant-time compare). Nest serves bridges under `/internal` (no `api` prefix). Public fallback must 404 `/internal/**`.

| `POST /internal/scan/source` (Rust) | S2 to S5 | `{mediaFileId:int, priority?:"low"\|"normal"\|"high"}`; scans the file's source unless its current version was; 204 once settled (a failed scan is logged, not an error), 404 for an unknown or off-disk file | S2 | S5 |
| `POST /internal/plugins/pre-roll` (Nest) | S2 to S8 | request `{mediaFileId:int, mediaId:int, episodeId?:int\|null, principal:{kind:"delegated", userId:int>=1}}` (bridge bearer); 200 `PreRollItem[]` (`{mediaFileId, labelKey?, skippable?}`), `[]` on any plugin failure; Rust ACL-gates every candidate itself and treats any bridge failure as `[]` | S2 | S8 |
| `POST /internal/notifications/dispatch` (Rust) | S4 to S8 | `{event, payload}`: `event` one of the 18 notification events, `payload` an object, no other keys (else 400); 204 once every matching sender settled (failures logged, never the status); 500 only when the connections SELECT fails. Nest `NotificationsService.dispatch` (never rejects) and `dispatchStrict` (plugin host) call it | S4 | S8 |
| `GET /internal/jobs` (Nest) | S5 to S8 | 200 `{jobs: [{name, cron, triggerable, labelKey, pluginId: string\|null}]}`: the registry jobs (`pluginId: null`) then the plugin-declared jobs; the three bridged core names are not in it; Rust lists them in `GET /api/commands/schedulers` and classifies a `POST /api/commands` name with it, an unreachable bridge shrinks the listing | S5 | S8 |
| `POST /internal/jobs/run` (Nest) | S5 to S8 | `{name}`; `RefreshPluginSources`, `SubtitleSearch`, `SubtitleUpgrade` and registry jobs run the body and answer when it ends (204; 500 `{message}` on a throw; 404 unknown name); a declared plugin job answers at once (202 started, 409 already running, 400 `{message}` = `unknown-job` or `not-triggerable`). The Rust client has no total timeout (connect 2 s only): a subtitle sweep lasts hours | S5 | S8 |

Rust bridge auth: `Authorization: Bearer $FLIKS_BRIDGE_TOKEN`, constant-time compare, 401 otherwise (`Bridge::check`). Nest bridge auth: missing `FLIKS_BRIDGE_TOKEN` answers 503 on every `/internal/bridge/*` call, a wrong or absent bearer 401. Nest reaches Rust through `FLIKS_SERVER_URL` (base URL, no trailing slash).

## Allowed duplication

- Library ACL verify in Nest until S8 (`LibrariesService.getAccessibleLibraryIds`, `assertMediaAccessible`, `getCountsByLibrary`, kept for `counts.service.ts` and the plugin guards, read queries only), duplicated by `libraries::accessible_library_ids` / `assert_media_accessible`, the single Rust implementation every route uses; both read the same tables live, so no endpoint. The live TV logo route reads the data directory's `livetv/` files itself until S7 (`images::disk_path` is the Rust table).
- Auth verify in Nest until S9: `jwt.strategy.ts`, guards, CASL factory, `PoliciesGuard`, `current-user` decorator, `jwt-secret.ts` (Nest still authenticates its own routes; Rust signs).
- Nest files kept for S6/S7 code that still imports them: the ffprobe wrapper (`modules/media-probe`, embedded subtitle detection and the `MediaFile.streamInfo` type) until S6, `common/utils/media-path.util.ts` and `atomic-file.ts` until S6, `modules/media-tools/fps.ts` until S7 (live TV presence), `modules/media/edl` until S7 (the playback-info DTO type). Rust has its own implementations; each file goes with its last importer.
- `GET /api/media/sync-queue` and the `/api/media/:id/subtitles*` routes are forwarded from Rust to Nest until S6: `MediaSubtitlesController` (`modules/subtitles`, registered by the scheduler module) keeps the handlers the deleted `MediaController` held.
- Live TV logo files: `LiveTvController.serveLogo` reads `<data dir>/livetv/<id>[-size].png` itself until S7 (`image-store.md` rule 20; `images::disk_path` is the Rust table).

## Known gaps until Sn

No new temporary bridge: each gap below is a Nest caller that loses a function when its callee moves to Rust, or the reverse. The release gate allows none. The two "Engine change" rows are engine follow-ups (no host workaround, plan §0 rule 3). `POST /internal/ingest` (plan §6.4) is dropped: known gap until S8.
