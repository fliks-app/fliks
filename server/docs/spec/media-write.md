# Spec: media-write (`/api/media` write routes, metadata import and refresh, delete, companions, `DELETE /api/libraries/:id`)

Sources: `[ts:src/modules/media/media.controller.ts]` (write handlers), `[ts:src/modules/media/media.service.ts]` (façade), `[ts:src/modules/media/media-service/{media-import,media-mutation,media-metadata,media-companions}.service.ts]`, `[ts:src/modules/media/media-service/tmdb-mapping.util.ts]`, `[ts:src/modules/media/dto/*.ts]`, `[ts:src/modules/media/entities/*.entity.ts]`, `[ts:src/modules/media/edl/{edl-sidecar,edl-parser}.ts]`, `[ts:src/modules/libraries/libraries.service.ts:225-247]`, `[ts:src/modules/requests/{request-lifecycle,requests}.service.ts]` (hooks), `[ts:src/modules/profiles/profiles.service.ts]` (profile lookups). Milestone: S5 (plan §10; the read routes of `/api/media` are `media-query.md`, S3). Tag paths are relative to `backend/`. Auth, CASL, validation-body and `ParseIntPipe` rules are in `auth.md` (cited "auth rule N"); library ACL helpers in `libraries.md` ("libraries rule N"); the filesystem model, the write inventory (`W` ids), file transfer, rescan and disk import in `ingest.md` ("ingest rule N").

Scope: 20 routes of `MediaController` (`media-query.md` "Out of scope" lists them) plus `DELETE /api/libraries/:id` (stays in Nest until S5, libraries rules 18-20). The 14 subtitle routes and `sync-queue` are S6. Provider clients, the circuit breaker and `resolveProviderForMedia` details are in the metadata spec (S5, `/api/metadata/*`); this spec states what the media services do with them.

## Routes

Class guards `JwtOrApiKeyGuard, PoliciesGuard` `[ts:src/modules/media/media.controller.ts:62-63]`. `scope:'stream'` tokens are rejected on every route (F8, auth rule 12); none is stream-allowed. Guards run before pipes (auth rule 17): an unauthorised caller gets 401/403 before any 400 of a bad path id. Permissions (`CaslAbilityFactory`, auth rule 25): `Create Media` = `media.create`, `Update Media` = `media.edit`, `Delete Media` = `media.delete`, `Grab Media` = `media.grab`, `Read Media` = `media.read`; `manage:all` and admins satisfy all `[ts:src/modules/auth/casl/casl-ability.factory.ts:84-95]`. "Gate" = `assertMediaAccessible(id)`: `getAccessibleLibraryIds(user)` then `assertAccessible` (libraries rules 32, 34; no row, null library or outside the caller's libraries = 404 `Media #<id> not found`, one body for missing and denied) `[ts:src/modules/media/media.controller.ts:85-88]`. No `@HttpCode` anywhere: POST = 201, PUT/PATCH/DELETE = 200. `ME`, `MD`, `Season`, `Episode`, `CompanionFile` are the shapes of rules 4-6, 33, 81. Path ids use `ParseIntPipe` (400 `Validation failed (numeric string is expected)`, auth rule 18; C20 canonical integers only).

## Rules

### A. Common

1. Per-media gate: every handler with `:id` clears `assertMediaAccessible` first, except the three create routes and `bulk`. Season and episode handlers resolve the parent media first (`getMediaIdForSeason`: 404 `Season #<id> not found`; `getMediaIdForEpisode`: 404 `Episode #<id> not found`) and gate on it. `[ts:src/modules/media/media.controller.ts:981-982,993-994]`, `[ts:src/modules/media/media-service/media-query.service.ts:606-620]`
2. Validation is the global pipe (auth rule 16, `[ts:src/common/pipes/tolerant-validation.pipe.ts:14-29]`; none of the DTOs here opts out with `@AllowExtraProperties`): `whitelist`, `forbidNonWhitelisted`, `transform`. DTO fields with `@Type(() => Number)` accept numeric strings (`"7"`); plain `@IsNumber` fields accept any JSON number including non-integers; `IsOptional` lets `null` through as the value `null`. `PATCH :id/library` and `POST :id/refresh|rescan` take no DTO.
3. [new] Hooks and events fire in-process in Rust after S5 (Nest calls them in process too, `[ts:src/modules/media/media-service/media-mutation.service.ts:227]`): `requestLifecycle.onMediaImported`, `onMediaRemoved`, `onMediaMonitorChange`, `onSeasonMonitorChange` (requests spec rules 36, 38-42) are function calls; domain events go to the S2 hub. Nothing is bridged.
4. `ME` (response of the three creates and of `identify`) = `findOne({where: {id}})` with TypeORM's eager relations only: `MLI` of `media-query.md` rule 30 without `files` and without derived fields (`sizeOnDisk`, `episodeStats`, `watched`, `progressPercent`), plus `metadata` (eager one-to-one: the `media_metadata` row, or `null`; right after an import it is usually `null` because cast and metadata persist in the background, so parity ignores `$.metadata`). Relation-id fields (`libraryId`, `qualityProfileId`, `languageProfileId`, `addedById`) are present only when non-null (rule 30 there), `path` is the getter (ingest rule 1). `[ts:src/modules/media/media-service/media-import.service.ts:608-614]`, `[ts:src/modules/media/entities/media.entity.ts:106-114,226-228]`
5. `MD` = `GET :id` shape (`media-query.md` rule 31), returned by `PUT :id`, `PATCH :id/library`, `PATCH :id/profiles` through `findOne(id)` after the write `[ts:src/modules/media/media-service/media-mutation.service.ts:78,129,168]`.
6. `Season` JSON (`PATCH seasons/:id`, rule 33) and `Episode` JSON (`PATCH episodes/:id`): the entity columns `id, createdAt, updatedAt, seasonNumber, monitored, preferredProvider, posterUrl, overview, airDate (varchar|null), mediaId` for a season; `id, createdAt, updatedAt, episodeNumber, endEpisodeNumber, title, overview, airDate, runtime, monitored, hasFile, stillUrl, markersScannedAt, seasonId` for an episode (no `searchVector`). `[ts:src/modules/media/entities/season.entity.ts:14-53]`, `[ts:src/modules/media/entities/episode.entity.ts:13-75]`
7. Activity claims (in-process registry in Rust, `bridge.md` `activity/claim` until S5): `Identify:<mediaId>`, `RefreshMetadata:<mediaId>`, `RefreshEpisodeMetadata:<episodeId>`, `Rescan:<mediaId>`; a duplicate is 409 `errors.already_running` (a `ConflictException('errors.already_running')`, body `{message: 'errors.already_running', error: 'Conflict', statusCode: 409}`). The claim is removed when the detached work settles, success or failure. `[ts:src/modules/media/media.controller.ts:337-349,397-403,446-452,498-504]`
8. Detached work is fire-and-forget (`void promise.then(...)`, `[ts:src/modules/media/media.controller.ts:358,406,453,506,560]`): the response never waits for it, the work survives a closed connection, nothing is retried, and a restart abandons it silently (the activity claim dies with the process, so a re-trigger after restart is allowed).
9. `[assumed]` Single-process in-memory state (claims, events) means no cross-instance guarantee; same as Nest.

### B. Import and create

10. `ImportTmdbDto`: `type` `'movie'|'series'` (required), `tmdbId` int >= 1 (`@Type(Number)`, `@IsNumber @IsInt @Min(1)`), `qualityProfileId?`, `languageProfileId?`, `libraryId?` (each `@Type(Number)` int >= 1). Unknown keys 400. `[ts:src/modules/media/dto/import-tmdb.dto.ts:1-35]`
11. `importFromTmdb(dto, addedByUserId = caller id, monitoredSeasons = null)`: (a) `config.get('TMDB_API_KEY', '')` blank → 400 `TMDB API key is not configured`; (b) `SELECT * FROM media WHERE "tmdbId" = $1 AND type = $2 LIMIT 1` found → 409 `This title is already in the library`; (c) `resolveImportTarget` (rule 14); (d) profiles (rule 15); (e) naming settings `naming_movie_folder_format` / `naming_series_folder_format` read with `SELECT key, value FROM app_settings WHERE key = ANY($1)`; (f) the details are read through the library's provider (rule 16); (g) persist (rules 19-21). `[ts:src/modules/media/media-service/media-import.service.ts:68-170]`
12. Same flow for series with `getTvShowSeasons(externalId, override)` for every season (full episode lists) before the first write; a provider failure aborts before any row exists. `[ts:src/modules/media/media-service/media-import.service.ts:140-169]`
13. `folderName` of an import: movies `applyMovieFolderFormat(fmt ?? '{Original Title} ({Release Year})', {title, originalTitle, year, tmdbId})`; series `applySeriesFolderFormat(fmt ?? '{Series Title}', {seriesTitle, originalTitle, year, tmdbId})` (naming spec; `sanitize` strips `<>:"/\|?*` and control characters, removes unreplaced `{tokens}`, empty `()`/`[]`, the substring `undefined` anywhere, collapses spaces and trims). Nothing is created on disk at import: the folder is created by the first ingest (W1) and, in Nest, by a rescan (W10; C51: no longer). The library `mkdir` (libraries rule 37) creates `L` only. [new] F44: the result must pass the one `fliks_domain::naming` folder-name validator of `ingest.md` rule 3 (not empty, not `.`/`..`, no separator or NUL, at most 255 bytes) before the row is written; an invalid name is REJECTED, never mapped to `''` (400 `Invalid folder name for "<title>"`, nothing written). `[ts:src/modules/media/media-service/media-import.service.ts:102-169]`, `[ts:src/modules/scheduler/naming.service.ts:407-420]`
14. `resolveImportTarget(type, {libraryId})`: `libraryId` given: `SELECT * FROM libraries WHERE id = $1`, missing → 400 `Library #<id> not found`; not given: `resolveSoleLibrary(type)` (exactly one library accepting `type`, unfiltered by ACL: 400 `Several libraries accept <type> — pass libraryId to choose one` or `No library accepts <type>`); then `mediaTypes` must include the type (400 `Library "<name>" does not accept <type>`) and `path` must be set (400 `Library "<name>" has no root path configured`). **No ACL check on the chosen library** (F46). `[ts:src/modules/media/media-service/media-import.service.ts:532-562]`, `[ts:src/modules/libraries/libraries.service.ts:414-422]`
15. Profiles: `resolveQualityProfileIdForImport(requested, library.defaultQualityProfileId)`: a requested id must exist (400 `Quality profile #<n> not found`), else the library default when it still exists, else the lowest-id profile, else `null`; language likewise (`Language profile #<n> not found`). `[ts:src/modules/profiles/profiles.service.ts:28-121]`
16. `readForLibrary(type, foundProvider, externalId, library, override)`: details from the provider that found the title; when the library prefers another available provider, the id is cross-referenced (`details.tmdbId`/`tvdbId`, else an IMDB lookup) and the details re-read from the preferred one, keeping the first provider's ids when the second lacks them; unavailable or no id: fall back to the finder with a `WARN`. `[ts:src/modules/media/media-service/media-import.service.ts:313-386]`

### C. Update, bulk, library, profiles, seasons, episodes

## Deferred (issue)

- Refuse `PATCH /api/media/:id/library` for a media that has files. Nest only updates `media."libraryId"`: the files stay on disk where they were, `Media.path` becomes `join(newLibrary.path, folderName)`, every file row then points at a path that does not exist, the next rescan removes the rows and a later delete removes the folder `newLibrary/folderName`. The fix is to answer 409 `media_has_files` (moving a title between libraries is a file move, out of scope) or to implement a real move, and it changes what the edit dialog (`patchLibrary`, `media-detail.ts:1224`) can do for a media with files, so the client must hide or explain the action first. Until then the port keeps Nest's behaviour; `ingest.md` C51 protects the rows from the next rescan.
