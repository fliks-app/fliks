# Spec: media-write (`/api/media` write routes, metadata import and refresh, delete, companions, `DELETE /api/libraries/:id`)

Auth, CASL, validation-body and numeric path-id rules are in `auth.md` (cited "auth rule N"); library ACL helpers in `libraries.md` ("libraries rule N"); the filesystem model, the write inventory (`W` ids), file transfer, rescan and disk import in `ingest.md` ("ingest rule N"). The read routes of `/api/media` are `media-query.md`.

Scope: 20 routes of the media controller (`media-query.md` "Out of scope" lists them) plus `DELETE /api/libraries/:id` (libraries rules 18-20). The 14 subtitle routes and `sync-queue` are in the subtitle specs. Provider clients, the circuit breaker and `resolveProviderForMedia` details are in the metadata spec (`/api/metadata/*`); this spec states what the media services do with them.

## Routes

Class guards `JwtOrApiKeyGuard, PoliciesGuard`. `scope:'stream'` tokens are rejected on every route (auth rule 12); none is stream-allowed. Guards run before validation (auth rule 17): an unauthorised caller gets 401/403 before any 400 of a bad path id. Permissions (`CaslAbilityFactory`, auth rule 25): `Create Media` = `media.create`, `Update Media` = `media.edit`, `Delete Media` = `media.delete`, `Grab Media` = `media.grab`, `Read Media` = `media.read`; `manage:all` and admins satisfy all. "Gate" = `assertMediaAccessible(id)`: `getAccessibleLibraryIds(user)` then `assertAccessible` (libraries rules 32, 34; no row, null library or outside the caller's libraries = 404 `Media #<id> not found`, one body for missing and denied). POST = 201, PUT/PATCH/DELETE = 200. `ME`, `MD`, `Season`, `Episode`, `CompanionFile` are the shapes of rules 4-6, 33, 81. Path ids are canonical integers only (400 `Validation failed (numeric string is expected)`, auth rule 18).

## Rules

### A. Common

1. Per-media gate: every handler with `:id` clears `assertMediaAccessible` first, except the three create routes and `bulk`. Season and episode handlers resolve the parent media first (`getMediaIdForSeason`: 404 `Season #<id> not found`; `getMediaIdForEpisode`: 404 `Episode #<id> not found`) and gate on it.
2. Validation is the global validation (auth rule 16; none of the request types here accepts extra fields): unknown keys are 400. Fields declared as numbers accept numeric strings (`"7"`); plain number fields accept any JSON number including non-integers; an optional field lets `null` through as the value `null`. `PATCH:id/library` and `POST:id/refresh|rescan` take no request class.
3. Hooks and events fire in-process: `requestLifecycle.onMediaImported`, `onMediaRemoved`, `onMediaMonitorChange`, `onSeasonMonitorChange` (requests spec rules 36, 38-42) are function calls; domain events go to the hub.
4. `ME` (response of the three creates and of `identify`) = the media row with its eager relations only: `MLI` of `media-query.md` rule 30 without `files` and without derived fields (`sizeOnDisk`, `episodeStats`, `watched`, `progressPercent`), plus `metadata` (one-to-one: the `media_metadata` row, or `null`; right after an import it is usually `null` because cast and metadata persist in the background, so parity ignores `$.metadata`). Relation-id fields (`libraryId`, `qualityProfileId`, `languageProfileId`, `addedById`) are present, `null` when the FK is null (parity-recorded), `path` is the getter (ingest rule 1).
5. `MD` = `GET:id` shape (`media-query.md` rule 31), returned by `PUT:id`, `PATCH:id/library`, `PATCH:id/profiles` through `findOne(id)` after the write.
6. `Season` JSON (`PATCH seasons/:id`, rule 33) and `Episode` JSON (`PATCH episodes/:id`): the entity columns `id, createdAt, updatedAt, seasonNumber, monitored, preferredProvider, posterUrl, overview, airDate (varchar|null), mediaId` for a season; `id, createdAt, updatedAt, episodeNumber, endEpisodeNumber, title, overview, airDate, runtime, monitored, hasFile, stillUrl, markersScannedAt, seasonId` for an episode (no `searchVector`); `hasFile` is true when the episode has an item part (`items.md` rule 21), and a file's `episodeId` is derived from its parts (`items.md` rule 22).
7. Activity claims (in-process registry): `Identify:<mediaId>`, `RefreshMetadata:<mediaId>`, `RefreshEpisodeMetadata:<episodeId>`, `Rescan:<mediaId>`; a duplicate is 409 `errors.already_running` (body `{message: 'errors.already_running', error: 'Conflict', statusCode: 409}`). The claim is removed when the detached work settles, success or failure.
8. Detached work is fire-and-forget (spawned tasks): the response never waits for it, the work survives a closed connection, nothing is retried, and a restart abandons it silently (the activity claim dies with the process, so a re-trigger after restart is allowed).
9. Single-process in-memory state (claims, events) means no cross-instance guarantee.

### B. Import and create

10. `ImportTmdbDto`: `type` `'movie'|'series'` (required), `tmdbId` integer >= 1, `qualityProfileId?`, `languageProfileId?`, `libraryId?` (each integer >= 1). Unknown keys 400.
11. `importFromTmdb(dto, addedByUserId = caller id, monitoredSeasons = null)`: (a) the configured `TMDB_API_KEY` blank → 400 `TMDB API key is not configured`; (b) a media of kind `type` already holding the `tmdb` id (`external-ids.md` rule 6) → 409 `This title is already in the library`; (c) `resolveImportTarget` (rule 14); (d) profiles (rule 15); (e) naming settings `naming_movie_folder_format` / `naming_series_folder_format` read with `SELECT key, value FROM app_settings WHERE key = ANY($1)`; (f) the details are read through the library's provider (rule 16); (g) persist (rules 19-21).
12. Same flow for series with `getTvShowSeasons(externalId, override)` for every season (full episode lists) before the first write; a provider failure aborts before any row exists.
13. `folderName` of an import: movies `applyMovieFolderFormat(fmt ?? '{Original Title} ({Release Year})', {title, originalTitle, year, tmdbId})`; series `applySeriesFolderFormat(fmt ?? '{Series Title}', {seriesTitle, originalTitle, year, tmdbId})` (naming spec; `sanitize` strips `<>:"/\|?*` and control characters, removes unreplaced `{tokens}`, empty ``/`[]`, the substring `undefined` anywhere, collapses spaces and trims). Nothing is created on disk at import: the folder is created by the first ingest (W1), never by a rescan (W10). The library `mkdir` (libraries rule 37) creates `L` only. The result must pass the one `fliks_domain::naming` folder-name validator of `ingest.md` rule 3 (not empty, not `.`/`..`, no separator or NUL, at most 255 bytes) before the row is written; an invalid name is REJECTED, never mapped to `''` (400 `Invalid folder name for "<title>"`, nothing written).
14. `resolveImportTarget(type, {libraryId})`: `libraryId` given: `SELECT * FROM libraries WHERE id = $1`, missing or outside the caller's ACL → 404 `Library #<id> not found` (rule 22); not given: `resolveSoleLibrary(type)` (exactly one library accepting `type`, unfiltered by ACL: 400 `Several libraries accept <type> — pass libraryId to choose one` or `No library accepts <type>`); then `mediaTypes` must include the type (400 `Library "<name>" does not accept <type>`) and `path` must be set (400 `Library "<name>" has no root path configured`). The sole-library resolution runs over the caller's accessible libraries (rule 22).
15. Profiles: `resolveQualityProfileIdForImport(requested, library.defaultQualityProfileId)`: a requested id must exist (400 `Quality profile #<n> not found`), else the library default when it still exists, else the lowest-id profile, else `null`; language likewise (`Language profile #<n> not found`).
16. `readForLibrary(type, foundProvider, externalId, library, override)`: details from the provider that found the title; when the library prefers another available provider, the id is cross-referenced (`details.tmdbId`/`tvdbId`, else an IMDB lookup) and the details re-read from the preferred one, keeping the first provider's ids when the second lacks them; unavailable or no id: fall back to the finder with a `WARN`.
17. `POST /media/import` (`ImportMediaDto`: `type` enum, `externalId` string, `provider?` string, profile and `libraryId` integers >= 1, `monitoredSeasons?` int[] each >= 0): provider = `providerRegistry.resolve(provider ?? null)`; duplicate check by the `tmdb` id `parseInt(externalId, 10)` (provider `tmdb` or absent) or the `tvdb` id (provider `tvdb`) within `type` (409 as above); a non-numeric `externalId` for `tmdb`/`tvdb` and a `provider` outside `tmdb|tvdb` are 400 (rule 24); `importMedia` has no `TMDB_API_KEY` check; then rules 14-16, with, for a title found without a `tmdbId`, a TMDB lookup by `tvdbId` to fill it; `monitoredSeasons ?? null` goes to the series persist (rule 21).
18. `POST /media` (`CreateMediaDto`: `title` string required; optional `originalTitle`, `year`, `type` (required enum), `tmdbId`, `imdbId`, `overview`, `status`, `monitored`, `path`, `posterUrl`, `fanartUrl`, `rating`, `genres`, `runtime`, `releaseDate` (ISO date string), `qualityProfileId`, `languageProfileId`): the row is created from the body, its `tmdbId` and `imdbId` linked as external ids in the same transaction (an id another media of the kind holds is the 409 of rule 98); only stored fields persist (`releaseDate` is the `release` row of `media_release_dates`, written in the same transaction, `media-details.md` rule 6; `path`, `qualityProfileId`, `languageProfileId` are derived or relation-id fields and are silently ignored); `updateSearchVector(id)`; re-read; domain `media.imported {mediaId, tmdbId: dto.tmdbId ?? null, mediaType, libraryId: null, addedByUserId: null}`. No lifecycle hook, no folder, no library.
19. `createUnmatched({title, year?, type, libraryId, folderName, qualityProfileId?, languageProfileId?, libraryDefault*ProfileId?, nfo?, artwork?}, addedByUserId)` (called by the disk relink only, `ingest.md` rules 79-81): profiles resolved as rule 15 with the given library defaults; `title = nfo.title` only when `!dto.title || dto.title === dto.folderName` and the nfo has a title; INSERT `media` with `originalTitle = nfo.originalTitle || title`, `year = dto.year ?? nfo.year`, `status = 'released'`, **`monitored = false`**, `alternativeTitles = []`, `overview = nfo.plot`, nfo `genres` (`[]` without) and `runtime/rating` and `releaseDate(premiered)` (the `release` row of `media_release_dates`), `libraryId`, `folderName`, profile FKs, `addedBy`; `updateSearchVector`; `storeLocalArtwork`; domain `media.imported {tmdbId: null, libraryId}`; re-read. No lifecycle hook (no `tmdbId`).
20. `storeLocalArtwork(mediaId, {poster?, fanart?, logo?})`: per present slot `imageService.storeFromDisk(absPath, 'media', mediaId, variant)` (reads the source image, resizes into the data dir: images spec; **not** a library write); failures are `WARN`ed and skipped; one `UPDATE media SET posterUrl|fanartUrl|logoUrl` with the local URLs that were produced.
21. Persist after the provider reads: movie: INSERT `media` (and, in the same transaction, its `video` edition and its item: `items.md` rule 7) from `buildMediaFieldsFromTmdb(details, 'movie')` and link its `tmdb`, `tvdb` and `imdb` ids (`external-ids.md` rule 8; a held TMDB id is the 409 of rule 11) (`undefined` fields are omitted, `genres` `[]` when none, the four dates sliced to `YYYY-MM-DD` and written as `media_release_dates` rows in the same transaction (`media-details.md` rule 6), `status` mapped by `mapTmdbStatusToMediaStatus`) plus `monitored = true`, `metadataRefreshedAt = now`, profile FKs when non-null, `libraryId`, `folderName` when non-empty, `addedBy` when the caller id is truthy; then in this order: log, detached `downloadMediaImagesInBackground`, `updateSearchVector`, `onMediaImported(saved, addedBy)` (before the response and before the event), domain `media.imported {mediaId, tmdbId|null, mediaType, libraryId|null, addedByUserId|null}`, re-read `ME`, detached `persistMediaMetadataInBackground` (cast, crew, persons, metadata row, rule 58). Series: the same media INSERT; detached images; for every provider season, sequentially: INSERT `item_groups ("mediaId", number, monitored = inScope(n))` with `inScope(n) = monitoredSeasons non-empty ? includes(n): n > 0`, then `applySeasonDetails(season, sd, {deferImages: true})` (rule 56: episode rows inline, stills and season poster detached); then `updateSearchVector`, `onMediaImported`, `media.imported`, re-read, detached cast persist. The media and its season/episode rows are written in one transaction (the provider reads all happen before it), so a failure leaves nothing; images and cast stay detached after commit.
22. The ordering above is a contract with the request lifecycle: `onMediaImported` runs before the import returns and before `media.imported` is emitted (requests spec rule 36). `libraryId` of the three import routes is checked against `getAccessibleLibraryIds` (an unknown library and one outside the caller's ACL are both 404 `Library #<id> not found`, as for unknown ids elsewhere); `resolveSoleLibrary` is evaluated over the caller's accessible libraries.
23. All three create routes accept no body field for `folderName`, `libraryId` (except the import DTOs), `addedBy`, `preferredProvider`: whitelist 400.
24. `externalId` non-numeric for `tmdb`/`tvdb` → 400; `provider` outside `tmdb|tvdb` → 400; `type` change via `PUT` (rule 26) moves the media's external ids with it and answers 409 when its TMDB id is already held in the new kind.
25. `importFromTmdb` is also called in-process by request approval and auto-approval (requests spec rules 24-25) with `monitoredSeasons` from the request; the caller id is the requester, not the approving admin.

### C. Update, bulk, library, profiles, seasons, episodes

26. `PUT /media/:id` (`UpdateMediaDto`, every field optional): `title`, `originalTitle`, `year`, `type` (enum), `tmdbId`, `imdbId`, `overview`, `status`, `monitored` (boolean), `path`, `posterUrl`, `fanartUrl`, `rating`, `genres` (string[]), `runtime`, `releaseDate` (ISO date string), `qualityProfileId`, `languageProfileId` (numbers), `preferredProvider` (`'tmdb'|'tvdb'|null`). Flow: `findOne(id)` (MD load), drop `path`, assign the rest (but `monitored`), save (`releaseDate` is the `release` row of `media_release_dates`: `null` deletes it, a changed date refreshes `updatedAt`, `media-details.md` rule 6); when `dto.monitored !== undefined`: rule 27 over `[id]`; `updateSearchVector(id)`; response `findOne(id)`. `path` is whitelisted and ignored; `qualityProfileId`/`languageProfileId` are relation-id virtuals and do not persist (profiles change through `PATCH:id/profiles`). `type`, `tmdbId` and `imdbId` are writable (a TMDB id is unique per kind, `external-ids.md` rule 4: a clash is 409 `This title is already in the library`; `null` removes an id, rule 8; a type change moves the ids with the media and clashes the same way, and a media that becomes a series loses its ungrouped item while one that becomes a movie gains one if it has none (`items.md` rule 9); a write that changed an id also refreshes `updatedAt`).
27. `setMediaMonitored(ids, monitored)`, the one owner of media monitoring (`PUT`, bulk, cleanup `delete_files_unmonitor` and an importer update that flips the flag): the prior state is read in one query, only for `monitored` writes; `UPDATE media SET monitored` on the ids whose flag differs, then the cascade `cascadeMonitoredToChildren` over every id: `UPDATE item_groups SET monitored = $1, "updatedAt" = now WHERE "mediaId" = ANY($2)` then `UPDATE items SET monitored = $1, "updatedAt" = now WHERE "groupId" IN (SELECT id FROM item_groups WHERE "mediaId" = ANY($2))` (`updatedAt` is set on both); a no-op for movies; two statements regardless of size; no `onSeasonMonitorChange` hook for the children. After the commit, for every media whose flag really flipped: domain `media.monitored.changed {mediaId, monitored}` then `onMediaMonitorChange` (rule 38); an unchanged media emits nothing.
28. `PUT` never touches the disk or the library; the lifecycle hook turns an unmonitored media's open requests off (requests spec rule 38).
29. `PATCH /media/:id/library`: body `{libraryId}` with `libraryId` a required integer >= 1 (400 otherwise, so `PATCH {}` is 400). `findOne(id)`; unknown library id or one outside the caller's accessible libraries → 404 `Library #<id> not found`; `library.path` null → 400 `Library "<name>" has no root path configured`; a media that has files (any `media_files` row on its `mediaId`, episode files included) answers 409 with `code: 'media_has_files'` and the English `message` `This media has files and cannot be moved to another library` (a sentence, because a 4.x client toasts an unknown key raw; the shape of `EDL_EXISTS` plus `statusCode` and `error`) after the library checks and changes nothing, unless `libraryId` is its current library (a no-op); moving the files is not implemented. Otherwise `UPDATE media SET "libraryId" = $1, "updatedAt" = now WHERE id = $2`; response `MD`. The media's `folderName` stays and `M` becomes `join(newLibrary.path, folderName)`; since a media with files is refused, no file row ever points at a missing path. The edit dialog (`patchLibrary`, `media-detail.ts`) locks the library select for such a media (client key `errors.media_has_files`).
30. `PATCH /media/:id/profiles` (`UpdateMediaProfilesDto`): `qualityProfileId?` int >= 1 or `null` (null clears), `languageProfileId?` int >= 1 or `null`; `findOne(id)`; per provided non-null id the profile must exist (404 `QualityProfile #<id> not found` / `LanguageProfile #<id> not found`); `null` sets the FK to null; neither key provided → 400 `Provide at least one of qualityProfileId or languageProfileId`; `UPDATE media SET "qualityProfileId", "languageProfileId"` for the provided keys; response `MD`. Policy: `media.grab` or `media.edit`.
31. `PATCH /media/bulk` (`BulkUpdateMediaDto`: `ids` array of numbers, `qualityProfileId?`, `languageProfileId?`, `monitored?` boolean, `libraryId?` numbers): build a patch from the provided keys (an explicit `null` profile clears it); empty patch → 400 `Provide at least one field to update`; `UPDATE media SET <patch>, "updatedAt" = now WHERE id = ANY($ids)`; `monitored` is applied through rule 27 over `ids` (cascade, events and hook after the commit); response `{updated: <affected rows>}` (ids that do not exist are simply not counted). **No per-media gate**: every id must be in `getAccessibleLibraryIds`, and the first inaccessible or unknown id answers 404 `Media #<id> not found` with nothing written (all or nothing). `ids` are non-empty integers (non-integers and ids above `i32` are 400), duplicates collapsed; `libraryId` follows rule 29 (400 when any media has files, 404 unknown library, 400 no path); unknown profile ids are 404; the whole update runs in one transaction.
32. `PATCH /media/seasons/:seasonId` (`PatchSeasonDto`: `monitored?` boolean, `preferredProvider?` `'tmdb'|'tvdb'|null`): season with its `media`; `wasMonitored`; apply the provided keys; `save`; when `monitored` provided `UPDATE items SET monitored = $1, "updatedAt" = now WHERE "groupId" = $2` (every episode of the season follows); `setSeasonMonitored` is the one owner (also cleanup rule 16b): when the flag really flips and the season has a media, after the commit `onSeasonMonitorChange(media, seasonNumber, wasMonitored, monitored)` and domain `media.season.monitored.changed {mediaId, seasonNumber, monitored}`; nothing otherwise; response the saved season.
33. `Season` response: the saved object: its columns (rule 6), `mediaId`, and the loaded `media` object (the media row with its eager relations; which of `media.library`/`media.metadata` appear is recorded by parity). `updatedAt` is refreshed only when a season column changed: the save skips the UPDATE for a same-value patch (the episodes UPDATE and the event still run).
34. `PATCH /media/episodes/:episodeId` (`{monitored: boolean}`): `SELECT` the episode (404), set `monitored`, `save`: `UPDATE items SET monitored = $1, "updatedAt" = now WHERE id = $2` only when the value changed (a same-value patch writes nothing and returns the unchanged `updatedAt`); response the episode (rule 6); no hook, no event, the parent season and media flags are not recomputed.
35. `bulk`, `PUT`, season and episode patches reject a `monitored` that is not a JSON boolean, non-integer ids in `bulk.ids` and ids above `i32` (400).

### D. Identify and refresh

46. Identify and refresh re-point or re-pull a media's metadata. They are asynchronous after the HTTP response; the provider clients (retry, breaker, stale fallback) are the metadata spec's. Progress is reported on SSE `metadata.started|refreshed|failed` (broadcast, `{mediaId, title}` and `{..., error}`) and through the activity registry (rule 7).
47. `IdentifyMediaDto`: `tmdbId?` int >= 1, `tvdbId?` int >= 1, `imdbId?` string, `preferredProvider?` string. At least one of the three ids is required (400 `Provide at least one external id to identify this media against`, checked in the service). **The ids sent are the new identity: an omitted id is cleared**, not kept. `preferredProvider` outside `tmdb|tvdb` is 400.

Then the controller emits `metadata.started` (broadcast), `upsertRunning('Identify:<id>', 'Identify', subject)`, starts `finishIdentify` detached and answers 201 with the media.
50. `finishIdentify(id)`: `completeIdentify` = `refreshMetadata(id, {deferAcquisitionKick: true})`, then for series `dropSeasonsAbsentFromProvider`; then `rescanFiles(id)` (`ingest.md` rule 38; any error, e.g. no root path, is `WARN`ed and swallowed: the file rows whose episode was dropped went back to `episodeId = NULL` by the FK and the rescan re-links them by filename against the new numbering); then domain `media.acquisition.requested {mediaIds: [id], reason: 'metadata-refresh'}`; resolves with the refreshed media. Success: claim removed, SSE `metadata.refreshed {mediaId, title (new title)}`; failure: claim removed, `ERROR`, SSE `metadata.failed {mediaId, title (previous title), error: <message>}`. The rescan inside identify runs under the `Identify` claim, not a `Rescan:<id>` claim.

Files survive as unmatched. An empty provider season list drops nothing.
52. `POST /media/:id/refresh`: gate; `findOne(id)` (404); **`metadata.started` is emitted before the claim**, so a duplicate refresh still announces; `claim('RefreshMetadata:<id>', 'RefreshMetadata', subject)` false → 409; detached `refreshMetadata(id)`; settle: remove claim, `metadata.refreshed {mediaId, title (from before)}` or `metadata.failed {mediaId, title, error}`; response `{ok: true}`.
53. `refreshMetadata(id, opts?)`: media missing → 404; provider and external id from `resolveProviderForMedia` (season override strict, media override strict, library preference soft, then tmdb id, tvdb id, tmdb unchecked, imdb-only cross-reference, else 400 `No provider ID available for this media`; metadata spec); movies: `details = getMovieDetails`; fill a missing `tvdbId` / `tmdbId` / `imdbId` (linked, `external-ids.md` rule 9: a TMDB id another media of the kind holds is skipped with a `WARN`); `UPDATE media SET <buildMediaFieldsFromTmdb(details)>` (provider nulls map to `undefined` and leave the column or stored date untouched, except `tmdbCollectionId`/`tmdbCollectionName`, set to null when absent; `originalTitle` falls back to `title`; `genres` and `alternativeTitles` replaced, `[]` when none; `status` always written; `posterUrl` etc. are first set to the provider's CDN URL); synchronous `downloadMediaImages` (rule 58: replaces the URLs by local paths when the download works); `persistMediaMetadata`; series: the same plus `refreshSeriesEpisodes` and, when it inserted episodes and `deferAcquisitionKick` is not set, domain `media.acquisition.requested {mediaIds, reason: 'metadata-refresh'}`; then `updateSearchVector`, `UPDATE media SET "metadataRefreshedAt" = now`; returns the re-read row.
54. `POST /media/:id/episodes/:episodeId/refresh`: like rule 52 with claim `RefreshEpisodeMetadata:<episodeId>`; the settle events carry the media's id and title. The gate clears `:id`; an episode not under `:id` is 404 `Episode #<episodeId> not found`.
55. `refreshEpisodeMetadata(mediaId, episodeId)`: episode with `season` (404 `Episode #<id> not found`), media (404 `Media #<id> not found`), provider with the **season's** override, `fetchSingleSeason` (TMDB single-season endpoint, else the full season list), find the episode by number, `UPDATE episodes` for the changed non-empty `title`, `overview`, `airDate`, `runtime`, and `downloadEpisodeStill(episodeId, stillUrl)` when the provider has a still. The route returns `{ok: true}`.

Returns `{insertedCount}`.
57. Provider resolution, cross-reference writes (the found `tvdb`/`tmdb` id linked, `external-ids.md` rule 8) and the language/region override from the library are the metadata spec's; the media services only call them.
58. 'B' (originalTitle) ||... 'C' (overview)` (a trigger maintains it, `media-query.md` search-vector rules).

### F. Delete

65. Three delete paths: `DELETE /media/:id` (media, rules 66-74), `DELETE /media/:id/files/:fileId` (one file, rules 77-80), `DELETE /libraries/:id` (every media of a library, rules 75-76). A fourth caller, delete-kind request approval, is the first path (requests spec rule 26). Library delete keeps files; media delete removes the media folder; file delete removes files only with `deleteOnDisk=true`.
66. `DELETE /media/:id`: gate; `remove(id)` (rule 67) returns `{title, diskPath}`; the response `{ok: true}` is sent after the **database** work; when `diskPath` is non-null the folder removal starts detached; on failure `ERROR Media file deletion failed — id=<id> title="<t>" path="<p>" error=<m>` and SSE `media.files.delete_failed {mediaId, title}` to the caller only.
67. `remove(id)`: `findOne(id)` (MD load: `files`, `seasons`,... 404 `Media #<id> not found`); capture `title`, `path`, `tmdbId`, `type`; `diskPath = resolveSafeMediaDir(media)` (rule 71) **computed before** the delete; `fileIds` of every file; then in this order: `requestLifecycle.onMediaRemoved(media)` (rule 68), `DELETE` of the media row (rule 69), detached `thumbnails.deleteForFile(fileId)` per file (W11, `ingest.md` rule 57), domain `media.removed {mediaId, tmdbId|null, mediaType}`, detached `mediaServers.dispatch('media.deleted', {title, path})`. No image cleanup: `<data>/images/media/<id>` stays (`imageService.deleteImages` has no caller, images spec). Returns `{title, diskPath}`.
68. `onMediaRemoved(media)` (requests spec rule 40): in-flight DELETE requests of the media become `approved` with `declinedReason = null`, `media = null`; in-flight ADD requests become `declined` with reason `Media removed from library`, `media = null`; `available` rows untouched; no notification. It runs **before** the delete, and its writes and the media `DELETE` run in one transaction: a failure of either leaves the media and the requests untouched (500).
69. The row delete: `DELETE FROM media WHERE id = $1` with the foreign keys doing the rest: `editions`, `item_groups`, `items`, `media_files`, `media_metadata`, `media_credits`, `subtitle_files`, `playback_states`, `download_history`, `likes`, `content_recommendations`, `playlist_items` cascade (through `item_groups` and `items` the episodes, their `item_markers`, `playback_states`, likes); `requests."mediaId"`, `blocklist."mediaId"`, `subtitle_blacklist."mediaId"` become NULL. Deleting a `media_files` row sets `playback_states."mediaFileId"` to NULL and cascades `media_file_scans`. All watch progress of the media is lost (by design: it is deleted). Schema: baseline `1777816212948_baseline.sql` and the migrations `1781200000000`, `1781600000000`, `1781700000000`, `1785900000000` (`server/migrations`)
70. `diskPath` rules (rule 71), evaluated **once**, in the detached task after the row is deleted (a library delete removes no folder and pays nothing), using the model of `ingest.md` rules 1, 5, 6: (a) `folderName` empty or the library path null: no folder removal; (b) `folderName` passes the single-component check (`ingest.md` rule 3); (c) `Lc = realpath(library.path)` exists; `D = Lc/folderName` is `lstat`ed: missing = nothing to remove; a **symlink** at `D` is unlinked itself and its target never touched; a non-directory is unlinked; (d) `realpath(D)` is a strict descendant of `Lc`; (e) `D` is not equal to, an ancestor of, or a descendant of the `realpath` of **any** library root (a library nested inside another library's folder, e.g. library B at `<A>/4k` and a media of A named `4k`), and not equal to or an ancestor/descendant of the directory of **any other media row** (same `folderName` in the same library, or a series folder containing another title's folder); any violation skips the removal with `WARN`, the media row is still deleted, the response is unchanged and SSE `media.files.delete_failed` is emitted to the caller so the admin sees the folder was kept; (f) removal is `remove_dir_all` semantics (symlinks inside are unlinked, never followed), contents included: **every file in the folder goes, not only the ones the app tracks** (nfo, artwork, subtitles, user files). The library root itself is never removed.
71. Containment is realpath-based (rule 70), never lexical: a `folderName` shared with another media, equal to a nested library root, or reached through a symlinked directory never deletes anything outside its own folder. A `folderName` of `..` or `a/../..` is refused at write time by the folder-name validator (rule 13, `ingest.md` rule 3).
72. `deleteMediaFolder(dir)` (W13): recursive removal (rule 70(f)), then `INFO Deleted media folder on disk: <dir>`; an already-missing folder is success, any other error is returned to the caller (rule 66's `delete_failed`). A symlink at `dir` is removed as the link only.
73. Delete-kind request approval (requests spec rule 26) runs rules 67-72 with the same failure behaviour except the failure is logged `ERROR Media file deletion failed after delete request #<id>...` and no SSE event; a failed `remove` rolls the request back to `pending`.
74. Order guarantee : the row is gone before the first byte is deleted, so a crash between leaves an orphan folder (harmless, re-scannable by the orphan scan), never a media row pointing at nothing; concurrent writers on the same media are serialised by the per-media lock (`ingest.md` rule 27).
75. `DELETE /libraries/:id` (libraries rules 18-20): library missing → 404 `Library #<id> not found`; `SELECT id FROM media WHERE "libraryId" = $1`; for each id sequentially `remove(id)` (rules 67-69, **including `onMediaRemoved`, `media.removed` and thumbnails**); the returned `diskPath` is **ignored: no folder is ever removed by a library delete**; then `DELETE FROM libraries WHERE id = $1` (cascades `library_user_access`, `role_default_libraries`; `root_folders` was dropped by `1779200000000`; sets `requests."libraryId"` NULL; `media."libraryId"` is `RESTRICT`, hence the media go first); log `Library #<id> deleted — <n> media row(s) removed, files kept`; 200 empty.
76. Not transactional: the k-th failing `remove` leaves the first k-1 removed and the library in place (the media are removed one by one so a retry continues). The delete calls rules 67-69 in-process for each media and **never** schedules W13 for a library delete; the escape test asserts the library tree is byte-identical afterwards (V3 below).
77. `DELETE /media/:id/files/:fileId`: gate; `deleteMediaFile(mediaId, fileId, deleteOnDisk)`; `deleteOnDisk` is true only for the exact string `true`.
78. `deleteMediaFile(mediaId, fileId, deleteOnDisk)`: media by id (404 `Media #<id> not found`); file `WHERE id = $1 AND "mediaId" = $2` (404 `File #<id> not found`); when `deleteOnDisk && media.path`: `fullPath = path.join(media.path, file.relativePath)`; `unlink(fullPath)` (W14): `ENOENT` is `WARN` (already gone), any other error is thrown and the row is **kept**; then `removeOrphanEdl(fullPath)` (W8: skipped when another video of that directory shares the stem; failures `WARN`), `subtitles.deleteSubtitleFilesOnDisk(mediaId, file.id)` (the subtitle service: unlinks the file's non-embedded subtitle files unless another video of the media still lists the same path; the subtitle rows go with the cascade). Then `DELETE FROM media_files WHERE id = $1`; detached `thumbnails.deleteForFile(id)`; its parts go with it (cascade), so an episode with no other file has none; detached `mediaServers.dispatch('file.deleted', {title, path})`. Without `deleteOnDisk` only the row (and its cascades) goes and the file stays on disk (a rescan re-adds it). Also called by the superseded removal (`ingest.md` rule 30).
79. `file.relativePath` is validated before the join: not absolute, no `..` component, no NUL, `\` normalised to `/`; `fullPath` is built from components, `realpath(parent(fullPath))` must be a strict descendant of `Lc` and the target must be a regular file (`lstat`, not a directory, a symlink is unlinked itself); otherwise 400 `Invalid file path` and nothing is unlinked (the row is kept). Same check for every `W7`, `W8`, `W14`, `W16`.
80. The subtitle callee `deleteSubtitleFilesOnDisk` applies rule 5's realpath containment to each subtitle path; a path outside the media root is skipped.

### G. Companions

81. `CompanionFile` = `{name: string, relativePath: string (relative to the media folder, `/`-separated, the key a delete or download is addressed by), size: number, mtime: string (ISO ms), kind: 'subtitle'|'edl'|'nfo'|'image'|'other', scope: 'file'|'folder', subtitle: {id: number|null, language: string, forced: boolean, hearingImpaired: boolean} | null, sharedWith: {fileId: number, name: string}[], hasPair: boolean}`.
82. `load(mediaId, fileId)`: media with `files` (404 `Media #<id> not found`), the file in `media.files` (404 `File #<id> not found`, also for a file of another media). `collect`: `subtitle_files WHERE "mediaId" = $1` filtered to rows with a `relativePath` and a `providerType` other than `embedded`; `entries = media.path ? scan(...): []` (a media without a path lists nothing).
83. `scan(media, file, rows)`: `root = media.path`; `videoAbs = resolve(root, file.relativePath)`; `{dir, stem}` of it (stem lowercased); regular files of `dir` (`readdir` + `isFile`, errors give `[]`); sibling files = other files of the media in the same directory with the same stem (versions side by side); `longerStems` = video stems in `dir` that are longer than `stem` and start with `stem + '.'`, a companion starting with `<longer stem>.` belongs to that video (`claimed`).
84. Entries, in order of discovery, de-duplicated by `relativePath` (`norm` = POSIX-normalise with `\` to `/`): (1) folder-level, only when `folderName` is set: series `tvshow.nfo` in `root`, in `dir` and in the parent of `dir` (each only if inside `root`), images named `poster|folder|cover|movie|fanart|backdrop|clearlogo|logo` + `.jpg|.jpeg|.png|.webp` in `root`; movies `movie.nfo` and the same image names in `dir`; `scope: 'folder'`, kinds `nfo`/`image`; (2) subtitle rows whose `relativePath` belongs to this file or a sibling version, resolved with `resolveSubtitleAbsolutePath`, `kind: 'subtitle'`, `scope: 'file'`, with the row's language/forced/hearingImpaired; (3) files in `dir` that are not videos: `.idx` collected for pairing; `<stem>.edl` → `edl`; `<stem>.nfo` → `nfo`; movies only `<stem>-poster|-fanart` + image extension → `image`; names that parse as a subtitle file (`parseSubtitleFilename`) and are not already a tracked row or claimed by a longer video, and `matchSubtitleVideo(...)` resolves to this file or a sibling → `subtitle` (untracked: `subtitle.id = null`, language parsed from the name); any other name starting with `<stem>.` and not claimed → `other`; (4) `.idx`: paired with an existing `.sub` entry of the same base → both get `hasPair = true`, the `.idx` entry's `subtitle = null`, shared with the pair's `sharedWith`; unpaired `.idx` starting with `<stem>.` → `other`. Each entry is `lstat`ed and kept only if it is a regular file (a symlink is excluded). Sorted: `scope: 'file'` before `'folder'`, then by `name.localeCompare` (by lowercase name then name, as `/api/fs/browse`; parity compares the list order-insensitively).
85. `sharedWith`: for `scope: 'file'` entries, the other files that also use the entry: subtitle rows of other files listing it, else sibling versions of the same directory and stem; excludes this file. Folder entries have `[]`.
86. The listing is the only authority for what a client may address: `findListed(mediaId, fileId, relativePath)` = collect again and require an exact `relativePath` match in the entries, else 404 `Companion file not found`. The client path is a lookup key, never a path component: `..`, absolute paths and unlisted names cannot match.
87. Download: `path` missing/empty → 400 `path is required` (before the gate); gate; `findListed`; open `join(media.path, hit.relativePath)` with `O_RDONLY | O_NOFOLLOW` (a swap to a symlink between listing and open fails, 404 `Companion file not found`); `fstat` must be a regular file; response: stream, `Content-Disposition` `attachment; filename="<name>"`, with `filename*=UTF-8''<pct-encoded>` and an ASCII fallback for non-ASCII names, `Content-Type` from the extension via the `mime-types` database (`application/octet-stream` when unknown), `Content-Length: <size>`; no `Range`, no `ETag`.
88. A directory entry or a symlink of the listing never reaches the open: the listing already excludes them (rule 84); `O_NOFOLLOW` covers the final component, and `realpath(parent)` must stay under `Lc`.
89. EDL upload (multipart field `file`, limit 1 MiB): order: guards (401/403), then the multipart body is parsed (an oversize body is 413 before the per-media gate, so also for an inaccessible media), then the handler: gate, then no file → 400 `No file uploaded`. `replace` is the query string `true` literal.
90. `importEdl(mediaId, fileId, buffer, replace, userId)`: size > 1 MiB → 400 `file_info.import_err_too_large`; a NUL byte → 400 `file_info.import_err_binary`; not valid UTF-8 (fatal decoder) → 400 `file_info.import_err_encoding`; `load` (404s); no `media.path` → 400 `file_info.import_err_no_folder`; `video = resolve(media.path, file.relativePath)`; `parseEdl(text, parseSourceFps(streamInfo.video[0].frameRate))` with no range → 400 `file_info.import_err_no_ranges`.
91. Write (W15): `existing = resolveEdlPath(video)` (`<dir>/<stem>.edl` by `lstat`, else a case-insensitive sibling); `existing && !replace` → 409 `{code: 'EDL_EXISTS', message: 'file_info.import_edl_exists'}` (the body is the object as is); `target = existing ?? <dir>/<stem>.edl`; when there was none, claim the name with `open(target, 'wx')` + close (`EEXIST` → the same 409: a racing first import loses cleanly); then `writeAtomically(target, tmp => writeFile(tmp, buffer))` (temp `.fliks-tmp-<uuid>` in the same directory, mode of the existing target kept, rename retry, `ingest.md` rule 10); on failure a name claimed here is removed (`rm -f`) and the error rethrown. The **uploaded bytes** are written, not a re-serialisation. Response `{ranges: parsed.ranges.length, rejected: parsed.rejected}` (`rejected` items `{line, reason}`), log with the user id.
92. The EDL target directory and file name are computed from `file.relativePath` (rule 79 validation), `dir` must be inside `Lc`, the name is `<stem>.edl` with the stem of the video file name (validated single component); a symlink at `target` is replaced by the rename (never followed); the `wx` claim uses `O_EXCL|O_NOFOLLOW`. For a root-level movie the file is created directly in `L` (the only write the port makes there besides companion unlink).
93. Delete: `path` missing → 400 `path is required`; gate; `findListed`; `targets` = the hit, or for a VobSub pair every entry with `hasPair` and the same base (`pairBase` = lowercase, `.idx`/`.sub` stripped). Per target: if tracked subtitle rows have exactly that `relativePath` (normalised): `subtitles.deleteSubtitle(row.id)` for each (subtitle delete: 404 `SubtitleFile #<id> not found`; 400 `Cannot delete an embedded subtitle`; resolves the path with `resolveSubtitleAbsolutePath`, unlinks (`ENOENT` counts as removed, any other unlink error is `WARN`ed and swallowed), then removes the row regardless), else `unlink(join(media.path, target.relativePath))` (W16; no `ENOENT` tolerance: a file that vanished after listing is a 500). Log `User <id> deleted companion file "<rel>" (media #, file #, <kind>)`. 200 empty. A folder-level entry (`poster.jpg`, `tvshow.nfo`) can be deleted through any file of the media and removes the shared file.
94. Contained unlink (rule 79); `ENOENT` after listing is 404 `Companion file not found`, not 500.
95. Companion deletes never touch the video, never delete a directory, and never delete a file the listing did not return in this request.

### H. Guarantees

96. Folder names pass the single folder-name validator (rule 13, `ingest.md` rule 3). Deletes and companions are `realpath`-contained (rules 70, 79, 88, 92, 94, with `ingest.md` rule 33). Write routes honour the library ACL (rules 22, 29, 31, 54): an inaccessible or unknown id in `bulk` is 404 (all or nothing) and an import into an inaccessible library is 404.
97. Bulk validation and its transaction (rule 31); the media delete and the request-lifecycle hook in one transaction (rule 68); a folder another library or media uses is never deleted (rule 70(e)); an import in one transaction (rule 21). Rescan, transfer, link and lock behaviours (missing media folder, no-replace renames, per-media lock, regular files only) are in `ingest.md`.
98. No 500 from input that passes field validation (as `libraries.md` rule 38): `PUT` external id clash and `type` change → 409; bulk `libraryId`/unknown profile ids; `PATCH:id/library` missing `libraryId`; import `externalId` `NaN`; `preferredProvider` outside `tmdb|tvdb`; `ids` out of range. Path ids are canonical integers (`007`, `0x7`, ` 7 ` → 400) on every route here.
99. Specified behaviours worth noting: `metadata.started`/`rescan.started` before the claim, `PUT` ignoring `path` and the profile ids, `DELETE` media removing the whole folder, library delete keeping files and being non-transactional, season patch emitting its event with an unchanged `monitored`, `analyze` having no claim.
100. `DELETE /media/:id` has no `deleteOnDisk` switch and always removes the folder (rule 66; the file route without `deleteOnDisk` and the library delete are the paths that keep files); `PUT` keeps ignoring `path`, `qualityProfileId` and `languageProfileId` (the web client sends them); the identify rescan runs under the `Identify` claim only, no `Rescan:<id>` claim, and the per-media lock (`ingest.md` rule 27) serialises it with a concurrent rescan.

## SQL

DDL is in `server/migrations`. Equivalent SQL of the database calls:

- Gate: `SELECT m."libraryId" FROM media m WHERE m.id = $1` (libraries rule 32); season gate `SELECT * FROM item_groups WHERE id = $1`; episode gate `SELECT e.*, s."mediaId" FROM items e JOIN item_groups s ON s.id = e."groupId" WHERE e.id = $1`.
- Import: the `media_external_ids` lookup of `external-ids.md` rule 6 (or by `tvdb`); `SELECT * FROM libraries WHERE id = $1`; sole library: `SELECT * FROM libraries ORDER BY name ASC` filtered in code by `mediaTypes`; `SELECT * FROM quality_profiles WHERE id = $1`, lowest id `ORDER BY id ASC LIMIT 1`, same for `language_profiles`; `INSERT INTO media (...)`, `INSERT INTO media_external_ids (...)` per id, `INSERT INTO item_groups (...)`, `INSERT INTO items (...)` (batched per season); the search vector is maintained by a trigger.
