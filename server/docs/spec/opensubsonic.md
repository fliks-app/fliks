# Spec: OpenSubsonic API

Scope: the music API third-party players speak (OpenSubsonic, a superset of Subsonic 1.16.1) over the `album` kind of `music.md`: routes, authentication, the response envelope in JSON and XML, ids, the endpoints and their shapes, the stream credential. Credentials are `device-tokens.md` (kind `subsonic`). Not in this spec: lyrics (`songLyrics`), smart playlists, the play queue, transcoding. The plan is `plans/music-library.plan.md` section "OpenSubsonic API", batch F7a.

## Routes

1. `GET` and `POST /rest/<endpoint>` and `/rest/<endpoint>.view`, outside `/api`, so the URL a client types is `https://<host>`. A `POST` body is `application/x-www-form-urlencoded` (extension `formPost`) and is merged after the query. A parameter may repeat (`songId`, `id`). An unknown endpoint is error 0 `Unknown endpoint`, with HTTP 200.
2. `f` is `xml` (the default), `json` or `jsonp` (with `callback`, `[A-Za-z0-9_.]` only, else the plain JSON). HTTP status is always 200 for a Subsonic answer, whatever its `status`, the media routes included; the one exception is `getCoverArt` of an id with no image (rule 28).
3. Mandatory parameters: `c` (client name) and `v` (client version) on every call but `getOpenSubsonicExtensions`; a missing one is error 10 `Required parameter is missing: <name>`. `v` is not compared with the server's.

## Envelope

4. `subsonic-response` carries `status` (`ok` | `failed`), `version` `1.16.1`, `type` `fliks`, `serverVersion` (the crate version) and `openSubsonic` true. A failure carries `error: {code, message}`.
5. XML: the root `<subsonic-response xmlns="http://subsonic.org/restapi" ...>`. In every object a scalar is an attribute (but a key `value` is the element's text), an object is a child element named by its key, an array is one child element per entry under the key (an array of scalars: the scalar as the element's text). A boolean is `true`/`false`, a number its shortest decimal. JSON: the same tree under the key `subsonic-response`, an absent value omitted, never `null`.
6. Error codes used: 0 generic, 10 missing parameter, 40 wrong username or password (also a throttled client, rule 12), 42 unsupported mechanism, 43 conflicting mechanisms, 44 invalid api key, 50 not authorized, 70 data not found.

## Authentication

7. Four ways, by the parameters present: `apiKey` alone; `u` + `t` + `s` (token and salt); `u` + `p`; `u` + `p=enc:<hex>`. `apiKey` together with `u`, `p`, `t` or `s` is error 43. A `u` with neither `p` nor `t`+`s`, or no `u` and no `apiKey`, is error 10. `getOpenSubsonicExtensions` takes none.
8. The credential is the secret of a `subsonic` device token (`device-tokens.md` rules 1-3): the app password the user copies once from their account. `apiKey` and `p` carry it whole (`p` plain or hex encoded with the `enc:` prefix); both are checked by its hash. `t` is `md5(secret + s)` in lower-case hex, compared without case in constant time against every `subsonic` row of the user, the secret being decrypted for that (`device-tokens.md` rule 15). `u` is matched against the username without case and must be the owner of the row; an `apiKey` names its owner.
9. The owner must be enabled and hold `read:media`, else error 40 (disabled or deleted) or 50 (no `read:media`). An unknown key is error 44, any other failure error 40, with the same message whatever failed.
10. A hit sets `lastUsedAt` at most once a minute. Revoking or renewing the row takes effect on the next call.
11. OIDC users have no password: they use an app password like everyone else, which is why it is the only credential.
12. Failures are throttled like the login (`auth.md` rule 39, the same limiter) per client network and `u` (without case), `apiKey` calls in one bucket per network no username can equal: 60 failures per window, and only a failed credential counts, so a success never adds up however many run at once. A call over the limit is error 40 `Too many failed attempts, try again later`, checked before any lookup.
13. `getOpenSubsonicExtensions` answers `openSubsonicExtensions` with `apiKeyAuthentication` and `formPost`, each `versions: [1]`. `songLyrics` is the next batch's. `transcodeOffset` is not advertised: the engine has no raw audio transcode, so `timeOffset` could not be honoured (rule 30).

## Ids and visibility

14. Ids are strings named by the table they point at, so an id of one kind never names another: `ar-<personId>` (an artist), `al-<mediaId>` (an album), `tr-<itemId>` (a track), `pl-<playlistId>`; a music folder is the library id as is. They are the database ids, which never change (a replaced file gives its track item back, `music.md` rule 32): clients can keep them across scans. An id of the wrong kind or an unknown one is error 70.
15. Library ACL everywhere, as the album pages: an album is visible when its media sits in a library of the caller (`accessible_library_ids`); a track when, besides, its edition does (`COALESCE(editions."libraryId", media."libraryId")`) and it has a file. Nothing outside is listed, counted, searched or served, and an id outside is error 70, never 50.
16. An album's songs are the tracks that have a file in any of its visible editions; counts and duration follow. Two pressings of one album that both hold files list both sets.
17. `musicFolderId` (library id) narrows `getIndexes`, `getArtists`, the lists, `search3`, `getGenres` and `getRandomSongs` to that library when the caller reads it; another library is the empty answer.

## Objects

18. A song (`Child`): `id`, `parent` (the album id), `isDir` false, `title`, `album`, `albumId`, `artist` and `artistId` (the first track artist, else the first album artist), `track` (`trackNumber`), `discNumber`, `year`, `genre` (the first of the album's), `coverArt` (the album's), `size`, `suffix`, `contentType` (the engine's table, `item-delivery.md` rule 13), `duration` (whole seconds, from the probe), `bitRate` (kbit/s, the stream's, else the container's, else size over duration), `samplingRate`, `channelCount`, `path` (`Artist/Album/file` as the file name, never an absolute path), `created`, `type` `music`, `mediaType` `song`, `isVideo` false, `userRating` and `starred` (the caller's), `playCount` and `played` (the caller's history), and the OpenSubsonic fields `genres[{name}]`, `artists[{id,name}]`, `displayArtist`, `albumArtists`, `displayAlbumArtist`, `contributors[{role, subRole, artist}]` (every `item_credits` role but `artist`, the instrument as `subRole`), `displayComposer`, `musicBrainzId` (the recording id), `isrc[]`, `replayGain {trackGain, albumGain, trackPeak, albumPeak}` (the keys it has), `explicitStatus` (`explicit`, else `""`), `sortName` (the title), `bpm` 0, `comment` `""`, `moods[]`. `displayArtist` joins the track credits' names with their `joinPhrase`, else with `" & "` (a credit's own `creditedName` wins over the person's name).
19. An album (`AlbumID3`): `id`, `name`, `artist`, `artistId`, `coverArt`, `songCount`, `duration`, `created`, `year`, `genre`, `playCount`, `played`, `userRating` (the caller's mean over the tracks they rated, absent when none), `starred` (an album-level `likes` row), `musicBrainzId` (the release group), `genres[]`, `artists[]`, `displayArtist`, `releaseTypes[]` (`primaryType` then `secondaryTypes`, capitalised: `Album`, `Live`), `isCompilation`, `originalReleaseDate` and `releaseDate` (`{year, month?, day?}` of `firstReleaseDate`), `recordLabels[{name}]` (the edition's `publisher`), `discTitles[{disc,title}]`, `sortName`, `moods[]`, `explicitStatus`, `version` (the edition's title when it differs). `getAlbum` adds `song[]`, in disc, position then id order.
20. An artist (`ArtistID3`): `id`, `name`, `albumCount` (visible albums credited with the role `artist`), `coverArt` (`ar-<id>`, only when the person has an image), `artistImageUrl` (the public `/api/images/person/<id>` URL, same condition), `musicBrainzId`, `sortName`, `roles` `["albumartist"]`. The artists listed are the persons credited as album artist on a visible album; `getArtist` answers any person row, with `albumCount` 0 when none of their albums is visible (a track artist, `artistId` of a song). No `starred`: favourite artists are not stored (rule 25).
21. The index of `getArtists` and `getIndexes` groups artists by the first letter of the sort name, else of the name, after dropping an `ignoredArticles` word (`The El La Los Las Le Les`), upper-cased and accent-folded, `#` for the rest; sorted by that key, then name, then id. `lastModified` is the newest `updatedAt` of the albums in milliseconds. `getIndexes` answers the same entries as `Artist` objects and ignores `ifModifiedSince`.
22. A playlist: `id`, `name`, `owner` (the username), `public` (`visibility` is `public`), `songCount`, `duration`, `created`, `changed`, and `entry[]` songs in `getPlaylist`. A playlist holds items of any kind: only the visible tracks are entries and are counted.

## Endpoints

23. System: `ping`; `getLicense` (`license {valid: true}`); `getOpenSubsonicExtensions` (rule 13); `tokenInfo` (`tokenInfo {username}`, error 44 for a call not made with an `apiKey`); `getUser` (the caller only: `username`, `email`, every role flag false but `streamRole`, `downloadRole`, `playlistRole`, `coverArtRole`, `adminRole` per `isAdmin`; another username is error 50). Browsing: `getMusicFolders` (the libraries that hold `album`), `getIndexes`, `getArtists`, `getArtist`, `getAlbum`, `getSong`, `getMusicDirectory` (an artist id lists its albums as `isDir` children, an album id its songs; the root of the folder tree is `getIndexes`), `getGenres` (`genre[{value, songCount, albumCount}]` over the albums' genres, sorted by name), `getArtistInfo2` (`biography`, `musicBrainzId`, `smallImageUrl`, `mediumImageUrl`, `largeImageUrl` as the person's public image URL at the three sizes, no similar artists) and `getAlbumInfo2` (`notes` the overview, `musicBrainzId`, the album's image URLs).
24. Lists: `getAlbumList2` (`type` `random`, `newest` by `createdAt`, `frequent` by the caller's play count, `recent` by their last play, `highest` by their rating, `starred`, `alphabeticalByName`, `alphabeticalByArtist`, `byYear` with `fromYear` and `toYear` (descending when `fromYear` is greater), `byGenre` with `genre`; `size` default 10, at most 500; `offset`; a missing `genre` or years is error 10, an unknown type error 0), `getRandomSongs` (`size`, `genre`, `fromYear`, `toYear`), `getSongsByGenre` (`genre`, `count` default 10 at most 500, `offset`), `getStarred2` (`starred2 {album[], song[]}`, no artists). Genre matches without case.
25. `search3`: `artistCount`, `albumCount`, `songCount` (default 20, at most 500) with their `...Offset`. The query is cut on spaces, double quotes and `*` dropped; every word must be contained, without case or accents, in the artist's name; in an album's title or its album artists' names; in a song's title, its album's title or its album artists' names. An empty query returns everything, paged (clients sync the library with it). Albums and songs order by title, artists by sort name. `star`, `unstar` and `setRating` act on `likes` and `item_ratings` of the caller: `id` and `songId` of a track, `albumId` of an album (a `likes` row with no item); a favourite artist and the rating of an album or artist are error 0 `Not supported` (nothing stored for them). `setRating` takes 1 to 5, 0 deletes. Starring twice and unstarring what is not starred succeed.
26. `scrobble`: `id` (repeatable) and `time` (milliseconds since the epoch, one per id, else now); `submission` true (the default) appends one `playback_history` row `(user, item, time)` unless that row exists (so a client replaying its queue adds nothing twice); `submission=false` is a now-playing notice, answered `ok` and not stored. A track outside the caller's libraries is error 70 and nothing is written.
27. Playlists: `getPlaylists` (the caller's own and those shared with them, by name), `getPlaylist`, `createPlaylist` (`name`, `songId`* appends; with `playlistId` it replaces the songs the caller can read, keeping every other item (videos, books, tracks of other libraries), and renames it when `name` is given), `updatePlaylist` (`playlistId`, `name`, `public`, `songIdToAdd`*, `songIndexToRemove`* as indexes of the playlist's entries, `comment` ignored), `deletePlaylist`. `assertRole` of `playlists.md` rule 4 decides: reading needs `viewer` (a public or followed playlist of someone else is read by id but not listed), editing songs `editor`, renaming and `public` `administrator`, deleting the owner (403 is error 50, a non-member error 70). `public=true` sets `visibility` `public`; `public=false` makes a `public` playlist `private` and leaves `private` and `followers` as they are; an opted-out user (`shareDisabled`) cannot set it (error 50). Songs go at the end, in order, and a song already in the playlist is skipped (`UQ_playlist_items_item`); a song the caller cannot read is error 70. A name is trimmed and cut to 255 characters.
28. Media: `getCoverArt` (`id` of an album, track or artist; `size` pixels, at most the thumb width (185 for an album, 45 for an artist) the thumb, at most 500 the medium, else the full image (`image-store.md` rule 7); none given is the full image; the bytes of the stored image, `image/jpeg`, `Cache-Control: public, max-age=86400`; an id with no image is a `404` with no body, and a playlist has none).
29. `stream` and `download` (`id` of a track): the answer is a `302` to `/api/stream/<fileId>?token=<credential>` (`&download=1` for `download`), the engine's data plane, which honours `Range`. The file is the first part of the track's highest version. The credential is a stream token (rule 31). Neither counts a play (`scrobble` does).
30. `maxBitRate`, `format`, `estimateContentLength` and `timeOffset` are read and ignored: the original bytes are served, the engine having no raw audio transcode (an HLS session needs a playback-info call a Subsonic client cannot make). A client that asks for a transcoded format gets the original container and reads it by its `contentType`.
31. The stream credential is a signed token like the stream tokens of `auth.md` rule 10, bound to the file (`mf`), to the user and to the `subsonic` row that issued it (`dt`, with `ds`, the start of the row's hash) instead of a session; it lives one hour, and ends when that row is renewed or deleted. `POST /engine/resolve` accepts it for the purposes `stream` and `download` only, and only while the row exists and its owner is enabled (`device-tokens.md` rules 6 and 9); a bound token never authenticates a host route (a token with no session is refused there). A failed media call is the Subsonic error of rules 4-6, in the requested format.

## Migration

32. `1789000000940_device-token-subsonic.sql` adds the `subsonic` value to `device_token_kind`; `1789000000941_device-token-secret.sql` adds `device_tokens."secret" bytea` with `CK_device_tokens_secret CHECK ("secret" IS NULL OR "kind" = 'subsonic')`. Two files because a new enum value cannot be used in the transaction that adds it.
