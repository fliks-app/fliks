This is the area where the server writes to real filesystems. Every filesystem operation is listed in rule group B with its path computation, its syscalls and its failure behaviour; the invariants of group A are what the port must enforce at **every** write site; the escape tests are listed under Vectors/parity (cases V1-V20). Naming (`NamingService`, `fliks_domain::naming`) and release parsing (`parseReleaseQuality`, `qualityFromResolution`, `extractMediaTitle`, `extractReleaseGroup`) are specified elsewhere (naming and release-parsing vectors, plan §5.2); this spec uses their results and only constrains what is done with them.

## Rules

### A. Path model and safety invariants (apply to every write site below)

1. Terms. `L` = `libraries.path` (the stored string after `sanitizeFsPath`, absolute per F19, libraries rule 37). `M` = the media directory = the `Media.path` getter: `null` when the library has no path, `L` when `folderName` is empty or null, else `path.join(L, folderName)` (lexical join: `..` collapses). A media with an empty `folderName` is a **root-level movie**: it owns only files sitting directly in `L` (rescan, companions and artwork never walk `L` for it). `media_files.relativePath` is relative to `M`, `/`-separated; readers normalise `\` to `/`. `[ts:src/modules/media/entities/media.entity.ts:106-114]`, `[ts:src/common/utils/media-path.util.ts:7-19]`
2. Nest enforces containment **relative to `M`, not to `L`**: ingest computes `relativePathUnderMediaRoot(media.path, dest)` and skips a destination that escapes `M` `[ts:src/common/library-ingest/library-ingest.service.ts:284-290]`; but `M` itself is `join(L, folderName)` and `folderName` is not validated at any of its writers (naming output `[ts:src/modules/scheduler/naming.service.ts:407-420]`, which strips `<>:"/\|?*` and control characters but keeps `.`, `..`, an empty result and any length; `RelinkOrphansDto.folderName` `[ts:src/modules/imports/dto/relink-orphans.dto.ts:83-86]`, written verbatim at `[ts:src/modules/imports/disk-import.service.ts:494-497]`). A `folderName` of `..` (a provider title of `..`, or the client body) makes `M` the parent of `L`, every `relativePath` check passes against that `M`, and ingest writes outside the library root. The only delete-side check is lexical (`resolveSafeMediaDir`, media-write rule 71).
3. [new] F44 (one row with `importers.md` rule 36 and `naming.md` rule 10): one `fliks_domain::naming` folder-name validator, applied by every `folderName` writer, checks it as exactly one path component; a failing name is REJECTED, never mapped to `''` (an empty name makes the media path the library root): non-empty unless the media is a root-level movie, not `.` or `..`, no `/`, `\`, NUL or ASCII control character, at most 255 bytes UTF-8, no leading or trailing space or trailing dot. Writers: metadata import (media-write rules 13, 17), `createUnmatched` and `relink` in place (rules 81, 83), the first-import pin in `confirmImport` (rule 92), `PUT /api/media/:id` never writes it. A violation is a 400 (routes) or a per-file `errors[]` entry (batch paths), never a partial write. Computed names (season folder, file base name + extension) get the same single-component check (rule 4).
4. [new] F44: every name the ingest computes is validated before any `mkdir` or transfer: the season folder component (empty is allowed: files land in `M`), the file name `newBaseName + ext`: base non-empty after trimming, not `.`/`..`, no separator or control character, whole name at most 255 bytes UTF-8 (the base is truncated at a character boundary, never the extension), `ext` (lowercased) must be in `VIDEO_EXTS` (`.mkv .mp4 .avi .mov .ts .m2ts .wmv .flv`, `[ts:src/common/constants/video-extensions.ts:2-11]`). Nest checks the video extension only in `confirmImport` `[ts:src/modules/imports/disk-import.service.ts:811-817]`, not for plugin ingest, and an over-long name fails with `ENAMETOOLONG` after the directory was created.
5. [new] F44: containment predicate `within(L, p)`. `Lc = realpath(L)` must exist and be a directory (else the operation fails before any write; a missing root is never created by ingest, rescan or delete, C51). For a target `p` the deepest existing ancestor is resolved with `realpath` and must have `Lc` as a **strict** ancestor (equal to `Lc` only for a file created directly in `L` by a root-level movie (the EDL upload and a companion unlink), or for the one-file creates of rule 6). `..` components never appear after rule 3-4. A symlinked intermediate directory is allowed only when its realpath is still inside `Lc` (a user may symlink a title folder to another disk of the same library tree, never out of it). The check runs after `mkdir -p` (the created components are re-resolved) and again immediately before each destructive call; the final component of a create is opened with `O_CREAT|O_EXCL|O_NOFOLLOW` or linked with no-replace (rule 12).
6. [new] F44: inside a library tree, directories are never created or removed outside this closed list (W11/W12 work in the cache and data dirs; the S6 sidecar `mkdir -p` of W18 is S6's): `dirname(dest)` under `M` for an ingest (rule 8); the library path itself by `libraries.md` rule 37 only; the media folder by `DELETE /media/:id` (media-write rule 70, which never removes `Lc`, an ancestor of another library root, a descendant-or-equal of another library root, or another media's directory, C49). Rescan creates nothing (C51).
7. Source side. `copy` leaves the source untouched; `move` removes it. A source is accepted only as a regular file after `realpath` (a symlink is resolved and the real file operated on, so a move never relocates a link into the library, and a dangling or special file is refused); the plugin path already `realpath`s `[ts:src/modules/plugins/host/fliks-host.service.ts:907-923]`, `confirmImport` stats (follows) but then renames the link itself `[ts:src/modules/imports/disk-import.service.ts:801-817]`, `[ts:src/common/services/file-transfer.service.ts:46]` (Nest moves a symlink into the library: `[new]` F47 forbids it). Sources are otherwise unrestricted for the disk-import routes (F48) and limited to the plugin's consented `ingestRoots` for the plugin path (rule 100, S8).

### C. file-transfer

8. Destination of an ingested file (computed per file, in this order): `ext = path.extname(file.path)` (original case, Nest keeps it; Rust validates the lowercased form, rule 4); movie: `destDir = M`, `newBaseName = applyMovieFormat(formats.movie, {title, originalTitle, year, quality, releaseGroup, tmdbId})`; series (any non-movie type): `newBaseName = applySeriesFormat(formats.series, {seriesTitle, season: seasonNumber ?? 1, episode: episodeNumber ?? 1, episodeTitle, quality, releaseGroup, airDate})`, `destDir = join(M, applySeasonFolderFormat(formats.seasonFolder, {season: seasonNumber ?? 1}))`; `destPath = join(destDir, newBaseName + ext)`. A file with no parsable numbering is placed as `S01E01`. `[ts:src/common/library-ingest/library-ingest.service.ts:250-280]`
9. `transferFile(src, dest, method)`: W1 first (also on `copy`), then `copy` = W2; `move` = `rename`, falling back to W2 + `unlink(src)` only for `EXDEV`. After a cross-device copy whose `unlink(src)` fails the call succeeds and the orphan source stays (logged `WARN`). `[ts:src/common/services/file-transfer.service.ts:35-63]`
10. W2 properties: the temp lives in `dirname(dest)` so the final `rename` is on one filesystem and atomic; its name is fixed length (`.fliks-tmp-` + 36 characters) so it never exceeds `NAME_MAX`; the data is `fsync`ed but the directory is not; permission bits are copied from the source by `copyFile` and from an existing destination by `chmod`; owner, mtime and xattrs are not preserved (mtime = copy time). A reader never sees a partial `dest`: either the previous file or the complete new one. `[ts:src/common/utils/atomic-file.ts:28-45]`
11. `.fliks-tmp-` files are invisible to the app (not video extensions) and are reaped only by W3. Windows differences (`rename` retry codes) are kept in the port, same table. `[ts:src/common/utils/atomic-file.ts:5-26]`
12. [new] C52: a transfer never replaces an existing file unless the caller asked to overwrite (rule 22): W2's last step becomes a no-replace rename (`renameat2(RENAME_NOREPLACE)` on Linux, `link` + `unlink(tmp)` where unsupported, `MoveFileEx` without `MOVEFILE_REPLACE_EXISTING` on Windows), `move` on one filesystem the same; a lost race returns `AlreadyPresent` for that file, not an overwrite. Nest checks `existsSync` then `rename`, so two concurrent ingests of one destination, or a file appearing between check and rename, replace silently; `uniquifyOnCollision` also falls out of its loop at `(99)` (`n < 100`) and then overwrites that name. In Rust the 99th collision is an error entry.
13. [new] C52: a source equal to the destination (same realpath, or the same device and inode) is not transferred: the file is linked in place (row created, `alreadyPresent` untouched). Nest re-running `reorganize` on a file already at its layout path sees `existsSync(dest)` true and, with `uniquifyOnCollision`, renames the file to `<name> (2)`.
14. Companions. `transferCompanions({srcDir, destDir, sourceBaseName, newBaseName, method, allowedExts})`: `readdir(srcDir, {withFileTypes})`, unreadable directory = return. For each entry: only `isFile()` (a symlink or directory entry is skipped: `Dirent` does not follow links); `ext = extname(name).toLowerCase()` must be in `allowedExts`; `stem = name` minus extension; the stem must **start with** `sourceBaseName` (both lowercased); `.edl` only with an exact stem match. Destination name: exact stem match → `<newBaseName><ext>`; otherwise the trailing language hint `stem.match(/\.([a-z]{2,3}(?:\.[a-z]+){0,2})$/i)` keeps the whole hint (`name.en.hi.forced.srt` keeps `en.hi.forced`) → `<newBaseName>.<hint><ext>`; no hint → `<newBaseName><ext>`. Each is W5. `[ts:src/common/services/file-transfer.service.ts:100-149]`
15. Companion hazards in Nest: the prefix test has no boundary, so `Movie 2.srt` matches the video `Movie.mkv` and a `move` carries another title's subtitle away; two non-exact companions with the same extension map to the same destination name and the second replaces the first; an existing file of the destination name is replaced. [new] C52: a companion whose stem starts with the stem of a **longer-named video in the same directory** is claimed by that video and skipped (the rule `claimed()` of the companion listing, `[ts:src/modules/media/media-service/media-companions.service.ts:109-113]`); a companion never replaces an existing file; both cases log `WARN` and leave the source in place on `move`.
16. `getCompanionExts()`: `SELECT value FROM app_settings WHERE key = 'companion_file_extensions' LIMIT 1`; `value ?? DEFAULT` (default `.srt,.ass,.ssa,.vtt,.idx,.sub,.nfo,.jpg,.jpeg,.png,.webp,.edl`); split on `,`, trim, lowercase, drop empties, prefix `.` when missing. A stored empty string yields an empty set (no companions at all). `[ts:src/common/services/file-transfer.service.ts:156-168]`

### D. library-ingest

17. `ingest(req)`: `req` = `{mediaId, files: [{path, episodeId?, size?}], transfer: 'copy'|'move', fallbackQuality?, releaseName?, sourceLabel, force?, uniquifyOnCollision?, replaceExisting?}`; result `{imported: [{file: MediaFile, episodeId?, seasonId?, sourcePath}], alreadyPresent: string[]}`. Callers: disk import (`confirmImport`, rule 92; `uniquifyOnCollision` only for reorganize, never `replaceExisting`) and the plugin `library.ingest` (`replaceExisting: true`, `releaseName = sourceLabel`, rule 100, S8). `[ts:src/common/library-ingest/library-ingest.service.ts:24-59]`, `[ts:src/modules/plugins/host/fliks-host.service.ts:835-843]`
18. Preconditions, all thrown as plain `Error` (the plugin caller sees the message; disk import turns it into an `errors[]` entry, rule 92): media missing `Media #<id> not found`; `media.path` null `Media #<id> is not anchored to a library folder`; empty `folderName` `Media #<id> has no folder of its own, refusing to place files at the library root`; `files: []` returns `{imported: [], alreadyPresent: []}`. [new] F44: plus rules 3-5 (folderName and path containment). `[ts:src/common/library-ingest/library-ingest.service.ts:90-112]`
19. File selection: a **season pack** is `type = series` with more than one file: every file is its own episode. Any other request keeps only the largest file by `size ?? 0` (`reduce` with `(a.size ?? 0) > (b.size ?? 0) ? a : b`: on equal sizes the **later** file wins) and ignores the rest (samples, proofs and extras ride in the same download folder). A one-file request is unaffected. Neither caller sends `size` (plugin `{path}` only, `confirmImport` one file), so a multi-file non-pack plugin request keeps the **last** path; [new] Rust `stat`s each source so "largest" is real. `[ts:src/common/library-ingest/library-ingest.service.ts:114-126]`
20. Episode resolution per file (non-movie only): `epNums = naming.parseEpisodeNumbers(basename-without-ext, path) ?? (releaseName ? parseEpisodeNumbers(releaseName) : null)` giving `{season, episode, episodeEnd?}`. A caller `episodeId` is authoritative only when `SELECT e.*, s.* FROM episodes e JOIN seasons s ON s.id = e."seasonId" WHERE e.id = $1 AND s."mediaId" = $2` finds it (else `WARN` and filename parsing); then `episodeNumber/seasonNumber (default 1)/title/airDate` come from the row. Else with `epNums`: `seasons WHERE "mediaId" = $1 AND "seasonNumber" = $2`, then `episodes WHERE "seasonId" = $1 AND "episodeNumber" = $2`; a found episode whose `endEpisodeNumber` differs from `epNums.episodeEnd` is updated only when `epNums.episodeEnd` is set (`UPDATE episodes SET "endEpisodeNumber" = $2`; a name without a range never clears one); a missing season or episode leaves the ids unset (**ingest never creates seasons or episodes**; the file is stored with `episodeId = null`). Else no numbering: season 0 with its episodes, `matchSpecialByTitle(sourceBase, episodes)`; a match sets season 0 / the episode, no match no link. `[ts:src/common/library-ingest/library-ingest.service.ts:154-232]`
21. Quality: `ffprobe.detectMediaFileInfo(file.path)` on the **source** (a bad file yields `{video: [], audio: [], subtitles: [], error}`, stored as `streamInfo`; an unreachable engine **throws**, which aborts the call at that file before its transfer, earlier files stay); with dimensions, `quality = qualityFromResolution(releaseName ?? basename(file.path), width, height)` (pixels win over the release label: a mislabeled 2160p of 1920x804 is 1080p); else `req.fallbackQuality ?? ''`. `releaseGroup = releaseName ? naming.extractReleaseGroup(releaseName) : undefined`. `[ts:src/common/library-ingest/library-ingest.service.ts:234-248]`, `[ts:src/modules/media-probe/ffprobe.service.ts:232-237]`
22. Collision. `relativePath = relativePathUnderMediaRoot(M, destPath)`; null = `ERROR computed dest outside media folder` and the file is skipped **silently** (in neither `imported` nor `alreadyPresent`, Rust reports it as an error entry, C53). `collides(rel, abs) = existsSync(abs) || a media_files row (mediaId, relativePath)`. `sourceSize` = `stat(source).size` (0 on failure). `overwrite = force || (replaceExisting && !sameSize(dest, sourceSize))` (`sameSize` = a destination of equal size exists: a retried import is a no-op). Without `overwrite` and colliding: no `uniquifyOnCollision` → push the source path to `alreadyPresent`, continue (companions are not touched); with it → `n = 2..99`, `base = "<newBaseName> (n)"`, destination `destDir/base+ext`, until free or `n = 100`. `[ts:src/common/library-ingest/library-ingest.service.ts:280-331]`
23. Write order per file, failures abort the **whole call** at that file (earlier files stay written and persisted): log; `transferFile` (W1, W2 or W4); when `overwrite || replaceExisting` the stale EDL of `dest` is removed (W6); `transferCompanions` with `srcDir = dirname(file.path)`, `destDir`, `sourceBaseName = basename(file.path)` minus ext, `newBaseName`, `allowedExts` (W5); then `finalSize = stat(dest).size` (fallback `file.size ?? sourceSize`); then the row. `[ts:src/common/library-ingest/library-ingest.service.ts:333-362]`
24. Row: `payload = {episode: {id} | null, size: finalSize, quality, streamInfo?}`; `SELECT * FROM media_files WHERE "mediaId" = $1 AND "relativePath" = $2`; found → `UPDATE media_files SET episodeId, size, quality, streamInfo, "updatedAt"` (an overwrite re-imports onto its own row); else `INSERT INTO media_files ("mediaId","episodeId","relativePath",size,quality,"streamInfo")`. Then `UPDATE episodes SET "hasFile" = true WHERE id = $1` when `episodeId` is set. 29. ## Vectors/parity

Rust tests run only on generated trees under `/tmp/fliks-parity/` (temp dirs per test, `tempfile`), asserting the final tree and every touched path. **No test or parity run writes to real media** (plan §0 rule 10). The `ingest-fs` unit tests are mandatory (plan §10 S5 "Safety"); each case asserts that nothing outside the temp library root changed (a sentinel file and directory mtime outside it, a recursive tree hash before and after).

Escape and safety cases (each runs for `copy` and `move`, as an ingest and, where it applies, through the relink route):

V1. `folderName` = `..`, `.`, `a/b`, `a\b`, absolute path, empty with a series, NUL, 300 bytes: rejected, nothing created (rule 3).
V2. Provider title `..`, `.`, `/`, `AC/DC`, `CON`, all-illegal characters: the folder name is validated, never `..` (rule 3, 4).
V3. Season folder format resolving to `..`: rejected.
V4. File name base empty, 300 bytes, ending in a space or dot; extension `.sh`, `.MKV`, none: rules 4.
V5. Symlinked media folder inside the root (target inside): allowed and written through; target outside the root: refused, nothing written (rule 5).
V6. Symlinked library root: `Lc` resolved, writes land under it.
V7. Library root missing, a file, unreadable: no `mkdir` of the root, error (rule 5).
V8. Source is a symlink to a regular file, to a directory, dangling, a FIFO, a directory named `x.mkv`: refused or resolved, `move` never relocates a link (rule 7).
V9. Source equals destination: no transfer, row linked (rule 13).
V10. Destination exists: `alreadyPresent`, bytes untouched; concurrent duplicate ingest: exactly one writer wins, the other `alreadyPresent`, no replaced file (rule 12); `uniquify` tries `(2)`..`(99)`, an error entry only when `(99)` is also taken (Nest overwrites `(99)`).
