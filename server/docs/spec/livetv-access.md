## Rules

### Vocabulary and storage

1. A group is a free-text `channel.groupName`; a channel with no provider group stores the sentinel `__livetv_ungrouped__` (never null after ingestion; null only on rows older than migration `1785600000000`), so it can be listed, counted and restricted. `normalizeGroupName(raw)` = `trim()` then the sentinel when empty (the one function of `livetv-sources.md` rule 27). `[ts:src/modules/livetv/parsing/group-name.ts:8-16]`
2. Fold key of a group = `trim().toLowerCase()` (accents kept on purpose). Every comparison of restrictions, grants and exemptions uses it, never exact text. `[ts:src/modules/livetv/parsing/group-key.ts:6-8]` Rust: `fliks_domain::js` JS `trim()` (the set of `livetv-sources.md` rule 27, one helper for both rules; never `str::trim`, which strips U+0085 and keeps U+FEFF) then `str::to_lowercase`; rule 14 pins where the fold runs.
3. F8: the only live TV route a stream-scope token may call is `GET channels/:id/logo` (native clients append `?token=` to `<img>` loads, `client-audit.md` line 33); every other route here and in `livetv-sessions.md` rejects it. Today Nest accepts it on every route without `SessionTokenGuard`, i.e. also the list, admin `GET`s and all admin writes `[ts:src/modules/livetv/controllers/livetv.controller.ts:55-136]` `[ts:src/modules/auth/strategies/jwt.strategy.ts:59-69]`. `[new]` (F8, listed so the milestone's stream-allowed list is complete)
4. Settings keys written by this module (all through `settings.set(key, value, OWN_MODULE_ORIGIN)`, which is the only way past the protected-key guard of the generic settings API): `livetv_restricted_groups`, `livetv_restricted_groups_exempt` (JSON array of strings), `livetv_restricted_groups_vanished` (JSON object group name to ISO date). `[ts:src/modules/livetv/services/livetv-access.service.ts:18-23]` `[ts:src/modules/settings/settings.service.ts:11-24]` The Rust generic settings PUT already refuses them (`settings.md` rule 9, `crates/server/src/settings/routes.rs`); the S7 writer calls the settings store directly with the own-module origin. Each write emits `settings.changed` like any write (settings.md).
5. Reading a group-set key: absent, empty, unparsable JSON, or not an array yields `[]`; non-string members are dropped. The vanished map: not an object or an array yields `{}`; non-string values dropped. A corrupt value never fails a read. `[ts:src/modules/livetv/services/livetv-access.service.ts:47-58]` `[ts:src/modules/livetv/services/livetv-access.service.ts:92-109]`
6. Writing a group set: trim each, drop empties, deduplicate by fold key keeping the first spelling met, sort with the default JS string sort (UTF-16 code units; Rust: sort by `str` byte order of the UTF-8, equal for BMP text, vectors avoid astral characters). `[ts:src/modules/livetv/services/livetv-access.service.ts:63-81]`
7. One in-process async mutex serialises every read-modify-write of the three keys and the grants table (sync pass `restrictAdultGroups`, `expireVanishedGroups`, admin `setRestrictedGroups`, `setGrants`). Rust: one `tokio::sync::Mutex` in the access service (single process, as the Nest comment says). `[ts:src/modules/livetv/services/livetv-access.service.ts:119-131]`

### Visibility (who sees which channel)

8. `deniedGroups(user)`: restricted set empty returns `[]` with one settings read; a user whose permissions include `manage:all` or `settings.access` returns `[]` (never filtered; an `isAdmin` user's permissions are `['manage:all']`); else every restricted group whose fold key is not among the fold keys of the user's `livetv_group_access` rows. `[ts:src/modules/livetv/services/livetv-access.service.ts:27]` `[ts:src/modules/livetv/services/livetv-access.service.ts:428-440]` `[ts:src/modules/users/entities/user.entity.ts:154-160]`
9. A restricted group is absent for a denied user, not hidden: no row in the list, the count, the guide, the programme lookup or the search, 404 on play, prefs and logo. Hiding (`pref.hidden`) is the viewer's own undoable preference and is never a control. `[ts:src/modules/livetv/services/livetv-channels.service.ts:162-170]`
10. Channel visible to a user (the list, `status`, guide pages) = `channel.enabled = true` and (no pref row or `pref.hidden = false`) and (`groupName IS NULL` or its fold key is not denied). Order: `COALESCE(pref.favorite,false) DESC, number ASC NULLS LAST, sortIndex ASC, name ASC` (C12 adds a final `id ASC`). `group` is an exact match on `groupName` (not folded), `favoritesOnly` adds `pref.favorite = true`, `query` is `name ILIKE '%' || q || '%'` with `%` and `_` in `q` acting as wildcards today ([new] C85: escaped in Rust, `ESCAPE '\'`, as the guide search `q` of `livetv-guide.md` rule 45); an empty `group` or `query` is no filter (truthiness test). `[ts:src/modules/livetv/services/livetv-channels.service.ts:146-184]`
11. `status.available` = count of rule 10 with no filter > 0. `[ts:src/modules/livetv/services/livetv-channels.service.ts:74-76]`
12. Playable (`findPlayable(id, user)`): `enabled = true`, plus the streams with their source, and not in a denied group; absent, disabled and denied are the same 404 `Live TV channel #<id> not found` (never distinguishable). A channel's `hidden` pref and an expired account do not block it. `[ts:src/modules/livetv/services/livetv-channels.service.ts:347-358]` Rust `[new]` (C89): only streams whose `source.enabled = true` are loaded (Nest never reads `source.enabled` here), so a disabled source's channels are not playable: no stream left is 503 `livetv_channel_unavailable` at open and a denial at the resolver (`livetv-sessions.md` rules 5, 30). They stay listed: the vanished-group sweep counts them `[ts:src/modules/livetv/services/livetv-sources.service.ts:641-644]`.
13. `assertVisible(id, user)` (logo): the channel row exists (enabled or not) and is not in a denied group, else the same 404. Prefs (`hidden`) and `enabled` are not checked. `[ts:src/modules/livetv/services/livetv-channels.service.ts:363-374]`
14. Where the fold runs: today the denied keys are folded in JS and compared to `lower(btrim("groupName"))` in SQL (list, guide) but to `foldGroupKey(groupName)` in JS (play, prefs, resolver). `btrim` only strips spaces and `lower` follows the database's `lc_ctype`, so the two predicates can differ for non-ASCII or non-space edge characters. `[ts:src/modules/livetv/services/livetv-channels.service.ts:166-169]` `[ts:src/modules/livetv/services/livetv-channels.service.ts:15-19]` Rust: one predicate only; pass the raw denied names as a `text[]` and fold both sides in SQL (`lower(btrim(x))` on the column and on `unnest($denied)`); play, prefs, logo and the resolver use the same SQL (no JS-side fold). `[new]` (C87)
15. `isGuideChannelVisibleToUser(user, guideChannelId)`: rule 10 with no filters and `"guideChannelId" = $2`, count > 0. Used by `GET programs/:id`. `[ts:src/modules/livetv/services/livetv-channels.service.ts:97-101]`
16. `scopeToAuthorizedGuideChannels(qb, user, column)`: appends a correlated `EXISTS (SELECT 1 FROM livetv_channels c LEFT JOIN livetv_user_channel_prefs pref ON pref."channelId" = c.id AND pref."userId" = $u WHERE c."guideChannelId" = <column> AND c.enabled = true AND (pref.hidden IS NULL OR pref.hidden = false) [AND (c."groupName" IS NULL OR lower(btrim(c."groupName")) NOT IN (denied))])`; never an `IN` list (a 15k-channel lineup would exceed the 65535 bind cap). Used by `search`. `[ts:src/modules/livetv/services/livetv-channels.service.ts:108-129]`
17. `listPageForUser(user, filters, page, pageSize)`: rule 10 counted then `OFFSET (page-1)*pageSize LIMIT pageSize`, used by `guide` and `on-now`; `search` takes page 1. `[ts:src/modules/livetv/services/livetv-channels.service.ts:83-93]`
18. Logo route: `assertVisible`, then `size` in `thumb|medium|full` else `full`; file `<images base>/livetv/<id>[-thumb|-medium].png`; a missing sized file falls back to `full` and adds `X-Image-Size-Served: full`; no file 404 (empty `NotFoundException`: `{statusCode:404,message:"Not Found"}`). `/api/images/livetv/*` is deliberately not served by the image controller (a logo may belong to a restricted group). `[ts:src/modules/livetv/controllers/livetv.controller.ts:74-99]` `[ts:src/modules/images/image.controller.ts:52-54]` `[ts:src/modules/images/image.service.ts:449-451]` `[ts:src/modules/images/image.service.ts:499-503]` `logoPath` in the list is the provider URL until the logo is cached, then `/api/livetv/channels/<id>/logo` `[ts:src/modules/livetv/entities/livetv-channel.entity.ts:20-22]`. Rust `[new]` (F64): every channel payload (this list and the `on-now`, `guide`, `search` items of `livetv-guide.md`) answers `logoPath` only when it is the local path, else `null`; never the provider URL. Contract check: the field stays `string | null` and a cached logo answers the same `/api/livetv/channels/<id>/logo?v=<hash>`, so the client's rendering is unchanged for it; an uncached logo (a channel enabled between two syncs, a dead logo url retried at each sync) shows the client's initials placeholder (`live-tv.html`) instead of the hotlinked provider image.
19. Prefs: channel must be enabled and not denied (404 otherwise, same body as play); no existing row creates one (`favorite false`, `hidden false`, `lastPlayedAt null`), then each given field overwrites. Both fields absent is a no-op 200. `lastPlayedAt` (channel and pref) is never written by any code (dead columns; Rust leaves them untouched). `[ts:src/modules/livetv/services/livetv-channels.service.ts:441-463]`
20. `GET /users/:userId` and `PUT /users/:userId` take the path id as `ParseIntPipe` (C20 applies). `[ts:src/modules/livetv/controllers/livetv-access.controller.ts:49-61]`

### Restricted groups

21. `restrictedGroupsView()`: for each stored restricted name, `automatic` = it matches `ADULT_GROUP_PATTERN` (rule 26), `vanishedSince` = the vanished map entry (exact name key) or null, `cleanupAt` = `vanishedSince + livetv_stale_stream_days * 86 400 000 ms` as ISO or null. `livetv_stale_stream_days`: `parseInt(raw,10)` if finite else 7 (negative and 0 accepted). `[ts:src/modules/livetv/services/livetv-access.service.ts:133-168]`
22. `setRestrictedGroups(groups)` (under the mutex): `previous` = stored set; `unique` = rule 6; `dropped` = previous groups whose fold key is not in `unique`. Order matters and is part of the contract: (a) delete the grants of `dropped` (every stored spelling matching by fold key; a grant stored as `XXX` goes when `xxx` is dropped), (b) write `livetv_restricted_groups`, (c) exemption bookkeeping (rule 23), (d) clear vanished timers of `unique` (rule 25). A failure in (a) leaves the group restricted (safe) rather than open with dangling grants. `[ts:src/modules/livetv/services/livetv-access.service.ts:174-209]` Rust: (a)+(b) in one transaction is allowed (C2 spirit) as long as the visible order holds.
23. Exemptions (`livetv_restricted_groups_exempt`): of the `dropped` groups, those matching the adult pattern are added (an explicit unrestriction that the next sync must not undo); of `unique`, those matching the pattern are removed from it (re-restricting retires the exemption). Keyed by fold key, stored spelling replaced, not duplicated. Written only when either list is non-empty. `[ts:src/modules/livetv/services/livetv-access.service.ts:190-202]`
24. `PUT restricted-groups` answers `unique`. Dropping a group never touches other groups' grants; resubmitting the same group under another casing is not a drop (no grant churn). `[ts:src/modules/livetv/services/livetv-access.service.ts:179-188]`
25. `clearVanished(names)`: deletes the vanished entries whose fold key matches; writes the map only if something changed. Called by `setRestrictedGroups` (for `unique`) and `setGrants` (for the matched groups): an admin confirmation cancels a pending expiry. `[ts:src/modules/livetv/services/livetv-access.service.ts:314-326]`
26. `ADULT_GROUP_PATTERN` (JS source, case-insensitive, no `u` flag so `\b`/`\w` are ASCII): `/\b(?:xxx|sex[eo]?|porn\w*|erot(?:ic|iqu|ik)\w*|x[- ]?rated|adult(?!\s*swim\b)\w*)\b|(?<![a-z0-9])(?:\+18|18\+)(?![a-z0-9])/i`. The Rust `regex` crate has neither look-around nor ASCII-only `\b` by default: use `fancy-regex` (already a `fliks_domain` dependency) with ASCII word semantics (`(?-u:\b)`, `[a-zA-Z0-9_]` for `\w`), or a hand matcher; vectors below are the contract. `[ts:src/modules/livetv/services/livetv-access.service.ts:15-16]`
27. `restrictAdultGroups(groupNames)` (called by the source sync after each source, `[ts:src/modules/livetv/services/livetv-sources.service.ts:457]`, owner of that call: `livetv-sources.md`): under the mutex, `known` = fold keys of restricted plus exempt; additions = names matching the pattern and not known; none returns the current set; else `setRestrictedGroupsLocked([...current, ...additions])` (each addition normalised, nothing dropped; rule 22 (d) also clears the vanished timer of every restricted group, not only the additions: kept). Returns the resulting set. A newly seen adult group is therefore restricted before any non-admin can list it. `[ts:src/modules/livetv/services/livetv-access.service.ts:214-228]`
28. `expireVanishedGroups(liveGroupNames)` (called after a full successful sweep, `[ts:src/modules/livetv/services/livetv-sources.service.ts:635]`, whose caller guarantees `liveGroupNames` is every group any source still carries a channel for, enabled or not `[ts:src/modules/livetv/services/livetv-sources.service.ts:641-644]`): candidates = restricted plus exempt names; a candidate absent (by fold key) from the live set gets `vanished[name] = now` if it had none; a candidate present loses its entry; entries for names no longer candidates are deleted. Expired = vanished entries that were already vanished before this pass (`previouslyVanished`: a group first marked in this pass can never expire in it, even with 0 grace days), are restricted (an exemption never expires), and `since <= now - graceDays`. Expired groups: grants deleted, removed from `livetv_restricted_groups` (re-read, then filtered), vanished entries dropped, one warn log. Map written only if changed; returns the expired names. `[ts:src/modules/livetv/services/livetv-access.service.ts:243-310]`
29. `setGrants(userId, groups)` (under the mutex): `requested` = trimmed, non-empty, exact-deduplicated; matched against the restricted set by fold key; a match is stored under the restricted list's own spelling, a non-match goes to `ignored`; delete all of the user's grants, insert the matched ones, `clearVanished(matched)`; Nest then fire-and-forgets `engine.revokeOwner(userId)` (`POST /v1/revoke {ownerId}`: kills every engine session of that user, VOD included, even when grants only grew). Answer `{groups, ignored}`. Grants for a non-restricted group are never stored (no dormant grant resurrecting later). `[ts:src/modules/livetv/services/livetv-access.service.ts:381-421]` `[ts:src/modules/engine/engine.service.ts:303-313]` Rust `[new]` (C90): no `revokeOwner`; after the write, each live viewer of that user (`livetv-sessions.md` rule 1) whose channel `findPlayable` now refuses is ended (engine `DELETE /v1/sessions/{sid}?reason=revoked`, then `dropViewer`); VOD sessions are untouched. The resolver alone does not suffice: a `direct.ts` viewer is one long response, resolved only when it connects.
30. Unknown `userId` on `PUT users/:userId`: grants are deleted (nothing), then with a non-empty match the insert violates the FK: 500 today. Rust: 404 before any write. `[new]` (C88, C1 spirit)

### Admin channel catalog (shares rule 10's table, not its predicate)

31. `bulkUpdate`: select `id, name` of channels matching the AND of the given selectors (`channelIds` IN, `group` exact, `sourceId` via `EXISTS (SELECT 1 FROM livetv_channel_streams s2 WHERE s2."channelId" = channel.id AND s2."sourceId" = $1)`, `namePattern` ILIKE `%x%`); a selector that is an empty string is skipped, so `{group: ""}` selects every channel; no match returns `{affected: 0}`. Then in this order and not in one transaction: `enabled` update; `groupName` update with `normalizeGroupName` then `UPDATE livetv_channels SET "groupNameSource" = 'manual' WHERE id = ANY($1)` (stops a later sync realigning it); `startNumber` renumbers `orderedIds` (the request's `channelIds` order filtered to matches, else matches sorted by `name.localeCompare`) with `UPDATE livetv_channels AS c SET number = v.n FROM (VALUES ($1,$2),...)
