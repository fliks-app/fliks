# Spec: live TV sources (sources, sync, M3U, Xtream, groups, logos, jobs)

Scope: the live TV source routes, playlist fetch and parse, group patterns, the sync and its lineup upsert, logo caching and the three jobs. Auth, CASL, validation body and error-body rules are in `auth.md` (cited "auth rule N"): validation body = auth rule 16, `ParseIntPipe` 400 = auth rule 18, 403 = auth rule 27; 4xx/5xx `Cache-Control: no-store` = `bootstrap.md` rule 7. Job lifecycle, `run_audited` and the registry listing are `scheduler.md` (rules 5, 11, 18). The logo store is `image-store.md` (rules 14, 18, 20, 23). Notification dispatch is `notifications.md`.

Boundary with the sibling live TV specs. This spec owns the **data side**: source rows, playlist fetch and parse, the lineup upsert (the `livetv_channels` / `livetv_channel_streams` writes made by a sync), the logo cache, the three jobs. `livetv-guide.md` owns guide sources, XMLTV, matching and the guide read routes. `livetv-access.md` owns the admin channel routes (`GET /channels`, `PATCH /channels/bulk|:id`, `POST /channels/merge`, its rules 31-34), the per-user lineup and visibility (rules 10-17), `GET /api/livetv/channels/:id/logo` (rule 18), `prefs`, restricted-groups storage (`livetv_restricted_groups*` settings, the bodies of `restrictAdultGroups` / `expireVanishedGroups`, the adult pattern: rules 21-28) and `foldGroupKey` (rules 2, 14). `livetv-sessions.md` owns play, capacity (it reads `maxStreams`, rule 39 here) and sessions; it reuses the request identity of rule 19 (`liveTvHeaders`) for the engine upstreams. Where a sync calls into them only the call contract is stated here (rules 41-42).

## Routes

7 routes under `/api/livetv/admin/sources`, all with the policy `ability.can(Action.Manage, 'Settings')` (= `manage:all` or `settings.access`); a `scope:'stream'` token is 401. Guards run before pipes (auth rule 17). Dates serialise as ISO strings, an `undefined` field is an absent key, SQL NULL is `null`.

| Method path | Auth | Request | Response | Errors | Side effects |
|---|---|---|---|---|---|
| `GET /api/livetv/admin/sources` | class policy | none | 200 `Source[]` ordered `priority ASC, name ASC, id ASC` | 401, 403 | none |
| `POST /api/livetv/admin/sources/test` | class policy | `TestSource` (rule 5) | **201** `TestResult` (rule 6), **always 201**: failure = `ok:false` + `error` | 400 validation, 401, 403 | outbound fetch, nothing persisted |
| `POST /api/livetv/admin/sources` | class policy | `CreateSource` (rule 3) | 201 `Source` | 400 validation, 400 `<field> is not a valid regular expression: <msg>`, 401, 403 | INSERT `livetv_sources` |
| `POST /api/livetv/admin/sources/playlist` | class policy | multipart, one part named `file`, no other part or field | 201 `{location: string}` (absolute server path) | 400 `No playlist uploaded` (no file or 0 bytes), 400 `That file is not an extended M3U playlist`, 413 over 128 MiB, 400 any extra field or part, 401, 403 | writes `<dataDir>/livetv/playlists/<stem>-<uuid>.m3u` |
| `PATCH /api/livetv/admin/sources/:id` | class policy | path `id` int; `UpdateSource` (rule 4) | 200 `Source` | 400, 404 `Live TV source #<id> not found`, 401, 403 | UPDATE `livetv_sources` |

| `POST /api/livetv/admin/sources/:id/sync` | class policy | path `id` | **201** `SyncResult` (also for `ok:false`; the web client ignores the body) `{ok, added, updated, removed, channelCount, error?}` | 400, 404, **409 `errors.already_running`**, 401, 403 | rules 33-43; the request stays open until the sync ends, unless it sends `Prefer: respond-async` (rule 33) |

`Source` = every `livetv_sources` column (`id, createdAt, updatedAt, name, kind, url, username, userAgent, referer, maxStreams, maxStreamsIsManual, refreshIntervalHours, includeGroupsPattern, excludeGroupsPattern, expiresAt, accountStatus, guideUrls, playlistEtag, playlistLastModified, enabled, priority, lastSyncAt, lastSyncStatus, lastSyncError, lastAdultGuardError, channelCount`) **minus `password`**: the key is absent on every route (list, create, update), like every secret field. Nullable columns are `null`; `guideUrls` is an array (`[]` default); `lastSyncStatus` is `never|ok|error`. The create response is the row as stored with its column defaults (same field set as the list). The 403 body is the standard one (auth rule 27).

## Rules

### A. DTOs and CRUD

1. `kind` is `m3u` or `xtream` (`IsIn`).
2. `url` (create, update, test) = `IsPlaylistLocation`: validation is skipped when the value is a string that `isManagedUpload` accepts (rule 12), otherwise `IsUrl({require_tld:false, require_protocol:true})`: hosts without TLD, IPs and `localhost` accepted; the scheme must be `http` or `https` (an `ftp://` url is rejected at validation).
3. `CreateSource`: `name` string; `kind`; `url`; optional strings `username, password, userAgent, referer, includeGroupsPattern, excludeGroupsPattern`; optional ints `maxStreams >= 0`, `refreshIntervalHours >= 1`, `priority` (any int); optional bool `enabled`. `IsOptional` lets `null` through validation (auth rule 16). Nothing ties `username/password` to `kind: xtream`. Unknown keys 400 `property <k> should not exist`.
4. `UpdateSource` = the same fields, all optional (`kind` and `url` included). Applied field by field on `!== undefined`: an omitted key never touches the row, `null` on a nullable column clears it, `null` on a NOT NULL column (`name, kind, url, maxStreams, refreshIntervalHours, enabled, priority`) is a 400. `maxStreams` present (any value) sets `maxStreamsIsManual = true`; nothing sets it back to false. `password`: absent or `''` keeps the stored value, `null` clears it. The patterns are validated with `dto.x ?? stored.x`.
5. `TestSource` = `kind, url, username, password, userAgent, referer, includeGroupsPattern, excludeGroupsPattern` (as above) plus optional `id` int `>= 1`.
6. `TestResult` fields: `ok, kind, channelCount, onDemandCount, groups:[{name,count}], guideUrl (string|null), guideUrls, playlistUrlFromFile, maxConnections (int|null), expiresAt (ISO|null), accountStatus (string|null), suggestion, error`. Success: `error` absent, `playlistUrlFromFile` a string or `null`, `suggestion` absent unless detected. Failure: `ok:false`, `channelCount:0, onDemandCount:0, groups:[], guideUrl:null, guideUrls:[], maxConnections:null, expiresAt:null, accountStatus:null`, `playlistUrlFromFile` **absent**, `suggestion` kept when detected, `error` = the message. `maxConnections` is `0` (not null) for an M3U header `max-conn="0"`, `null` for an Xtream `0` (rule 21).
7. Test steps in order; any throw becomes the failure body of rule 6 (a bad pattern included: 201 `ok:false`, not 400): (a) `kind=m3u` and the url looks like a panel link (rule 17) fills `suggestion = {suggestedKind:'xtream', baseUrl, username, password}` first, so it survives a failure; (b) `assertNotInternal(url)` (rule 14); (c) compile both patterns; (d) `fetchLineup` with the DTO fields and the resolved password (rule 8), no validators; (e) `classifyEntries` (rule 31); (f) `kind=m3u`, a non-HTTP location and no suggestion yet: `detectXtreamFromStreamUrl(first live entry url)` fills `suggestion`; (g) `playlistUrlFromFile = suggestion ? xtreamPlaylistUrl(suggestion) : null`, `guideUrl = guideUrls[0] ?? null`.
8. Test password: `dto.password` if non-empty, else when `dto.id` is set and that stored row has the **same kind and same url**, the stored password, else `dto.password`. For `kind=xtream` the returned `guideUrl` / `guideUrls` have the query removed (`<base>/xmltv.php`), so the stored password never leaves the server (the client only tests `guideUrl` for presence).
9. Delete, one transaction: collect `DISTINCT "channelId"` of the source's streams, delete the source (streams cascade; `livetv_guide_sources.sourceId` cascades, hence those guide sources' programmes and guide channels), then delete the collected channels that have no stream left (`NOT EXISTS`); their `livetv_user_channel_prefs` cascade. After commit, a managed-upload `url` file is removed (failure only logged). `livetv_group_access` and the restricted-groups settings are untouched.
10. Create stamps `maxStreamsIsManual = (dto.maxStreams != null)`; column defaults: `maxStreams` 0 (= no known limit), `enabled` true, `priority` 0, `refreshIntervalHours` 12, `lastSyncStatus` `never`, `channelCount` 0. A create neither syncs nor creates a guide source.
11. `PATCH` and `DELETE` of an unknown id: 404 `Live TV source #<id> not found`; the stored row is read with its `password` for the update.

### B. Playlist upload and local files

12. `isManagedUpload(location)`: not an http(s) string (`^https?://` after trim, case-insensitive) and the canonical path lies under `<dataDir>/livetv/playlists` (component-wise prefix on the canonical path, so a sibling `playlists-x/` does not match).
13. Upload: limits `fileSize` 128 MiB, `files` 1, `fields` 0, `parts` 2; a missing or empty file is 400; the first 64 bytes decoded as UTF-8 and `trimStart()`ed (JS whitespace, BOM included) must start with `#EXTM3U` or `#EXTINF`, else 400. File name `<stem>-<uuid v4>.m3u`: `stem` = basename of the original name without extension, runs of `[^A-Za-z0-9_-]` replaced by `-`, cut to 40 chars, `playlist` when empty; directory created with `mkdir -p`; the response `{location}` is that absolute path, which the DTO then accepts as `url` (rule 2). The part is streamed to a temp file in the same directory and renamed, never holding 128 MiB in memory.
14. `assertNotInternal` guards **only** the test probe: parse the URL (a parse failure or a local path returns, no guard), `dns.lookup(host, {all:true})`; a lookup failure throws `Could not resolve "<host>": <msg>`; an address flagged by `isInternalAddress` throws `Refused: "<host>" resolves to an internal address (<ip>)`. Blocked IPv4: `0/8, 10/8, 100.64/10, 127/8, 169.254/16, 172.16/12, 192.0.0/24, 192.0.2/24, 192.168/16, 198.18/15, 198.51.100/24, 203.0.113/24, 224/4, 240/4`; IPv6 `::`, `::1`, `fe80::/10`, `fc00::/7`, `ff00::/8`, and `::ffff:0:0/96` / `64:ff9b::/96` judged on the embedded IPv4; an unparsable address counts as internal. Registered sources, syncs, guide fetches and logo downloads are never guarded: a LAN provider must keep working (admin-set urls are accepted, as admin-set notification endpoints are). The probe resolves once, connects to the vetted address (no second resolution), re-vets every redirect hop (max 5) and accepts `http` and `https` only.
15. A source `url` that is neither http(s) nor a managed upload fails the sync with `Not an uploaded playlist` (no file is read).
16. Local playlist read = the whole file as UTF-8 (invalid bytes become U+FFFD) plus `version = String(stat.mtimeMs)` stored in `playlistLastModified`. The file is read line by line with lossy decoding; the `version` format is not part of the contract.

### C. Xtream client

17. `detectXtreamFromUrl(raw)`: `pathname` matches `/\/(get|player_api|xmltv)\.php$/i` and `username` and `password` query params are non-empty (URLSearchParams decoding): result `{baseUrl: protocol//host (the host keeps its port, any path prefix is dropped), username, password}`. `detectXtreamFromStreamUrl(raw)`: split `pathname` on `/`, drop empties, skip one leading `live|movie|series` (case-insensitive); the next three segments are `username, password, last`, all required; `last` must match `^[^/]+\.[A-Za-z0-9]+$`; credentials stay percent-encoded as in the path. `xtreamPlaylistUrl` = `<base>/get.php?username=<enc>&password=<enc>&type=m3u_plus&output=ts`.
18. Two encodings, do not unify: panel API calls build the query with form encoding (space as `+`, only alphanumerics and `*-._` kept); `streamUrl`, `guideUrl` and `xtreamPlaylistUrl` use `encodeURIComponent` encoding (keeps `A-Za-z0-9-_.!~*'()`). One explicit encoder per case. The base URL is concatenated verbatim (`<baseUrl>/player_api.php`; a trailing slash gives `//`).
19. Panel calls: `GET <base>/player_api.php?username&password[&action=…]`, socket idle timeout 20 s, max 2 redirects, UA `source.userAgent || "VLC/3.0.20 LibVLC/3.0.20"`, `Referer` when set, status 2xx or 304 (a bodiless 304 then fails as below), body cap 512 MiB, body parsed as JSON (a non-JSON body stays a string).
20. `account()`: `user_info` absent (a non-JSON body too) or `String(auth ?? '1') === '0'` throws `authentication refused by the provider`. Fields: `status` trimmed string or null; `expiresAt` from `exp_date` (int seconds, `0` or missing → null); `maxConnections` int (`parseInt`, NaN → 0); `allowedOutputFormats` = lowercase strings of an array, else `[]`. `liveStreams()`: `get_live_categories` and `get_live_streams` in parallel; `null`/`undefined` answers count as empty; any non-array, non-null answer is a clear error; category map `String(category_id)` → `String(category_name ?? '').trim()`; per stream: skip `stream_id == null`; `streamId = String(stream_id)`; `name` trimmed, **skipped when empty**; `number = int(num) || null`; `logo = stream_icon`, `guideChannelId = epg_channel_id`, `directSource = direct_source`, each a trimmed non-empty string or null; `categoryName = normalizeGroupName(map[String(category_id)])`. Values use JS `String()`/`parseInt` semantics (panels send numbers and numeric strings). `expiresAt` and billing dates are ISO 8601 only, read as UTC; an int32 out of range in a provider payload is read as null.
21. `pickOutputFormat(allowed)`: empty → `ts`, contains `ts` → `ts`, else `allowed[0]`. Entry url = `direct_source` when present, else `<base>/live/<enc user>/<enc pass>/<streamId>.<format>`. Xtream entries have `qualityLabel null, shiftMinutes 0, userAgent null, referer null`; the guide url list is `[<base>/xmltv.php?username=<enc>&password=<enc>]`; `maxConnections = account.maxConnections || null`. A repeated `streamId` would violate `UQ_livetv_stream_source_external`, hence the dedup. Entries are deduped by `externalId`, first wins (as M3U).

### D. M3U parser (`parseM3u`, pure; vectors)

22. Lines split on `\r?\n`, `trim()`med (JS whitespace), empty lines skipped. `#EXTM3U…` (any line starting so, the last wins): attrs via `/([A-Za-z0-9_-]+)="([^"]*)"/g`, keys lowercased, a later duplicate overwrites; `guideUrls` = `x-tvg-url || url-tvg` split on `,`, trimmed, empties dropped; `maxConnections = intOrNull(max-conn)` (`parseInt`; absent or empty → null; `"0"` → 0); `expiresAt = parseDateAttr(billed-till)`: digits only → epoch seconds when `> 1_000_000_000` else null, otherwise `Date.parse`, NaN → null.
23. `#EXTINF…`: attrs parsed on the **whole line** (a `key="v"` inside the display name counts), display name = text after the **first** comma, trimmed (no comma → `''`); it starts a pending entry and resets `pendingGroup`. A line starting `#EXTGRP` sets `pendingGroup` = the text after its first `:` (trimmed, empty → null; with no `:` the whole line, e.g. `#EXTGRP`), so it only counts after its `#EXTINF`. `#EXTVLCOPT:` while an entry is pending: `http-user-agent` → userAgent, `http-referrer` or `http-referer` → referer (non-empty values only). `#KODIPROP:inputstream.adaptive.stream_headers=<qs>`: `&`-separated `k=v`, `k` lowercased, value `decodeURIComponent` (undecodable kept raw), `user-agent` and `referer|referrer` taken. Any other `#` line, and any non-`#` line without a pending entry, is ignored.
24. A non-`#` line with a pending entry closes it (the url is not validated). `displayName = name || attrs['tvg-name'] || ''`, empty → entry dropped. `externalId = deriveExternalId`; an id already seen in this playlist drops the later entry (first wins). Entry: `logo = tvg-logo || null`, `groupName = normalizeGroupName(group-title || pendingGroup)`, `tvgId = tvg-id || null`, `number = intOrNull(tvg-chno ?? channel-number)` (`??`: an empty `tvg-chno=""` is used and gives null), `shiftMinutes = round(parseFloat(tvg-shift) * 60)` (hours, fractional; NaN → 0; `Math.round` = half up, `fliks_domain::js`), `userAgent/referer` from the directives; all raw attrs are kept (`tvg-quality` becomes `qualityLabel`).
25. `deriveExternalId(attrs, url, name)`: path = url before the first `?`; `last` = text after the last `/` with one trailing `.<alnum>` extension removed; returned when non-empty, not in the generic set (`index master playlist live stream chunklist variant manifest tracks-v1a1 video`, case-insensitive) and `^[A-Za-z0-9_.-]+$`; else the whole url; else `normalizeChannelName(name)`. Never `tvg-id` (quality variants share it).
26. `isOnDemandUrl(url)` = `/\/(movie|series)\//i` on the url before `?`.
27. `normalizeGroupName(raw)` = JS `trim()` (set: `\t-\r`, space, U+00A0, U+1680, U+2000-U+200A, U+2028, U+2029, U+202F, U+205F, U+3000, U+FEFF; **not** U+0085, which Rust's `str::trim` strips: use `fliks_domain::js`) or the sentinel `__livetv_ungrouped__` when empty or null. One Rust function, also used by `livetv-access.md` rule 1 (the trim set here is the contract). The sync never folds group keys (`foldGroupKey` is `livetv-access.md`'s).
28. `normalizeChannelName(raw)`: `toLowerCase`, NFD, remove U+0300-U+036F, replace `[...]` and `(...)` (not nested) by a space, strip one leading `^[a-z]{2,3}\s*[:|]\s*` (only when the text starts with it after the bracket pass, so `[HD] FR: x` keeps its prefix), runs of `[^a-z0-9+]` → space, remove the noise words `fhd uhd hd sd 4k 8k 1080p? 720p? 576p? 480p? h265 hevc h264 raw backup multi vip plus\+?` with an **ASCII** `\b` (Rust: `(?-u:\b)`), collapse spaces, trim. NFD needs the `unicode-normalization` crate. `nameTokens` = the space-split set in insertion order; `tokenSimilarity` = Jaccard, 0 when either side is empty.
29. Provider text (names, groups, logos, urls) never contains U+0000: it is stripped at parse (Postgres rejects it), for M3U and Xtream alike.

### E. Group patterns and classification

30. `includeGroupsPattern` / `excludeGroupsPattern` are tested against the **normalised group name** (the sentinel included), case-insensitively. At save and test time an invalid regex is `BadRequestException` `<field> is not a valid regular expression: <engine message>`. At sync time an invalid saved pattern is ignored with a warn log (include: every group imports; exclude: nothing excluded). Empty string = no pattern. Patterns are free text (no default, no client preset), so stored patterns must keep compiling: matching uses `fancy-regex` (already a `fliks_domain` dependency, as for the adult pattern) with `(?i)`, which accepts look-around and back-references; a 200 000-step backtrack limit bounds a match: a match that hits it counts as an invalid pattern for that sync (ignored with a warn; a test answers `ok:false`), and a pattern `fancy-regex` rejects is 400 at save and test, ignored with a warn at sync. Remaining syntax gaps (JS-only escapes such as `\cX`, ASCII-only `\d`/`\w`/`\b` without the `u` flag) are listed by the vectors.
31. `classifyEntries(entries, include, exclude)`: drop `isOnDemandUrl` entries (counted in `onDemandCount`); `groups` = counts of `groupName` over the remaining entries **before** the patterns, sorted by count descending (stable: ties keep first-seen order); `live` = remaining entries not matching `exclude` and (no `include` or matching it): exclude wins.
32. `liveTvAccountStateOf(expiresAt, accountStatus, now)`: `accountStatus` lowercased equals `expired` → `expired`; no `expiresAt` → `ok`; `expiresAt <= now` → `expired`; within 7 days → `expiring`; else `ok`.

### F. Sync

33. Single-flight: `POST …/:id/sync` and the cron both claim the activity `LiveTvSourceSync:<id>` (type `LiveTvSourceSync`) in the activity registry; a held claim → 409 `errors.already_running`; the claim is released in `finally`. The claim is taken before the source is loaded, so an unknown id answers 404 after claiming. With `Prefer: respond-async` the route answers **202** with `Preference-Applied: respond-async` and the queued `commands` row (`name` `LiveTvSourceSync`, `body {sourceId}`) once the claim is held and the source exists; the sync then runs detached under that row (`command.started`, then `command.completed` with `completed`, or `failed` when it ends `ok:false`), holding the claim until it ends. A 404 and a 409 are answered before the 202; without the header nothing changes (201 and the blocking sync).
34. Fetch phase (rules 15-21, 35). A throw from the fetch: row updated `lastSyncAt = now, lastSyncStatus = 'error', lastSyncError = <message>`, lineup untouched, response 201 `{ok:false, added:0, updated:0, removed:0, channelCount:<previous>, error}`. Messages never contain the request URL, userinfo or query. Other throws (database errors) propagate as 500.
35. Conditional fetch (M3U only): `If-None-Match: <playlistEtag>` and `If-Modified-Since: <playlistLastModified>` when stored; a 304 (for a local file: `playlistLastModified === version`) = not modified. M3U fetch: UA and Referer from the source, socket idle timeout 30 s, max 5 redirects, status 2xx or 304 only, `Content-Encoding` decoded by the client, body cap 512 MiB counted after that decoding, text decoded as UTF-8 with a leading BOM stripped; the response `ETag` / `Last-Modified` (strings, else null) are stored on success. A PATCH that **changes** one of `url, kind, username, password, userAgent, referer` or either pattern (compared with the stored row: the web form resends every field on each save) clears `playlistEtag` and `playlistLastModified` and sets `channelCount = 0` (the next sync is full and the shrink guard of rule 37 is off for it; the list shows 0 channels until then). A refused provider connection reports `connect ECONNREFUSED host:port`.
36. Not modified: row `lastSyncAt = now, lastSyncStatus = 'ok', lastSyncError = null` only (`channelCount`, `guideUrls`, account fields untouched), then the vanished-group sweep (rule 41); response `{ok:true, added:0, updated:0, removed:0, channelCount:<stored>}`.
37. Shrink guard, after classify: when the stored `channelCount > 0` and `live.length < channelCount * 0.5`, only `lastSyncAt`, `lastSyncStatus 'error'` and `lastSyncError` = `refresh returned <n> live entries against <m> known: treating it as a truncated response and keeping the current lineup` are written; response `ok:false` with that message and the stored `channelCount`. `channelCount` is the previous **post-pattern** count, so a legitimate pattern narrowing over 50 % is refused until it is reset (rule 35).
38. Upsert (one transaction), `staleDays = int(setting livetv_stale_stream_days, 7)`. Existing streams of this source are keyed by `externalId`; all channels (enabled or not, every source) are loaded with their `groupNameSource`.
    1. Entry whose `externalId` matches an existing stream of this source: update that stream's `url, providerName (= entry name), qualityLabel, userAgent, referer, lastSeenAt = now`; on its channel: `guideChannelId` null and `entry.tvgId` set → set it (never overwritten); `groupNameSource <> 'manual'` and the group differs → `groupName = entry.groupName`. Name, number, logo, `guideShiftMinutes`, `enabled` are never touched.
    2. Otherwise fold: `key = normalizeChannelName(entry.name)`; the target is the **first** channel with that key among the channels that have **no stream from this source** (key map built once before the loop; channels are read `ORDER BY id`, so the lowest id wins). A target not already used by an earlier fold of this sync gets a new stream with `priority = its stream count at load` (a target takes one fold per sync), the same guide-id backfill and group realign as step 1, and counts as having a stream of this source afterwards. Empty key → no fold.
    3. Otherwise a new channel `{name, number: entry.number, logoPath: entry.logo, groupName, enabled:false, guideChannelId: tvgId, guideMatchKind:null, guideShiftMinutes: entry.shiftMinutes}` (`sortIndex` 0, `groupNameSource 'provider'`) and a stream with `priority 0`. A channel created in this sync is not a fold target for later entries of the same sync.
    4. Removal: streams of this source whose `externalId` is not among this sync's entries **and** (`lastSeenAt` null or `< now - staleDays days`) are deleted; a channel left with no stream is deleted (prefs cascade). `staleDays` 0 or negative removes every unseen stream at once.
    5. Counts: `added` = new streams (folds included), `updated` = existing streams matched (changed or not), `removed` = streams deleted. Stored `channelCount` = `live.length` (entries, not channels).
39. After the upsert the source row is updated: `lastSyncAt, lastSyncStatus 'ok', lastSyncError null, channelCount, guideUrls = fetched.guideUrls, playlistEtag, playlistLastModified` (null for Xtream), `expiresAt = fetched.expiresAt ?? stored`, `accountStatus = fetched.accountStatus ?? stored`, `maxStreams = fetched.maxConnections` when it is truthy and `maxStreamsIsManual` is false, else unchanged. Xtream `guideUrls` are stored as `[]` (the guide url is derived from the credentials on demand, rule 21), so the panel password is never stored there. This row is written in the upsert transaction.
40. Account notifications, before the row update, fire-and-forget: compare `liveTvAccountStateOf(stored expiresAt, stored accountStatus)` with the state of the values about to be written; only a **change** to `expired` dispatches `livetv.account_expired`, to `expiring` `livetv.account_expiring`, payload `{sourceName, expiresAt: ISO|null}` (`notifications.md`); `ok` and unchanged states are silent. Not run on 304 or error.
41. Adult guard and sweep, after the row update: `access.restrictAdultGroups(distinct group names of the post-on-demand, pre-pattern groups)` (contract: adds adult-looking groups to the restricted set unless exempt; body in the access spec). A throw is caught: error log, `notifications.dispatch('livetv.adult_guard_failed', {sourceName})` (fire-and-forget), `lastAdultGuardError = <message>` (best effort); `lastSyncStatus` stays `ok`; a success clears a stored `lastAdultGuardError`. Then `maybeExpireVanishedGroups`: skipped unless at least one source is enabled **and every enabled source has `lastSyncStatus = 'ok'`** (`never` blocks it); otherwise `access.expireVanishedGroups(DISTINCT "groupName" of channels that have at least one stream, any source, enabled or not)`; errors are only logged. A disabled source's channels stay in that input although they cannot be played (`livetv-access.md`): disabling is reversible, so it must not expire a group's restriction and grants. A PATCH `enabled:false` only writes the column; the play path filters. Runs after success and after 304, not after an error or a shrink refusal.
42. Logo pass, last, fire-and-forget (the response does not wait): channels with `enabled = true` and a stream of this source whose `logoPath` matches `^https?://` (case-insensitive) go through `cacheLogos` (rule 44).
43. Response `{ok:true, added, updated, removed, channelCount: live.length}`; the info log `Sync "<name>": added=… updated=… removed=… (live=… onDemandSkipped=…)` carries no url.

### G. Logos

44. `cacheLogos(channels)`: 4 workers on one queue; each target runs `ImageStore::download_and_store(url, &Target::livetv(channel id))` in-process (the image store, `image-store.md` rule 20); a non-null result is written with `UPDATE livetv_channels SET "logoPath" = <path>` (form `/api/livetv/channels/<id>/logo?v=<hash>`, image-store rule 14); `null` (undecodable image) or a throw leaves the remote url and only warns (the URL logged without userinfo and query, image-store rule 23). A dead logo url is retried at every sync. The `logoPath` of an existing channel is never refreshed from the provider (the cached path does not match `^https?://`); a channel enabled after a sync gets its logo cached at the next sync.
45. Logo serving (`GET /api/livetv/channels/:id/logo`) and the layout `<dataDir>/livetv/<id><S>.png` belong to the sibling channels spec and `image-store.md` rule 18.

### H. Jobs

46. Three jobs, `triggerable: true`, labels `liveTv.jobs.sourceRefresh`, `liveTv.jobs.guideRefresh`, `liveTv.jobs.guidePrune`: `LiveTvSourceRefresh` cron `0 0-23/1 * * *` (hourly at :00), `LiveTvGuideRefresh` the same, `LiveTvGuidePrune` `0 01 * * *` (01:00, server local time like the other crons, `scheduler.md`; `scheduler.md` states the DST behaviour). The three names are a list of their own in `jobs::names`, outside `CORE`, counted by `is_core` and spawned by `jobs::spawn` (listed after the core five, in this order, `pluginId: null`, `scheduler.md` rules 11, 15); their bodies are in `jobs::bodies::run`. The job runner audits them: the cron tick through `run_audited(name, Scheduled)`, a manual trigger through its queued row (`scheduler.md` rule 6), so a body writes no row itself. Both take the name's `jobs::Running` claim (a trigger while it runs is 409, an overlapping tick is skipped; a restore is refused meanwhile, `system.md` rule 25).
47. `refreshSources`: `findAll()` order, sequential, skipping `enabled = false` and not-due sources; due = `lastSyncAt` null or `now - lastSyncAt >= refreshIntervalHours * 3600 s` (less the tolerance below); a failing `sync(id)` (a 409 included) is logged `Source #<id> sync skipped: <err>` and the loop continues. A manual `POST …/:id/sync` runs whatever `enabled` says. Due when `now - lastSyncAt >= interval - 5 min` (a 5-minute tolerance), so with hourly ticks a sync finished at 10:00:03 with a 12 h interval runs at the 22:00 tick.
48. `refreshGuides` and `pruneGuide`: `livetv-guide.md` rules 31 and 47.

### I. Decisions

49. `livetv_sources.password` is stored in clear, as secret settings are. Encryption at rest of every secret is a separate concern.
50. No 500 on input the DTO lets through: `null` on `name, kind, url, maxStreams, refreshIntervalHours, enabled, priority`, a `priority` outside int32 and an `:id` deleted by a concurrent request are 400 (404 for the deleted id). Every list of this spec ends with `id ASC`.
51. Stored patterns keep compiling (`fancy-regex`, rule 30; no default pattern exists to migrate); SSRF on registered sources and admin-set guide urls stays open like admin-set notification endpoints, while a guide url the provider chose (an `x-tvg-url` off the source host) is fetched vetted, every hop pinned, and so is the engine upstream of a stream url off the source host (`livetv-sessions.md` rule 10); logo urls stay open (rule 14, `image-store.md` rule 14); the boundary with `livetv-access.md` and `livetv-sessions.md` is the paragraph at the top (no rule owned twice).

## SQL

Columns are camelCase, quoted.

- list: `SELECT <all columns but password> FROM livetv_sources ORDER BY priority, name, id`.
- by id (with password): `SELECT * FROM livetv_sources WHERE id = $1`.
- insert: `INSERT INTO livetv_sources (name, kind, url, username, password, "userAgent", referer, "maxStreams", "maxStreamsIsManual", "refreshIntervalHours", enabled, priority, "includeGroupsPattern", "excludeGroupsPattern") VALUES (…) RETURNING *` (omitted fields take the column defaults; `maxStreamsIsManual = ($maxStreams IS NOT NULL)`).
- patch: `UPDATE livetv_sources SET <only the present fields> WHERE id = $1 RETURNING *`; `"updatedAt"` is bumped by the BEFORE UPDATE trigger; an empty patch writes nothing.
- delete (one tx): `SELECT DISTINCT "channelId" FROM livetv_channel_streams WHERE "sourceId" = $1`, `DELETE FROM livetv_sources WHERE id = $1`, `DELETE FROM livetv_channels c WHERE c.id = ANY($1) AND NOT EXISTS (SELECT 1 FROM livetv_channel_streams s WHERE s."channelId" = c.id)`.
- sync load: `SELECT * FROM livetv_channel_streams WHERE "sourceId" = $1`; `SELECT id, name, "groupName", "groupNameSource", "guideChannelId" FROM livetv_channels ORDER BY id` and `SELECT "channelId", "sourceId" FROM livetv_channel_streams` (fold targets, per-channel stream counts).
- sync writes (set based): `INSERT INTO livetv_channels (name, number, "logoPath", "groupName", enabled, "guideChannelId", "guideMatchKind", "guideShiftMinutes") SELECT … FROM UNNEST(…) WITH ORDINALITY … RETURNING id` (row order preserved to pair with entries); `INSERT INTO livetv_channel_streams ("channelId", "sourceId", "externalId", url, priority, "qualityLabel", "providerName", "userAgent", referer, "lastSeenAt") SELECT … FROM UNNEST(…)`; `UPDATE livetv_channel_streams s SET url = v.url, "providerName" = v.name, "qualityLabel" = v.q, "userAgent" = v.ua, referer = v.ref, "lastSeenAt" = $now FROM (SELECT … FROM UNNEST(…)) v WHERE s.id = v.id`; `UPDATE livetv_channels c SET "guideChannelId" = COALESCE(NULLIF(c."guideChannelId", ''), v.g), "groupName" = CASE WHEN c."groupNameSource" = 'manual' THEN c."groupName" ELSE v.grp END FROM (…) v WHERE c.id = v.id` with **one `v` row per channel**, reduced in code in entry order (Postgres picks an arbitrary row among duplicates): `g` = the first non-null `tvgId` of the entries hitting that channel, `grp` = the last entry's group (realigned entry by entry); removal `DELETE FROM livetv_channel_streams WHERE id = ANY($1)` then `DELETE FROM livetv_channels c WHERE c.id = ANY($affected) AND NOT EXISTS (SELECT 1 FROM livetv_channel_streams s WHERE s."channelId" = c.id)`.
- unique index `UQ_livetv_stream_source_external ("sourceId", "externalId")`: a duplicate inside one sync would abort the transaction (hence the dedup of rule 21).
- vanished-group input: `SELECT DISTINCT "groupName" FROM livetv_channels c WHERE EXISTS (SELECT 1 FROM livetv_channel_streams s WHERE s."channelId" = c.id)`.
- jobs: `SELECT * FROM livetv_sources ORDER BY priority, name, id` (filtered in code).
- logos: `SELECT c.id, c."logoPath" FROM livetv_channels c WHERE c.enabled AND EXISTS (SELECT 1 FROM livetv_channel_streams s WHERE s."channelId" = c.id AND s."sourceId" = $1)`; `UPDATE livetv_channels SET "logoPath" = $2 WHERE id = $1`.
- migration: `UPDATE livetv_sources SET "guideUrls" = '[]'::jsonb WHERE kind = 'xtream'`.
