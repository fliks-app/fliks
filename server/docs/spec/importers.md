# Spec: importers (Radarr, Sonarr, Seerr) and the NFO reader

Out of scope here: the disk import / orphan routes of the same controller and the local artwork helpers (`disk-import` spec). The NFO reader is specified here because only the disk import and `media-import` call it (rule 48).

## Routes

8 routes of the 12 in the imports controller (the other 4 are `library/**` and `orphans/preview`). Class-level guards `JwtOrApiKeyGuard, PoliciesGuard`; the extractor rejects a `scope:'stream'` token with 401. `Manage Settings` and `Create Settings` are both satisfied by `settings.access` or `manage:all` (auth rules 20, 25). Every POST answers **201**. Bodies are validated by the global pipe (auth rule 16; whitelist, forbid unknown keys, transform): unknown keys 400, nested objects included.

Shapes: `TestResult` = `{ok: boolean, message: string}`. `ApiImportResult` = `{imported: number, errors: string[], rootFoldersCreated: string[] (always `[]`, rule 21), qualityProfilesCreated: string[], subtitlesImported?: number}`; `subtitlesImported` is absent on the "nothing found" early return and present (possibly `0`) otherwise. `PreviewImportResult` = `{remoteRootFolders: {remotePath: string, suggestedLocalLibraryId: number|null}[], localLibraries: {id: number, name: string, path: string|null}[]}`.

## Rules

### A. Request handling (all importer routes)

1. API key resolution `resolveApiKey(provided, settingKey)`: a `provided` string that is non-blank after `trim()` is used as sent (not trimmed); otherwise the stored `app_settings` value of `radarr_api_key` / `sonarr_api_key` / `seerr_api_key` (subject to rule 35); neither → 400 `apiKey is required`. Secrets are never readable through `GET /api/settings`, so the imports endpoints fall back to the stored key when the body omits it.
2. `TestConnectionDto` (all three `/test`): `url` a non-empty string only (no URL check: a bare `localhost:7878` passes validation and fails at fetch); `apiKey` optional string.
3. `ImportApiDto`: `url` validator.js `isURL` with `require_tld: false, require_protocol: true` and its other defaults: scheme `http`, `https` or `ftp` (case-insensitive; `ftp://` passes and fails at fetch, rule 45), a host (`localhost`, a bare name, IPv4 or `[IPv6]`; `_` in the host rejected), userinfo allowed, at most 2083 characters; `radarr:7878` fails; `apiKey?` string; `mode?` `'skip'|'update'` (absent = `skip`); `importSubtitles?` boolean (absent = false); `targetLibraryId` int >= 1 (required; numeric strings are accepted); `pathMappings` required array (may be empty) of `PathMappingDto {remotePath: string (required, may be empty), localLibraryId: int >= 1 | null (absent or null both pass), ignore?: boolean}`. `PreviewImportDto` = the same `url` + `apiKey?`. Rule 1 runs in the controller before any service code, so `apiKey is required` precedes the rule 9 checks.
4. Settings read by the server: `seerr_url`, `seerr_api_key` (Seerr import, rule 27), `radarr_api_key`, `sonarr_api_key` (key fallback, rule 1), and `radarr_url`, `sonarr_url`, `seerr_url` for the stored-key comparison (rule 35). The client prefills its form from `radarr_url` / `sonarr_url` (`client/src/app/features/settings/data-imports/data-imports.ts`). The three `*_api_key` keys are secrets (settings rule 17).
5. `testConnection` (Radarr, Sonarr): `baseUrl` = `url` with every trailing `/` removed; `GET {baseUrl}/api/v3/system/status` with header `X-Api-Key`, no timeout. Non-2xx → `{ok:false, message:"<Radarr|Sonarr> returned <status> <statusText>"}`; 2xx → `{ok:true, message:"Connecté à <instanceName ?? 'Radarr'|'Sonarr'>"}` (French, with the accent); any thrown error (network, a 2xx body that is not JSON) → `{ok:false, message:<error message>}`. Seerr: `GET {url minus one trailing slash}/api/v1/settings/main`, `X-Api-Key`, timeout 15 s; 2xx → `{ok:true, message:"Connecté à <applicationTitle ?? 'Seerr'>"}`; any non-2xx → `{ok:false, message:"Request failed with status code <status>"}`, any other error → `{ok:false, message:<error message>}`; a 2xx body that is not JSON is NOT an error (the title falls back) → `{ok:true, message:"Connecté à Seerr"}`. The `statusText` / error texts are free text (the client shows them): parity compares `ok` only; `<statusText>` is rendered with `StatusCode::canonical_reason()` (the remote reason phrase is not exposed), here and in rules 6 and 10.
6. `previewRootFolders` (Radarr, Sonarr, identical): `GET {baseUrl}/api/v3/rootfolder`; non-2xx → 400 `<Radarr|Sonarr> API returned <status>: <statusText>`; any other failure → 400 `Cannot connect to <Radarr|Sonarr>: <message>`. Then read all libraries (`ORDER BY id`) and answer `remoteRootFolders` = the remote entries whose `path` is non-blank after trim, in remote order, each with `suggestedLocalLibraryId = suggestLocalLibraryId(path, libraries)` (rule 7); `localLibraries` = every library `{id, name, path}`, no ACL filter (the caller holds `settings.access`). A 2xx JSON body that is not an array, or holds a `null` entry, is 400 `Cannot connect to <Radarr|Sonarr>: <decode error>` (rule 44).
7. Path helpers (pure, `fliks_domain::arr_import`; vectors `arr-import`). `normalizePath(p)`: JS `trim`, POSIX `path.normalize`, strip trailing `/` and `\` runs, THEN replace every `\` with `/` (order matters: a Windows path `D:\Movies\X` stays one segment through `normalize`, then becomes `D:/Movies/X`). `suggestLocalLibraryId(remote, libs)`: `remoteBase = basename(normalize(remote))`; blank remote, no libs or empty base → null; libraries whose normalised path ends with `'/' + remoteBase`: exactly one → its id; else libraries whose basename equals `remoteBase`: exactly one → its id; else null (ambiguous or none). Libraries without a path never match.
8. `applyPathMapping(fullPath, mappings)` → `{libraryId, folderName}` | `{ignore:true}` | `null`: blank path or no mappings → null; mappings sorted by normalised `remotePath` length DESC (stable); a mapping whose normalised remote is empty is skipped (incl. `remotePath: "/"`, which normalises to `''`); a mapping matches when `full === remote` or `full` starts with `remote + '/'`; the FIRST match decides: `ignore` → `{ignore:true}`; `localLibraryId == null` → null (the longer mapping wins even if a shorter one would map); else `folderName` = first `/` segment of `full` under `remote` (when `full === remote`: `basename(full)`), an empty folder name → null. No match → null.
9. Import preconditions, in this order (before any remote call): (a) `resolveTargetLibrary(targetLibraryId, type)` (`movie` for Radarr, `series` for Sonarr): unknown id → 400 `Library #<id> not found`; library whose `mediaTypes` lacks the type → 400 `Library "<name>" does not accept <movie|series>`; (b) `assertMappingsBelongToLibrary`: the distinct `localLibraryId` of the non-ignored, non-null mappings must all equal `targetLibraryId`, else 400 `Path mappings target a different library than the import (target #<t>, mappings: <offending ids joined ", ">)` (only the distinct ids `!= t`, in mapping order). The target library is not checked against the caller's library ACL (settings admin).

### B. Radarr import (`POST /api/imports/radarr`)

10. Fetch `GET {baseUrl}/api/v3/movie` (no timeout); non-2xx → 400 `Radarr API returned <status>: <statusText>`; other failure → 400 `Cannot connect to Radarr: <message>`. A non-array or empty body answers 201 `{imported:0, errors:["No movies found in Radarr"], rootFoldersCreated:[], qualityProfilesCreated:[]}` (no `subtitlesImported` key, no profile import).
11. Quality profiles are imported BEFORE the movie loop (rules 14-17), on every non-empty run, whatever `mode`.
12. Per movie, sequentially, each in its own try/catch (a failure pushes `"<title>: <message>"` to `errors` and the loop continues; nothing is rolled back): `title = movie.title ?? ''`; `tmdbId` must be an integer >= 1 (JSON number or numeric string), else error `"<title or (no title)>: invalid tmdbId"`, continue (a missing, `null`, `0` or non-numeric id is this error, rule 40). A `null` array entry makes the whole body undecodable (rule 44). The catch-all error text uses the raw title (`": <message>"` for an untitled movie). `exists` = the `media` row with that `tmdbId` and `type = 'movie'`. `localProfileId = profileMap.get(movie.qualityProfileId)` when the remote id is non-null. `resolved = applyPathMapping(movie.path, pathMappings)`: `null` → error `"<title or (no title)>: no path mapping for \"<path or ''>\""`, continue; `{ignore}` → continue silently (not counted, not an error).
13. Existing media: `mode = 'skip'` → continue (not counted). `'update'` → `UPDATE media SET title, year = movie.year ?? existing.year, folderName, imdbId = movie.imdbId || existing.imdbId, overview = movie.overview || existing.overview, qualityProfileId = localProfileId ?? existing.qualityProfileId, libraryId` (`updatedAt` bumped), then when `movie.monitored` differs from the existing flag `setMediaMonitored` (`media-write.md` rule 27: cascade, event, request hook), and `imported++`. New media: INSERT `{title, tmdbId, year: movie.year ?? NULL, type 'movie', status 'released', monitored: movie.monitored ?? true, libraryId, folderName, imdbId: movie.imdbId || NULL, overview: movie.overview || NULL, qualityProfileId: localProfileId ?? NULL}` and `imported++`; every other column keeps its default (`addedById` NULL). `searchVector` is never written here (NULL on insert, stale after a title update; there is no DB trigger): new Sonarr series get it from the rule 24 refresh, Radarr movies only at their next metadata refresh. Text search still matches them through the `ILIKE title` branch (media-query spec).
14. `importQualityProfiles`: `GET {baseUrl}/api/v3/qualityprofile` (no timeout); non-2xx → empty map and no error; any throw (incl. a failing DB write midway) → logged warn, the map built so far is returned, no entry in `errors`. For each remote profile: an existing local profile with the same `name` (exact; profiles are read `ORDER BY id` and among duplicate local names the highest id wins) → `map[remote.id] = local.id`, nothing created; else INSERT `{name, cutoff: resolveCutoff(...), upgradeAllowed: remote.upgradeAllowed, items: mapRemoteItems(remote.items)}` (other columns default) → `map[remote.id]` = the new id and `name` pushed to `qualityProfilesCreated`. Two remote profiles sharing a name both create (the first is not added to the name index).
15. `mapRemoteItems(remoteItems)` (identical in both services: one function, vectors `arr-import`): iterate remote items in order; an item with `quality.name` adds that quality with the item's `allowed`; an item with `items` adds each sub-item that has `quality.name` with the SUB-item's `allowed` (groups are flattened one level, a group's own `allowed` is ignored; both the item and its sub-items are processed when both exist); a name that matches no local quality is dropped; `sortOrder` counts up from 0 over the kept entries; no de-duplication (two remote names mapping to one local quality yield two entries). Then every `APP_QUALITIES` entry whose id is not present is appended with `allowed:false` and the next `sortOrder`. Entry shape `{quality:{id,name,resolution,source}, allowed, sortOrder}` (no `groupId`).
16. `findLocalQuality(name)`: compare after removing every space, `-` and `_` and lower-casing, against the same normalisation of `APP_QUALITIES[].name` (first match; table = `APP_QUALITIES`, vector set `app-qualities`).
17. `resolveCutoff(remoteCutoffId, items)`: depth-first search of the remote items for `quality.id === remoteCutoffId` (an item's own quality first, then its sub-items), take that quality's name, map through `findLocalQuality`; not found or unmapped → local id **16** (WEBDL-1080p).
18. Subtitles (`importSubtitles = true`, after the movie loop, over the movies fetched in rule 10, in order): skip a movie without a truthy `id` or `tmdbId`, without a local movie row, or without any `media_files` row (latest file = highest id). `GET {baseUrl}/api/v3/extrafile?movieId=<id>` (no timeout); non-2xx → skip silently; a throw → `errors.push("Subtitles for \"<title>\": <message>")`, continue. Per extra file: `type === 'subtitle'`; `ext = extname(relativePath).toLowerCase()` in `{.srt,.ass,.ssa,.sub,.vtt}`; `language = extra.language?.name?.toLowerCase() ?? parseLanguageFromPath(relativePath)`; `tags = parseSubtitleTags(relativePath)`; `forced` = tags include `forced`; `relativePath = extra.relativePath.trim() || null` (null → skip); `count += upsertImportedSubtitleFile(...)` (rule 20). A missing `relativePath` makes `extname` throw, caught by the per-movie try/catch (error entry; the error text uses `movie.title` raw, `"undefined"` when absent).
19. `parseLanguageFromPath(rel)`: basename without extension split on `.`; scanning from the LAST part to the first, the first (lower-cased) part found in the fixed set `{en fr de es it pt nl ja ko zh ru ar pl sv da no fi eng fra fre deu ger spa ita por nld dut jpn kor zho chi rus ara pol swe dan nor fin}` wins; none → `'und'`. `parseSubtitleTags(rel)`: on the lower-cased basename without extension: `forced` if it contains `forced`; `sdh` if `sdh`; `cc` if it contains `.cc` or `_cc`; `hi` if it contains `.hi` or `_hi` (substring tests, no word boundary, in that order). `hearingImpairedFromTags` = tags include `sdh`, `cc` or `hi`.
20. `upsertImportedSubtitleFile` (shared Radarr/Sonarr; returns 1 when a row was inserted or updated, else 0). The `language` is stored canonical: every read AND write goes through `fliks_domain::language::normalize_language_code` (`eng` becomes `en`); a Radarr `language.name` such as `English` is first mapped to its ISO 639-1 code through the `APP_LANGUAGES` names. Lookup: `subtitle_files WHERE "mediaFileId" = ? AND language = norm(lang) AND forced = ? AND "filePath" = ?` (column `filePath` is the `relativePath` property). Not found and `mode = 'update'`: take the first EMBEDDED row `(mediaFileId, language, forced, providerType 'embedded')` (`ORDER BY id LIMIT 1`) and use it only when ITS `streamIndex` is NULL (a mis-tagged embedded row); an embedded row with a stream index is not passed over for a later one. Found: `mode = 'skip'` → 0; `'update'` → `UPDATE SET providerType = <radarr|sonarr>, hearingImpaired, tags, filePath = relativePath ?? existing, status = 'downloaded', score = 100` plus `streamIndex = NULL, codec = NULL` when it was embedded; return 1. Not found: INSERT `{mediaId, mediaFileId, episodeId (Sonarr only, else NULL), language, forced, hearingImpaired, providerType, status 'downloaded', score 100, filePath, tags}`; return 1. `tags` is JSON text.
21. Result `{imported, errors, rootFoldersCreated: [], qualityProfilesCreated, subtitlesImported}`; `imported` counts inserts and (in `update` mode) updates; ignored / skipped / errored movies are not counted.
22. `rootFoldersCreated` is a dead field (always `[]`), kept in the body for the client's `ArrImportResult`.

### C. Sonarr import (`POST /api/imports/sonarr`): differences from Radarr

23. Rules 10-17 and 21 apply with `GET {baseUrl}/api/v3/series` (empty-answer error text `No series found in Sonarr`). Differences: `tmdbId` comes from `s.tmdbId` only, with no `tvdbId` fallback (rule 40); error text `"<title or (no title)>: invalid tmdbId"`; the lookup is `type = 'series'`; a new row gets `status 'continuing'` (everything else as rule 13); the ids of newly INSERTED series are collected (updates and skips are not).
24. After the loop, for the new series only, a fire-and-forget background task refreshes metadata sequentially (the TMDB seasons / episodes import of the media spec); each failure is logged and skipped; the HTTP response does not wait. No activity row, no event; a restart loses the remaining ones.
25. Subtitles (`importSubtitles = true`) never call Sonarr: for each fetched series with a truthy `id` and a `tmdbId` integer >= 1 (rule 40), the local series (with its library) must have a non-null `path` (`library.path` joined with `folderName`); then for every `media_files` row of the series (`ORDER BY id ASC`) list the directory of `join(media.path, file.relativePath)` (a directory-read failure = no subtitles) and take the entries whose extension is in the subtitle set and whose lower-cased stem equals the lower-cased video stem or starts with `<stem>.` or `<stem> `. Per match: `language = parseLanguageFromPath(name)`, `tags`, `forced`, `rel = relative(media.path, abs)` with `\` → `/`, null when empty, starting with `..` or absolute (logged error, skipped); upsert (rule 20) with `episodeId = file.episodeId`, provider `sonarr`. A throw per series → error `Subtitles for "<title or 'series'>": <message>`.
26. Rule 8's `folderName` becomes `media.folderName` and therefore the on-disk path of every later rescan, delete-with-files and subtitle write. `normalizePath` turns `\` into `/` AFTER `normalize`, so with a mapping `remotePath: "/movies"` a remote path such as `/movies/..\x` normalises to `/movies/../x` and would give `folderName = '..'` (`/movies/.\x` gives `.`), because `path.normalize` never sees the `..` (on POSIX `\` is not a separator). The folder-name validator of rule 36 rejects such a name, in `update` mode too.

### D. Seerr request import (`POST /api/imports/seerr/import-requests`)

27. Configuration comes from settings: `seerr_url` and `seerr_api_key`, either absent or empty → throws `Configure Seerr URL and API key first` (surfaced as `seerr.import.failed {error}`, rule 29). The URL has ONE trailing `/` removed.
28. Paging: `GET {base}/api/v1/request?take=50&skip=<n>&filter=all&sort=added` with `X-Api-Key`, timeout 60 s; `total = pageInfo.results ?? 0`, `results ?? []`; stop when a page is empty or `skip + len >= total`; `skip += len`. A page error aborts the whole import (the throw reaches rule 29); the requests already applied stay. Each request runs in its own try/catch: a failure pushes `request #<id>: <message>` to `stats.errors` (never sent to the client) and goes on. Stats: `users` = distinct resolved usernames seen (of requests that pass the TMDB-id check of rule 30), `usersCreated`, `imported` (created), `updated`, `skipped`, `errors[]`.
29. Lifecycle and events (the route returns 201 `{ok:true}` before any of it): emit SSE `seerr.import.started` `{}`; (fire and forget) the audited command wrapper (`ImportSeerrRequests`, `manual`): INSERT `commands {name, status:'running', trigger:'manual', startedOn: now}`, emit `command.started {name}`, run the import, then UPDATE the row `completed|failed` with `endedOn`, emit `command.completed {name, status}`. The import: `importFromSeerr()` then `seerr.import.completed {users, usersCreated, imported, updated, skipped}`; on a throw: log, emit `seerr.import.failed {error: <message>}`; the wrapper marks the row `failed` and does not rethrow. If the audit row cannot be written, the controller emits `seerr.import.failed {error: ''}`; the same happens when the final `commands` update fails, then AFTER the `seerr.import.completed|failed` event and without `command.completed`. Event order seen by clients: `seerr.import.started`, `command.started`, `seerr.import.completed|failed`, `command.completed`. All are broadcasts (events-hub audience B). A second import while one runs is 409 (rule 41).
30. `applyRequest(req)` returns `'created'|'updated'|'skipped'`: (1) `username = trim(jellyfinUsername || plexUsername || username || displayName)`, blank → skipped; (2) `mediaType = req.type === 'tv' ? 'series' : 'movie'`; `tmdbId = req.media.tmdbId` falsy or <= 0 → skipped (no user is created and the username is not counted in `users`); (3) the username is counted in `users` and the Fliks user is resolved (rule 33); (4) `media` = the row with `(type, tmdbId)`, cached per key for the run (a miss is cached too); (5) `status = mapStatus(req.status, req.media.status)` (rule 32); (6) `title = media.title ?? req.media.title ?? req.media.name ?? ''` and, only when still empty, `fetchTitle` (cached per key, null cached too): `GET {base}/api/v1/<movie|tv>/<tmdbId>` (the Seerr `type` string verbatim in the path), timeout 15 s, `title` (movie) or `name` (tv) trimmed, any error → null with a warn log; (7) `seasons` = the `seasonNumber`s when the type is series and `req.seasons` is non-empty, else null; (8) `createdAt = parse(req.createdAt) ?? now`, `updatedAt = parse(req.updatedAt) ?? createdAt` (`parse` = a valid date or null).
31. Upsert: `existing` = the request with the same `userId`, `tmdbId`, `mediaType` and `kind = 'add'`, lowest `id`. Media claim first: when `media` exists, `UPDATE media SET "addedById" = <user> WHERE id = $2 AND "addedById" IS NULL`, so the first requester in Seerr's order keeps it. Existing: `status` and `seasons` replaced, `mediaId = media.id` only when `media` exists, `title` only when the stored title is empty and the new one is not (`declinedReason`, profiles, library, `approvedBy`, `kind` untouched); then, only when the stored `createdAt` / `updatedAt` differ from Seerr's, `UPDATE requests SET "createdAt", "updatedAt"` (the `updatedAt` trigger would otherwise bump an unchanged `updatedAt`) → `'updated'`. Absent: INSERT `{userId, mediaType, tmdbId, title, status, seasons, mediaId: media?.id ?? NULL, qualityProfileId NULL, languageProfileId NULL, libraryId NULL, approvedById NULL, declinedReason NULL}` (`kind` default `'add'`, `posterUrl` / `fanartUrl` NULL) then `UPDATE "createdAt", "updatedAt"` to Seerr's → `'created'`. No notification, no request-lifecycle hook, no domain event.
32. `mapStatus(requestStatus, mediaStatus)`: media status 5 (AVAILABLE) → `available`; media status 3 (PROCESSING) or 4 (PARTIALLY_AVAILABLE) → `processing` (availability wins over the request status); else request status 2 → `approved`, 3 → `declined`, 4 → `failed`, 1 or anything else → `pending`. `failed` is only ever written by this importer (requests rule 5).
33. `resolveUser(username)`: cached per run by username; users matched by exact, case-sensitive `username`. Absent → read the default role with its `defaultLibraries` (`roles WHERE "isDefault" = true`, first row, Rust `ORDER BY id LIMIT 1`; may be none) and INSERT a user `{username, passwordHash: NULL, roleId: role?.id ?? NULL, mediaServerType: 'local'}` (every other column default: `enabled` true, `isAdmin` false, no email); `usersCreated++`; then, when the role has default libraries, INSERT one `library_user_access` row per library in the same transaction as the user insert; a unique violation on `username` (concurrent writer) re-reads the winner instead of failing (rule 42). A user with `passwordHash NULL` cannot log in (auth rule 29).
34. Seerr calls use `reqwest` with timeouts of 15 s, 15 s and 60 s (rule 39). Seerr types used: request `{id, status 1..4, type 'movie'|'tv', createdAt, updatedAt, media: {id, tmdbId, status 1..5, title?, name?}, requestedBy: {id, email?, displayName?, jellyfinUsername?, plexUsername?, username?}, seasons?: [{seasonNumber}]}`; no schema validation: absent members are tolerated (a missing `media` skips the request).

### E. Security and robustness

35. The stored-key fallback (rule 1) applies only when the body `url`, normalised (trailing `/` removed, scheme and host compared case-insensitively), equals the stored `radarr_url` / `sonarr_url` / `seerr_url` setting; otherwise a body without a usable `apiKey` is 400 `apiKey is required`. The key cannot be read back, so without this an admin could aim the stored key at any URL (the server sends it as `X-Api-Key`). Client impact: the data-imports page omits `apiKey` only when a key is stored and the field is blank (the submit gates accept a stored key), and sends the URL field trimmed minus one trailing `/`, the same form it saves; so only a URL edited and not yet saved, without a retyped key, becomes 400 `apiKey is required` (shown as the test result or an error toast).
36. `folderName` from rule 8 goes through the one `fliks_domain::naming` folder-name validator (shared with `ingest.md` rule 3 and every `folderName` writer): empty, `.`, `..`, a name containing a separator or NUL is REJECTED, never mapped to `''` (an empty name makes the media path the library root); the title is an `errors` entry `"<title>: invalid folder name for \"<path>\""` and is skipped (Radarr and Sonarr). The `\` → `/` order of rule 7 is kept (vectors), so Windows paths keep working.
37. No importer error string, `ok:false` message, log line or SSE `error` contains the request URL or its userinfo: `reqwest::Error` is rendered with `without_url()` (its `Display` embeds the URL), and a `url` with `user:pass@` keeps its credentials for the request (Basic auth) but never shows them in text. Redirects are followed only within the same scheme and host.
38. The HTTP client of the importers (and of the media servers) follows a redirect only when the target host equals the host of the previous URL (custom `redirect::Policy`, limit 5); any other redirect is a plain failure (`... returned 302`). Otherwise `X-Api-Key` would be forwarded to the `Location` host.
39. Every outbound call has a timeout: 15 s for `/test` and `fetchTitle`, 60 s for list calls (`movie`, `series`, `rootfolder`, `qualityprofile`, `request`), 30 s per `extrafile` call. A timeout is an ordinary failure of that call (rules 5, 6, 10, 14, 18, 28).
40. A Radarr/Sonarr title is imported only with `tmdbId` an integer >= 1 taken from `tmdbId` (JSON number or numeric string); otherwise the error entry of rule 12 (`invalid tmdbId`) applies. There is no fallback to `tvdbId` (a different id space that can collide with real TMDB ids), in the series loop and in the rule 25 lookup alike. **Sonarr v4 is the minimum** (v3 series carry no `tmdbId`): a Sonarr import whose series list is non-empty and holds no entry with a `tmdbId` answers 400 `Sonarr v4 or later is required (the series list carries no tmdbId)` before any write; documented in the user docs next to the import page. Rows imported by 4.x with a TVDB id as `tmdbId` are not matched again (a re-import inserts a second row for the show).
41. A Seerr import is refused with 409 `Import already running` while another one runs (one in-process flag, released on completion or failure); the 409 comes before `seerr.import.started`. Re-runs after completion are fine (rule 31 is idempotent). Client impact: none; `importSeerrRequests` catches the HTTP error, resets its spinner and toasts `error.message`, and the running import's SSE events still reach the page.
42. Seerr user creation (shared with `media-servers.md` rule 24): the user INSERT and its `library_user_access` rows run in one transaction, and a unique violation on `username` (concurrent writer) re-reads the winner instead of failing. The TMDB-id check, the `kind = 'add'` match and the first-requester media claim are rules 30 and 31.
43. The Radarr / Sonarr subtitle import writes real rows (rule 20; a Radarr `language.name` such as `English` is mapped to its ISO 639-1 code through the `APP_LANGUAGES` names, then normalised before the lookup and the write), so `subtitlesImported` counts real rows. `update` mode updates existing titles and the mapped `qualityProfileId` is stored on update and insert (rule 13).
44. A 2xx `rootfolder`, `movie` or `series` body that cannot be walked (rootfolder: not an array, a `null` entry, a `path` that is neither a string nor absent/null; movie / series: a `null` entry; other entry and field types stay lenient) is 400 `Cannot connect to <Radarr|Sonarr>: <decode error>` (the invalid-JSON branch of rules 6 and 10); a `movie` / `series` body that is not an array keeps the rule 10 "No movies found" answer.
45. The importer `url` may be any http(s) host (loopback, private, link-local) because the caller holds `settings.access` (SSRF accepted for admin-set endpoints); other schemes fail at connect (`Cannot connect to ...`). A `/test` `url` that is not a URL passes validation (rule 2) and is reported as `ok:false`.
46. HTTP: one shared `reqwest::Client` per process, rustls, no cookie jar, header `X-Api-Key` only (Seerr, Radarr, Sonarr); response bodies read fully.

### F. NFO reader (pure parse + file lookup; used by disk import and media import)

47. `NfoData` = `{tmdbId?: int, imdbId?: string, tvdbId?: int, title?, originalTitle?, year?: int, plot?, genres?: string[], runtime?: int, rating?: number (0..10), premiered?: 'YYYY-MM-DD'}`; absent keys are OMITTED (never `null`). `parse(xml)` (pure, never throws; vectors `nfo`) reads the document with a lenient tag-soup parser: nothing is ever rejected, unclosed or mismatched tags still yield their text (`<movie><title>X` → `title: 'X'`), and text without any element (`not xml at all`, `<<<>>>garbage&&&`, `''`) gives `{}`. Element names are matched case-sensitively (`<Title>` is not `title`) at any depth, first occurrence in document order wins; a value is the element's full descendant text, XML entities decoded and CDATA content included. The parser is a lenient tokenizer (`quick-xml` without end-name checks, keeping what was read before a hard error), pinned by the vectors. Ids: every `<uniqueid type=T>` with non-empty text, in document order (`type` lower-cased): `tmdb` → `tmdbId` (parseInt), `tvdb` → `tvdbId`, `imdb` → `imdbId` (text, not validated); a slot counts as set only when truthy, so the first value that parses to a non-zero int wins (`0` or `abc` does not block a later one); then, for ids still falsy, `<tmdbid>`, `<tvdbid>` (parseInt, may yield `0`, which is kept), `<imdbid>` (trimmed, non-empty); then `<id>`: starting with `tt` and no imdb yet → `imdbId`, else all digits and no tvdb yet → `tvdbId`. `title` = first non-empty of `<showtitle>`, `<title>`; `originalTitle` = `<originaltitle>`; `plot` = `<plot>` else `<outline>`; `genres` = distinct non-empty `<genre>` texts in order (omitted when none); `runtime` = parseInt of `<runtime>` when truthy (0 omitted); `rating` = first non-empty of `<ratings><rating default="true"><value>`, `<ratings><rating><value>`, `<rating>` (selector order), decimal comma accepted, kept only when finite and within 0..=10; `premiered` = the `YYYY-MM-DD` prefix (`^\d{4}-\d{2}-\d{2}`) of the trimmed raw text (`<premiered>` when its untrimmed text is non-empty, else `<aired>`), kept only when JS `Date.parse` semantics accept it: month `01`-`12` and day `01`-`31` with no per-month check (`2020-13-45`, `2020-01-00` dropped; `2020-02-30`, `2021-02-29` kept); `year` = parseInt of `<year>` when truthy, else the first 4 characters of the raw premiered/aired text parsed. `parseInt` semantics (leading whitespace skipped, optional sign, leading digits: `12abc` → 12, `-5` → -5, `abc` → none).
48. `readNfoFile(path)`: read as UTF-8 text (a read error, incl. a directory or a missing file → `null`; invalid UTF-8 is replaced, not an error), then `parse`. `readForVideoFile(video)`: candidates in order `<dir>/<basename-without-ext>.nfo`, `<dir>/movie.nfo`, `<dir>/tvshow.nfo`, `<parent dir>/tvshow.nfo`; each existing file is parsed and merged key by key (a key is taken only while still unset: the most specific file wins its keys, show-level files backfill); stop after the first file that leaves any of `tmdbId`, `tvdbId`, `imdbId` truthy (a `0` id does not stop); `null` when no candidate file exists (a file that exists but parses to `{}` counts as found: result `{}`, not `null`). Callers: the disk-import scan (`readForVideoFile` per group) and transfer (`readNfoFile` of `tvshow.nfo` / `<artworkBasename>.nfo`, else `readForVideoFile`), and `media-import` (the `nfo` field feeds `title` (only over a folder-name fallback), `originalTitle`, `year` (after the DTO's), `overview` (= `plot`), `genres`, `runtime`, `rating`, `releaseDate` (= `premiered`); the ids are not used there). Read-only.
49. No importer URL allow-list (rule 45; the stored key follows the URL only under rule 35 and redirects stay on one host under rule 38); a Seerr update overwrites `status` even when Fliks advanced it (Seerr is the source the admin chose to import, a re-run is explicit); Seerr user matching is case-sensitive exact and an imported `approved` request triggers no lifecycle hook (rule 31).

## SQL

Rust uses `sqlx` with explicit columns (camelCase quoted).

1. Library list (preview): `SELECT id, name, path FROM libraries ORDER BY id`. Target library: `SELECT * FROM libraries WHERE id = $1` (`mediaTypes` jsonb, checked in code).
2. Media lookup per title: `SELECT * FROM media WHERE "tmdbId" = $1 AND type = $2 LIMIT 1` (`UQ(type, tmdbId)` guarantees at most one row).
3. Radarr/Sonarr insert: `INSERT INTO media (title, "tmdbId", year, type, status, monitored, "libraryId", "folderName", "imdbId", overview, "qualityProfileId") VALUES (...) RETURNING id`; update: `UPDATE media SET title=$, year=$, "folderName"=$, "imdbId"=$, overview=$, "qualityProfileId"=$, "libraryId"=$, "updatedAt"=now() WHERE id=$` (the merges of rule 13 are computed in code).
4. Profiles: `SELECT * FROM quality_profiles ORDER BY id`; `INSERT INTO quality_profiles (name, cutoff, items, "upgradeAllowed") VALUES ($1,$2,$3::jsonb,$4) RETURNING id`.
5. Subtitles: `SELECT id FROM media_files WHERE "mediaId" = $1 ORDER BY id DESC LIMIT 1` (Radarr); `SELECT id, "relativePath", "episodeId" FROM media_files WHERE "mediaId" = $1 ORDER BY id ASC` plus `SELECT m.*, l.path FROM media m JOIN libraries l ON l.id = m."libraryId" WHERE m."tmdbId" = $1 AND m.type = 'series'` (Sonarr); the rule 20 reads and writes on `subtitle_files` (column `filePath`).
6. Seerr: `SELECT * FROM users WHERE username = $1`; default role with its libraries `SELECT r.id, r.name, rdl."libraryId" FROM roles r LEFT JOIN role_default_libraries rdl ON rdl."roleId" = r.id WHERE r."isDefault" = true ORDER BY r.id`; `INSERT INTO users (username, "passwordHash", "roleId", "mediaServerType") VALUES ($1, NULL, $2, 'local') RETURNING id`; `INSERT INTO library_user_access ("userId", "libraryId") VALUES ...`; `SELECT * FROM requests WHERE "userId" = $1 AND "tmdbId" = $2 AND "mediaType" = $3 AND kind = 'add' ORDER BY id LIMIT 1`; `UPDATE requests SET status, seasons, "mediaId", title, "updatedAt" WHERE id`; `UPDATE requests SET "createdAt" = $, "updatedAt" = $ WHERE id = $`; `INSERT INTO requests (...)`; `UPDATE media SET "addedById" = $1 WHERE id = $2 AND "addedById" IS NULL`. `requests.seasons` is jsonb (`null` or a non-empty array here).
7. Settings: `SELECT value FROM app_settings WHERE key = $1` (`radarr_api_key`, `sonarr_api_key`, `seerr_api_key`, `seerr_url`, and for rule 35 `radarr_url`, `sonarr_url`). Commands: `INSERT INTO commands (name, status, trigger, "startedOn") VALUES ('ImportSeerrRequests','running','manual', now()) RETURNING id`; `UPDATE commands SET status = $2, "endedOn" = now() WHERE id = $1`.
