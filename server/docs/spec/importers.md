## Rules

### A. Request handling (all importer routes)

1. API key resolution `resolveApiKey(provided, settingKey)`: a `provided` string that is non-blank after `trim()` is used as sent (not trimmed); otherwise the stored `app_settings` value of `radarr_api_key` / `sonarr_api_key` / `seerr_api_key`; neither → 400 `apiKey is required`. This is the F5 read-back replacement (plan §15.1: "the imports endpoints fall back to the stored key when the body omits it"). `[ts:src/modules/imports/imports.controller.ts:54]`–`[ts:src/modules/imports/imports.controller.ts:62]`
2. `TestConnectionDto` (all three `/test`): `url` `@IsString @IsNotEmpty` only (no URL check: a bare `localhost:7878` passes validation and fails at fetch); `apiKey` optional string. `[ts:src/modules/imports/dto/test-connection.dto.ts:3]`–`[ts:src/modules/imports/dto/test-connection.dto.ts:12]`
3. `ImportApiDto`: `url` `@IsUrl({require_tld:false, require_protocol:true})` = validator.js `isURL` with its defaults: scheme `http`, `https` or `ftp` (case-insensitive; `ftp://` passes and fails at fetch, rule 45), a host (`localhost`, a bare name, IPv4 or `[IPv6]`; `_` in the host rejected), userinfo allowed, at most 2083 characters; `radarr:7878` fails; `apiKey?` string; `mode?` `'skip'|'update'` (absent = `skip`); `importSubtitles?` boolean (absent = false); `targetLibraryId` int >= 1 (required; numeric strings coerce through `@Type(()=>Number)`); `pathMappings` required array (may be empty) of `PathMappingDto {remotePath: string (required, may be empty), localLibraryId: int >= 1 | null (`@IsOptional`: absent or null both pass), ignore?: boolean}`. `PreviewImportDto` = the same `url` + `apiKey?`. Rule 1 runs in the controller before any service code, so `apiKey is required` precedes the rule 9 checks. `[ts:src/modules/imports/dto/import-api.dto.ts:14]`–`[ts:src/modules/imports/dto/import-api.dto.ts:62]`, `[ts:src/modules/imports/dto/preview-import.dto.ts:3]`–`[ts:src/modules/imports/dto/preview-import.dto.ts:11]`

The `statusText` / axios texts are free text (the client shows them): parity compares `ok` only; Rust renders `<status>` with `StatusCode::canonical_reason()` (reqwest does not expose the remote reason phrase), here and in rules 6 and 10. `[ts:src/modules/imports/radarr.service.ts:102]`–`[ts:src/modules/imports/radarr.service.ts:125]`, `[ts:src/modules/imports/sonarr.service.ts:91]`–`[ts:src/modules/imports/sonarr.service.ts:114]`, `[ts:src/modules/imports/seerr.service.ts:65]`–`[ts:src/modules/imports/seerr.service.ts:83]`
6. `previewRootFolders` (Radarr, Sonarr, identical): `GET {baseUrl}/api/v3/rootfolder`; non-2xx → 400 `<Radarr|Sonarr> API returned <status>: <statusText>`; any other failure → 400 `Cannot connect to <Radarr|Sonarr>: <message>`. Then read all libraries (no ORDER BY in Nest; Rust `ORDER BY id`, C12) and answer `remoteRootFolders` = the remote entries whose `path` is non-blank after trim, in remote order, each with `suggestedLocalLibraryId = suggestLocalLibraryId(path, libraries)` (rule 7); `localLibraries` = every library `{id, name, path}`, no ACL filter (the caller holds `settings.access`). Libraries without a path never match. `[ts:src/modules/scheduler/utils/arr-import.util.ts:21]`–`[ts:src/modules/scheduler/utils/arr-import.util.ts:26]`, `[ts:src/modules/scheduler/utils/arr-import.util.ts:70]`–`[ts:src/modules/scheduler/utils/arr-import.util.ts:87]`
8. `applyPathMapping(fullPath, mappings)` → `{libraryId, folderName}` | `{ignore:true}` | `null`: blank path or no mappings → null; mappings sorted by normalised `remotePath` length DESC (stable); a mapping whose normalised remote is empty is skipped (incl. `remotePath: "/"`, which normalises to `''`); a mapping matches when `full === remote` or `full` starts with `remote + '/'`; the FIRST match decides: `ignore` → `{ignore:true}`; `localLibraryId == null` → null (the longer mapping wins even if a shorter one would map); else `folderName` = first `/` segment of `full` under `remote` (when `full === remote`: `basename(full)`), an empty folder name → null. No match → null. `[ts:src/modules/scheduler/utils/arr-import.util.ts:38]`–`[ts:src/modules/scheduler/utils/arr-import.util.ts:62]`

### B. Radarr import (`POST /api/imports/radarr`)

10. Fetch `GET {baseUrl}/api/v3/movie` (no timeout); non-2xx → 400 `Radarr API returned <status>: <statusText>`; other failure → 400 `Cannot connect to Radarr: <message>`. A non-array or empty body answers 201 `{imported:0, errors:["No movies found in Radarr"], rootFoldersCreated:[], qualityProfilesCreated:[]}` (no `subtitlesImported` key, no profile import). `[ts:src/modules/imports/radarr.service.ts:191]`–`[ts:src/modules/imports/radarr.service.ts:216]`
11. Quality profiles are imported BEFORE the movie loop (rules 14-17), on every non-empty run, whatever `mode`. `[ts:src/modules/imports/radarr.service.ts:218]`–`[ts:src/modules/imports/radarr.service.ts:222]`
12. Per movie, sequentially, each in its own try/catch (a failure pushes `"<title>: <message>"` to `errors` and the loop continues; nothing is rolled back): `title = movie.title ?? ''`; `tmdbId = Number(movie.tmdbId)`; non-finite → error `"<title or (no title)>: invalid tmdbId"`, continue (a missing tmdbId or a non-numeric string is `NaN` → this error; `null`, `""`, `false` and `0` give `0`, which is finite and imported with `tmdbId = 0`: C?1). The title and id checks run outside the per-title try: a `null` array entry is an uncaught TypeError → Nest 500 (Rust: C?13). The catch-all error text uses the raw title (`": <message>"` for an untitled movie). `exists` = the `media` row with that `tmdbId` and `type = 'movie'`. `localProfileId = profileMap.get(movie.qualityProfileId)` when the remote id is non-null. `resolved = applyPathMapping(movie.path, pathMappings)`: `null` → error `"<title or (no title)>: no path mapping for \"<path or ''>\""`, continue; `{ignore}` → continue silently (not counted, not an error). `[ts:src/modules/imports/radarr.service.ts:224]`–`[ts:src/modules/imports/radarr.service.ts:248]`
13. Existing media: `mode = 'skip'` → continue (not counted). `'update'` → `UPDATE media SET title, year = movie.year ?? existing.year, monitored = movie.monitored ?? existing.monitored, folderName, imdbId = movie.imdbId || existing.imdbId, overview = movie.overview || existing.overview, qualityProfileId = localProfileId ?? existing.qualityProfileId, libraryId` (`updatedAt` bumped) and `imported++`. New media: INSERT `{title, tmdbId, year: movie.year ?? NULL, type 'movie', status 'released', monitored: movie.monitored ?? true, libraryId, folderName, imdbId: movie.imdbId || NULL, overview: movie.overview || NULL, qualityProfileId: localProfileId ?? NULL}` and `imported++`; every other column keeps its default (`addedById` NULL). `searchVector` is never written here (NULL on insert, stale after a title update; there is no DB trigger): new Sonarr series get it from the rule 24 refresh, Radarr movies only at their next metadata refresh. Frozen: text search still matches them through the `ILIKE title` branch (media-query spec). `[ts:src/modules/imports/radarr.service.ts:250]`–`[ts:src/modules/imports/radarr.service.ts:283]`
14. `importQualityProfiles`: `GET {baseUrl}/api/v3/qualityprofile` (no timeout); non-2xx → empty map and no error; any throw (incl. a failing DB write midway) → logged warn, the map built so far is returned, no entry in `errors`. For each remote profile: an existing local profile with the same `name` (exact; the name index is a JS `Map` built from `find()`, so among duplicate local names the LAST row wins: Rust reads `ORDER BY id` and keeps the highest id) → `map[remote.id] = local.id`, nothing created; else INSERT `{name, cutoff: resolveCutoff(...), upgradeAllowed: remote.upgradeAllowed, items: mapRemoteItems(remote.items)}` (other columns default) → `map[remote.id]` = the new id and `name` pushed to `qualityProfilesCreated`. Two remote profiles sharing a name both create (the first is not added to the name index). `[ts:src/modules/imports/radarr.service.ts:376]`–`[ts:src/modules/imports/radarr.service.ts:424]`
15. `mapRemoteItems(remoteItems)` (identical in both services: ONE Rust function, vectors `arr-import`): iterate remote items in order; an item with `quality.name` adds that quality with the item's `allowed`; an item with `items` adds each sub-item that has `quality.name` with the SUB-item's `allowed` (groups are flattened one level, a group's own `allowed` is ignored; both the item and its sub-items are processed when both exist); a name that matches no local quality is dropped; `sortOrder` counts up from 0 over the kept entries; no de-duplication (two remote names mapping to one local quality yield two entries). Then every `APP_QUALITIES` entry whose id is not present is appended with `allowed:false` and the next `sortOrder`. Entry shape `{quality:{id,name,resolution,source}, allowed, sortOrder}` (no `groupId`). `[ts:src/modules/imports/radarr.service.ts:426]`–`[ts:src/modules/imports/radarr.service.ts:481]`
16. `findLocalQuality(name)`: compare after removing every space, `-` and `_` and lower-casing, against the same normalisation of `APP_QUALITIES[].name` (first match; table = the S3 `app-qualities` vector set). `[ts:src/modules/imports/radarr.service.ts:483]`–`[ts:src/modules/imports/radarr.service.ts:489]`
17. `resolveCutoff(remoteCutoffId, items)`: depth-first search of the remote items for `quality.id === remoteCutoffId` (an item's own quality first, then its sub-items), take that quality's name, map through `findLocalQuality`; not found or unmapped → local id **16** (WEBDL-1080p). `[ts:src/modules/imports/radarr.service.ts:491]`–`[ts:src/modules/imports/radarr.service.ts:513]`
18. Subtitles (`importSubtitles = true`, after the movie loop, over the movies fetched in rule 10, in order): skip a movie without a truthy `id` or `tmdbId`, without a local movie row, or without any `media_files` row (latest file = highest id). `GET {baseUrl}/api/v3/extrafile?movieId=<id>` (no timeout); non-2xx → skip silently; a throw → `errors.push("Subtitles for \"<title>\": <message>")`, continue. Per extra file: `type === 'subtitle'`; `ext = extname(relativePath).toLowerCase()` in `{.srt,.ass,.ssa,.sub,.vtt}`; `language = extra.language?.name?.toLowerCase() ?? parseLanguageFromPath(relativePath)`; `tags = parseSubtitleTags(relativePath)`; `forced` = tags include `forced`; `relativePath = extra.relativePath.trim() || null` (null → skip); `count += upsertImportedSubtitleFile(...)` (rule 20). A missing `relativePath` makes `extname` throw, caught by the per-movie try/catch (error entry; the error text uses `movie.title` raw, `"undefined"` when absent). In Nest the first upsert of a movie always throws (rule 20), so the movie gets that error entry and its remaining extras are skipped. `[ts:src/modules/imports/radarr.service.ts:310]`–`[ts:src/modules/imports/radarr.service.ts:374]`
19. `parseLanguageFromPath(rel)`: basename without extension split on `.`; scanning from the LAST part to the first, the first (lower-cased) part found in the fixed set `{en fr de es it pt nl ja ko zh ru ar pl sv da no fi eng fra fre deu ger spa ita por nld dut jpn kor zho chi rus ara pol swe dan nor fin}` wins; none → `'und'`. `parseSubtitleTags(rel)`: on the lower-cased basename without extension: `forced` if it contains `forced`; `sdh` if `sdh`; `cc` if it contains `.cc` or `_cc`; `hi` if it contains `.hi` or `_hi` (substring tests, no word boundary, in that order). `hearingImpairedFromTags` = tags include `sdh`, `cc` or `hi`. `[ts:src/modules/scheduler/utils/arr-import.util.ts:102]`–`[ts:src/modules/scheduler/utils/arr-import.util.ts:167]`
20. `upsertImportedSubtitleFile` (shared Radarr/Sonarr). **Nest never gets past its first query**: `findOne({where: {mediaFileId, ...}})` names the `@RelationId` property `mediaFileId`, which is not a column for TypeORM's find builder, so every call throws `Property "mediaFileId" was not found in "SubtitleFile". Make sure your query is correct.` (caught by the caller: rules 18, 25 error entries); `subtitlesImported` is always `0` and no `subtitle_files` row is ever written by an import (same trap as the comment at `[ts:src/modules/imports/seerr-request-import.service.ts:222]`). Rust implements the intended upsert below (C?12; returns 1 when a row was inserted or updated, else 0): the `language` is stored canonical, i.e. every read AND write goes through `normalize_language_code` (TypeORM column transformer; raw SQL bypasses it, so Rust normalises explicitly with `fliks_domain::language`); a Radarr `language.name` such as `english` therefore stays `english` while `eng` becomes `en` (Q2). Lookup: `subtitle_files WHERE mediaFileId = ? AND language = norm(lang) AND forced = ? AND "filePath" = ?` (column `filePath` is the `relativePath` property). Not found and `mode = 'update'`: take the first EMBEDDED row `(mediaFileId, language, forced, providerType 'embedded')` (no ORDER BY in Nest, Rust `ORDER BY id LIMIT 1`) and use it only when ITS `streamIndex` is NULL (a mis-tagged embedded row); an embedded row with a stream index is not passed over for a later one. Found: `mode = 'skip'` → 0; `'update'` → `UPDATE SET providerType = <radarr|sonarr>, hearingImpaired, tags, filePath = relativePath ?? existing, status = 'downloaded', score = 100` plus `streamIndex = NULL, codec = NULL` when it was embedded; return 1. Not found: INSERT `{mediaId, mediaFileId, episodeId (Sonarr only, else NULL), language, forced, hearingImpaired, providerType, status 'downloaded', score 100, filePath, tags}`; return 1. `tags` is `simple-json` text. `[ts:src/modules/scheduler/utils/arr-import.util.ts:206]`–`[ts:src/modules/scheduler/utils/arr-import.util.ts:299]`, `[ts:src/modules/subtitles/entities/subtitle-file.entity.ts:49]`–`[ts:src/modules/subtitles/entities/subtitle-file.entity.ts:55]`
21. Result `{imported, errors, rootFoldersCreated: [], qualityProfilesCreated, subtitlesImported}`; `imported` counts inserts and (in `update` mode) updates; ignored / skipped / errored movies are not counted. `[ts:src/modules/imports/radarr.service.ts:298]`–`[ts:src/modules/imports/radarr.service.ts:307]`

### C. Sonarr import (`POST /api/imports/sonarr`): differences from Radarr

23. Rules 10-17 and 21 apply with `GET {baseUrl}/api/v3/series` (empty-answer error text `No series found in Sonarr`). Differences: `tmdbId = Number(s.tmdbId || s.tvdbId)` (a TVDB id is used as a TMDB id when the TMDB id is falsy: wrong id space, C?1); error text `"<title or (no title)>: no valid tmdbId or tvdbId"`; the lookup is `type = 'series'`; a new row gets `status 'continuing'` (everything else as rule 13); the ids of newly INSERTED series are collected (updates and skips are not). `[ts:src/modules/imports/sonarr.service.ts:159]`–`[ts:src/modules/imports/sonarr.service.ts:275]`
24. After the loop, for the new series only, a fire-and-forget background task refreshes metadata sequentially (`MediaService.refreshMetadata(id)`, the TMDB seasons / episodes import of the media spec); each failure is logged and skipped; the HTTP response does not wait. No activity row, no event; a restart loses the remaining ones. `[ts:src/modules/imports/sonarr.service.ts:277]`–`[ts:src/modules/imports/sonarr.service.ts:283]`, `[ts:src/modules/imports/sonarr.service.ts:536]`–`[ts:src/modules/imports/sonarr.service.ts:550]`

### F. NFO reader (pure parse + file lookup; used by disk import and media import)

47. `NfoData` = `{tmdbId?: int, imdbId?: string, tvdbId?: int, title?, originalTitle?, year?: int, plot?, genres?: string[], runtime?: int, rating?: number (0..10), premiered?: 'YYYY-MM-DD'}`; absent keys are OMITTED (never `null`). `parse(xml)` (pure, never throws; vectors `nfo`) reads the document with cheerio in XML mode, a lenient tag-soup parser (htmlparser2): nothing is ever rejected, unclosed or mismatched tags still yield their text (`<movie><title>X` → `title: 'X'`), and text without any element (`not xml at all`, `<<<>>>garbage&&&`, `''`) gives `{}`. Element names are matched case-sensitively (`<Title>` is not `title`) at any depth, first occurrence in document order wins; a value is the element's full descendant text, XML entities decoded and CDATA content included. Rust uses a lenient tokenizer with these semantics (e.g. `quick-xml` without end-name checks, keeping what was read before a hard error), pinned by the vectors. Ids: every `<uniqueid type=T>` with non-empty text, in document order (`type` lower-cased): `tmdb` → `tmdbId` (parseInt), `tvdb` → `tvdbId`, `imdb` → `imdbId` (text, not validated); a slot counts as set only when truthy, so the first value that parses to a non-zero int wins (`0` or `abc` does not block a later one); then, for ids still falsy, `<tmdbid>`, `<tvdbid>` (parseInt, may yield `0`, which is kept), `<imdbid>` (trimmed, non-empty); then `<id>`: starting with `tt` and no imdb yet → `imdbId`, else all digits and no tvdb yet → `tvdbId`. `title` = first non-empty of `<showtitle>`, `<title>`; `originalTitle` = `<originaltitle>`; `plot` = `<plot>` else `<outline>`; `genres` = distinct non-empty `<genre>` texts in order (omitted when none); `runtime` = parseInt of `<runtime>` when truthy (0 omitted); `rating` = first non-empty of `<ratings><rating default="true"><value>`, `<ratings><rating><value>`, `<rating>` (selector order), decimal comma accepted, kept only when finite and within 0..=10; `premiered` = the `YYYY-MM-DD` prefix (`^\d{4}-\d{2}-\d{2}`) of the trimmed raw text (`<premiered>` when its untrimmed text is non-empty, else `<aired>`), kept only when V8's `Date.parse` accepts it: month `01`-`12` and day `01`-`31` with no per-month check (`2020-13-45`, `2020-01-00` dropped; `2020-02-30`, `2021-02-29` kept); `year` = parseInt of `<year>` when truthy, else the first 4 characters of the raw premiered/aired text parsed. `parseInt` semantics (leading whitespace skipped, optional sign, leading digits: `12abc` → 12, `-5` → -5, `abc` → none); `toInt` never yields NaN, so the final NaN-id drop is dead code. `[ts:src/modules/imports/nfo-metadata.service.ts:6]`–`[ts:src/modules/imports/nfo-metadata.service.ts:19]`, `[ts:src/modules/imports/nfo-metadata.service.ts:78]`–`[ts:src/modules/imports/nfo-metadata.service.ts:167]`
48. `readNfoFile(path)`: read as UTF-8 text (a read error, incl. a directory or a missing file → `null`; invalid UTF-8 is replaced, not an error), then `parse`. `readForVideoFile(video)`: candidates in order `<dir>/<basename-without-ext>.nfo`, `<dir>/movie.nfo`, `<dir>/tvshow.nfo`, `<parent dir>/tvshow.nfo`; each existing file is parsed and merged key by key (a key is taken only while still unset: the most specific file wins its keys, show-level files backfill); stop after the first file that leaves any of `tmdbId`, `tvdbId`, `imdbId` truthy (a `0` id does not stop); `null` when no candidate file exists (a file that exists but parses to `{}` counts as found: result `{}`, not `null`). ## Open questions

Q1. SSRF on importer URLs is accepted (rule 45) by the §15.3 precedent for admin-set endpoints; what differs here is that the stored key follows the URL, which F?1 and F?4 close. Recommendation: no allow-list.
Q2. Subtitle `language` from Radarr `language.name` (`English`) would be stored as `english` (not an ISO code, never matches a language profile) once C?12 makes the import write rows, while `parseLanguageFromPath` gives `en`. Recommendation: map Radarr language names to ISO 639-1 through the `APP_LANGUAGES` names (one more C row, folded into C?12), since no Nest-written row exists to stay compatible with.
Q3. A Seerr update overwrites `status` even when Fliks advanced it (an `available` Fliks request becomes `approved` when Seerr says `media.status != 5`). Recommendation: freeze (Seerr is the source the admin chose to import; a re-run is explicit).
Q4. Seerr user matching is case-sensitive exact, so `Alice` and `alice` become two accounts; an imported `approved` request triggers no lifecycle hook (rule 31), so one for a media that is never grabbed stays `approved`. Recommendation: freeze both.
Q5. C?1 drops the Sonarr `tvdbId` fallback, but Sonarr v3 series carry no `tmdbId` (added in Sonarr v4) `[assumed]`, so against a v3 server every series becomes an `invalid tmdbId` error, and rows Nest imported with a TVDB id as `tmdbId` are no longer matched (a re-import inserts a second row for the same show). Recommendation: keep C?1 and document Sonarr v4 as the minimum, unless v3 support matters, in which case resolve `tvdbId` through TMDB `/find?external_source=tvdb_id` instead.
