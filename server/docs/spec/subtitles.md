## Routes

Manifest proof: `jq '[.[]|select(.path|test("^/api/subtitles($|/)|^/api/media/(sync-queue|:id/subtitles)"))]|length' server/contract/nest-routes.json` = 41: 8 activity + 9 providers + 9 translation-providers + 14 media subtitle + `sync-queue`. This spec owns 23: 8 activity, `providers/:id/stats`, 13 media subtitle routes (`translate` excluded) and `sync-queue`.

Guards on all of them: `JwtOrApiKeyGuard`, `PoliciesGuard` (class level `[ts:src/modules/subtitles/subtitle-activity.controller.ts:45]`, `[ts:src/modules/media/media.controller.ts:63]`); no `SessionTokenGuard`, so F8 makes the Rust extractor answer 401 to a `scope:'stream'` token on all of them. Policies on `SubtitleFile`: Read = `media.read`; Create, Update, Delete = `subtitles.manage` (rule 1); `manage:all` satisfies all. 401 / 403 on every route (auth rules 14, 27). Per-media routes first run the media ACL gate (rule 2). `SF` = stored row JSON (rule 4), `SFnew` = partial row returned by an insert (rule 5), `Item` = history/recent item (rule 21), `Cand` = search candidate (rule 8). No handler has `@HttpCode`: every POST answers **201** (also `auto` with an empty body), GET/PATCH/DELETE 200. On `:subtitleId` routes the binding (rule 3) answers 404 `Subtitle #<id> not found` first, so the services' own `SubtitleFile #<id> not found` is unreachable there.

Static segments win over `:id`/`:subtitleId` in Rust: `/api/media/sync-queue` and `/api/media/:id/subtitles/{search,auto,download,upload,search-missing}` must never reach an integer parser; `/api/subtitles/{history,stats,health,missing,blacklist}` are distinct from `/api/subtitles/providers/*`.

## Rules

### A. Authorization and binding

1. CASL on `SubtitleFile`: `Read` from `media.read`; `Create`/`Update`/`Delete` from `subtitles.manage`; `settings.access` grants none of them (only `Manage SubtitleProvider`/`TranslationProvider`). `[ts:src/modules/auth/casl/casl-ability.factory.ts:88]`, `[ts:src/modules/auth/casl/casl-ability.factory.ts:125]`
2. Per-media routes call `assertMediaAccessible(id, user)` = library ACL (`getAccessibleLibraryIds` then `assertAccessible`): a media outside the caller's libraries is 404 `Media #<id> not found`, never 403. `GET /subtitles/{history,stats,missing}`, `sync-queue` and the blacklist have no ACL in Nest. `[ts:src/modules/media/media.controller.ts:85]`
3. Subtitle-addressed routes (`:subtitleId`) additionally bind the row to the path media: `SELECT id FROM subtitle_files WHERE id = $1 AND "mediaId" = $2`, else 404 `Subtitle #<subtitleId> not found`. The service methods themselves load by id alone, so the Rust handler must bind before any call. `[ts:src/modules/subtitles/subtitles.service.ts:312]`, `[ts:src/modules/media/media.controller.ts:92]`
4. `SF` (a row read with `find`, no relation loaded) = every column as stored: `id`, `createdAt`, `updatedAt` (ISO strings), `mediaId: number`, `episodeId: number\|null`, `mediaFileId: number`, `language: string`, `forced`, `hearingImpaired`, `providerType`, `providerFileId: string\|null`, `relativePath: string\|null` (DB column `filePath`), `status`, `streamIndex: number\|null`, `sourceStreamIndex: number\|null`, `codec: string\|null`, `score: number`, `hashMatched`, `synced`, `syncFailed`, `syncOffset: number\|null`, `errorMessage: string\|null`, `locked`, `tags: string[]` (JSON text, default `[]`), `translationProviderId: number\|null`, `translationEngine`, `translationModel`, `translationProviderName` (each `string\|null`). Relation objects (`media`, `mediaFile`, `episode`, `translationProvider`) are never present. `translationProgress: number` exists only on `GET /media/:id/subtitles` rows with a running translation (absent, not null, otherwise). `[ts:src/modules/subtitles/entities/subtitle-file.entity.ts:20]`–`[ts:src/modules/subtitles/entities/subtitle-file.entity.ts:150]`, `[ts:src/modules/media/media.controller.ts:579]`
5. `SFnew` (the value `repo.save({...})` returns after an insert of a plain object; `download`, `upload`, `auto`, OCR placeholder) is NOT a full row: it is the object Nest passed plus the columns Postgres returned (`RETURNING` of generated and defaulted columns, checked in TypeORM `EntityMetadata.getInsertionReturningColumns`). Present: `id`, `createdAt`, `updatedAt`, the relation stubs `media: {id}`, `mediaFile: {id}`, `episode: {id}` or `episode: null`, the fields set by the writer (rules 16, 17, files rules 8, 24), and every column with a DB default (`forced`, `hearingImpaired`, `status`, `score`, `hashMatched`, `synced`, `syncFailed`, `locked`, `tags: []`). Absent (not null): `mediaId`, `episodeId`, `mediaFileId`, and every nullable column the writer did not set (`providerFileId` on upload, `codec`, `streamIndex`, `sourceStreamIndex`, `syncOffset`, `errorMessage`, translation columns, `relativePath` on the OCR placeholder). The client reads `id`, `language`, `status` only (record by parity `subtitles-download-shape` before port; the Rust response must reproduce this exact key set). `[ts:src/modules/subtitles/subtitles.service.ts:399]`, `[ts:src/modules/subtitles/subtitles.service.ts:472]`, `[ts:src/modules/subtitles/subtitle-ocr.service.ts:101]`
6. `GET /media/:id/subtitles` order: `language ASC, score DESC, id ASC`. `language` ordering follows DB collation for ASCII codes (equal to byte order for `[a-z]` codes). `[ts:src/modules/subtitles/subtitles.service.ts:53]`, `[ts:src/modules/subtitles/subtitles.service.ts:528]`

### B. Search, score, dedup

7. `searchSubtitles(params)`: (a) when `filePath` is given and no `moviehash`, compute the OpenSubtitles hash (files rule 37); no route passes `filePath`, so the hash always comes from `media_files.osdbHash`/`osdbBytesize`; (b) a search with no hash, imdb id or tmdb id only logs `WARN`; (c) enabled providers in `priority ASC, id ASC`, queried **sequentially**; each call is timed and recorded (rule 30); a provider error is logged `WARN`, recorded with its message, and skipped; (d) blacklist filter (rule 27 key); (e) language filter; (f) flag filter; (g) dedup; (h) rescore; (i) sort. All providers failing is `[]` with status 200 (indistinguishable from "no result"). `[ts:src/modules/subtitles/subtitles.service.ts:87]`–`[ts:src/modules/subtitles/subtitles.service.ts:229]`
8. `Cand` (what providers return, camelCase, this is also the `searchResult` the client posts back): `{providerFileId: string, title: string, releaseName?: string, imdbId?: string, hashMatched?: boolean, language: string, forced: boolean, hearingImpaired: boolean, score: number, downloadCount?: number, providerName: string, providerType: string}`. `score` is overwritten with the central percent (rule 12); any provider-set score is ignored. Optional fields are absent when the provider has none. The search response items also carry `_score: {raw: number, max: number, percent: number, matches: string[]}` (the scorer output is `Object.assign`ed onto each candidate, `[ts:src/modules/subtitles/subtitles.service.ts:217]`); the client posts it back inside `searchResult`, where it is ignored. `[ts:src/modules/subtitles/providers/subtitle-provider.interface.ts:34]`
9. Filters in order. Blacklist: drop a candidate whose `providerType + ':' + providerFileId` is in the whole `subtitle_blacklist` table (read in full per search, regardless of `mediaId`: an entry is global). Language: keep `normalizeLanguageCode(r.language) === normalizeLanguageCode(params.language)` (files rule 3). Flags (`matchesRequestedFlags`): `forced` set on the request = exact match both ways (`!!sub.forced === req.forced`); absent = no constraint; HI mode default `avoid`; `require` keeps only HI candidates, `forbid` only non-HI, `prefer`/`avoid` never filter. `[ts:src/modules/subtitles/subtitles.service.ts:145]`, `[ts:src/common/constants/subtitle-flags.ts:83]`
10. Dedup (after the filters, in provider-priority encounter order, the first occurrence wins): key = `lower(releaseName) + '|' + r.language + '|' + (hearingImpaired ? 'hi' : 'normal') + '|' + (forced ? 'forced' : 'full')` when `releaseName` is non-empty, else `providerType + ':' + providerFileId`. The key uses the provider's raw `language` string, not the normalised one. `[ts:src/modules/subtitles/subtitles.service.ts:184]`–`[ts:src/modules/subtitles/subtitles.service.ts:193]`
11. Scoring context: `kind = 'episode'` iff `season != null && episode != null`, else `'movie'`; `hearingImpairedMode` = request mode (default `avoid`); `videoReleaseName`, `title`, `year`, `imdbId` from the params. `score` = `percent` of rule 12. Sort: `percent DESC`, then `downloadCount DESC` (absent = 0); a remaining tie keeps the dedup order (stable sort). `[ts:src/modules/subtitles/subtitles.service.ts:201]`–`[ts:src/modules/subtitles/subtitles.service.ts:227]`
12. `scoreSubtitle(candidate, ctx)` (pure, the `subtitles` vector set): weights episode `{hash 359, series 180, year 90, season 30, episode 30, releaseGroup 14, source 7, audioCodec 3, resolution 2, videoCodec 2, hearingImpaired 1}`, movie `{hash 119, title 60, year 30, releaseGroup 13, source 7, audioCodec 3, resolution 2, videoCodec 2, edition 1, hearingImpaired 1}`; max = the hash weight; `percent = clamp(round(raw / max * 100), 0, 100)` (JS `Math.round`: halves round up). `hashMatched` returns `{raw: hash weight, matches: ['hash']}` = 100 and ignores everything else. Each name is credited once. `[ts:src/modules/subtitles/subtitle-scorer.ts:16]`–`[ts:src/modules/subtitles/subtitle-scorer.ts:127]`
13. Credits otherwise: imdb equivalence (`replace(/^tt/, '')` equal on both sides, both non-empty) credits `series` (episode) or `title` (movie) and `year` when the context has a year. With a candidate `releaseName` and a context `videoReleaseName`: `releaseGroup`, `source`, `resolution`, `videoCodec`, `audioCodec` (and `edition` for movies) when both parsed values are non-empty and equal (`parseReleaseAttributes`, `release-parsing` spec); title not yet credited: `looseTitleMatch` (lowercase, strip `[^a-z0-9]+`, release contains the title, empty title never matches); year not yet credited: regex `\b<year>\b` on the release name; episodes: `parseSeasonEpisode(releaseName)` equal to the context season / episode. HI bit: `prefersHI = mode in (prefer, require)`; credited when `candidate.hearingImpaired` equals `prefersHI` (truthiness). `[ts:src/modules/subtitles/subtitle-scorer.ts:130]`–`[ts:src/modules/subtitles/subtitle-scorer.ts:256]`
14. `GET /media/:id/subtitles/search` builds the params from `media` (as `GET /api/media/:id`, `media-query.md` rule 31): `imdbId`, `tmdbId` (may be null), `title`, `year`, `language` (query, default `en`), `season`/`episode` looked up by DB episode id `episodeId` in `media.seasons[].episodes[]` (a non-numeric or unknown `episodeId` is silently ignored: movie scoring), `videoReleaseName` = basename without extension of the matching file's `relativePath` (the file linked to the resolved episode, else the first file; `/`-split, last segment, trailing `.ext` removed), `moviehash`/`moviebytesize` from that file. It never sends `forced` or `hearingImpairedMode` (defaults: no forced filter, mode `avoid`). `[ts:src/modules/media/media.controller.ts:594]`–`[ts:src/modules/media/media.controller.ts:640]`
15. `POST /auto`: language default `fr` (not `en`), no `videoReleaseName`, no hash (scores lean on imdb and HI bit), season/episode resolved from `episodeId`; takes `results[0]` whatever its score (no `subtitle_min_score`); none = `null` = 200 with an empty body; then `downloadSubtitle`. `[ts:src/modules/media/media.controller.ts:643]`, `[ts:src/modules/subtitles/subtitles.service.ts:232]`
16. `downloadSubtitle(mediaId, mediaFileId, episodeId, cand)`, in order: (1) provider = the **enabled** provider whose `type` equals `cand.providerType` (the first by priority), else 404 `No matching provider found`; (2) `resolveMediaFilePath` (files rule 5); (3) `impl.download(cand)` timed and recorded (rule 30); failure → 400 `Download failed (<provider name>): <message>`; (4) `removeHiTags` and `customExclusions` settings (rule 40); (5) `lang = normalizeLanguageCode(cand.language)`; `hearingImpaired = cand.hearingImpaired && !removeHiTags`; suffix `sidecarLangSuffix` (files rule 2); (6) `cleanSubtitle(buffer, {removeAds: true, removeHiTags, customExclusions})` (files rules 30-33); (7) `writeSidecar` (files rule 6); (8) INSERT with `language: lang`, `forced: cand.forced`, `hearingImpaired`, `providerType: provider.type`, `providerFileId: cand.providerFileId`, `relativePath`, `status: 'downloaded'`, `score: cand.score`, `hashMatched: !!cand.hashMatched`, `synced: false`. The client-supplied `score`, `hashMatched`, `providerFileId` are stored as sent (not a security gap: `validate` already pins any score to 100 for the same permission; Q2). `[ts:src/modules/subtitles/subtitles.service.ts:322]`–`[ts:src/modules/subtitles/subtitles.service.ts:413]`
17. `upgradeSubtitle(id, cand)`: row missing 404 `SubtitleFile #<id> not found`; `embedded` → 400 `Cannot upgrade an embedded subtitle`; `ocr` → 400 `Cannot upgrade an OCR subtitle`; the replacement is downloaded and persisted FIRST (rule 16, same media file and episode as the old row), then `status = 'upgraded'`, `locked` and `tags` copied from the old row, saved again; only then the old file is unlinked (a failed unlink is logged; a missing file counts as removed) and the old row deleted. A failed download leaves the old subtitle untouched. The replacement gets a `-N` suffixed name when the old file holds the plain one (files rule 6). `[ts:src/modules/subtitles/subtitles.service.ts:932]`–`[ts:src/modules/subtitles/subtitles.service.ts:964]`
18. `setLanguage`: blank/whitespace → 400 `Language is required`; stored `normalizeLanguageCode(language)`; no check that the result is a known code (stores e.g. `xyz123`; C?4 validates `^[a-z]{2,3}$`). `validateSubtitle`: `score = 100`, idempotent. `[ts:src/modules/subtitles/subtitles.service.ts:544]`–`[ts:src/modules/subtitles/subtitles.service.ts:559]`
19. Upload (`uploadSubtitle`): see `files` rule 8 for the write; the route checks `file` present (400 `No file uploaded`), `mediaFileId` integer (`Number.isInteger`, 400 `mediaFileId is required`), `episodeId` = `Number(x)` when truthy. ```sql
WITH required AS (
  SELECT m.id AS media_id, m.title AS media_title, m.type::text AS media_type,
         lang->>'isoCode' AS language,
         COALESCE((lang->>'forced')::boolean, false) AS forced,
         COALESCE(lang->>'hearingImpaired',

  FROM media m
  JOIN language_profiles lp ON lp.id = m."languageProfileId"
  CROSS JOIN LATERAL jsonb_array_elements(lp."subtitleLanguages") AS lang
  WHERE m.monitored = true
)
SELECT r.media_id, r.media_title, r.media_type, r.language, r.forced,
       f.id AS file_id, f."relativePath", f."episodeId",
       s."seasonNumber", e."episodeNumber", COUNT(*) OVER () AS total
FROM required r
JOIN media_files f ON f."mediaId" = r.media_id
LEFT JOIN episodes e ON e.id = f."episodeId"
LEFT JOIN seasons  s ON s.id = e."seasonId"
WHERE NOT EXISTS (
  SELECT 1 FROM subtitle_files sf
  WHERE sf."mediaFileId" = f.id AND sf.language = r.language AND sf.forced = r.forced
    AND (r.hi_mode <> 'require' OR sf."hearingImpaired" = true)
    AND (r.hi_mode <> 'forbid'  OR sf."hearingImpaired" = false)
    AND COALESCE(sf.codec, '') <> ALL ($1::text[])

ORDER BY r.media_title, f.id, r.language, r.forced
LIMIT $2 OFFSET $3

## Jobs/timers

- `SubtitleSchedulerService.tick`: every 6 h at minute 0 (rule 34); runs `searchMissingSubtitles` then `upgradeSubtitles` sequentially when due. Rust: `croner` job, server TZ, same in-memory `lastRun` (start 0). Not audited in `commands`.
- `SubtitleSearch`, `SubtitleUpgrade` commands: listed with cron `0 0 */6 * * *`, triggerable, dispatched by the scheduler framework (`scheduler.md`), recorded in `commands`, activity rows per file.
- Sync queue worker (rule 47), OCR boot sweep (files rule 27), per-file search guard (rule 36): in-memory state, none survives a restart.
- Engine jobs (`SubtitleOcr`, `SubtitleSync`): no timeout on the wait (`engine-glue.md` rule 30); the engine bounds them (extract 900 s, OCR tool 1800 s, ffsubsync 900 s: `[engine:docs/spec/subtitle-jobs.md:25]`, `[engine:docs/spec/subtitle-jobs.md:35]`).
