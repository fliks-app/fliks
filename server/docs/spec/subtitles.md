# Spec: subtitles (routes, search, score, download, blacklist, stats, jobs)

Scope: the subtitle routes (activity, stats, missing, blacklist, per-media search/download/upload/upgrade/sync routes), search and scoring, download, blacklist, provider stats writes, the scheduled search and upgrade passes and the sync queue.

Companion spec: `subtitle-files.md` (sidecar paths, writing, post-processing, cleaner, OCR/sync jobs, embedded detection, rescan helpers). Rules there are cited "files rule N". Auth, CASL and error-body rules are in `auth.md` ("auth rule N": 14 = 401 body, 15 = HTTP error body, 16 = validation body, 18 = integer path parameters, 20/25 = CASL, 27 = 403). Library ACL = `libraries.md` rules 30-36. Path model (`M` = media directory, `Mc` = realpath of `M`) = `ingest.md` rules 1-6; `within(M, p)` below is that file's containment predicate applied to `M`.

Out of scope (specified elsewhere): provider scraping/rate limiter/breaker and the provider CRUD routes (`/api/subtitles/providers/*`, `:id/stats` included: `subtitle-providers.md` rule 42), translation (`/api/subtitles/translation-providers/*`, `POST /api/media/:id/subtitles/:subtitleId/translate`, `subtitle_translation_*` keys, engine `SubtitleToSrt`). This spec calls the provider interface (`search`, `download`, `testConnection`) as a black box.

## Routes

This spec owns 22 routes: 8 activity, 13 media subtitle routes (`translate` excluded) and `sync-queue`; `providers/:id/stats` belongs to `subtitle-providers.md`.

All of them need authentication (JWT or API key) plus a policy; none accepts a session token, so the extractor answers 401 to a `scope:'stream'` token on all of them. Policies on `SubtitleFile`: Read = `media.read`; Create, Update, Delete = `subtitles.manage` (rule 1); `manage:all` satisfies all. 401 / 403 on every route (auth rules 14, 27). Per-media routes first run the media ACL gate (rule 2). `SF` = stored row JSON (rule 4), `SFnew` = partial row returned by an insert (rule 5), `Item` = history/recent item (rule 21), `Cand` = search candidate (rule 8). Every POST answers **201** (also `auto` with an empty body), GET/PATCH/DELETE 200. On `:subtitleId` routes the binding (rule 3) answers 404 `Subtitle #<id> not found` first, so the services' own `SubtitleFile #<id> not found` is unreachable there.

Static segments win over `:id`/`:subtitleId`: `/api/media/sync-queue` and `/api/media/:id/subtitles/{search,auto,download,upload,search-missing}` must never reach an integer parser; `/api/subtitles/{history,stats,health,missing,blacklist}` are distinct from `/api/subtitles/providers/*`.

## Rules

### A. Authorization and binding

1. CASL on `SubtitleFile`: `Read` from `media.read`; `Create`/`Update`/`Delete` from `subtitles.manage`; `settings.access` grants none of them (only `Manage SubtitleProvider`/`TranslationProvider`).
2. Per-media routes call `assertMediaAccessible(id, user)` = library ACL (`getAccessibleLibraryIds` then `assertAccessible`): a media outside the caller's libraries is 404 `Media #<id> not found`, never 403. `GET /subtitles/{history,stats,missing}` and `sync-queue` are filtered by library instead (rule 26); the blacklist has no ACL.
3. Subtitle-addressed routes (`:subtitleId`) additionally bind the row to the path media: `SELECT id FROM subtitle_files WHERE id = $1 AND "mediaId" = $2`, else 404 `Subtitle #<subtitleId> not found`. The service methods load by id alone, so the handler binds before any call.
4. `SF` (a row, no relation loaded) = every column as stored: `id`, `createdAt`, `updatedAt` (ISO strings), `mediaId: number`, `episodeId: number\|null`, `mediaFileId: number`, `language: string`, `forced`, `hearingImpaired`, `providerType`, `providerFileId: string\|null`, `relativePath: string\|null` (DB column `filePath`), `status`, `streamIndex: number\|null`, `sourceStreamIndex: number\|null`, `codec: string\|null`, `score: number`, `hashMatched`, `synced`, `syncFailed`, `syncOffset: number\|null`, `errorMessage: string\|null`, `locked`, `tags: string[]` (JSON text, default `[]`), `translationProviderId: number\|null`, `translationEngine`, `translationModel`, `translationProviderName` (each `string\|null`). Relation objects (`media`, `mediaFile`, `episode`, `translationProvider`) are never present. `translationProgress: number` exists only on `GET /media/:id/subtitles` rows with a running translation (absent, not null, otherwise).
5. `SFnew` (the row returned after an insert; `download`, `auto`, `upload`, `upgrade`, the OCR and translation placeholders; parity `subtitles-provider-download-shape`, `-upload-flags-from-name`, `subtitles-media-ocr-placeholder-shape`): every column of rule 4 with its value or `null` (`providerFileId`, `relativePath`, `streamIndex`, `sourceStreamIndex`, `codec`, `syncOffset`, `errorMessage`, `translationEngine`, `translationModel`, `translationProviderName`), `mediaId`, `mediaFileId`, `episodeId` (`null` without an episode), plus the relation stubs `media: {id}`, `mediaFile: {id}`, `episode: {id}` or `null`, and `createdAt`/`updatedAt`. `translationProviderId` and `translationProvider: {id}` exist only on a translation placeholder. The client reads `id`, `language`, `status` only.
6. `GET /media/:id/subtitles` order: `language ASC, score DESC, id ASC`. `language` ordering is the database collation, equal to byte order for `[a-z]` codes.

### B. Search, score, dedup

7. `searchSubtitles(params)`: (a) the hash always comes from `media_files.osdbHash`/`osdbBytesize` (the stored hash is the engine probe's, files rule 37); (b) a search with no hash, imdb id or tmdb id only logs `WARN`; (c) enabled providers in `priority ASC, id ASC`, queried **sequentially**; each call is timed and recorded (rule 30); a provider error is logged `WARN`, recorded with its message, and skipped; (d) blacklist filter (rule 27 key); (e) language filter; (f) flag filter; (g) dedup; (h) rescore; (i) sort. All providers failing is `[]` with status 200 (indistinguishable from "no result").
8. `Cand` (what providers return, camelCase, this is also the `searchResult` the client posts back): `{providerFileId: string, title: string, releaseName?: string, imdbId?: string, hashMatched?: boolean, language: string, forced: boolean, hearingImpaired: boolean, score: number, downloadCount?: number, providerName: string, providerType: string}`. `score` is overwritten with the central percent (rule 12); any provider-set score is ignored. Optional fields are absent when the provider has none. The search response items also carry `_score: {raw: number, max: number, percent: number, matches: string[]}` (the scorer output is merged onto each candidate); the client posts it back inside `searchResult`, where it is ignored.
9. Filters in order. Blacklist: drop a candidate whose `providerType + ':' + providerFileId` is in the whole `subtitle_blacklist` table (read in full per search, regardless of `mediaId`: an entry is global). Language: keep `normalizeLanguageCode(r.language) === normalizeLanguageCode(params.language)` (files rule 3). Flags (`matchesRequestedFlags`): `forced` set on the request = exact match both ways (`!!sub.forced === req.forced`); absent = no constraint; HI mode default `avoid`; `require` keeps only HI candidates, `forbid` only non-HI, `prefer`/`avoid` never filter.
10. Dedup (after the filters, in provider-priority encounter order, the first occurrence wins): key = `lower(releaseName) + '|' + r.language + '|' + (hearingImpaired ? 'hi' : 'normal') + '|' + (forced ? 'forced' : 'full')` when `releaseName` is non-empty, else `providerType + ':' + providerFileId`. The key uses the provider's raw `language` string, not the normalised one.
11. Scoring context: `kind = 'episode'` iff `season != null && episode != null`, else `'movie'`; `hearingImpairedMode` = request mode (default `avoid`); `videoReleaseName`, `title`, `year`, `imdbId` from the params. `score` = `percent` of rule 12. Sort: `percent DESC`, then `downloadCount DESC` (absent = 0); a remaining tie keeps the dedup order (stable sort).
12. `scoreSubtitle(candidate, ctx)` (pure, the `subtitles` vector set): weights episode `{hash 359, series 180, year 90, season 30, episode 30, releaseGroup 14, source 7, audioCodec 3, resolution 2, videoCodec 2, hearingImpaired 1}`, movie `{hash 119, title 60, year 30, releaseGroup 13, source 7, audioCodec 3, resolution 2, videoCodec 2, edition 1, hearingImpaired 1}`; max = the hash weight; `percent = clamp(round(raw / max * 100), 0, 100)` (halves round up). `hashMatched` returns `{raw: hash weight, matches: ['hash']}` = 100 and ignores everything else. Each name is credited once.
13. Credits otherwise: imdb equivalence (`replace(/^tt/, '')` equal on both sides, both non-empty) credits `series` (episode) or `title` (movie) and `year` when the context has a year. With a candidate `releaseName` and a context `videoReleaseName`: `releaseGroup`, `source`, `resolution`, `videoCodec`, `audioCodec` (and `edition` for movies) when both parsed values are non-empty and equal (`parseReleaseAttributes`, `release.md`; `fliks_domain::release::parsing::attributes`); title not yet credited: `looseTitleMatch` (lowercase, strip `[^a-z0-9]+`, release contains the title, empty title never matches); year not yet credited: regex `\b<year>\b` on the release name; episodes: `parseSeasonEpisode(releaseName)` (`release::parsing::season_episode`) equal to the context season / episode. HI bit: `prefersHI = mode in (prefer, require)`; credited when `candidate.hearingImpaired` equals `prefersHI` (truthiness).
14. `GET /media/:id/subtitles/search` builds the params from `media` (as `GET /api/media/:id`, `media-query.md` rule 31): `imdbId`, `tmdbId` (may be null), `title`, `year`, `language` (query, default `en`), `season`/`episode` looked up by DB episode id `episodeId` in `media.seasons[].episodes[]` (a non-numeric or unknown `episodeId` is silently ignored: movie scoring), `videoReleaseName` = basename without extension of the matching file's `relativePath` (the file linked to the resolved episode, else the first file; `/`-split, last segment, trailing `.ext` removed), `moviehash`/`moviebytesize` from that file. It never sends `forced` or `hearingImpairedMode` (defaults: no forced filter, mode `avoid`).
15. `POST /auto`: language default `fr` (not `en`), no `videoReleaseName`, no hash (scores lean on imdb and HI bit), season/episode resolved from `episodeId`; takes `results[0]` whatever its score (no `subtitle_min_score`); none = `null` = 200 with an empty body; then `downloadSubtitle`.
16. `downloadSubtitle(mediaId, mediaFileId, episodeId, cand)`, in order: (1) provider = the **enabled** provider whose `type` equals `cand.providerType` (the first by priority), else 404 `No matching provider found`; (2) `resolveMediaFilePath` (files rule 5); (3) `impl.download(cand)` timed and recorded (rule 30); failure → 400 `Download failed (<provider name>): <message>`; (4) `removeHiTags` and `customExclusions` settings (rule 40); (5) `lang = normalizeLanguageCode(cand.language)`; `hearingImpaired = cand.hearingImpaired && !removeHiTags`; suffix `sidecarLangSuffix` (files rule 2); (6) `cleanSubtitle(buffer, {removeAds: true, removeHiTags, customExclusions})` (files rules 30-33); (7) `writeSidecar` (files rule 6); (8) INSERT with `language: lang`, `forced: cand.forced`, `hearingImpaired`, `providerType: provider.type`, `providerFileId: cand.providerFileId`, `relativePath`, `status: 'downloaded'`, `score: cand.score`, `hashMatched: !!cand.hashMatched`, `synced: false`. The client-supplied `score`, `hashMatched`, `providerFileId` are stored as sent (`validate` already pins any score to 100 for the same permission; rule 52).
17. `upgradeSubtitle(id, cand)`: row missing 404 `SubtitleFile #<id> not found`; `embedded` → 400 `Cannot upgrade an embedded subtitle`; `ocr` → 400 `Cannot upgrade an OCR subtitle`; the replacement is downloaded and persisted FIRST (rule 16, same media file and episode as the replaced row), then `status = 'upgraded'`, `locked` and `tags` copied from the replaced row, saved again; only then the replaced file is unlinked (a failed unlink is logged; a missing file counts as removed) and the replaced row deleted. A failed download leaves the current subtitle untouched. The replacement gets a `-N` suffixed name when the replaced file holds the plain one (files rule 6).
18. `setLanguage`: blank/whitespace → 400 `Language is required`; stored `normalizeLanguageCode(language)`; the result must match `^[a-z]{2,3}$` (else 400), with no check that it is a known code. `validateSubtitle`: `score = 100`, idempotent.
19. Upload (`uploadSubtitle`): see `files` rule 8 for the write; the route checks `file` present (400 `No file uploaded`), `mediaFileId` integer (`Number.isInteger`, 400 `mediaFileId is required`), `episodeId` = `Number(x)` when truthy. Score stored `100`, `synced: true`, `providerType: 'disk'`.

### C. Activity, stats, missing

20. `history`: `page = max(1, Number(page) \|\| 1)`, `limit = min(100, max(1, Number(limit) \|\| 25))` (a fractional `page` or `limit` is floored). Filters AND-ed: `excludeEmbedded === 'true'` → `providerType != 'embedded'`; `status`, `language`, `providerType` equality when truthy. Order `createdAt DESC`, `id ASC`. A `status` or `providerType` outside the enums is 400.
21. `Item` = `{id, mediaId: number, mediaTitle: string ('?' when the media row is gone), mediaType: string\|null, episodeId: number\|null, seasonNumber: number\|null, episodeNumber: number\|null, episodeTitle: string\|null, language, providerType, score, status, forced, hearingImpaired, synced, syncFailed, errorMessage: string\|null, createdAt}`. Episode scope = the row's own `episode`, else the media file's episode (`episodeScope`): `episodeId`, `episode.season.seasonNumber`, `episodeNumber`, `title`. `mediaId` comes from the `media` join (`sf.mediaId` relation id).
22. `stats`: `total` = count of rows with `providerType != 'embedded'`; `byStatus` and `byProvider` = `{key: count}` objects over the same rows (a key absent when its count is 0; counts are JSON numbers, `::int`); `recent` = the 10 newest non-embedded rows as `RecentItem` = `Item` minus `forced`, `hearingImpaired`, `synced`, `syncFailed`, `errorMessage`.
23. `health`: for each enabled provider (priority order) `testConnection(type, provider.settings)` with the **stored** settings (no secret merge needed); `error = detail ?? null`. A provider whose test throws is `{ok: false}` with the message (never an error response). Sequential, so a slow provider delays the response; no timeout of its own. Only `subtitles.manage` can trigger the N upstream logins.
24. `missing` = one statement (SQL section Q4): every (media file, profile language item) pair of a monitored media with no servable subtitle. `take = clamp(Number(limit) \|\| 50, 1, 500)`, `skip = (max(Number(page) \|\| 1, 1) - 1) * take`; `burnInCovers = setting === 'true'` makes `$1 = []` (image codecs then count as covering), else `$1 = IMAGE_BASED_SUBTITLE_CODECS` (`hdmv_pgs_subtitle, dvd_subtitle, dvb_subtitle, xsub`). `total` = `COUNT(*) OVER ()` of the first row (0 when no row, including when `skip` is past the end: `total` is then 0, not the real count). `fileName` = last `/` segment of `relativePath`; `episodeLabel` = `S<2-digit season>E<2-digit episode>` when both exist (3-digit numbers keep their digits), else `null`. `forced`/`hi` of a language item: `hi_mode` = `hearingImpaired` when present, else `hi` boolean → `prefer`/`avoid`. Like the scheduler's `hasCoveringSub` (rule 38) the statement ignores the HI `require`/`forbid` modes: HI never decides coverage, so `/missing` lists what the scheduler would fetch, and a language item without an `isoCode` is skipped.
25. Media without a language profile, or whose profile has no `subtitleLanguages`, produce no row; a media whose files list is empty produces none. Unmonitored media are excluded.
26. `history`, `stats`, `missing` and `sync-queue` return only rows of media in the caller's accessible libraries (`libraries.md` rules 30-36; admins and `manage:all` see all; `subtitle_files.mediaId` cascades, so no row outlives its media).

### D. Blacklist

27. `Blacklist` JSON = the row: `{id, createdAt, updatedAt, providerType: string, providerFileId: string, mediaId: number\|null, language: string\|null, sourceTitle: string\|null, reason: string\|null}`. `GET`: `ORDER BY createdAt DESC` (+ `id ASC`), `OFFSET (page-1)*limit`, `LIMIT limit` with `page = Number(x) \|\| 1`, `limit = Number(x) \|\| 25` (no clamp; `0` and non-numeric read as the default; a negative or fractional result is 400). The search filter key is `providerType:providerFileId`.
28. `POST`: the body is validated (wrong type → 400) and the two required fields must be truthy (else 400). `mediaId` is stored (404 `Media #<id> not found` for an unknown media); the 201 body is the partial entity of the route table plus `id`, `createdAt`, `updatedAt`, without `mediaId` (parity `blacklist-add-mediaid`). Duplicates of `(providerType, providerFileId)` are accepted (no unique index).
29. Blacklisting never touches the subtitle row or its file; it only hides the candidate from later searches. `DELETE :id` unknown = 404. `DELETE` all deletes every row and returns `{deleted}` = affected rows. `subtitle_blacklist.mediaId` is `ON DELETE SET NULL`.

### E. Provider stats

30. `subtitle_provider_stats` rows are written by `searchSubtitles` and `downloadSubtitle`, fire-and-forget (a failed insert is lost silently): `{providerId, queryType: 'search'|'download', responseTimeMs: now - start, resultCount: results.length (search) or 1/0 (download ok/fail), errorMessage: null | err.message}`; `queryDate` = `now()`.
31. `GET /providers/:id/stats` (read side, SQL, `date` serialisation, parity `providers-stats`) is owned by `subtitle-providers.md` rule 42 together with the other 8 `providers/*` routes of one controller; this spec keeps only the write side (rule 30).
32. Provider rows are not edited here; `subtitle_provider_stats.providerId` is `ON DELETE CASCADE`, so deleting a provider drops its stats (providers spec). Provider CRUD, `rate-limits`, `test-connection`, `:id/test` and every redaction (`secretsSet` for provider `settings.password`/`apiKey`) belong to the providers spec; this one only requires `findEnabled()` (`enabled = true ORDER BY priority ASC, id ASC`) and `factory.create(type, settings).search/download/testConnection`.
33. (Number kept so cross-references stay valid; the route ownership note is rule 31.)

### F. Scheduled passes (SubtitleSearch / SubtitleUpgrade)

34. Scheduler: a `tick()` every 6 hours (`0 0-23/6 * * *`, server TZ) is the only timer. `searchInterval = Number(setting ?? '360') * 60000`, `upgradeInterval = Number(setting ?? '720') * 60000`; a pass runs when `now - lastRun >= interval`, with `lastRun` an in-memory timestamp starting at 0 (so each pass runs at the first tick after boot, and an interval below 360 min is floored to the 6 h tick). A non-finite setting reads as the default (360, 720). The ticks are not recorded in `commands`; `SubtitleSearch` and `SubtitleUpgrade` appear in `SCHEDULERS` only to list `nextRun`/`lastRun` and to be triggerable (`dispatchCommand` calls the same methods, recorded as a command).
35. `searchMissingSubtitles` (scheduled and triggered): `subtitle_auto_search === 'false'` → return (any other value, or none, is on). Options (`resolveSearchOpts`): `minScore = Number(subtitle_min_score ?? '70')` (percent), `autoSyncEnabled = subtitle_auto_sync === 'true'`, `encodeUtf8 = subtitle_encode_utf8 !== 'false'` (accepted and ignored: files rule 29), `burnInCovers = subtitle_burn_in_covers_language === 'true'`. Walk: monitored media ordered `id ASC`, batches of 50 (`OFFSET`), each media's `files`; for each file `searchMissingForFile`.
36. `searchMissingForFile(media, file, opts, skipEmbeddedDetect)`: a per-file in-memory guard (`filesSearching` set) makes a concurrent call for the same file return `[]`; an activity row `SubtitleSearch:<fileId>` (subject = media/episode) is running for its duration; the guard and the row are released in `finally`. Then `doSearchMissingForFile`: no profile languages → `[]`; unless skipped, `detectAndStore` (files rule 25); existing rows of the file; `videoReleaseName` = basename sans extension of `file.relativePath`; season/episode from the file's episode. Per profile language item, sequentially: (a) `hasCoveringSub(existing, item)` → skip; (b) OCR-first (rule 37) → counted as downloaded and skip; (c) `burnInCovers` and an image track covers (`imageTracksCount`) → skip; (d) search with `language: item.isoCode`, season, episode, release name, the file's `osdbHash`/`osdbBytesize`, and `requestFlagsOf(item)` (`forced: !!item.forced`, `hearingImpairedMode` = `item.hearingImpaired ?? (item.hi ? 'prefer' : 'avoid')`); (e) `best` = first result with `score >= minScore` (results are sorted), none → next language; (f) `downloadSubtitle` (rule 16); (g) `encodeUtf8` is not applied (files rule 29); (h) `autoSyncEnabled` → `syncSubtitle(id, {automatic: true})` run inline (files rule 22); (i) notification `subtitle.downloaded {title, language, provider: best.providerName, score}` and media-server dispatch `subtitle.downloaded {title, path}` (fire-and-forget); (j) iso code added to the result. Any error in (d)-(h) is logged `WARN`, notification `subtitle.failed {title, language, error: String(err)}`, and the loop continues with the next language.
37. OCR-first (`tryOcrFirst`): off unless `subtitle_ocr_burn_in_auto === 'true'`; `und` or empty iso code → false; runs matching the language and flags with `providerType = 'ocr'`: any non-failed → true (a run exists or is in progress); only failed ones → false (hand to providers, no retry); else candidate rows = same language and flags, OCR-supported codec (`hdmv_pgs_subtitle`, `dvd_subtitle`), `streamIndex != null`, not failed; prefer the one whose HI flag equals `prefersHearingImpaired(req)`, else the first; none → false; start `ocrSubtitle(id, isoCode, {automatic: true})` (files rule 24) → true, a thrown error → logged, false.
38. `hasCoveringSub(subs, item, {imageTracksCount})`: a sub covers when `sub.language === item.isoCode`, `matchesRequestedFlags(sub, {forced: !!item.forced})` (only `forced` decides; HI is deliberately ignored so a cleaned file that dropped its HI flag does not re-fetch forever), the codec is not image-based unless `imageTracksCount`, and `status !== 'failed'`.
39. `upgradeSubtitles`: `subtitle_auto_search === 'false'` → return; `threshold = Number(subtitle_upgrade_threshold ?? '90')`. Walk by id cursor, batches of 100: rows with `score < threshold AND status != 'failed' AND locked = false AND id > lastId`, joined with media, its language profile, the media file and its episode/season, `ORDER BY id ASC`. Per batch `buildMissingLangsByFile`: for each file of the batch, `true` when some required profile language has no non-failed sub of that **language** (flags ignored here on purpose); a profile with no languages = `false`. Per row: `langItem` = the profile item with `isoCode === sub.language` and `matchesRequestedFlags(sub, requestFlagsOf(item))`, none → skip (the profile is the contract); file with missing languages → skip; search (as rule 36 d, language `sub.language`); `candidates` = results, restricted to `hashMatched` ones when the row is `hashMatched`; `better` = first with `score > sub.score`, none → skip; `upgradeSubtitle` (rule 17); `autoSync` as in rule 36; notification `subtitle.upgraded {title, language, oldScore, newScore, provider}` and media-server dispatch `subtitle.upgraded`; errors logged `WARN`, the batch continues. Embedded and OCR rows are never upgraded (rule 17 raises, caught). Rows with `score = 100` (validated, disk-discovered, uploaded, OCR, embedded) are never below a threshold of at most 100.
40. Settings read per operation (no cache): `subtitle_remove_hi_tags === 'true'`; `subtitle_custom_exclusions` newline-separated regex patterns (blank lines dropped; files rule 33). See Settings keys.
41. `POST /media/:id/subtitles/search-missing` = `searchMissingForMedia`: loads the media with profile, files, episodes; unknown media or file → `{downloaded: []}`; runs rule 36 for that file with the same options (ignores `subtitle_auto_search`); returns the iso codes of languages handled (OCR-started counts as downloaded). A concurrent run on the file returns `[]`.
42. `onMediaFileImported(mediaId, mediaFileId, episodeId?)` (called by the post-import queue): `detectAndStore` always (files rule 25), then, unless `subtitle_auto_search === 'false'`, rule 36 for that file with `skipEmbeddedDetect = true`.
43. Numeric settings (`subtitle_min_score` 70, `subtitle_upgrade_threshold` 90, the two intervals 360 and 720) parse as finite numbers, else the default; a non-numeric value never disables downloads or a pass.
44. The sync queue carries its own options per item (rule 47).

### G. Sync queue and engine jobs

45. `enqueueSyncSubtitle(id, options)`: row (with media, episode, season) missing → 404 `SubtitleFile #<id> not found`; `embedded` → 400 `Cannot sync an embedded subtitle`; then `locked = true` is saved (also when the request is a duplicate); a queued or running item for the same `subtitleId` is returned as is (no second item, its options kept); else an item `{subtitleId, status: 'queued', queuedAt: epoch ms, subject}` is pushed, an activity row `SubtitleSync:<id>` (type `SubtitleSync`) goes pending, the queue is trimmed (while longer than 50 and the head is `completed`/`failed`, drop the head), and `processQueue` runs unawaited. The response is the item object (it mutates later; the JSON is a snapshot at send time = `queued` or whatever the existing item has).
46. `SyncQueueItem` JSON: `{subtitleId: number, status: 'queued'|'running'|'completed'|'failed', error?: string, queuedAt: number, startedAt?: number, completedAt?: number, subject: MediaProgressSubject}` (absent, not null, until set). `subject` = `buildMediaProgressSubject(media, episode?)`, shape per `events-hub.md` (`task.progress` `subject`). The queue is in memory only: lost on restart, never persisted (no `GET` of past runs beyond the last 50 ended + live).
47. `processQueue`: at most `MAX_CONCURRENT = 2` run at once; picks the first `queued` item; marks `running`/`startedAt`, activity row running; `doSync(next.subtitleId, next.options)`; `completed` or `failed` (+ `error = message`); `finally` `completedAt`, release the slot, remove the activity row, recurse. Each item keeps the options of the request that queued it (an item queued with `maxOffsetSeconds: 60` runs with 60 whatever later requests pass).
48. `doSync`: see `files` rules 22-28 (reads the sidecar, runs the engine `SubtitleSync` job, writes back, events). Events and notifications after a success: SSE `subtitle.synced`, notification `subtitle.synced {language, subtitleId}`, media-server dispatch `subtitle.synced {title, path}`.
49. OCR start/finish and the boot sweep: `files` rules 24-27. The engine jobs used by this scope: `SubtitleOcr` and `SubtitleSync` through `runJob` (`engine-glue.md` rules 30-33); `SubtitleToSrt` is consumed by translation only. `post-process convertToSrt` stays in-process (`assToSrt`, files rule 17), it does not use the engine job.

### H. Decisions

50. Input validation (400 with the standard validation body): a missing, non-object or wrongly typed body on `auto`, `search-missing`, `download`, `upgrade`, `ocr`, `language`, `post-process` and `blacklist`; `history` `status` / `providerType` outside the enums; `history` floors a fractional `page` / `limit` and keeps the clamps of rule 20; `blacklist` reads `0` and non-numeric as the default and answers 400 for a negative or fractional result; `setLanguage` must produce a code matching `^[a-z]{2,3}$` (rule 18). `missing`, `history` and the blacklist list end with `id ASC`.
51. The blacklist read (`GET /api/subtitles/blacklist`) needs `media.read` only: the rows hold only provider ids and a title.
52. A client-supplied `score`, `hashMatched` and `providerFileId` on `download` and `upgrade` are stored as sent (rule 16); `validate` already grants score 100 to the same permission.
53. The `date` of `GET /providers/:id/stats` is an instant, not a plain `YYYY-MM-DD` (rule 31, `subtitle-providers.md` rule 42).
54. The scheduled `tick` is not recorded in `commands` (rule 34) while the manual trigger is: recording scheduled runs is a `scheduler.md` decision, not a subtitle one.
55. Each pass of the tick holds the `jobs::Running` claim of its name (`SubtitleSearch` for `searchMissingSubtitles`, `SubtitleUpgrade` for `upgradeSubtitles`) for its whole run, like a core job (`scheduler.md` rules 8, 19). A pass whose claim is held (a manual run, or a restore) is skipped with a warn and keeps its `lastRun`, so it runs at the next due tick; a manual `POST /api/commands` of that name during the pass answers 409 `Command "<name>" is already running`; a restore is refused while a pass runs (`system.md` rule 25).

## SQL

Tables: `subtitle_files` (`sf`), `subtitle_blacklist`, `subtitle_provider_stats`, `media`, `media_files`, `items`, `item_groups`, `language_profiles`, `app_settings`. DDL: the baseline migration plus `1782200000000`, `1780200000000`, `1784700000000`; `subtitle_files."updatedAt"` has the `set_updated_at` trigger. Columns are camelCase quoted. Enum columns: `subtitle_files."providerType"` and `"status"` (a bogus filter value is rejected with 400 before the query).

- Q1 history: `SELECT sf.*, media.*, episode.*, season.*, mf.*, fe.*, fs.* FROM subtitle_files sf LEFT JOIN media ON media.id = sf."mediaId" LEFT JOIN items episode ON episode.id = sf."episodeId" LEFT JOIN item_groups season ON season.id = episode."seasonId" LEFT JOIN media_files mf ON mf.id = sf."mediaFileId" LEFT JOIN items fe ON fe.id = mf."episodeId" LEFT JOIN item_groups fs ON fs.id = fe."groupId" WHERE [sf."providerType" <> 'embedded'] [AND sf.status = $s] [AND sf.language = $l] [AND sf."providerType" = $p] ORDER BY sf."createdAt" DESC, sf.id ASC LIMIT $limit OFFSET $offset` plus `SELECT count(*)` with the same filters The query selects only the sources of the 13 `Item` fields (`media.title`, `media.type`, episode and season numbers/titles).
- Q2 stats: `SELECT count(*) FROM subtitle_files WHERE "providerType" <> 'embedded'`; `SELECT status, COUNT(*)::int AS count FROM subtitle_files WHERE "providerType" <> 'embedded' GROUP BY status`; same grouped by `"providerType"`; recent: Q1's joins, same filter, `ORDER BY "createdAt" DESC, id ASC LIMIT 10`.
- Q3 list for media: `SELECT * FROM subtitle_files WHERE "mediaId" = $1 ORDER BY language ASC, score DESC, id ASC`; by file: `WHERE "mediaFileId" = $1`, same order.
- Q4 missing (`$1 text[]`, `$2` limit, `$3` offset):

```sql
WITH required AS (
  SELECT m.id AS media_id, m.title AS media_title, m.type::text AS media_type,
         lang->>'isoCode' AS language,
         COALESCE((lang->>'forced')::boolean, false) AS forced,
         COALESCE(lang->>'hearingImpaired',
           CASE WHEN COALESCE((lang->>'hi')::boolean, false) THEN 'prefer' ELSE 'avoid' END) AS hi_mode
  FROM media m
  JOIN language_profiles lp ON lp.id = m."languageProfileId"
  CROSS JOIN LATERAL jsonb_array_elements(lp."subtitleLanguages") AS lang
  WHERE m.monitored = true
)
SELECT r.media_id, r.media_title, r.media_type, r.language, r.forced,
       f.id AS file_id, f."relativePath", f."episodeId",
       s."number", e."number", COUNT(*) OVER () AS total
FROM required r
JOIN media_files f ON f."mediaId" = r.media_id
LEFT JOIN items e ON e.id = f."episodeId"
LEFT JOIN item_groups  s ON s.id = e."groupId"
WHERE NOT EXISTS (
  SELECT 1 FROM subtitle_files sf
  WHERE sf."mediaFileId" = f.id AND sf.language = r.language AND sf.forced = r.forced
    AND (r.hi_mode <> 'require' OR sf."hearingImpaired" = true)
    AND (r.hi_mode <> 'forbid'  OR sf."hearingImpaired" = false)
    AND COALESCE(sf.codec, '') <> ALL ($1::text[])
    AND COALESCE(sf.status::text, '') <> 'failed')
ORDER BY r.media_title, f.id, r.language, r.forced
LIMIT $2 OFFSET $3
```

  The `ORDER BY` is `lower(r.media_title), r.media_id, f.id, r.language, r.forced` (bytewise, then ids). A profile item whose `lang->>'isoCode'` is NULL (malformed) is skipped. The two HI predicates of the `NOT EXISTS` are not applied (rule 24).
- Q5 provider stats: moved with the route to `subtitle-providers.md` (SQL section).
- Q6 blacklist: `SELECT * FROM subtitle_blacklist ORDER BY "createdAt" DESC, id ASC LIMIT $1 OFFSET $2` + `count(*)`; insert `(providerType, providerFileId, language, sourceTitle, reason)` (+ `mediaId`); `DELETE ... WHERE id = $1`; `DELETE FROM subtitle_blacklist` (returns the row count); search filter: `SELECT "providerType", "providerFileId" FROM subtitle_blacklist`.
- Q7 provider stat insert: `INSERT INTO subtitle_provider_stats ("providerId", "queryType", "responseTimeMs", "resultCount", "errorMessage") VALUES (...)`.
- Q8 upgrade candidates and per-batch coverage: `SELECT sf.*, media.*, lp.*, mf.*, mfEpisode.*, mfSeason.* FROM subtitle_files sf LEFT JOIN media ... WHERE sf.score < $t AND sf.status <> 'failed' AND sf.locked = false AND sf.id > $last ORDER BY sf.id ASC LIMIT 100`; coverage: `SELECT * FROM subtitle_files WHERE "mediaFileId" = ANY($ids)`.
- Q9 scheduler walk: `SELECT media.* FROM media WHERE monitored = true ORDER BY id ASC LIMIT 50 OFFSET $n` with `languageProfile`, `files`, `files.episode`, `files.episode.season`. The walk is by id cursor (`id > $last`), not OFFSET, so files added during a pass cannot skip a media.
- Q10 row writes: INSERT of a sidecar row (rule 16/files rule 8), `UPDATE subtitle_files SET score = 100`, `SET language`, `SET locked = true`, `SET "synced", status`, `DELETE FROM subtitle_files WHERE id = $1`. A row is addressed by id after the media binding (rule 3).

## Events

Emitted (audience `Us(viewersForMedia)`; payloads in `events-hub.md` rows 4-8): `subtitle.synced {subtitleId, language, mediaId?, automatic?}` after a successful sync (files rule 22); `subtitle.downloaded {mediaId, title, language, provider: 'ocr', automatic?}` and `subtitle.failed {mediaId, title, language, error, automatic?}` from OCR (files rules 26-27); `subtitle.list_changed {mediaId}` from the OCR placeholder and from `detectAndStore` when it changed anything (files rule 25). Consumed: none.

## Jobs/timers

- `SubtitleSchedulerService.tick`: every 6 h at minute 0 (rule 34); runs `searchMissingSubtitles` then `upgradeSubtitles` sequentially when due. It is a `jobs::cron::spawn` timer in `jobs::cron::server_tz()` (it fires every valid local time on DST days), with an in-memory `lastRun` (start 0). Not audited in `commands`; each pass holds its name's `jobs::Running` claim (rule 55). `jobs::runner::spawn` keeps skipping both names (`names::SUBTITLE`), so only this tick fires them on a schedule.
- `SubtitleSearch`, `SubtitleUpgrade` commands: listed with cron `0 0-23/6 * * *` (`scheduler.md` rule 10), triggerable, dispatched by the scheduler framework (`scheduler.md`), recorded in `commands`, activity rows per file. Both have an arm of `jobs::bodies::run`; the manual path is a queued row plus a `jobs::Running` claim (a command already `queued`/`running` is 409 `Command "<name>" is already running`).
- Sync queue worker (rule 47), OCR boot sweep (files rule 27), per-file search guard (rule 36): in-memory state, none survives a restart.
- Engine jobs (`SubtitleOcr`, `SubtitleSync`): no timeout on the wait (`engine-glue.md` rule 30); the engine bounds them (extract 900 s, OCR tool 1800 s, ffsubsync 900 s: `fliks-engine/docs/spec/subtitle-jobs.md`).
