### C. Watch-history import (`POST /api/media-servers/:id/import-watch-history`)

13. 14. Emby calls (header `X-Emby-Token`, base = url minus ONE trailing `/`, path segments percent-encoded in Rust; Nest interpolates the ids raw): `GET /Users` (timeout 30 s; `res.data ?? []`, an empty body is `''` in axios: zero users either way) = `{Id, Name}`; `GET /Users/<userId>/Items` with query `IncludeItemTypes=Movie,Episode`, `Fields=ProviderIds,UserData,ParentIndexNumber,IndexNumber,SeriesName,SeriesId,RunTimeTicks,DateCreated,PremiereDate`, `Recursive=true`, `StartIndex`, `Limit` (500), plus `IsPlayed=true` (mode `played`) or `IsResumable=true` (mode `resumable`), timeout 60 s; mode `resume` uses `GET /Users/<userId>/Items/Resume` with the same query minus the flags; `GET /Users/<userId>/Items/<itemId>` (timeout 30 s; any failure → null). 15. `importForServer`: a non-Emby server throws 404 (guarded earlier); `listUsers` failure → push `listUsers failed: <message>` to `stats.errors` and RETURN the zeroed stats (no throw): the controller then reports `completed` with all zeros (C45). Otherwise per Emby user, sequentially, each in its own try/catch (a failure pushes `user "<Name>": <message>` to `stats.errors`, never sent to the client); totals: `users` (every Emby user seen), `usersCreated`, `imported`, `skipped`; `perUser` and `errors` stay server-side. Caches shared across users in the run: movie by TMDB id, series by TMDB id, series TMDB id by Emby `SeriesId` (misses cached as null). `[ts:src/modules/media-servers/emby-watch-history-import.service.ts:69]`–`[ts:src/modules/media-servers/emby-watch-history-import.service.ts:133]`
16. User resolution: `users WHERE username = <Emby Name>` (exact, case-sensitive); absent → the default role (`RolesService.getDefaultRole()`: first `roles` row with `"isDefault" = true`, no relations; Rust `ORDER BY id LIMIT 1`, may be none) and INSERT `{username, passwordHash: NULL, roleId: role?.id ?? NULL, mediaServerType: 'emby'}` (other columns default); `created = true`. No `library_user_access` rows are seeded (unlike the Seerr importer): the new user sees no library until an admin assigns access (C43). An existing user keeps its `mediaServerType`. A `Name` of `''` is an ordinary username (matched or created as `''`). A missing or `null` `Name` drops the condition (TypeORM 0.3.31 `invalidWhereValuesBehavior` default `ignore`): `findOne` returns an arbitrary user and the history is written to that account; on an empty `users` table the INSERT fails (NOT NULL) and the per-user catch records it. 17. Per user, three sets are fetched fully before any write (pages of 500 until a page is empty or `offset >= total`; `offset += items.length`): `resume` (`/Items/Resume`, the authoritative Continue Watching queue; its Emby ids form `resumeIds`), `played`, `resumable`. Processing order resume, played, resumable; an Emby item id already seen is skipped (first occurrence wins). An item is skipped (`skipped++`, nothing written) when `UserData.Played !== true` AND `PlaybackPositionTicks` (default 0) is 0 AND it is not in `resumeIds`. Otherwise `applyItem` returns true (`imported++`) or false (`skipped++`); a throw counts `errors++` (per-user stat, warn log) and continues. `[ts:src/modules/media-servers/emby-watch-history-import.service.ts:135]`–`[ts:src/modules/media-servers/emby-watch-history-import.service.ts:252]`
18. `applyItem` values: `resolvedDate = LastPlayedDate ?? DateCreated ?? PremiereDate ?? now` (each parsed with `new Date`, an invalid value is skipped to the next), used for BOTH `lastPlayedAt` and `playedAt`; `positionSeconds = floor(PlaybackPositionTicks / 10_000_000)`; `durationSeconds = floor(RunTimeTicks / 10_000_000)` (0 when absent); `completed = inResume ? false : Played === true`; `hiddenFromContinueWatching = !inResume && !Played && PlaybackPositionTicks > 0`. A re-watch (Played and in the resume queue) is therefore not completed. `[ts:src/modules/media-servers/emby-watch-history-import.service.ts:268]`–`[ts:src/modules/media-servers/emby-watch-history-import.service.ts:298]`
19. Matching (false = skipped, never an error): Movie: `Number(ProviderIds.Tmdb)` finite and > 0 (JS `Number`: `' 12 '`, `'1e3'`, `'0x1f'` pass; a fraction such as `'12.5'` reaches the `int` column and the query throws: `errors++`; Rust: integer >= 1 after trim, else false), then `media WHERE type = 'movie' AND tmdbId = ?` (cached); no row → false; state key `(userId, mediaId, episodeId NULL)`. Episode (any other `Type`): `SeriesId` required; the series' TMDB id comes from `getItem(userId, SeriesId)` `ProviderIds.Tmdb` and must match `^\d+$` (else null, cached), `0`/null → false; series `media WHERE type = 'series' AND tmdbId = ?` (cached); `ParentIndexNumber` and `IndexNumber` both required; the episode is `episodes e JOIN seasons s ON s.id = e."seasonId" WHERE s."mediaId" = <series> AND s."seasonNumber" = ParentIndexNumber AND e."episodeNumber" = IndexNumber` (first row; a multi-episode file matches only by its first number); state key `(userId, series mediaId, episodeId)`. The library ACL of the user is not applied. `[ts:src/modules/media-servers/emby-watch-history-import.service.ts:300]`–`[ts:src/modules/media-servers/emby-watch-history-import.service.ts:378]`

### D. Security and robustness (new in Rust)

22. [new] F29 (extended, shared with `importers.md` rule 37): no `ok:false` message, log, SSE `error` or `stats.errors` entry contains the request URL or its userinfo; `reqwest::Error` goes through `without_url()`. F42 (`importers.md` rule 38): redirects followed only to the same host (the `X-Emby-Token` must not follow a `Location` to another host). Emby timeouts stay as in rules 8, 11, 14.
23. [new] C42: a second `import-watch-history` for a server whose import is running is 409 `Import already running` (one in-process set of server ids, released on completion or failure), checked after the 404s and before `watch-history.import.started`.
24. [new] C43: a user created by the Emby import gets `library_user_access` rows for the default role's `defaultLibraries`, as the Seerr importer already does in Nest (`importers.md` rule 33), with the same transaction and unique-violation re-read as `importers.md` rule 42(d); a missing or blank Emby `Name` is skipped (rule 16). Without it the imported accounts cannot see any media.
25. [new] C44: the playback write is ONE statement: `INSERT INTO playback_states (...) VALUES (...) ON CONFLICT (...) DO UPDATE SET ... WHERE playback_states."lastPlayedAt" <= EXCLUDED."lastPlayedAt"` (one statement per key shape, the two partial indexes), returning whether a row was written; `durationSeconds = CASE WHEN EXCLUDED."durationSeconds" > 0 THEN EXCLUDED."durationSeconds" ELSE playback_states."durationSeconds" END`. "Fliks wins" and the race with a live heartbeat are then decided by the database.
26. [new] C1 (extended): `events: null` / `enabled: null` on PUT are 400 with the standard validation body instead of Nest's 500 (rule 3; POST keeps rule 2's `??` defaults); `type` stays any of the 4 enum values.
27. [new] C45: a `listUsers` failure (rule 15) is reported as `watch-history.import.failed {serverId, serverName, error}` (Command row `failed`) instead of a `completed` event with zeros; per-user failures stay in `stats.errors` and the event contract is unchanged.
28. Kept as is: the Emby URL may be any host (SSRF accepted for admin-set endpoints, plan §15.3); `type` of an existing row can be changed; importing with `enabled = false` works (the flag only gates `dispatch`).
29. [new] Decided (reviewer recommendations, kept): `watch-history.import.*` and `seerr.import.*` stay broadcast to every connected client (events-hub audience B; no secret in the payload); `dispatch` runs one full Emby library refresh per event, no debounce; `jellyfin`, `plex` and `local` stay accepted by CRUD without a provider (test says unsupported, dispatch skips, import 404s), because restricting the enum on write would break the round-trip of stored rows through PUT; an imported user keeps `passwordHash NULL` and the admin sets a password through `PUT /api/users/:id`.
