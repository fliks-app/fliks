### C. Watch-history import (`POST /api/media-servers/:id/import-watch-history`)

13. Order of checks: the row (404 `MediaServer #<id> not found`, thrown by `findOne`: the controller's own `!server` branch is unreachable), then `type !== 'emby'` → 404 `Watch-history import is only supported for Emby servers`; then C?3 (409); then the lifecycle of rule 20. `[ts:src/modules/media-servers/media-servers.controller.ts:88]`–`[ts:src/modules/media-servers/media-servers.controller.ts:97]`
14. Emby calls (header `X-Emby-Token`, base = url minus ONE trailing `/`, path segments percent-encoded in Rust): `GET /Users` (timeout 30 s; `[]` when the body is empty) = `{Id, Name}`; `GET /Users/<userId>/Items` with query `IncludeItemTypes=Movie,Episode`, `Fields=ProviderIds,UserData,ParentIndexNumber,IndexNumber,SeriesName,SeriesId,RunTimeTicks,DateCreated,PremiereDate`, `Recursive=true`, `StartIndex`, `Limit` (500), plus `IsPlayed=true` (mode `played`) or `IsResumable=true` (mode `resumable`), timeout 60 s; mode `resume` uses `GET /Users/<userId>/Items/Resume` with the same query minus the flags; `GET /Users/<userId>/Items/<itemId>` (timeout 30 s; any failure → null). Page response `{Items, TotalRecordCount}`: `[]` / 0 when absent. `[ts:src/modules/media-servers/providers/emby.provider.ts:86]`–`[ts:src/modules/media-servers/providers/emby.provider.ts:166]`
15. `importForServer`: a non-Emby server throws 404 (guarded earlier); `listUsers` failure → push `listUsers failed: <message>` to `stats.errors` and RETURN the zeroed stats (no throw): the controller then reports `completed` with all zeros (C?11). Otherwise per Emby user, sequentially, each in its own try/catch (a failure pushes `user "<Name>": <message>` to `stats.errors`, never sent to the client); totals: `users` (every Emby user seen), `usersCreated`, `imported`, `skipped`; `perUser` and `errors` stay server-side. Caches shared across users in the run: movie by TMDB id, series by TMDB id, series TMDB id by Emby `SeriesId` (misses cached as null). `[ts:src/modules/media-servers/emby-watch-history-import.service.ts:69]`–`[ts:src/modules/media-servers/emby-watch-history-import.service.ts:133]`
16. User resolution: `users WHERE username = <Emby Name>` (exact, case-sensitive); absent → the default role (`RolesService.getDefaultRole()`: first `roles` row with `"isDefault" = true`, no relations; Rust `ORDER BY id LIMIT 1`, may be none) and INSERT `{username, passwordHash: NULL, roleId: role?.id ?? NULL, mediaServerType: 'emby'}` (other columns default); `created = true`. No `library_user_access` rows are seeded (unlike the Seerr importer): the new user sees no library until an admin assigns access (C?5). An existing user keeps its `mediaServerType`. An Emby user with an empty `Name` makes the INSERT fail (NOT NULL): the per-user catch records it; Rust skips a blank name the same way `[assumed]`. `[ts:src/modules/media-servers/emby-watch-history-import.service.ts:143]`–`[ts:src/modules/media-servers/emby-watch-history-import.service.ts:159]`, `[ts:src/modules/roles/roles.service.ts:13]`
17. Per user, three sets are fetched fully before any write (pages of 500 until a page is empty or `offset >= total`; `offset += items.length`): `resume` (`/Items/Resume`, the authoritative Continue Watching queue; its Emby ids form `resumeIds`), `played`, `resumable`. Processing order resume, played, resumable; an Emby item id already seen is skipped (first occurrence wins). An item is skipped (`skipped++`, nothing written) when `UserData.Played !== true` AND `PlaybackPositionTicks` (default 0) is 0 AND it is not in `resumeIds`. Otherwise `applyItem` returns true (`imported++`) or false (`skipped++`); a throw counts `errors++` (per-user stat, warn log) and continues. `[ts:src/modules/media-servers/emby-watch-history-import.service.ts:135]`–`[ts:src/modules/media-servers/emby-watch-history-import.service.ts:252]`
18. `applyItem` values: `resolvedDate = LastPlayedDate ?? DateCreated ?? PremiereDate ?? now` (each parsed with `new Date`, an invalid value is skipped to the next), used for BOTH `lastPlayedAt` and `playedAt`; `positionSeconds = floor(PlaybackPositionTicks / 10_000_000)`; `durationSeconds = floor(RunTimeTicks / 10_000_000)` (0 when absent); `completed = inResume ? false : Played === true`; `hiddenFromContinueWatching = !inResume && !Played && PlaybackPositionTicks > 0`. A re-watch (Played and in the resume queue) is therefore not completed. `[ts:src/modules/media-servers/emby-watch-history-import.service.ts:268]`–`[ts:src/modules/media-servers/emby-watch-history-import.service.ts:298]`
19. Matching (false = skipped, never an error): Movie: `Number(ProviderIds.Tmdb)` finite and > 0, then `media WHERE type = 'movie' AND tmdbId = ?` (cached); no row → false; state key `(userId, mediaId, episodeId NULL)`. Episode (any other `Type`): `SeriesId` required; the series' TMDB id comes from `getItem(userId, SeriesId)` `ProviderIds.Tmdb` and must match `^\d+$` (else null, cached), `0`/null → false; series `media WHERE type = 'series' AND tmdbId = ?` (cached); `ParentIndexNumber` and `IndexNumber` both required; the episode is `episodes e JOIN seasons s ON s.id = e."seasonId" WHERE s."mediaId" = <series> AND s."seasonNumber" = ParentIndexNumber AND e."episodeNumber" = IndexNumber` (first row; a multi-episode file matches only by its first number); state key `(userId, series mediaId, episodeId)`. The library ACL of the user is not applied. `[ts:src/modules/media-servers/emby-watch-history-import.service.ts:300]`–`[ts:src/modules/media-servers/emby-watch-history-import.service.ts:378]`
20. Lifecycle and events (the route returns 201 `{ok:true}` before any of it): SSE `watch-history.import.started {serverId, serverName}`; (fire and forget) `runAuditedCommand('ImportWatchHistory', 'manual', fn)`: INSERT `commands {name, status:'running', trigger:'manual', startedOn}`, `command.started {name}`, run `fn`, UPDATE the row `completed|failed` with `endedOn`, `command.completed {name, status}`. `fn`: `importForServer(server)` then `watch-history.import.completed {serverId, serverName, users, usersCreated, imported, skipped}`; on a throw: log, `watch-history.import.failed {serverId, serverName, error: <message>}`, rethrow (the wrapper marks the row `failed`). A failing audit insert emits `watch-history.import.failed {serverId, serverName, error: ''}`. `serverId` / `serverName` are taken from the row read BEFORE the run. Client order: `started`, `command.started`, `completed|failed`, `command.completed`. All broadcasts (events-hub audience B). `[ts:src/modules/media-servers/media-servers.controller.ts:97]`–`[ts:src/modules/media-servers/media-servers.controller.ts:150]`
21. `upsertPlaybackState(userId, mediaId, episodeId|null, positionSeconds, durationSeconds, lastPlayed, playedAt, completed, hidden)`: existing row = `playback_states` with `(userId, mediaId)` and `episodeId = ?` or `episodeId IS NULL`. If it exists and its `lastPlayedAt` is strictly newer than `lastPlayed` → return false (Fliks wins: skipped). Existing, not newer: `positionSeconds`, `completed`, `hiddenFromContinueWatching`, `lastPlayedAt`, `playedAt` replaced, `durationSeconds` replaced only when the new value > 0; `mediaFileId` untouched; return true. Absent: INSERT all those columns (`mediaFileId` NULL); return true. Two partial unique indexes guard `(user, media) WHERE episodeId IS NULL` and `(user, episode)`; the select-then-write is not atomic, so a concurrent playback heartbeat can lose the race with a unique violation (counted as `errors++`, C?6). `[ts:src/modules/media-servers/emby-watch-history-import.service.ts:385]`–`[ts:src/modules/media-servers/emby-watch-history-import.service.ts:445]`, `[ts:src/modules/playback/entities/playback-state.entity.ts:24]`–`[ts:src/modules/playback/entities/playback-state.entity.ts:25]`

### D. Security and robustness (new in Rust)

22. [new] F?3 (shared with `importers.md` rule 37): no `ok:false` message, log, SSE `error` or `stats.errors` entry contains the request URL or its userinfo; `reqwest::Error` goes through `without_url()`. F?4 (`importers.md` rule 38): redirects followed only to the same host (the `X-Emby-Token` must not follow a `Location` to another host). Emby timeouts stay as in rules 8, 11, 14.
23. [new] C?3: a second `import-watch-history` for a server whose import is running is 409 `Import already running` (one in-process set of server ids, released on completion or failure), checked after the 404s and before `watch-history.import.started`.
24. [new] C?5: a user created by the import (Emby and, per `importers.md` rule 42, Seerr) gets `library_user_access` rows for the default role's `defaultLibraries`, inserted in the same transaction as the user; a unique violation on `username` re-reads the winner. Without it the imported accounts cannot see any media.
25. [new] C?6: the playback write is ONE statement: `INSERT INTO playback_states (...) VALUES (...) ON CONFLICT (...) DO UPDATE SET ... WHERE playback_states."lastPlayedAt" <= EXCLUDED."lastPlayedAt"` (one statement per key shape, the two partial indexes), returning whether a row was written; `durationSeconds = CASE WHEN EXCLUDED."durationSeconds" > 0 THEN EXCLUDED."durationSeconds" ELSE playback_states."durationSeconds" END`. "Fliks wins" and the race with a live heartbeat are then decided by the database.
26. [new] C?10: on POST and PUT, `url` must be an http(s) URL (400 otherwise) and every `events` entry must be one of the supported events of the given `type` (400 with the standard validation body); `type` stays any of the 4 enum values. Existing rows are not rewritten.
27. [new] C?11: a `listUsers` failure (rule 15) is reported as `watch-history.import.failed {serverId, serverName, error}` (Command row `failed`) instead of a `completed` event with zeros; per-user failures stay in `stats.errors` and the event contract is unchanged.
28. Kept as is: the Emby URL may be any host (SSRF accepted for admin-set endpoints, plan §15.3); `type` of an existing row can be changed; importing with `enabled = false` works (the flag only gates `dispatch`).

## Settings keys

None. Connection settings live in the `media_servers` table (`url`, `apiKey`, `events`, `enabled`), not in `app_settings`; `apiKey` is the F?5 secret of this table.

## Jobs/timers

None scheduled. The import is fire-and-forget, audited as a `commands` row (`ImportWatchHistory`, trigger `manual`); the scheduler framework (S5) marks `running` rows `failed` at boot. `ImportWatchHistory` is in neither core job list, so `POST /api/commands` cannot start it. `dispatch` calls are one-shot tasks.

## Vectors/parity

No pure logic worth a vector set: the Emby mapping rules (rules 17-19) are small and covered by Rust unit tests built from recorded Emby payloads (`server/fixtures/media-servers/emby/*.json`: `Users`, `Items` pages for `Resume` / `IsPlayed` / `IsResumable`, series `Items/<id>`, `System/Info`): resume beats played beats resumable, re-watch not completed, hidden-from-resume, date fallback chain, tick conversion, episode matching by series TMDB id, Fliks-newer skip, blank names, 500-item paging with `TotalRecordCount`.

External HTTP is mocked, never real: Rust tests start an in-process `axum` stub (random port) serving those fixtures (modes: ok, 401, 500, slow, cross-host redirect for F?4, `Users` failure for C?11); parity uses the shared `server/parity/stubs/arr-stub.mjs` (`importers.md`, port 4860) with an `/emby` base path serving the same fixtures; a seeded `media_servers` row points at `http://127.0.0.1:4860/emby`. `Library/Refresh` is a stub endpoint that records its hits (`GET /__hits`) so `dispatch` scenarios can assert them.

Parity scenarios (`server/parity/scenarios/media-servers/`, recorded against Nest; seed: 2 media servers (one enabled with `events`, one disabled), movies/series with TMDB ids matching the fixtures, the default role): `media-servers-types`, `media-servers-list`, `media-servers-create` (+ `-validation-400`), `media-servers-get` (+ `-404`), `media-servers-update` (+ `-404`, `-missing-name-400`), `media-servers-delete` (+ `-404`), `media-servers-test-ok|bad-key|unsupported-type`, `media-servers-import-history` (SSE step then `GET /api/playback/history` as the imported user), `media-servers-import-history-rerun` (Fliks-newer skip), `media-servers-import-history-not-emby-404`, `media-servers-apikey-redacted` (F?5 deviation), `media-servers-import-concurrent` (C?3 deviation), `media-servers-import-listusers-fails` (C?11 deviation), `media-servers-import-user-library-access` (C?5 deviation), plus 401 and 403 (`readonly`, `user`) per route. Dispatch scenarios run through a Rust test (callers are internal): enabled + event match hits the stub once, disabled / non-matching / failing stub never errors.
