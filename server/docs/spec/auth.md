# Spec: auth

Covers the auth controllers, services, extractors, `casl/*` and `pairing/*`. Env vars (`JWT_SECRET`, `FLIKS_CONF_DIR`, `JWT_EXPIRATION`, `STREAM_TOKEN_TTL`, `REFRESH_TOKEN_TTL_DAYS`) are inventoried in `config.md` (Auth table); rules below cite them, not repeat them.

## Routes

18 routes, plus the OpenID Connect routes of rules 68 to 86. The extractor `Authed` accepts JWT only: `X-Api-Key` is NOT accepted.

`SafeUser` = JSON object defined in rule 40. `TokenPair` = `{accessToken: string, refreshToken: string, accessTokenExpiresAt: number (unix s), refreshTokenExpiresAt: number (unix s)}`.

## Rules

### A. Secret, claims, signing

1. Secret resolution: `JWT_SECRET` env if non-empty (verbatim, no trim); else `<conf>/.jwt-secret` when it is adopted (content trimmed); else generate 32 random bytes as 64 hex chars, `mkdir -p <conf>` mode 0700, write the file mode 0600 with an exclusive create, so two starts cannot diverge; with no usable `<conf>` a process-local fresh hex secret. Cached for the process lifetime.
2. `<conf>` = first usable of `[FLIKS_CONF_DIR.trim || '/app/conf', <os.tmpdir>/fliks-conf]`, the engine's own list and order (it keeps `.engine-token` there, so both agree). A candidate is skipped when it exists and its owner is not the effective uid, when the secret file exists and is not owned by the effective uid or has any group/other permission bit (`mode & 0o077 != 0`), or when it cannot be created. `.engine-token` (`FLIKS_ENGINE_TOKEN` empty) follows the same rule. A shared `/tmp` entry planted by another user is never adopted.
3. HMAC key bytes = the secret string's UTF-8 bytes (the 64-char hex is NOT hex-decoded). Header `{"alg":"HS256","typ":"JWT"}`.
4. Access token claims `{sub: number (user id), username: string, sid: number (the `sessions` row, rule 64), iat, exp}`; no `scope` key (absent, not null). `exp - iat` = `JWT_EXPIRATION` (default `'1h'`, parsed by `ms`, see `config.md`).
5. Stream/Cast tokens: same claims plus `scope: 'stream'`; every stream, cast and live token carries the `sid` of the session that minted it. Cast: fixed `expiresIn: '4h'`. Stream: `STREAM_TOKEN_TTL` (default `'6h'`, `ms` grammar). A stream token minted with `{mediaFileId}` carries `mf` and the resolver opens only that file with it (rule 51); a legacy one (no body) has no `mf` and opens any file the user can read, kept for released clients. No other claim (no `jti`, no session binding).
6. Tokens verify against the same secret file with the same claim names and HS256.

### B. Request authentication (extractor `Authed`)

7. Token source order, first non-empty wins, no fall-through on a bad token: (1) cookie `fliks_access` parsed from the raw `Cookie` header (split on `;`, trimmed, first `fliks_access=` match, percent-decoded with raw fallback; repeated headers are joined with `'; '`); (2) `Authorization: Bearer <t>` (scheme matched case-insensitively, first two whitespace-separated tokens); (3) query `?token=`. An empty value counts as absent. A stale cookie therefore shadows a valid Bearer.
8. Verification: signature with the secret; `exp` enforced with zero leeway; `nbf` honoured if present. Only HS256 is accepted and `exp` is required: a token without `exp` or signed HS384/HS512 is 401. Fliks only signs HS256 with `exp`, so no issued token is affected.
9. After verification: load the user with its role where `id = sub AND enabled = true` and a `sessions` row `id = sid AND "userId" = sub AND "revokedAt" IS NULL` exists, on every request (no caching); none found, or no `sid` claim: 401. `username` and every other claim are ignored (a renamed user's token stays valid). A `sub` missing or not an integer is 401. Invalidation is this lookup: a deleted or disabled user, a revoked session (logout, password change, admin sign-out, refresh reuse) and a role change apply on the next request, for access, stream, cast and live tokens alike. Deleting a user cascades its `sessions` and `refresh_tokens` rows.
10. Token scope: the payload `scope`, or null when absent. Any non-null value is "scoped" (only `'stream'` is ever issued).
11. `SessionAuthed`: a scoped token gets 403 `{"message":"session_token_required","error":"Forbidden","statusCode":403}`; unscoped passes. It guards the routes that must not take a stream token (declared in their own specs).
12. A `stream`-scope token is refused everywhere it is not explicitly accepted: `Authed` answers 401 (rule 14 body) to any scoped token, `OptionalAuthed` too; only `StreamAuthed` routes (media delivery, each listed in the spec of its domain) accept it, and `SessionAuthed` keeps rule 11's 403. So no auth route takes a stream token (`me`, `stream-token`, `cast-info` included), and a stream token cannot mint new stream tokens, approve pairings or change a password.
13. `OptionalAuthed`: no auth route needs it; unguarded auth routes ignore credentials entirely, except `logout` (rule 50).
14. Every authentication failure (no token, bad signature, expired, unknown or disabled user) returns 401 `{"message":"Unauthorized","statusCode":401}` (no `error` key: the bare form).

### C. Error bodies

15. Error bodies: with a string message `{"message": <string>, "error": <reason phrase>, "statusCode": n}` (`error` = `Unauthorized`, `Forbidden`, `Bad Request`, `Not Found`, `Conflict`, `Payload Too Large`); bare (no message) `{"message": <reason phrase>, "statusCode": n}` with no `error` key. Key order irrelevant. `AppError{status, message: Value, error}` omits `error` for the bare form.
16. Validation failure: 400 `{"message": [<validation messages>], "error": "Bad Request", "statusCode": 400}`; request bodies reject unknown keys and do not coerce JSON types (a boolean field rejects `"true"`, a number field accepts non-integers, an optional field accepts `null` and the value stays `null`). Message text is free-form for the parity runner unless it matches `^[a-z0-9_.]+$`. Unknown body keys: 400 `property <k> should not exist`.
17. Authentication and authorisation run before body validation: an unauthenticated or forbidden request with an invalid body is 401/403, never 400.
18. Integer path params: non-integer string → 400 `Validation failed (numeric string is expected)`. Pairing `:pairingId` is a plain string.

### D. CASL and `Permissions`

19. `User.permissions` getter: `isAdmin` → `['manage:all']`; else the role's `permissions` array; no role → `[]`.
20. If the permission list contains the literal `manage:all` (via `isAdmin` or a role that stores it), the ability is exactly `can(manage, all)` and nothing else is evaluated.
21. Actions (closed enum, string values): `manage create read update delete approve decline grab track`. `manage` as a rule action matches every requested action; a request for `manage` matches only a `manage` rule.
22. Subjects: `User Media FliksRequest QualityProfile LanguageProfile SubtitleProvider SubtitleFile TranslationProvider Library Playlist LiveTvChannel Role Party` (class names), the strings `Settings` and `all`, and `plugin:<id>:<name>`.
23. Plugin grants: for each permission string `p`: bare `plugin:<rest>` (starts with `plugin:` and is longer than the prefix) → `can(manage, p)`; else split at the **first** `:`, `<action>:<subject>` where `<subject>` is a plugin subject → `can(<action>, <subject>)` if `<action>` is in the enum, otherwise skipped (not widened to `manage`); anything else ignored. Shape only, no check that the plugin exists.
24. Unconditional grants (every non-`manage:all` user): `read` and `update` on `User` with condition `{id: self}`; `read create update delete` on `Playlist`.
25. Core permission table (15 strings, this order). Unknown strings grant nothing.

    | Permission | Grants |
    |---|---|
    | `media.read` | read: Media, QualityProfile, LanguageProfile, SubtitleFile, SubtitleProvider, Library |
    | `media.create` | create Media; plus track Media (shared with `requests.create`) |
    | `media.edit` | update Media |
    | `media.delete` | delete Media |
    | `media.grab` | grab Media |
    | `livetv.read` | read LiveTvChannel |
    | `requests.create` | create FliksRequest; read FliksRequest `{userId: self}`; delete and update FliksRequest `{userId: self, status: 'pending'}`; track Media |
    | `requests.manage` | manage FliksRequest |
    | `subtitles.manage` | create, update, delete SubtitleFile |
    | `settings.access` | read Settings; manage Settings, QualityProfile, LanguageProfile, SubtitleProvider, TranslationProvider, Library |
    | `users.manage` | manage User; read Role |
    | `roles.manage` | manage Role |
    | `parties.create` | create Party |
    | `parties.manage` | manage Party (any action) |
    | `parties.read_public` | read Party (see public parties) |

26. Class-level vs instance checks: `can(action, Class)` is true when ANY rule exists for that action and subject type, conditions ignored (so every authenticated user passes `can(read, User)` and `can(update, User)` at class level); conditions only bite when an instance is passed. Handlers re-check instances (users.md, roles.md).
27. Policy check: handler policies win over class policies; zero policies declared → deny; no authenticated user → deny; every policy must return true. Denial is 403 `{"message":"Forbidden resource","error":"Forbidden","statusCode":403}`. The explicit "any authenticated user" policy is always true. Every handler's first line requires a permission or that policy.
28. Plugin route policies (`<action>:<Subject>`, split at first `:`, action in enum, subject in the closed core set `User Media FliksRequest QualityProfile LanguageProfile SubtitleProvider SubtitleFile TranslationProvider Library Playlist Settings` or in that plugin's own declared subjects, otherwise deny) are owned by the plugin proxy.

### E. Login, logout, refresh

29. Login lookup: user by exact (case-sensitive) `username` with `passwordHash` selected and role joined. Steps and order: (a) `serverType` defaults `local`; any other value → 401 `Media server login for <serverType> not yet implemented` before any DB access; (b) no user or `passwordHash` null (Emby-imported users) → 401 `Invalid credentials` without running bcrypt; (c) bcrypt mismatch → 401 `Invalid credentials`; (d) `enabled = false` → 401 `Account disabled` (revealed only with the right password); (d2) a non-admin while setting `password_login` is `admins` → 401 `Password login is disabled` (also only with the right password; admins always keep password login); (e) set `lastLogin = now`; (f) issue pair (rule 31); (g) body `user = SafeUser`.
30. bcrypt: cost 12 for every hash (login seed, register, create user, change password); verify accepts the stored hash as is (`$2a$/$2b$/$2y$`), no rehash on login. bcrypt ignores bytes past 72.
31. Token pair issue: a new sign-in (login, pairing claim) inserts a `sessions` row (`method` `password`, `pairing` or `oidc`, the request `User-Agent` truncated to 255 chars) and the access token (rule 4) carries its id as `sid`; `accessTokenExpiresAt` = decoded `exp` (fallback `now/1000 + 3600`), refresh token (rule 33), `refreshTokenExpiresAt = floor(expiresAt_ms / 1000)`. A rotation stores the request `User-Agent` on the new token and on the session.
32. The refresh token plaintext is JSON-only (login, refresh, pairing status body), never in a cookie.
33. Refresh token = `randomBytes(48)` base64url (64 chars); stored as `sha256(raw)` lower-case hex (hash input = the token's UTF-8 bytes); `expiresAt = now + REFRESH_TOKEN_TTL_DAYS` days (default 60; `parseInt`, must be finite and > 0 else 60); `userAgent` truncated to 255 chars; `lastUsedAt` null.
34. Rotation (`POST /auth/refresh`), strictly in this order: empty/missing `refreshToken` → 401 `Missing refresh token`; row by hash not found → 401 `Invalid refresh token`; row already `revokedAt`: if `now - revokedAt <= 30 000 ms` → 401 `Refresh token already rotated` (session untouched), else if the token that replaced it (`parentId` = this row) exists and was never used (`lastUsedAt` NULL), the response was lost: 401 `Refresh token already rotated`, nothing revoked; otherwise (successor used, or none) revoke that row's session (rule 66) and 401 `Refresh token reuse detected`; `expiresAt < now` → 401 `Refresh token expired` (row not revoked); a session with `method = 'oidc'` created more than 30 days ago → 401 `Refresh token expired` (rule 83); else set `revokedAt = lastUsedAt = now`. Then user must be `enabled` else 401 `Account disabled` (token already consumed); else issue a new pair (rule 31) and set the cookie. A session is one login or pairing chain: every sign-in starts a new session and rotation keeps the consumed row's `sessionId`, so other devices of the user keep working. The session check comes right after the hash lookup: a revoked session is 401 `Invalid refresh token`, whatever the token state. A rotation sets `sessions.lastSeenAt`. The reuse logs a warning with the user, token, session and both user agents.
35. Rotation is atomic: one transaction over `SELECT … FOR UPDATE` on the token row (insert of the new token included); a concurrent duplicate lands in the 30 s grace branch.
36. Logout revokes the session of the presented refresh token (rule 66), so that session's access, stream and cast tokens stop at once and presenting its refresh token again is 401 `Invalid refresh token`.
37. Register: username taken (exact match) → 409 `Username already taken`; role = the role with `isDefault = true`, and the user gets that role's `role_default_libraries` (`library_user_access`), as `POST /api/users`; user row: `passwordHash = bcrypt12`, `isAdmin = false`, `mediaServerType = 'local'`, `roleId`. Response is the `SafeUser` of the saved user, whose role is not loaded: `role` is `null` and `permissions` is `[]`.
38. `POST /api/auth/register` requires authentication and `users.manage` (`manage:all` qualifies); otherwise 403. Anonymous or invalid credentials get 401 from the extractor (auth runs before the handler). Register has no first-user branch: the first admin comes from `POST /api/auth/setup`.
39. Login throttle (in-process): each attempt for a (client network, lower-cased username) pair is counted before the password is checked, in one locked step with the limit test, so concurrent attempts cannot all pass; the 6th attempt within 15 minutes of the first is 429 `Too many failed login attempts, try again later` (no bcrypt, no DB). A successful password clears the pair. Client network = the address of rule 63, an IPv6 client keyed by its /64. At 10 000 pairs, expired ones are dropped, then the pair with the fewest attempts (oldest first), never the whole map. Usernames over 255 bytes are a 400 before the throttle (`username must be shorter than or equal to 255 characters`).

### F. Response shapes

40. `SafeUser` (login `user`, `GET /auth/me`, register): every `users` column except `passwordHash`, plus the quota keys, `role`, `permissions`, `libraryIds`, `features`. Column keys (the two `<kind>QuotaLimit` keys come from `user_quotas`, one per media kind, `0` without a row; they are not columns): `id, createdAt, updatedAt, username, email, roleId, mediaServerType, mediaServerId, avatar, lastLogin, isAdmin, enabled, requirePasswordChange, movieQuotaLimit, seriesQuotaLimit, quotaPeriodDays, libraryOrder, hiddenLibraryIds, profileVisibility, shareTastes, shareRecommendations, shareWatchHistory, shareLikes, shareStats, shareDisabled, hideSpoilers, edlEnabled, edlAutoSkipCommercials, spoilerHideStills, spoilerHideOverviews, spoilerHideTitles` (types: users.md rule 2). Computed: `role` = role name, else `'Admin'` if `isAdmin`, else `null` (differs from the users module, which gives `null`); `permissions` = rule 19; `libraryIds` always `[]` here (never hydrated); `features` = rule 41. Dates are ISO-8601 with ms (`...000Z`). `passwordHash` never serialised (`select: false` and `@Exclude`); the object is a plain object so class-transformer does nothing.
41. `features`: `['deviceProfileExtensions','hlsSubtitleRequest','muxedAudioRendition','sessionReplaces']` filtered by the engine's `hello.features`: `deviceProfileExtensions` needs `decide`, `sessionReplaces` needs `session-replaces`, the other two need `serve`; no engine hello yet → `[]`. Order preserved.
42. `GET /auth/me` side effect: if `lastLogin` is null or older than 60 000 ms, `UPDATE users SET "lastLogin" = now, "updatedAt" = now WHERE id`; the response carries the value loaded before the update (stale). Runs for scoped tokens too.
43. `users-public`: enabled users only, fields exactly `id, username, avatar` (`avatar` null when unset), `ORDER BY username ASC` (database collation). No auth. Setting `users_public_mode` (`everyone` default and any unknown value, `lan`, `hidden`; `settings.md` validates it on write): `hidden` answers `[]`; `lan` answers the roster only when the client address (rule 63) is not public (`fliks_domain::net::classify`: private, CGNAT 100.64/10, loopback, link-local, reserved), else `[]`. A reverse proxy that does not set `X-Forwarded-For` makes every client look local.
44. `cast-info`: `token` = Cast token (rule 5); `streamBaseUrl` = setting `public_url` with trailing `/`s stripped when non-empty; else `<proto>://<Host>` where `proto` is the raw `X-Forwarded-Proto` header (not split on `,`) or `http`, and `Host` the request `Host` header; else `http://localhost:<PORT||4848>`.
45. `stream-token`: `streamToken` = rule 5; `expiresAt = now + ttlMs` in **milliseconds**, where `ttlMs` is the TTL of the token actually signed, from the one `ms` parser (rule 48; `config.md`).
51. Resolver and `mf`: a token with `mf` is denied (bare denial) for any file other than `mf` on the `stream`, `download`, `sprite` and `subtitle` purposes; a live (`mediaId` = viewer id) request is denied too; tokens without `mf` (legacy stream tokens, access tokens, cast tokens) are not file-bound. The heartbeat (`FileBoundAuthed`) accepts a token with `mf` only when the body's `mediaFileId` is `mf` and that file is a part of the item the beat names (`item_parts`, `heartbeat.md`); the token still names a file, never an item.

### G. Cookies

46. Name `fliks_access`, value = the access JWT (`encodeURIComponent`), set on login, refresh and on the pairing `status` response that carries tokens.
47. Attributes: `HttpOnly`; `Path=/`; `Secure` iff the request is secure (TLS, or `X-Forwarded-Proto` first comma-separated value equals `https`, case-insensitive); `SameSite=None` iff `Origin` is exactly one of `https://localhost`, `capacitor://localhost`, `http://localhost` AND secure, else `SameSite=Lax`; `Max-Age = floor(maxAgeMs/1000)` and `Expires = now + maxAgeMs`. No `Domain`.
48. One parser for `JWT_EXPIRATION` and `STREAM_TOKEN_TTL`, the `ms` grammar (a bare number is milliseconds, `3600` = 3 s; an unparsable value or one under 1 s falls back to the default with a warning); cookie `Max-Age` equals `exp - iat` (default 3600). Applies to login, refresh and pairing status.
49. Logout clears the cookie: `Set-Cookie fliks_access=; Path=/; Expires=Thu, 01 Jan 1970 00:00:00 GMT; HttpOnly; Secure iff secure; SameSite per rule 47` (no `Max-Age`). Sent even when no credentials were presented.
50. Logout ordering: clear cookie; if `refreshToken` given revoke its session (rule 66), errors swallowed; token for the SSE drop = cookie value, else `Authorization` starting with exactly `Bearer ` (no `?token=`); verify it (signature and `exp`, no user lookup); if valid and `targetId` present: drop that user's SSE and polled connections whose target id equals `targetId` ; valid but no `targetId`: only a warning, nothing dropped (other devices untouched); invalid/expired token: silent. An empty `fliks_access=` cookie still counts as the token source, so it suppresses the Bearer fallback and nothing is dropped. Always 204.

### H. Pairing state machine

51. Constants: TTL 10 min (`expiresIn: 600` in the response), at most 3 live `pending` rows per `deviceId` (live: `expiresAt >= now`; an unflipped expired row does not count). A hinted request is also capped at 10 per `userId`; an unhinted one at 5 per client network (`clientNet`, keyed like the login throttle: IPv4 address, IPv6 /64) and 1000 in all (approximate under concurrency).
52. States `pending → approved | denied | expired`. `approved` additionally has a one-shot claim: row `accessToken` holds the sentinel `'__approved__'` from approval until the issuing device polls, then `NULL` (status stays `approved`).
53. `request` (anonymous): a request without the `X-Fliks-Pairing-Code` header comes from a client that never shows the code (5.x), stored as `pairing_requests.legacyClient` and relayed as `legacyClient: true` so the approver says to update that device instead of asking for a code; header `X-Device-Id` empty/missing → 400 `Missing X-Device-Id header` (checked after body validation, rule 17); `userId` is an optional hint: when present it must exist AND be enabled else 404 `User not found`; `COUNT(*) WHERE deviceId = ? AND status = 'pending' AND expiresAt >= now` `>= 3` → 400 `Too many pending requests for this device`; then, for a hinted request, under a per-user advisory lock, the same live count by `userId` `>= 10` → 400 `Too many pending requests for this account`; for an unhinted one, under an advisory lock on the client network, the live count of unhinted rows by `clientNet` `>= 5` → 400 `Too many pending requests for this network` and of all unhinted rows `>= 1000` → 400 `Too many pending requests` (the device id is the caller's choice, so only these bound a flood; the global ceiling is approximate under concurrency, the other caps hold). The device, user and network locks use distinct key namespaces and are taken in that order; insert `publicId = uuid v4`, `code` (6 random digits, unique among all `pending` rows, so a code names one row whoever approves: a clash draws again, 10 clashes answer the global `Too many` 400), `userId` (the hint, else null), `clientIp` (`client_ip` as for login, null when unknown), `clientNet` (the throttle key of that address), `deviceName` (cut to 80), `systemName` (cut to 60, else null), `status 'pending'`, `accessToken null`, `expiresAt = now + 10 min`; emit `pairing.requested` to the hinted user only, nothing without a hint (Events); return `{pairingId: publicId, code, expiresIn: 600}`, 201. The device shows the code; only the code approves, so the approver proves they read the device they mean to sign in. Any anonymous caller can open a request, hinted at any enabled user id (ids come from `users-public`) or not.
54. `status`: missing `pairingId` → 400 `Missing pairingId`; missing header → 400 `Missing X-Device-Id header`; unknown `publicId` → 404 `Pairing request not found`; a `pending` row past `expiresAt` is flipped to `expired` (persisted) and returned as such; claim condition = `status = 'approved' AND row.deviceId = header AND accessToken = '__approved__' AND approvedByUserId is set`: then load the approver user (by id, **no `enabled` check**; not found → `{status:'approved'}` without tokens), issue a pair (rule 31, `userAgent` null), set row `accessToken = NULL`, return `{status,...TokenPair}` and set the cookie. Every other case returns `{status}` only (wrong device, already claimed, pending, denied, expired) with no error. The claim checks `expiresAt`: an unclaimed approved row past it is flipped to `expired` (sentinel cleared) and answers `{"status":"expired"}`. The claim runs under `SELECT … FOR UPDATE` in one transaction, so one of two simultaneous polls gets tokens.
55. Note: the account the claim mints for is `approvedByUserId`: the hinted `userId` when there is one (only that user may approve), else whoever approved.
56. `pending` list (hinted rows only): rows where `userId = caller AND status = 'pending'` `ORDER BY createdAt DESC`, then drop rows with `expiresAt < now` in memory; fields `pairingId` (= `publicId`), `deviceId`, `deviceName`, `systemName`, `requestedAt` (= `createdAt`), `expiresAt`; never `code`.
57. `lookup` (`Authed`): the `pending` row with that `code`, `expiresAt >= now`, whose `userId` is the caller or null, else 404 `No pending request with this code` (same answer for a foreign hinted row, an expired or an already settled one); answers `{pairingId, deviceName, systemName, clientIp, requestedAt}` and changes nothing.
57b. `approve` (`Authed`, body `{code, pairingId?}`): the `pending` row with that `code` that is hinted to the caller or unhinted, whose `publicId` equals `pairingId` whenever one is sent (the one `lookup` returned, so the approver confirmed that very request) and always for an unhinted row, else 404 `No pending request with this code`; `expiresAt < now` → persist `expired`, 400 `Pairing request expired`; else `status='approved'`, `approvedByUserId = caller`, `accessToken = '__approved__'`; 204.
57c. `lookup` and `approve` throttle: every attempt counts in a `LoginThrottle` instance of its own (not the login one) under `pairing:<callerId>`; the 6th failure in 15 min from one client network answers 429 `Too many failed attempts, try again later`. A hit is refunded, never resets the failures; the window only expires.
58. `deny`: ownership as above (404; an unhinted row has no owner, so it is simply not approved and expires); if `status != 'pending'` no-op; else `status='denied'`, `approvedByUserId = caller`; 204 (expiry is not checked).
59. Validation: `userId` optional integer; `deviceName` string, non-empty, max 80; `systemName` optional string max 60.

### I. Jobs and token hygiene

60. Pairing cleanup cron hourly: `DELETE FROM pairing_requests WHERE "expiresAt" < now - 10 min` (rows are removed 10 min after they expired, not at expiry).
61. A daily job deletes `refresh_tokens` rows expired for more than 30 days or revoked for more than 30 days, then every `sessions` row left with no `refresh_tokens` row (SQL below).
62. A token replayed after its revoked row was pruned yields `Invalid refresh token` instead of the session revoke; rows younger than 30 days (far past the 30 s grace) keep detection intact.
63. Client address (login throttle, `users-public`): the chain is every `X-Forwarded-For` entry in order (unparsable ones ignored, IPv4-mapped IPv6 folded to IPv4) followed by the socket peer. It is walked from the right and the first public address (`fliks_domain::net::classify` = `Public`) is the client; private, CGNAT, loopback, link-local and reserved hops are trusted proxies by design (the engine gateway, a Docker bridge, a LAN reverse proxy). With no public address (a LAN client) the client is the rightmost `X-Forwarded-For` entry, else the peer. A client forging `X-Forwarded-For` only adds entries left of the one its proxy appends.

### J. Sessions

64. A `sessions` row (`id`, `userId`, `method`, `userAgent`, `createdAt`, `lastSeenAt`, `revokedAt`) is one signed-in device. `method` is `password` or `pairing`; NULL marks a session backfilled from a refresh-token family when the table was introduced. `refresh_tokens.sessionId` points at it (`ON DELETE CASCADE`), and a backfilled session reuses its family id.
65. A token minted before sessions existed has no `sid` and is 401 once: an access token recovers through refresh (the family is the backfilled session), a stream, cast or live token is minted again by its client. A restore replaces every row, sessions included, so restoring a backup that predates a session signs that device out.
66. Revoking a session sets `sessions.revokedAt` and `refresh_tokens.revokedAt` of its live tokens in one transaction, tokens first (a refresh locks its token before the session). A logout without `refreshToken` revokes nothing, so a profile switch can resume the session. Every revocation path of a single session (logout with a refresh token, refresh reuse, `DELETE /auth/sessions/:id`) also closes the SSE connections opened under that session (`events-hub.md` rule 28a). Revocation paths: logout (rule 36), refresh reuse (rule 34), `DELETE /auth/sessions/:id` (own sessions only), a password change (every session of the target, except the caller's when it is a self change, users rule 17) and `DELETE /users/:id/sessions`. Disabling or deleting a user needs no revoke: the user lookup of rule 9 already fails.
67. The engine resolver applies the same check as rule 9 to a JWT credential. Its cached resolution lives up to 60 s unless the engine announces `revoke`. The engine revoke (which flushes every resolution of the owner) is called after an admin password reset, `DELETE /users/:id/sessions`, disabling, deleting and role or library changes; a self password change and `DELETE /auth/sessions/:id` leave the 60 s window, as the engine revoke would also end the caller's other sessions. A password change drops the user's SSE connections, whose devices reconnect with their own session; `DELETE /auth/sessions/:id` closes only that session's. Device tokens (OPDS, kosync, Kobo) are not sessions and keep their own revocation. A NULL `passwordHash` also means the user has no password to sign in with (SSO-only); `kosync /users/create` still creates no Fliks user.

### K. OpenID Connect

68. OIDC is optional: with no enabled provider nothing changes (`GET /api/auth/oidc` answers `providers: []`, login behaves as before). Providers are rows of `oidc_providers` (rules of `oidc-providers.md`); an identity is a `user_identities` row `(userId, providerId, subject)` unique per `(providerId, subject)` and per `(userId, providerId)`. A user with a NULL `passwordHash` is SSO-only.
69. `start`: 404 for a missing or disabled provider; the attempt counts in the login throttle under `oidc:` and the client network (the 31st within 15 minutes is 429, a successful exchange clears it); `returnTo` is exactly `web`, `app` or `http://127.0.0.1:<1024-65535>/oidc` (canonical port), else 400; `challenge` is 43 base64url characters (the client keeps the verifier, the server never sees it); `prompt` only `none` (a silent run), which replaces an unset or `select_account` provider `prompt` and is 409 `Silent sign-in is not available` when the provider's is `login` or `consent`, so the client falls back to the login page; `link: true` needs a session (the row stores `linkUserId`) and proof of ownership: the account's `currentPassword` when it has a password (400 when missing or wrong, throttled like users rule 17), else a session opened by a password or SSO login (not a refresh, not a pairing) at most 5 minutes ago (`sessions.createdAt`, `method`; 403 `account.recent_sign_in_required`). `expectUserId` needs `prompt: 'none'` and no `link` (else 400); the row stores it with no foreign key, so an unknown id behaves like a known one and is refused at `exchange`. The row (`state` and `nonce` 32 random bytes base64url, 10 min) is inserted and `authorizeUrl` = `authorization_endpoint` + `response_type=code`, `client_id`, `redirect_uri = <public_url>/api/auth/oidc/<id>/callback`, `scope`, `state`, `nonce`, `code_challenge`, `code_challenge_method=S256`, `prompt`. The provider's discovery must list `S256` (400 otherwise), `public_url` must be set (409).
70. `callback` makes no token call. The row of `state` (unexpired) must belong to the provider of the path and an RFC 9207 `iss` must equal the issuer; else 302 `error=expired` to the web target. An `error` parameter or a missing `code` is `error=idp`. Success is a 302 with `code` and `state` to `<public_url>/oidc/complete#...` (web, a fragment keeps them out of logs), `media.fliks.app:/oidc/complete?...` (app) or `http://127.0.0.1:<port>/oidc?...`; an error carries `error=<kind>` and the `state` when known. Responses are `no-store` with `Referrer-Policy: no-referrer`.
71. `exchange`: `DELETE FROM oidc_logins WHERE state = $1 AND "expiresAt" > now() RETURNING ...` claims the row (single use, before any provider call); none → `{error: 'expired'}`. A link row needs the session of `linkUserId` (else `expired`). Refusal kinds and statuses: `expired` 400, `idp` 400, `pkce` 400, `not_allowed` 403, `no_account` 403, `disabled` 403 (a user; a provider disabled or deleted meanwhile is `expired`), `already_linked` 409, `login_required` 403 (rule 73); the cause of an `idp` is logged as a kind, never returned. The token request carries `code`, `redirect_uri` and the client's `code_verifier`; client authentication is derived (a secret goes in the `Authorization: Basic` header, form-encoded, unless discovery lists only `client_secret_post`; no secret sends `client_id` in the body).
72. ID token checks: `alg` in {RS256, RS384, RS512, PS256, PS384, PS512, ES256, ES384, EdDSA} and advertised by discovery (never `none` or `HS*`); `kid` found in the provider's JWKS (an unknown `kid` refetches the set, at most once a minute (the attempt time is written before the fetch, and a failed discovery is remembered 30 s, so unauthenticated back-channel calls cannot amplify); a header without `kid` accepts a one-key set); signature; `iss` equal to the issuer; `exp` and `iat` required, 60 s leeway; `aud` contains the client id and `azp` equals it when present or when several audiences; `nonce` equals the row's; a non-empty `sub`. The userinfo endpoint is called when the groups claim, the username claim or `email` is missing from the ID token, or `email_verified` is while `matchByEmail` is on, but for an identity already linked only when the groups claim is missing; its `sub` must equal the ID token's, and any failure of a call made is `idp`; a missing endpoint or access token is `idp` only when the groups claim is missing.
73. Account resolution at a login, in order: (1) the identity `(provider, sub)`; (2) `matchByEmail` with `email_verified = true`: the single user with that email (case-insensitive) that an admin created for SSO (no password, no sign-in yet, no identity, not an admin), which gets the identity; zero or several fall through. Any other account keeps its email unproven (`users.email` is self-set), so it links from the account page; (3) `autoRegister`: a new user; else `no_account`. An admin is never adopted by email. A provider that advertises `authorization_response_iss_parameter_supported` must send `iss` on the callback (rule 70). A row with `expectUserId` (the silent re-run) resolves only step (1) and only to that user: another identity, an email match or a new account is `login_required`, with no adoption and no registration. A disabled user is `disabled`. `allowedGroups`, when set, gate every login and link (`not_allowed`).
74. New users go through `users::db::create_user` (the one insert of `POST /api/users`, `register` and SSO): role (given, else the default role), the row, then libraries (given, else the role's defaults). SSO users have a NULL hash, `requirePasswordChange` false, `isAdmin` from the admin groups, the email only when verified. The username is the username claim, else the email's local part, else `user-` and 8 hex of `sha256(sub)`, cut to 255 characters; a case-insensitive clash adds `-2`, `-3`, ... and an insert race retries the next candidate, all in the transaction that inserts the identity.
75. Access from groups, only with a `groupsClaim`, each part at creation and at every login when configured: `adminGroups` non-empty sets `isAdmin`; role mappings (by `position`, first match wins, else the default role) set the role and replace `library_user_access` with that role's `role_default_libraries` (`libraryOrder` and `hiddenLibraryIds` untouched). `apply_access` writes them; `PUT /api/users` uses it for the library replacement. A change drops the user's SSE connections and flushes the engine. Demoting the last enabled admin is skipped with a warning.
76. Link: `(provider, sub)` linked to another user is `already_linked`; a user already linked to the provider under another `sub` is `already_linked`; else the identity is inserted for the caller. The session routes use `SessionAuthed`, so a device or scoped token cannot link or unlink. Unlinking the only identity of a user with no password is 400 `oidc.error_last_method`; the admin route has no such guard. Unlinking revokes no session.
77. Login mints its session through the same `sign_in` as password login (`sessions.method = 'oidc'`, `providerId`, `subject`, `sid` of the ID token, the ID token for `id_token_hint`), and the response is the exact `LoginBody` of `POST /api/auth/login`. `users.lastLogin` and `user_identities.lastLoginAt` are set.
78. Password policy `password_login`: `everyone` (default) changes nothing; `admins` refuses a non-admin's password login (rule 29 d2). Setting it needs one enabled provider (409), and disabling or deleting the last enabled provider while it is `admins` is 409. Quick Connect, device tokens and stream, cast and party tokens are unaffected, so a device token or Quick Connect login made from an SSO session outlives the 30 day cap, a provider disable and a back-channel logout. The last-method check of rule 76 treats a password as unusable when this policy is `admins` and the user is not an admin. Only an admin may write `password_login` and `oidc_auto_launch` (`settings.md`).
79. Outbound calls (discovery, JWKS, token, userinfo) go through `net::guard::vet` with `internal = true`: one lookup, every address vetted, the connection pinned, no redirect, 10 s, 256 KiB. Reserved addresses (metadata, multicast) are refused; `http` is allowed only when every address is private or loopback; an optional per-provider CA (`caPem`) adds trust roots. Failures are kinds (`network error`, `status 404`, `invalid discovery`), never URLs.
80. The discovery document must carry the configured issuer exactly and http(s) `authorization_endpoint`, `token_endpoint` and `jwks_uri`; discovery and keys are cached 1 hour per provider and dropped when the provider is updated or deleted.
81. `end-session`: when the caller's session came from a provider with `endSessionAtProvider` and discovery has an `end_session_endpoint`, `{url}` = that endpoint with `id_token_hint`, `client_id`, `post_logout_redirect_uri = <public_url>/login?autoLaunch=0` and a random `state`; else 204. It revokes nothing: the client then calls `logout`.
82. Back-channel logout: the logout token is verified like an ID token (`alg`, `kid`, signature, `iss`, `aud`/`azp`) before any session lookup (the provider row and its discovery are read first), and needs `exp` (60 s leeway), `iat`, `jti`, the event `http://schemas.openid.net/event/backchannel-logout`, a `sid` or a `sub`, and no `nonce`. The provider's sessions with that `sid` (else that `sub`) are revoked, then the users' SSE connections drop and the engine is flushed. No `jti` store: revocation is idempotent. Any failure is 400.
83. Absolute lifetime: a refresh of an `oidc` session whose `createdAt` is more than 30 days old is 401 `Refresh token expired`, so the client runs the provider login again: on every shell that can sign in with a provider (web, phone, desktop), the last provider re-runs with `prompt: 'none'` and `expectUserId` of the expired session, unless the one-minute loop guard holds; `login_required` lands on the login page without a toast.
84. Disabling a provider revokes its sessions; deleting it removes its identities, login rows and sessions (and their refresh tokens) by foreign keys, so those users are signed out at once. Both drop the users' SSE connections and flush the engine.
85. Secrets, tokens and the ID token are never logged or returned (the stored ID token is only an `id_token_hint`); logs carry the user id, the provider id and a hash prefix of the `sub`. Hourly, `oidc_logins` rows expired for an hour are deleted.
86. Residual risk: an attacker who starts a flow on a native or loopback target and sends the victim the `authorizeUrl` never receives the code (it lands on the victim's device), but can still lure the victim through the provider; `prompt=consent` on the provider reduces it and no server check closes it.

## SQL

Tables `users`, `roles`, `sessions`, `refresh_tokens`, `pairing_requests`, `oidc_providers`, `oidc_role_mappings`, `user_identities`, `oidc_logins` (base columns `id, "createdAt", "updatedAt"`). `roles.permissions` is `simple-json` (a text column holding a JSON array). Table DDL is in the sqlx migrations.

- Extractor, per request: `SELECT u.*, r.* FROM users u LEFT JOIN roles r ON r.id = u."roleId" WHERE u.id = $1 AND u.enabled = true AND EXISTS (SELECT 1 FROM sessions s WHERE s.id = $sid AND s."userId" = u.id AND s."revokedAt" IS NULL) LIMIT 1`; `u."passwordHash"` is never selected here.
- Login: `SELECT u.*, u."passwordHash", r.* FROM users u LEFT JOIN roles r ON r.id = u."roleId" WHERE u.username = $1`.
- Login activity: `UPDATE users SET "lastLogin" = $1, "updatedAt" = now WHERE id = $2`. `GET /me`: same statement, gated by rule 42.
- Users public: `SELECT id, username, avatar FROM users WHERE enabled = true ORDER BY username ASC`.
- Register: `SELECT... FROM users WHERE username = $1`, then `users::db::create_user` (role, `INSERT INTO users (username, "passwordHash", email, "roleId", "isAdmin", enabled)`, the role's default libraries).
- Sign-in: `DELETE FROM oidc_logins WHERE state = $1 AND "expiresAt" > now() RETURNING ...`; identity `SELECT "userId" FROM user_identities WHERE "providerId" = $1 AND subject = $2`; the session `INSERT INTO sessions (..., "providerId", subject, sid, "idToken")`.
- Refresh tokens: issue `INSERT INTO refresh_tokens ("userId","tokenHash","expiresAt","userAgent","lastUsedAt","sessionId","parentId") VALUES ($1,$2,$3,$4,NULL,$5,$6)` ($5,$6 = the consumed row's session and id on rotation, else the id of the `sessions` row inserted just before and NULL); rotate lookup `SELECT rt.*, u.*, r.* FROM refresh_tokens rt JOIN users u ON u.id = rt."userId" LEFT JOIN roles r ON r.id = u."roleId" WHERE rt."tokenHash" = $1`; mark used `UPDATE refresh_tokens SET "revokedAt" = $1, "lastUsedAt" = $1, "updatedAt" = now WHERE id = $2`; revoke session `UPDATE sessions SET "revokedAt" = now WHERE id = $1 AND "revokedAt" IS NULL` then `UPDATE refresh_tokens SET "revokedAt" = now WHERE "sessionId" = $1 AND "revokedAt" IS NULL`.
- Refresh-token prune: `DELETE FROM refresh_tokens WHERE "expiresAt" < now - interval '30 days' OR ("revokedAt" IS NOT NULL AND "revokedAt" < now - interval '30 days')`, then `DELETE FROM sessions s WHERE NOT EXISTS (SELECT 1 FROM refresh_tokens t WHERE t."sessionId" = s.id)`.
- Pairing: user check `SELECT... FROM users WHERE id = $1 AND enabled = true`; pending counts `SELECT count(*) FROM pairing_requests WHERE "deviceId" = $1 AND status = 'pending'` (same by `"clientNet"`, then over all pending rows); insert; by id `SELECT... FROM pairing_requests WHERE "publicId" = $1`; lazy expire / approve / deny / claim are `UPDATE pairing_requests SET status|"approvedByUserId"|"accessToken", "updatedAt" = now WHERE id = $n`; pending list `SELECT... WHERE "userId" = $1 AND status = 'pending' ORDER BY "createdAt" DESC`; cleanup `DELETE FROM pairing_requests WHERE "expiresAt" < $1` with `$1 = now - 10 min`.
- Settings read for cast-info: `SELECT value FROM settings WHERE key = 'public_url'` (settings table/shape owned by the settings spec).
