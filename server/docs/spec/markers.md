## Rules

### A. Marker table and CRUD

1. Table `episode_markers`: `id`, `createdAt`, `updatedAt`, `episodeId` (nullable FK `episodes(id)` ON DELETE CASCADE), `type` varchar(16), `startSeconds` float8, `endSeconds` float8, `confidence` float8 default 1, `manual` boolean default false; UNIQUE `uq_episode_marker_type (episodeId, type)`. Marker types: `intro`, `outro` (both detectable) and `recap` (manual only). `manual = true` means "user-edited": detection never overwrites it. `[ts:src/modules/markers/entities/episode-marker.entity.ts:21]`–`[ts:src/modules/markers/entities/episode-marker.entity.ts:47]`
2. `CreateMarkerDto`: `episodeId` int (no minimum), `type` one of `intro|outro|recap`, `startSeconds` number >= 0, `endSeconds` number >= 0. `create`: `endSeconds <= startSeconds` → 400 `endSeconds must be > startSeconds`; then DELETE every marker of `(episodeId, type)` (manual or detected) and INSERT `{episodeId, type, startSeconds, endSeconds, confidence: 1, manual: true}`. The two statements are not in a transaction (a failing INSERT, e.g. an unknown episode, leaves the old marker deleted; C39). `[ts:src/modules/markers/dto/create-marker.dto.ts:3]`–`[ts:src/modules/markers/dto/create-marker.dto.ts:17]`, `[ts:src/modules/markers/markers.service.ts:88]`–`[ts:src/modules/markers/markers.service.ts:105]`
3. `UpdateMarkerDto`: `startSeconds?`, `endSeconds?` numbers >= 0, both `@IsOptional` (absent or `null` pass and are ignored); `type` is not accepted (unknown key 400). `update`: 404 `Marker #<id> not found`; assign each of the two that is `!= null`; if the merged `endSeconds <= startSeconds` → 400 `endSeconds must be > startSeconds`; always set `manual = true` and `confidence = 1` (even for `{}`, so any PUT turns a detected marker into a protected one); save (TypeORM writes only changed columns: a PUT on a manual marker that changes nothing issues no UPDATE and `updatedAt` stays); answer the saved entity (`Marker` shape, `updatedAt` refreshed when written). `[ts:src/modules/markers/dto/update-marker.dto.ts:3]`–`[ts:src/modules/markers/dto/update-marker.dto.ts:13]`, `[ts:src/modules/markers/markers.service.ts:107]`–`[ts:src/modules/markers/markers.service.ts:118]`
4. `remove`: DELETE by id, 0 rows → 404 `Marker #<id> not found`, else 200 with an empty body. `[ts:src/modules/markers/markers.service.ts:120]`–`[ts:src/modules/markers/markers.service.ts:125]`
5. Reads: `findForEpisode` = markers of the episode ordered by `startSeconds`; `findForSeason` = the ids of the season's episodes, then their markers ordered by `episodeId`, `startSeconds` (one join in Rust); an unknown id yields `[]`. `findIntroForEpisode` / `findOutroForEpisode` (first marker of that type) are used only by the S2 playback-info port, which already reads the table itself: the two methods are dropped, not ported. `[ts:src/modules/markers/markers.service.ts:51]`–`[ts:src/modules/markers/markers.service.ts:82]`
6. [new] F43: the two read routes apply the library ACL like the media routes (`episode → season → media → library` through `getAccessibleLibraryIds`, the same accessible-check helper as `media-query`, admins see all); an unknown or inaccessible episode / season is 404 (the F20 pattern; media-query rule 11: a media with `libraryId IS NULL` is 404 even for admins). Nest lets any `media.read` holder read the markers of any episode id (id enumeration, no library check). Kept, rule 29.

### B. Detection orchestration (`MarkersService`)

7. Setting `markers_auto_detect_on_import`: read per call; absent → on; the value must be exactly `'true'` to run (any other string disables). `[ts:src/modules/markers/markers.service.ts:400]`–`[ts:src/modules/markers/markers.service.ts:403]`
8. In-flight guard: ONE in-process `Set<seasonId>` shared by `detectSeason`, `runDetection`, `runDetectionInline` and `autoDetectMissing` (`AppState` mutex set in Rust; it is process-local by design, Rust is the only process after S5). `[ts:src/modules/markers/markers.service.ts:29]`
9. `detectSeason(seasonId, trigger)` (`trigger` = `'manual'` for the routes, `'auto'` for `autoDetectMissing`): season id already in the set → 400 `Detection already running for season #<id>`; add it (held across the lookups so a concurrent call is refused); load the season with its media, missing → release and 404 `Season #<id> not found`; INSERT `commands {name:'IntroDetection', status:'queued', trigger, body:{seasonId, mediaId: season.mediaId, seasonNumber}}` (a failing insert releases the id and rethrows); log; start `runDetection` WITHOUT awaiting (a crash is logged); return the `commands` row. `seasonNumber 0` (specials) is accepted here (only the bulk paths exclude it). `[ts:src/modules/markers/markers.service.ts:132]`–`[ts:src/modules/markers/markers.service.ts:187]`
10. Priority sent to the engine jobs: `trigger === 'manual' ? 'high' : 'low'` for `detectSeason`; `'normal'` for `runDetectionInline`. `[ts:src/modules/markers/markers.service.ts:179]`, `[ts:src/modules/markers/markers.service.ts:253]`
11. `detectSeries(mediaId, trigger)`: the seasons of the media ordered `seasonNumber ASC`, keep `seasonNumber > 0`; for each, `detectSeason` in order; a failure (already running, vanished) is logged and skipped; answer the rows that were created. Unknown media or a media with no seasons → `[]` (C41 makes an unknown media 404). `[ts:src/modules/markers/markers.service.ts:260]`–`[ts:src/modules/markers/markers.service.ts:283]`
12. `runDetection(cmdId, seasonId, mediaId, seasonNumber, mediaTitle, priority)`: add the id to the set; `UPDATE commands SET status = 'running', "startedOn" = now()`; emit `command.started {name:'IntroDetection'}`; `subject = buildMediaProgressSubject({id: mediaId, title, type: series}, {seasonNumber})` (events-hub / activity spec; `mediaTitle` = the media title or `media #<id>`); activity `IntroDetection:<seasonId>` (type `IntroDetection`) set running with that subject; `onProgress(current, total, message)` emits `task.progress {command:'IntroDetection', current, total, message, subject}` AND updates the activity row with `current/total`; run rule 16; success: `UPDATE commands SET status = 'completed', "endedOn" = now()`, emit `command.completed {name:'IntroDetection', status:'completed'}`, emit `markers.season.completed {mediaId, seasonId, seasonNumber, introsDetected: intros + outros}`; failure (any throw, incl. intro detection, a missing engine feature, a failing `commands` update): log, `UPDATE commands SET status = 'failed', "endedOn" = now()`, emit `command.completed {name, status:'failed'}` (no `markers.season.completed`; if that `failed` UPDATE itself throws, no `command.completed` is emitted and `detectSeason`'s `.catch` logs `IntroDetection #<cmd> crashed`); finally release the id and remove the activity row. `[ts:src/modules/markers/markers.service.ts:323]`–`[ts:src/modules/markers/markers.service.ts:394]`
13. `runDetectionInline(seasonId, subject?)` (bulk jobs `DetectMarkers` / `DetectMissingMarkers`, no `commands` row of its own, no SSE per season): season id already in the set → remove the caller's pre-registered pending activity row (when `subject`) and return `{introsDetected: 0, outrosDetected: 0}`; else add the id, set activity `IntroDetection:<seasonId>` running `(0, 1)` when `subject` is given, run rule 16 with `onProgress` updating the activity row, finally release the id and remove the activity row. `[ts:src/modules/markers/markers.service.ts:235]`–`[ts:src/modules/markers/markers.service.ts:258]`
14. `listSeasonsForScan(onlyMissing, mediaId?)`: `SELECT s.id, s."mediaId", s."seasonNumber", m.title AS "mediaTitle" FROM seasons s JOIN media m ON m.id = s."mediaId" WHERE s."seasonNumber" > 0 AND m.type = 'series' [AND s."mediaId" = $1] [AND EXISTS (SELECT 1 FROM episodes e WHERE e."seasonId" = s.id AND e."hasFile" = true AND e."markersScannedAt" IS NULL)] ORDER BY m.title ASC, s."seasonNumber" ASC` (Rust adds `, s.id ASC`, C12); `onlyMissing` adds the `EXISTS`. `[ts:src/modules/markers/markers.service.ts:194]`–`[ts:src/modules/markers/markers.service.ts:226]`
15. `autoDetectMissing(mediaId)` (post-import, rule 7 first): `listSeasonsForScan(true, mediaId)` then `detectSeason(id, 'auto')` for each, in order; every failure is swallowed (debug log). `[ts:src/modules/markers/markers.service.ts:400]`–`[ts:src/modules/markers/markers.service.ts:415]`
16. `detectIntrosAndOutros(seasonId, onProgress, priority)`: (a) `detectSeasonIntros` (a throw aborts the run: rule 12 failure path, episodes stay unscanned); (b) `detectSeasonOutros` in its own try/catch (a failure is logged, `outrosDetected = 0`, the run continues); (c) `UPDATE episodes SET "markersScannedAt" = now() WHERE "seasonId" = $1 AND "hasFile" = true` (EVERY episode with a file, including ones whose fingerprint failed, whose outro failed, or that were skipped for lack of a second episode or a media path: `markersScannedAt` means "a detection pass ran", not "a marker was found"); result `{introsDetected, outrosDetected}`. `[ts:src/modules/markers/markers.service.ts:290]`–`[ts:src/modules/markers/markers.service.ts:321]`

### C. Detection of one kind (`IntroDetectionService`, intro and outro)

17. Preconditions (checked by each of the two passes): engine feature `intro-detect` in `hello.features` of the adopted engine (Rust `Engine::engine_features()`, not the server-features `features()`), else throw `The engine has no intro-detect feature` (also the case while no engine is adopted); season missing → throw `Season #<id> not found`; the parent media without a `path` (no library path) → intro: warn and return `{introsDetected: 0, skipped: 0}`, outro: return `{outrosDetected: 0, skipped: 0}`. `[ts:src/modules/markers/intro-detection.service.ts:51]`–`[ts:src/modules/markers/intro-detection.service.ts:71]`, `[ts:src/modules/markers/intro-detection.service.ts:138]`–`[ts:src/modules/markers/intro-detection.service.ts:154]`
18. Episodes: `episodes WHERE seasonId = ? AND hasFile = true ORDER BY episodeNumber ASC`. Intros need at least 2 such episodes (fewer → log, `{introsDetected: 0, skipped: <count>}`); outros return `{0, 0}` for an empty list and have no minimum. The file of an episode = its `media_files` row with the highest `id`. Lookup window `lookupSec = (Number(introMaxLookupMinutes) || 10) * 60`; `minSegmentSec = Number(introMinSegmentSeconds) || 15` (settings, rule 28). Manual markers: `manualIds` = episodes having a marker of that `type` with `manual = true`; they are neither fingerprinted nor sent to the engine. `[ts:src/modules/markers/intro-detection.service.ts:73]`–`[ts:src/modules/markers/intro-detection.service.ts:97]`, `[ts:src/modules/markers/intro-detection.service.ts:209]`–`[ts:src/modules/markers/intro-detection.service.ts:249]`
19. Fingerprinting (`fingerprintEpisodes`): targets = episodes not in `manualIds`, with a file, and for outros a file whose `streamInfo.durationSeconds > 0`. In slices of 4 (`FINGERPRINT_CONCURRENCY`, each slice awaited whole), per target run the engine job `{kind: {type:'Fingerprint', window: {type:'head'} | {type:'outro', durationSeconds: file duration}, maxLookupMinutes: lookupSec / 60}, media: {mediaFileId: file.id, path: path.resolve(media.path, file.relativePath)}, priority}` and keep `{...fingerprint, baseOffsetSec: fingerprint.baseOffsetSec ?? 0}`. A failing job logs a warning and drops that episode. Progress: `onProgress(0, n, "<label> 0/<n>")` first, then after every target `onProgress(processed, n, "<label> <processed>/<n>")`; label `Fingerprinting` (intro) or `Outro fingerprinting`. The kept fingerprints are sorted by `episodeNumber`. `[ts:src/modules/markers/intro-detection.service.ts:251]`–`[ts:src/modules/markers/intro-detection.service.ts:315]`, `[ts:src/modules/markers/intro-detection.service.ts:396]`–`[ts:src/modules/markers/intro-detection.service.ts:416]`
20. Matching (`runIntroDetect`): nothing fingerprinted → `{detected: 0}` and no engine call. Else `POST /v1/intro-detect {kind, lookupSeconds: lookupSec, minSegmentSeconds: minSegmentSec, episodes: [{mediaFileId, durationSeconds: streamInfo.durationSeconds ?? 0, chapters: streamInfo.chapters ?? omitted, introFingerprint | outroFingerprint: <fingerprint>}]}` (key by kind); the engine answers `{results: [{mediaFileId, startSeconds, endSeconds, confidence, source: chapter|reference|pairwise}]}` for the episodes that resolved (it answers 400 with a text body for a missing fingerprint, a non-finite or `<= 0` `lookupSeconds` (`lookupSeconds must be positive`), or an outro episode with duration `<= 0`; `minSegmentSeconds` is optional there, default 15, unvalidated). The host never sends those, except a negative `introMaxLookupMinutes` (only `0` / `NaN` fall back to 10, on both sides): it goes as is to the `Fingerprint` jobs (the engine also defaults only `0` / `NaN`) and, if any fingerprint comes back, as a negative `lookupSeconds` that the engine rejects (C40) `[assumed]` that fpcalc / ffmpeg with a negative length fail first, so the pass usually ends with nothing fingerprinted and no call. An `EngineError` fails the intro pass (season `failed`, rule 12) or the outro pass (logged, rule 16 b). `[ts:src/modules/markers/intro-detection.service.ts:317]`–`[ts:src/modules/markers/intro-detection.service.ts:346]`
21. Persist, per returned segment in order: results whose `mediaFileId` is not among the fingerprinted files are ignored; DELETE the markers `(episode, kind)` with `manual = false`, then INSERT `{episodeId, type: kind, startSeconds, endSeconds, confidence, manual: false}`. Two statements per segment, no transaction (C39: one upsert); a marker made manual during the run makes the INSERT hit `uq_episode_marker_type` and throw, which aborts that pass like an `EngineError` (rule 20). Episodes the engine did not resolve keep their OLD detected marker (stale markers are never cleared). `detected = results.length` (counts ignored segments too). `[ts:src/modules/markers/intro-detection.service.ts:348]`–`[ts:src/modules/markers/intro-detection.service.ts:377]`
22. `skipped` = episodes not manual, with a file (outro: file duration > 0), whose file id is not in the result set. Intro progress ends with `onProgress(episodes.length, episodes.length, "Detection complete: <n> intro(s)")`; the outro pass sends no completion tick. `[ts:src/modules/markers/intro-detection.service.ts:119]`–`[ts:src/modules/markers/intro-detection.service.ts:131]`, `[ts:src/modules/markers/intro-detection.service.ts:379]`–`[ts:src/modules/markers/intro-detection.service.ts:394]`
23. Outro positioning is the engine's (`baseOffsetSec`, window from the duration); the host only passes the file duration and the head / outro fingerprints. Constants of the algorithm (`HAMMING_THRESHOLD`, windows, clustering) live in `fliks-engine/docs/spec/intro.md` section 2 and are not host rules.

### E. New in Rust

25. [new] C39: marker writes are atomic and never 500: `POST /api/markers` checks the episode (404 `Episode #<id> not found`, `episodeId >= 1`) and writes ONE statement `INSERT INTO episode_markers (...) VALUES (...) ON CONFLICT ("episodeId", type) DO UPDATE SET "startSeconds" = EXCLUDED."startSeconds", "endSeconds" = EXCLUDED."endSeconds", confidence = 1, manual = true, "updatedAt" = now() RETURNING *` (a manual create replaces a detected or manual marker, as today; the row keeps its id and `createdAt`, Nest's delete-then-insert gave a new id); the response is the `Marker` shape. Detection persists one segment with `INSERT ... 27. [new] C41: `POST /api/markers/series/:mediaId/detect-all` on an unknown media is 404 `Media #<id> not found`; a media with no eligible season stays `[]`.

## Jobs/timers

No timer of its own.
