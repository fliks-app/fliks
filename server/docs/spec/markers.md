# Spec: markers (episode markers CRUD, intro / outro detection orchestration)

Engine side: `fliks-engine/docs/spec/intro.md` (`POST /v1/intro-detect`, `core::intro`) and `fliks-engine/docs/spec/jobs.md` section 7 (`Fingerprint` job).

What the engine does and what stays host-side: the matching algorithm (chapter shortcut, reference search, pairwise chromaprint matching, clustering, consensus) is in the engine (`POST /v1/intro-detect`, announced as feature `intro-detect`; the `Fingerprint` job runs through `run_job`); the engine client has `Engine::intro_detect` and `Engine::run_job` (`server/crates/server/src/engine/{calls,jobs}.rs`). The host has no matching code. The host keeps: queries, the `Fingerprint` job submissions (batches of 4), manual-marker protection, marker upserts, counters, activity and events (engine spec section 3). The playback-info marker READ is in `playback-info.md`.

## Routes

7 routes under `/api/markers`. Class-level guards `JwtOrApiKeyGuard, PoliciesGuard`; no `SessionTokenGuard` (a `scope:'stream'` token is 401). `Read Media` = `media.read` (or `manage:all`); `Manage Media` is granted by NO permission string: only `isAdmin` / `manage:all` hold it (CASL factory `media.create|edit|delete|grab` grant narrower actions, as in `acl.rs`), so every write and detect route is admin-only. Validation body = auth rule 16 (unknown keys 400); path ids are canonical integers (auth rule 18).

Shapes. `Marker` (GET, PUT; the entity loaded with its relation id): `{id: number, createdAt: ISO, updatedAt: ISO, type: 'intro'|'outro'|'recap', startSeconds: number, endSeconds: number, confidence: number (0..1), manual: boolean, episodeId: number}`; no `episode` key (relation not loaded). `CommandRow` (detect routes) = the saved `commands` entity: `{id, createdAt, updatedAt, name:'IntroDetection', status:'queued', trigger:'manual', body:{seasonId, mediaId, seasonNumber}, startedOn: null, endedOn: null}` (the queued row, never the later `running` state; nullable columns not set are `null`). `POST /api/markers` returns the `Marker` shape (`client/src/app/core/services/api/markers-api.service.ts:7` declares `episodeId`).

## Rules

### A. Marker table and CRUD

1. Table `episode_markers`: `id`, `createdAt`, `updatedAt`, `episodeId` (nullable FK `episodes(id)` ON DELETE CASCADE), `type` varchar(16), `startSeconds` float8, `endSeconds` float8, `confidence` float8 default 1, `manual` boolean default false; UNIQUE `uq_episode_marker_type (episodeId, type)`. Marker types: `intro`, `outro` (both detectable) and `recap` (manual only). `manual = true` means "user-edited": detection never overwrites it.
2. `CreateMarkerDto`: `episodeId` int (no minimum), `type` one of `intro|outro|recap`, `startSeconds` number >= 0, `endSeconds` number >= 0. `create`: `endSeconds <= startSeconds` → 400 `endSeconds must be > startSeconds`; then the marker of `(episodeId, type)` (manual or detected) is replaced by `{episodeId, type, startSeconds, endSeconds, confidence: 1, manual: true}` in one statement (rule 25).
3. `UpdateMarkerDto`: `startSeconds?`, `endSeconds?` numbers >= 0, both optional (absent or `null` are ignored); `type` is not accepted (unknown key 400). `update`: 404 `Marker #<id> not found`; assign each of the two that is `!= null`; if the merged `endSeconds <= startSeconds` → 400 `endSeconds must be > startSeconds`; always set `manual = true` and `confidence = 1` (even for `{}`, so any PUT turns a detected marker into a protected one); only changed columns are written (a PUT on a manual marker that changes nothing issues no UPDATE and `updatedAt` stays); answer the saved row (`Marker` shape, `updatedAt` refreshed when written).
4. `remove`: DELETE by id, 0 rows → 404 `Marker #<id> not found`, else 200 with an empty body.
5. Reads: markers of the episode ordered by `startSeconds`, `id`; markers of the season (one join on the season's episodes) ordered by `episodeId`, `startSeconds`, `id`. An unknown or inaccessible episode or season is 404 (rule 6).
6. The two read routes apply the library ACL like the media routes (`episode → season → media → library` through `getAccessibleLibraryIds`, the same accessible-check helper as `media-query`, admins see all); an unknown or inaccessible episode / season is 404 (media-query rule 11: a media with `libraryId IS NULL` is 404 even for admins; the same pattern as the library reads). The only client reader, `remote-playback-target.ts:292`, swallows errors.

### B. Detection orchestration (`MarkersService`)

7. Setting `markers_auto_detect_on_import`: read per call; absent → on; the value must be exactly `'true'` to run (any other string disables).
8. In-flight guard: ONE in-process set of season ids shared by `detectSeason`, `runDetection`, `runDetectionInline` and `autoDetectMissing` (an `AppState` mutex set; process-local by design).
9. `detectSeason(seasonId, trigger)` (`trigger` = `'manual'` for the routes, `'auto'` for `autoDetectMissing`): season id already in the set → 400 `Detection already running for season #<id>`; add it (held across the lookups so a concurrent call is refused); load the season with its media, missing → release and 404 `Season #<id> not found`; INSERT `commands {name:'IntroDetection', status:'queued', trigger, body:{seasonId, mediaId: season.mediaId, seasonNumber}}` (a failing insert releases the id and rethrows); log; start `runDetection` WITHOUT awaiting (a crash is logged); return the `commands` row. `seasonNumber 0` (specials) is accepted here (only the bulk paths exclude it).
10. Priority sent to the engine jobs: `trigger === 'manual' ? 'high': 'low'` for `detectSeason`; `'normal'` for `runDetectionInline`.
11. `detectSeries(mediaId, trigger)`: the seasons of the media ordered `seasonNumber ASC`, keep `seasonNumber > 0`; for each, `detectSeason` in order; a failure (already running, vanished) is logged and skipped; answer the rows that were created. Unknown media or a media with no seasons → `[]` (an unknown media is 404, rule 27).
12. `runDetection(cmdId, seasonId, mediaId, seasonNumber, mediaTitle, priority)`: add the id to the set; `UPDATE commands SET status = 'running', "startedOn" = now()`; emit `command.started {name:'IntroDetection'}`; `subject = buildMediaProgressSubject({id: mediaId, title, type: series}, {seasonNumber})` (events-hub / activity spec; `mediaTitle` = the media title or `media #<id>`); activity `IntroDetection:<seasonId>` (type `IntroDetection`) set running with that subject; `onProgress(current, total, message)` emits `task.progress {command:'IntroDetection', current, total, message, subject}` AND updates the activity row with `current/total`; run rule 16; success: `UPDATE commands SET status = 'completed', "endedOn" = now()`, emit `command.completed {name:'IntroDetection', status:'completed'}`, emit `markers.season.completed {mediaId, seasonId, seasonNumber, introsDetected: intros + outros}`; failure (any throw, incl. intro detection, a missing engine feature, a failing `commands` update): log, `UPDATE commands SET status = 'failed', "endedOn" = now()`, emit `command.completed {name, status:'failed'}` (no `markers.season.completed`; if that `failed` UPDATE itself throws, no `command.completed` is emitted and `detectSeason`'s `.catch` logs `IntroDetection #<cmd> crashed`); finally release the id and remove the activity row (as soon as the detection settles, before the `commands` update and the events).
13. `runDetectionInline(seasonId, subject?)` (bulk jobs `DetectMarkers` / `DetectMissingMarkers`, no `commands` row of its own, no SSE per season): season id already in the set → remove the caller's pre-registered pending activity row (when `subject`) and return `{introsDetected: 0, outrosDetected: 0}`; else add the id, set activity `IntroDetection:<seasonId>` running `(0, 1)` when `subject` is given, run rule 16 with `onProgress` updating the activity row, finally release the id and remove the activity row.
14. `listSeasonsForScan(onlyMissing, mediaId?)`: `SELECT s.id, s."mediaId", s."seasonNumber", m.title AS "mediaTitle" FROM seasons s JOIN media m ON m.id = s."mediaId" WHERE s."seasonNumber" > 0 AND m.type = 'series' [AND s."mediaId" = $1] [AND EXISTS (SELECT 1 FROM episodes e WHERE e."seasonId" = s.id AND e."hasFile" = true AND e."markersScannedAt" IS NULL)] ORDER BY m.title ASC, s."seasonNumber" ASC, s.id ASC`; `onlyMissing` adds the `EXISTS`.
15. `autoDetectMissing(mediaId)` (post-import, rule 7 first): `listSeasonsForScan(true, mediaId)` then `detectSeason(id, 'auto')` for each, in order; every failure is swallowed (debug log).
16. `detectIntrosAndOutros(seasonId, onProgress, priority)`: (a) `detectSeasonIntros` (a throw aborts the run: rule 12 failure path, episodes stay unscanned); (b) `detectSeasonOutros` in its own try/catch (a failure is logged, `outrosDetected = 0`, the run continues); (c) `UPDATE episodes SET "markersScannedAt" = now() WHERE "seasonId" = $1 AND "hasFile" = true` (EVERY episode with a file, including ones whose fingerprint failed, whose outro failed, or that were skipped for lack of a second episode or a media path: `markersScannedAt` means "a detection pass ran", not "a marker was found"); result `{introsDetected, outrosDetected}`.

### C. Detection of one kind (`IntroDetectionService`, intro and outro)

17. Preconditions (checked by each of the two passes): engine feature `intro-detect` in `hello.features` of the adopted engine (`Engine::engine_features()`, not the server-features `features()`), else throw `The engine has no intro-detect feature` (also the case while no engine is adopted); season missing → throw `Season #<id> not found`; the parent media without a `path` (no library path) → intro: warn and return `{introsDetected: 0, skipped: 0}`, outro: return `{outrosDetected: 0, skipped: 0}`.
18. Episodes: `episodes WHERE seasonId = ? AND hasFile = true ORDER BY episodeNumber ASC`. Intros need at least 2 such episodes (fewer → log, `{introsDetected: 0, skipped: <count>}`); outros return `{0, 0}` for an empty list and have no minimum. The file of an episode = its `media_files` row with the highest `id`. Lookup window `lookupSec = introMaxLookupMinutes * 60` (default 10, rule 26); `minSegmentSec = introMinSegmentSeconds` (default 15, rule 26); settings: rule 28. Manual markers: `manualIds` = episodes having a marker of that `type` with `manual = true`; they are neither fingerprinted nor sent to the engine.
19. Fingerprinting (`fingerprintEpisodes`): targets = episodes not in `manualIds`, with a file, and for outros a file whose `streamInfo.durationSeconds > 0`. In slices of 4 (`FINGERPRINT_CONCURRENCY`, each slice awaited whole), per target run the engine job `{kind: {type:'Fingerprint', window: {type:'head'} | {type:'outro', durationSeconds: file duration}, maxLookupMinutes: lookupSec / 60}, media: {mediaFileId: file.id, path: the media path joined with `file.relativePath`}, priority}` and keep `{...fingerprint, baseOffsetSec: fingerprint.baseOffsetSec ?? 0}`. A failing job logs a warning and drops that episode. Progress: `onProgress(0, n, "<label> 0/<n>")` first, then after every target `onProgress(processed, n, "<label> <processed>/<n>")`; label `Fingerprinting` (intro) or `Outro fingerprinting`. The kept fingerprints are sorted by `episodeNumber`.
20. Matching (`runIntroDetect`): nothing fingerprinted → `{detected: 0}` and no engine call. Else `POST /v1/intro-detect {kind, lookupSeconds: lookupSec, minSegmentSeconds: minSegmentSec, episodes: [{mediaFileId, durationSeconds: streamInfo.durationSeconds ?? 0, chapters: streamInfo.chapters ?? omitted, introFingerprint | outroFingerprint: <fingerprint>}]}` (key by kind); the engine answers `{results: [{mediaFileId, startSeconds, endSeconds, confidence, source: chapter|reference|pairwise}]}` for the episodes that resolved (it answers 400 with a text body for a missing fingerprint, a non-finite or `<= 0` `lookupSeconds` (`lookupSeconds must be positive`), or an outro episode with duration `<= 0`; `minSegmentSeconds` is optional there, default 15, unvalidated). The host never sends those: the lookup window and minimum segment fall back to their defaults unless finite and > 0 (rule 26). An `EngineError` fails the intro pass (season `failed`, rule 12) or the outro pass (logged, rule 16 b).
21. Persist, per returned segment in order: results whose `mediaFileId` is not among the fingerprinted files are ignored; one upsert per segment (rule 25) that never overwrites a manual marker (a marker made manual during the run is left as is). Episodes the engine did not resolve keep their existing detected marker (stale markers are never cleared). `detected = results.length` (counts ignored segments too).
22. `skipped` = episodes not manual, with a file (outro: file duration > 0), whose file id is not in the result set. Intro progress ends with `onProgress(episodes.length, episodes.length, "Detection complete: <n> intro(s)")`; the outro pass sends no completion tick.
23. Outro positioning is the engine's (`baseOffsetSec`, window from the duration); the host only passes the file duration and the head / outro fingerprints. Constants of the algorithm (`HAMMING_THRESHOLD`, windows, clustering) live in `fliks-engine/docs/spec/intro.md` section 2 and are not host rules.

### D. Callers (function interface; the scheduler spec owns the callers)

24. `markers::auto_detect_missing(state, media_id)` ← post-import queue after its 60 s settle, the import-queue idle wait (5 min ceiling) and the sprite pass (errors logged as `marker detection failed`); `markers::list_seasons_for_scan(state, only_missing, media_id: Option)` and `markers::run_detection_inline(state, season_id, subject: Option)` ← core trigger-only commands `DetectMarkers` (all seasons) / `DetectMissingMarkers` (`onlyMissing`) (the loop, its `task.progress` events and the pre-registered pending activity rows `IntroDetection:<seasonId>` belong to that spec). No other module calls `MarkersService`.

### E. Atomic writes and input limits

25. Marker writes are atomic and never 500: `POST /api/markers` checks the episode (404 `Episode #<id> not found`, `episodeId >= 1`) and writes ONE statement `INSERT INTO episode_markers (...) VALUES (...) ON CONFLICT ("episodeId", type) DO UPDATE SET "startSeconds" = EXCLUDED."startSeconds", "endSeconds" = EXCLUDED."endSeconds", confidence = 1, manual = true, "updatedAt" = now() RETURNING *` (a manual create replaces a detected or manual marker; the row keeps its id and `createdAt`); the response is the `Marker` shape. Detection persists one segment with `INSERT... ON CONFLICT ("episodeId", type) DO UPDATE SET..., manual = false WHERE episode_markers.manual = false` (a marker made manual during the run is never overwritten, and there is no delete-then-insert window).
26. `introMaxLookupMinutes` and `introMinSegmentSeconds` that are not finite numbers > 0 fall back to 10 and 15, so the engine never receives a non-positive window.
27. `POST /api/markers/series/:mediaId/detect-all` on an unknown media is 404 `Media #<id> not found`; a media with no eligible season stays `[]`.
28. Settings read (rule 18): `introMaxLookupMinutes`, `introMinSegmentSeconds`; `markers_auto_detect_on_import` (rule 7).
29. The detect routes answer 201 even when the engine is down or lacks `intro-detect` (the command row ends `failed`); `markersScannedAt` is stamped for every file episode after any pass (rule 16), so `DetectMissingMarkers` skips them; a re-detection that resolves nothing keeps the existing detected marker (rule 21); `Manage Media` stays admin-only (no permission string grants it); the 404 of rule 6 stays.

## SQL

1. Marker reads: `SELECT m.* FROM episode_markers m WHERE m."episodeId" = $1 ORDER BY m."startSeconds", m.id`; season: `SELECT m.* FROM episode_markers m JOIN episodes e ON e.id = m."episodeId" WHERE e."seasonId" = $1 ORDER BY m."episodeId", m."startSeconds", m.id`.
2. Create: the upsert of rule 25; update: `UPDATE episode_markers SET "startSeconds", "endSeconds", manual, confidence, "updatedAt" WHERE id`; delete: `DELETE FROM episode_markers WHERE id = $1`.
3. Detection inputs: `detectSeason` loads the season with its media (`seasons` JOIN `media`); each pass then re-reads the season and its media (one join), `SELECT * FROM episodes WHERE "seasonId" = $1 AND "hasFile" = true ORDER BY "episodeNumber"`, `SELECT * FROM media_files WHERE "episodeId" = ANY($1) ORDER BY id DESC` (first per episode wins), `SELECT "episodeId" FROM episode_markers WHERE "episodeId" = ANY($1) AND type = $2 AND manual = true`.
4. Detection writes: rule 25 upsert; `UPDATE episodes SET "markersScannedAt" = now() WHERE "seasonId" = $1 AND "hasFile" = true` (rule 16).
5. `listSeasonsForScan`: rule 14. Commands: `INSERT INTO commands (name, status, trigger, body) VALUES ('IntroDetection','queued',$1,$2::jsonb) RETURNING id, "createdAt", "updatedAt"`; `UPDATE commands SET status = $2, "startedOn" =...` / `"endedOn" = now() WHERE id = $1`.

## Jobs/timers

No timer of its own. Driven by: the post-import queue (rule 24, auto, priority `low`), the core trigger-only commands `DetectMarkers` / `DetectMissingMarkers` (rule 24, priority `normal`), and the two routes (priority `high`). Fingerprint jobs run on the engine (its slot budget queues them); the host awaits them with no timeout (`run_job`: an events reconnect re-checks a job that finished while disconnected). A restart leaves an unfinished `IntroDetection` row to the scheduler framework's boot sweep, which sets every `running` AND `queued` row to `failed` with `endedOn` (scheduler spec).

## Vectors/parity

Vectors: none for matching (engine-owned; its own fixtures `fliks-engine/fixtures/intro/*.json`). Host-side pure parts are tested as Rust unit tests with a fake engine (`Engine` behind a small trait object in the test only): the segment persistence rules (rules 21-22: manual untouched, stale kept, ignored segments counted), `listSeasonsForScan` filters, the in-flight set (a second `detectSeason` is refused, released after success and after failure, `runDetectionInline` clears the pre-registered pending row), progress message strings (rules 19, 22), `markersScannedAt` stamping (rule 16, also after a failed outro pass), settings parsing (rules 7, 18, 26).

External HTTP is the ENGINE, not a third party: Rust tests (`server/crates/server/src/markers/tests.rs`, the double is crate-private) run against the engine's own test double (`server/crates/server/src/engine/testkit.rs`) serving canned `Fingerprint` job results and `/v1/intro-detect` answers (known intro at a known offset for a generated 3-episode season; an engine without the `intro-detect` feature; a 400 from `/v1/intro-detect`). Parity runs the same canned answers through a stub engine process `server/parity/stubs/engine-stub.mjs` (no dependencies, port 4963: `GET /v1/hello` with the `intro-detect` feature, `POST /v1/jobs` completing `Fingerprint` at once, `POST /v1/intro-detect` answering a fixed segment per `mediaFileId`) adopted through `FLIKS_ENGINE_URL` / `FLIKS_ENGINE_TOKEN`; the seed is `parity/seed/markers.sql`.

Parity scenarios (`server/parity/scenarios/markers/`; seed: a series with 2 seasons, season 1 with 3 episodes with files, markers in manual and detected states, a movie, `user` / `readonly` actors): `list-episode` (+ `-empty`), `list-season`, `list-unknown-ids` (404), `list-non-integer-id`, `list-acl`, `create` (+ `-replaces-existing`, `-end-before-start-400`, `-bad-type-400`, `-unknown-key-400`, `-validation-400`, `-unknown-episode` (404)), `update` (+ `-marks-manual`, `-404`, `-end-before-start-400`, `-type-key-400`), `delete` (+ `-404`), `detect-season` (201 `CommandRow`; `-row` checks its shape), `detect-season-already-running-400`, `detect-season-404`, `detect-series` (only seasons > 0; `-row`, `-empty`, `-unknown` (404)); an engine without `intro-detect` (row ends `failed`) is covered by the Rust test only, the parity stub always announces the feature. Each write and detect route also has `-unauthenticated` (401) and `-forbidden` (`user` for the admin-only routes) scenarios. Everything runs on `/tmp/fliks-parity/`; detection only reads the generated files.
