# Spec: comics in the catalogue

Scope: what the `comic` kind adds to the data model and to the media payloads: the kind and its family, a volume and its issues, `comic_details`, `comic_issues`, the wire shapes of the detail and the list. Archive ingest, the page routes, `ComicInfo.xml` and file-name parsing, metadata providers, acquisition, OPDS and the reader are later work (`plans/books-audiobooks.plan.md`, phase 7). The wire contract shared with the client is `plans/comics-contract.md`; the migration is `1789000000700_comics.sql`.

## Kind and families

1. `MediaKind::Comic`: wire name `comic` (`media.type`, `requests."mediaType"`, `user_quotas.kind`, the `comic` level of `cleanup_rules.levels`), `has_seasons` false, `families` `[Image]`, `count_key` `comics`, `completed_stat_key` `comicsFinished`. Every exhaustive `match` on `MediaKind` has a `comic` arm. The kind CHECKs list `MediaKind::ALL`; the family CHECKs (`editions.family`, `wants.family`, the quality families) gain `image`, the family `Family::Image` was reserved for (`items.md` rule 39).
2. A comic is one `media` row of type `comic`: one series volume (a run, e.g. the one that started in 2016), with the work-level title, overview, year and poster on `media`. A library accepts the type like any kind: `"comic"` in `libraries."mediaTypes"`.
3. `create_shell` for a comic inserts one `image` want (`language` NULL, with the quality profile the creation resolved, like any kind) and no edition and no item, like a book. Ingest creates the volume's one `image` edition and one item per issue. The format of a file is not the edition's: a volume can mix `cbz` and `pdf` files (rule 10).
4. A media cannot become a comic or stop being one: `PUT /api/media/:id` answers `400 A comic cannot change type`. A comic is not requestable (`POST /api/requests` answers `400 mediaType must be one of the following values: movie, series, book`) and the TMDB and TVDB imports refuse a kind that is not video.

## Volume and issues

5. `comic_details("mediaId", kind = 'comic', publisher, "startYear", volume, "originalLanguage")` is the volume-level detail row, one per comic, `kind` pinned by a composite foreign key (`media-details.md` rule 12). `"startYear"` is 1 to 9999, `volume` the number printed on the cover (`>= 0`), NULL when unknown. `media_details_json` has a fourth arm for it (every video-only key NULL). The row is created by ingest; a payload of a comic without one reads `null` for each field.
6. An issue is an ungrouped item of the volume's edition (`items.md` rule 4: a comic has no group) and its `items."number"` stays NULL. A comic therefore never appears in an episode list, count or lookup (`items.md` rule 12), and `item_of(comic, NULL)` answers `NULL` with several issues (`items.md` rule 36): an issue is addressed by its item id.
7. `comic_issues("itemId", "mediaId", kind, "sortNumber", label, "pageCount")` holds the facts of an issue item, one row per item, with `FOREIGN KEY ("itemId", "mediaId") REFERENCES items (id, "mediaId") ON DELETE CASCADE`. `kind` is `issue`, `annual` or `special`; `"sortNumber"` is the finite decimal sort key (`1`, `1.5`, `0`, `-1`); `label` the printed number (`"1"`, `"1.5"`, `"0"`), never empty; `"pageCount"` is positive or NULL. `UNIQUE ("mediaId", kind, "sortNumber")` is the key ingest upserts on. **Decision:** `items."number"` stays an integer (every series path reads it), so the decimal key and the label live in this table, and annuals are a `kind`, not an item group: a group makes an item an episode for every query of `items.md` rule 12. `items.title` and `items."airDate"` carry the issue's title and release date.
8. A variant cover or a second scan of one issue is another version of the same item (`items.md` rule 35: another part with a higher `"version"`), never another issue: the unique key above refuses it. Story arcs and collected editions (TPB, omnibus) as collections of comics are later work: `collection_entries` can hold them (`items.md` rule 38) but no collection route reads comic entries yet.

## Wire

Keys absent for other kinds: a movie, series or book payload carries no `comic` key.

9. `GET /api/media/:id` of a comic carries `comic: ComicDetail` (`plans/comics-contract.md`): `publisher`, `startYear` and `volume` from `comic_details` (null when no row), and `issues` in the readable editions (`COALESCE(editions."libraryId", media."libraryId")` in the caller's libraries): the issues (`kind = 'issue'`) by `"sortNumber"` ascending, then the annuals and specials by `"sortNumber"`, then `kind`, then item id. An issue is `{itemId, mediaFileId, format, number (label), sort, annual (kind <> 'issue'), kind, title, releaseDate (YYYY-MM-DD or null), pageCount, progression, finished}`.
10. The part of an issue is picked once, by the order of `items.md` rule 35 using the caller's `playback_states` row: the file the state names when it is still a part, else the first part of the state's version, else the first part of the highest version. `mediaFileId` is that file, `format` the lower-cased extension of the same file when it is `cbz`, `cb7`, `cbr` or `pdf`, else `null`; both are `null` for an issue without a file. `progression` is the caller's state: `1` when completed, else its `progression`, else position over duration, `null` when the caller never opened the issue. `finished` is the state's `completed`.
11. A list item of `GET /api/media?type=comic` and of the recently-added list carries `comic: {publisher, startYear, issueCount, readCount}`: the issues of the volume in the readable editions, and the ones the caller completed. Other lists (collections, playlists) carry none yet.
12. A comic counts in `GET /api/media/counts` and `GET /api/counts` under `comics`, in a user's `comicQuotaLimit` (read and written like `bookQuotaLimit`, `users.md` rule 19) and in the social stats as `comicsFinished`, the number of volumes finished (rule 13).
13. A comic is `watched` (and finished) when it has an issue with a part and every issue with a part is completed, the series rule (`media-query.md` rule 20) over its ungrouped items; its `progressPercent` is 100 then, else the progress of the most recently played unfinished issue.

## Migration

14. `1789000000700_comics.sql` is one transaction: the widened CHECKs, `comic_details`, `media_details_json` and `comic_issues` (with its keys). It backfills nothing. Numbers `1789000000700` to `709` are reserved by track for comics.
