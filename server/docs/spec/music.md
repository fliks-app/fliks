# Spec: music in the catalogue

Scope: what the `album` kind adds to the data model: the kind and its family, an album and its releases, tracks, credits, works, ratings, the ids of music namespaces, the records a music provider answers, and the resolution of an artist. Ingest of music files, acquisition, the pages and the player are later work (`plans/music-library.plan.md`, batches F2 to F4); the metadata provider plugins are their own batches. The migration is `1789000000880_music.sql`.

## Kind and families

1. `MediaKind::Album`: wire name `album` (`media.type`, `requests."mediaType"`, `user_quotas.kind`, the `album` level of `cleanup_rules.levels`), `has_seasons` false, `families` `[Audio]`, `count_key` `albums`, `completed_stat_key` `albumsFinished`. Every exhaustive `match` on `MediaKind` has an `album` arm. The kind CHECKs list `MediaKind::ALL` (`items.md` rule 39); no family CHECK changes, `audio` is already listed. The test of that rule skips the column `primaryType`, whose vocabulary has an `album` of its own.
2. An album is one `media` row of type `album`: one release group (an album, an EP, a single), with the title, overview, year and poster on `media`. A library accepts the type: `"album"` in `libraries."mediaTypes"`. **A library holds `album` or `book`, never both**: both own `.mp3`, `.m4a` and `.flac`, so `POST` and `PATCH /api/libraries` answer `400 mediaTypes cannot hold both album and book`. A library of albums owns no file yet: `books::owns(Album, _)` is false until the music ingest.
3. `create_shell` for an album inserts one `audio` want (`language` NULL) and no edition and no item, like a book. A release becomes an edition when a provider describes it or a file matches it (rule 9).
4. A media cannot become an album or stop being one: `PUT /api/media/:id` answers `400 An album cannot change type`. An album is not requestable yet (`POST /api/requests` answers `400 mediaType must be one of the following values: movie, series, book`), the TMDB and TVDB imports refuse a kind that is not video, and `create_identified` of an album answers `400`.
5. An album counts in `GET /api/media/counts` and `GET /api/counts` under `albums`, in a user's `albumQuotaLimit` (read and written like `comicQuotaLimit`, `users.md` rule 19), and in the social stats as `albumsFinished` (the generic rule of `media-query.md` rule 20 until the music finish rule, `item-delivery.md` rule 22).
6. Cleanup excludes the album in v1: the CHECK `CK_cleanup_rules_levels` lists `album` (rule 1), but `levels_allowed()` does not, so a rule naming it is a 400, and the built-in recommendations (`cleanup.md` rules 33-36) skip it.

## Model

7. `album_details("mediaId", kind = 'album', "primaryType", "secondaryTypes", "firstReleaseDate", "isCompilation", "targetEditionId", popularity, "originalLanguage", "orphanedAt")` is the release-group row, one per album, `kind` pinned by a composite foreign key (`media-details.md` rule 12). `"primaryType"` is `album`, `single`, `ep`, `broadcast`, `other` or NULL; `"secondaryTypes"` a set of `compilation`, `soundtrack`, `spokenword`, `interview`, `audiobook`, `audio drama`, `live`, `remix`, `dj-mix`, `mixtape/street`, `demo`, `field recording` (the `text[]` CHECK is `<@` that list, empty by default). `"firstReleaseDate"` is a date (a partial one is its first day). `"isCompilation"` is the Various Artists flag: an album with several artists is no person row named "Various Artists". `popularity` is `>= 0` (rule 24). `media_details_json` has a fifth arm for it: every video-only key NULL but `popularity` and `originalLanguage`.
8. The facts of a release are columns of `editions`, beside the ones books added: `country` (two upper-case letters), `status` (`official`, `promotion`, `bootleg`, `pseudo-release`, `withdrawn`, `expunged`, `cancelled`), `media` (`cd`, `vinyl`, `digital`, `cassette`, `other`), `barcode` (8 to 14 digits), `"catalogNumber"`, `"trackCount"` (`>= 0`), `"discCount"` (`>= 1`), `"albumGain"` (dB) and `"albumPeak"` (linear, `> 0`), `"orphanedAt"`. `publisher` is the label, `title` the release title when it differs from the album's, `format` the file format. The MusicBrainz release id is in `edition_external_ids` (rule 15), the release date a `media_release_dates` row of the edition.
9. **Target edition.** A want is `(mediaId, family, language)` and names no edition (`wants-follows.md` rule 1), while a track exists only per edition. Monitoring an album picks a target edition: the release that best fits the library's pressing preferences (country, media, track count, status). It is stored in `album_details."targetEditionId"` (`ON DELETE SET NULL ("targetEditionId")`: a removed edition leaves the album), and only its tracks are created; other releases become editions when files match them. A track want is `items.monitored` on the target edition. The `audio` want of an album is satisfied when every monitored track of the target edition has a part (`wants-follows.md` rule 2 gains this case with the acquisition batch). An import that matches another release better creates that edition and moves the target only while the album has no part yet. The columns exist since `1789000000880`; the picking is the acquisition batch's.
10. A track is an ungrouped item of its edition, `items."number"` NULL: a disc is never an `item_groups` row, because a grouped item is an episode for every series query (`items.md` rule 12) and groups are shared by every edition while the disc count differs per release. `track_details("itemId", "mediaId", "discNumber", "discTitle", position, "trackNumber", label, "recordingMbid", "releaseTrackMbid", isrc, "durationMs", explicit, gain, peak, popularity, "orphanedAt")` holds the facts, one row per item, `FOREIGN KEY ("itemId", "mediaId") REFERENCES items (id, "mediaId") ON DELETE CASCADE`. `"discNumber"` is 1 to 999 (default 1); `position` the rank in the release, disc after disc, from 1 (the sort key); `"trackNumber"` 0 to 9999 and `label` the number as printed (`A1`); the two MBIDs are `uuid`; `isrc` is twelve characters (`^[A-Z]{2}[A-Z0-9]{3}[0-9]{7}$`); `"durationMs"` is positive; `gain` (dB, at most 100 in absolute value) and `peak` (`> 0`) are the track ReplayGain. Indexes on `"mediaId"`, on `"recordingMbid"` and on `isrc` (the lookups of a track already owned through another album).
11. **A metadata miss never deletes.** An album refresh is its own apply path (`metadata/comics/apply.rs` is the pattern), never the video path of `media-write.md` rule 51: it deletes no edition, item or credit. A `not-found` sets `"orphanedAt"` on `album_details` (the album is gone), on `editions` (the release is gone) or on `track_details` (the track is gone from the release); a later hit clears it. Rows named by a merged MusicBrainz id are relinked through the redirect (rule 15). The apply path is the ingest batch's; the three columns and the tests of a 404, a shrunk tracklist and a merged id are theirs.
12. Credits. An album artist is a `media_credits` row of role `artist` (`CK_media_credits_role` gains it), several, ordered by `position`. A track's credits are `item_credits("id", "itemId", "personId", role, position, "creditedName", "joinPhrase", instrument)` with `UNIQUE ("itemId", role, position)`, role `artist`, `composer`, `lyricist`, `performer`, `conductor`, `orchestra` or `ensemble`. `"creditedName"` is the text printed on the release when it differs from the person's name; `"joinPhrase"` follows the credit in a line of artists (`" feat. "`), not trimmed; `instrument` only for a performer. Deleting an item or a person deletes its credits.
13. Classical music. `works("id", mbid, title, "parentWorkId", "composerPersonId")`: a movement is a work with a parent, `mbid` is unique, a deleted parent or composer leaves the work (`ON DELETE SET NULL`), a work is never its own parent. `item_works("itemId", "workId", position)`, `PRIMARY KEY ("itemId", "workId")`, cascades on both. A track plays several works (a medley) and a work is played on many tracks.
14. Ratings and favourites. `item_ratings("userId", "itemId", rating, "createdAt", "updatedAt")`, `PRIMARY KEY ("userId", "itemId")`, `rating` 1 to 5 and no row for an unrated item, cascades on the user and the item. A favourite is the existing item-level `likes` row (`UQ_likes_item`).
15. Namespaces are the core's. `ExternalProvider` gains `musicbrainz` (a UUID, stored in lower case), `isrc` (twelve characters, hyphens dropped, upper case), `spotify` (22 base-62 characters), `deezer` (a positive integer of at most 18 digits) and `fanarttv` (images keyed by the MusicBrainz artist id: a UUID). `musicbrainz` is unique per kind: `UQ_media_external_ids_anchor` covers `("kind", provider, value)` for `tmdb`, `openlibrary` and `musicbrainz`, and `is_unique` is true for it. A MusicBrainz release group is a media id, a release an edition id (`EDITION_NAMESPACES`), an artist a person id; the CHECKs of `media_external_ids`, `edition_external_ids`, `person_external_ids` and `requests."externalId"` require a lower-case UUID for it. `isrc`, `spotify` and `deezer` are sources of `findBy` and are never stored as ids, nor a `preferredProvider`. A merged MusicBrainz id is kept in `media_external_id_aliases("mediaId", kind, provider, value)` (`PRIMARY KEY (kind, provider, value)`, cascade) or `person_external_id_aliases("personId", provider, value)` (`PRIMARY KEY (provider, value)`, cascade), because the id tables hold one id per provider and media. The plugins declare these core namespaces, as an official plugin declares `openlibrary` (`provider-plugins.md` rule 20).
16. A follow of role `artist` joins `author` in `person_follows` (`CK_person_follows_role`); what a follow of an artist does is the acquisition batch's (`wants-follows.md` rules 5-14).
17. `fanarttv` has a compiled default key: `plugins/defaults.rs` holds `(ExternalProvider::FanartTv, "apiKey", option_env!("FLIKS_DEFAULT_FANARTTV_API_KEY"))`, passed as a build argument or environment variable beside the TMDB and TVDB ones (`provider-plugins.md` rules 34-36); empty in a local build.

## Provider records

A music provider is a plugin that declares the kind `album`. `search work children edition person credits findBy` are its capabilities: `search` and `work` serve release groups, `children` lists the releases of a group, `fetch-edition` answers one release with its tracklist, `person` an artist and `credits` the discography of an artist. The checks are `fliks_domain::music::provider` (`album`, `albums`, `release`, `releases`, `edition`, `person`, `credit`), pure functions over the JSON. Every optional key out of its bounds is dropped from the record, not the record. Dates are `YYYY`, `YYYY-MM` or `YYYY-MM-DD`; a partial date is its first day.

18. A `search` hit, a `work` record and an entry of a discography are an album: `externalId` (1 to 128 characters, the MusicBrainz release group id) and `title` (1 to 500 characters after trim, no control character) are required; optional `overview` (at most 10 000 characters, line breaks and tabs allowed), `year` (1 to 9999, else the year of `firstReleaseDate`), `posterUrl` and `sourceUrl` (`https`), `primaryType` and `secondaryTypes` (the lists of rule 7, matched without case; an unknown secondary type is dropped, duplicates collapse), `firstReleaseDate`, `isCompilation` (absent: true when `secondaryTypes` holds `compilation` or an artist is Various Artists), `releaseCount` (`>= 0`), `popularity` (finite, `>= 0`), `mediaType` (`"album"` when present) and `artists`. A record that fails a requirement is a malformed record (`provider-plugins.md` rule 14: `Upstream` 502, counted by the breaker). The search text goes in `query`, with `author` (the artist's name) and `author_id` (its MusicBrainz id) when the query has them.
19. A credit (`artists` of an album, an edition or a track, and the entries of a track's `credits`) is `{name, id?, sortName?, creditedName?, joinPhrase?, role?, instrument?}`: `name` (1 to 255 characters) is required; `id` is a MusicBrainz id (the Various Artists id names no person and is dropped); `joinPhrase` is 1 to 64 characters, kept as sent; `role` is one of rule 12's seven, absent meaning `artist` in `artists` and `performer` in `credits`, an unknown one drops the credit; `instrument` is kept for a performer only. Order is the order of the list.
20. `children` of an album is its releases, one object each: `externalId` and `title` (as rule 18), `country` (two upper-case letters), `status` and `media` (rule 8's lists, matched without case), `releaseDate`, `barcode` (8 to 14 digits), `catalogNumber`, `label`, `trackCount` (0 to 9999), `discCount` (1 to 999). A child that breaks a requirement is dropped and the host warns once per answer with the number dropped and the first reason, never a value; releases that share an `externalId` keep the first.
21. The tracklist is part of the edition record. `fetch-edition` of a `musicbrainz` id answers a release (rule 20's keys) plus `language` (at most 8 characters), `coverUrl` (`https`), `albumGain` and `albumPeak` (rule 8), `artists`, and `tracks`, a list of at most 2000 tracks: `title` (required), `discNumber` (1 to 999, default 1), `discTitle`, `position` (from 1, default the place in the list), `number`, `label`, `recordingId` and `releaseTrackId` (MusicBrainz ids), `isrc` (normalised by `ExternalProvider::Isrc`), `durationMs` (positive), `explicit`, `gain` and `peak` (rule 10), `artists`, `credits` and `works`. A work is `{externalId?, title, parentId?, parentTitle?, composer?}`: a movement names its parent. A track that breaks a requirement is dropped, as is a track whose `position` an earlier one holds; a record whose `tracks` is not a list or holds more than 2000 is malformed.
22. A `person` record keeps the keys of the video persons the host reads (`name`, `biography`, `birthday`, `deathday`, `placeOfBirth`, `avatarUrl`) and adds `sortName`, `disambiguation` and `type` (`person`, `group`, `orchestra`, `choir`, `character`, `other`). Every key is optional: a provider that only has images answers an `avatarUrl`. A partial `birthday` or `deathday` is its first day, so the row's date columns accept it; a record that is not an object is malformed.
23. `credits` of an artist is `{albums: [album]}`: its discography, each entry an album (rule 18); `cast` and `crew` are not read. An entry that breaks a requirement is dropped; more than 10 000 entries, or no `albums` list, is malformed. A provider is told from a video provider by declaring `credits` under `album`.
24. `PluginProvider` runs these checks on every `album` answer: `work` (rule 18), `children` (rule 20), `fetch-edition` of a `musicbrainz` id (rule 21), `person` of a provider that declares `person` under `album` (rule 22) and `credits` of one that declares it under `album` (rule 23). The ingest and the routes run the same functions again on what they read from a snapshot, so a record that does not come from a plugin is held to the same rules. `popularity` is a score of the provider (a listen count), only comparable inside one provider.

## Artists

25. A person with a `musicbrainz` id and no video id resolves to the provider keyed by `musicbrainz`: `GET /api/persons/:id` refreshes it (`persons.md` rule 10) by `fetch_person` of that provider, the record kept whole. `Metadata::person_providers(kind, ns)` lists the available providers of `kind` that describe the people of `ns`: the one keyed by `ns` first, then the others in `metadata.provider_order.<kind>` that declare `person` under `kind` and list `ns` in `findBy` (`MetadataProvider::serves_persons_of`). For `album` and `musicbrainz` they are asked the artist's MusicBrainz id, so an image provider is keyed by it (rule 15).
26. **Image and biography fill.** A MusicBrainz artist has no image. When the first provider's record lacks an `avatarUrl` or a `biography` (empty counts as missing), the next providers of rule 25 are asked in turn and fill only those two keys, never the others, until both are held. A filler that fails is logged and skipped: the artist is refreshed with what the first provider gave. The avatar is then stored like any person's (`persons.md` rule 12).

## Migration

27. `1789000000880_music.sql` is one transaction: the widened kind CHECKs, the MusicBrainz id CHECKs and the anchor index, the alias tables, the credit and follow roles, `album_details` and `media_details_json`, the edition facts, `track_details`, `item_credits`, `works`, `item_works` and `item_ratings`. It backfills nothing.
