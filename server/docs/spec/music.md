# Spec: music in the catalogue

Scope: what the `album` kind adds to the data model: the kind and its family, an album and its releases, tracks, credits, works, ratings, the ids of music namespaces, the records a music provider answers, and the resolution of an artist. The ingest of music files (grouping, tags, identification, covers, the apply path of a provider) is batch F2; acquisition, the pages and the player are later work (`plans/music-library.plan.md`, batches F3 and F4); the metadata provider plugins are their own batches. The migrations are `1789000000880_music.sql` and `1789000000890_music-ingest.sql`.

## Kind and families

1. `MediaKind::Album`: wire name `album` (`media.type`, `requests."mediaType"`, `user_quotas.kind`, the `album` level of `cleanup_rules.levels`), `has_seasons` false, `families` `[Audio]`, `count_key` `albums`, `completed_stat_key` `albumsFinished`. Every exhaustive `match` on `MediaKind` has an `album` arm. The kind CHECKs list `MediaKind::ALL` (`items.md` rule 39); no family CHECK changes, `audio` is already listed. The test of that rule skips the column `primaryType`, whose vocabulary has an `album` of its own.
2. An album is one `media` row of type `album`: one release group (an album, an EP, a single), with the title, overview, year and poster on `media`. A library accepts the type: `"album"` in `libraries."mediaTypes"`. **A library holds `album` or `book`, never both**: both own `.mp3`, `.m4a` and `.flac`, so `POST` and `PATCH /api/libraries` answer `400 mediaTypes cannot hold both album and book`. A library of albums owns the files of `MUSIC_EXTS` (rule 28) and no other.
3. `create_shell` for an album inserts one `audio` want (`language` NULL) and no edition and no item, like a book. A release becomes an edition when a provider describes it or a file matches it (rule 9).
4. A media cannot become an album or stop being one: `PUT /api/media/:id` answers `400 An album cannot change type`. An album is requestable (rule 57) and the TMDB and TVDB imports refuse a kind that is not video. `POST /api/media/import` with `type: album`, a `provider` that serves albums and its release group id as `externalId` creates the album (rule 41), as `create_identified` does for an orphan relink.
5. An album counts in `GET /api/media/counts` and `GET /api/counts` under `albums`, in a user's `albumQuotaLimit` (read and written like `comicQuotaLimit`, `users.md` rule 19), and in the social stats as `albumsFinished` (the generic rule of `media-query.md` rule 20 until the music finish rule, `item-delivery.md` rule 22).
6. Cleanup excludes the album in v1: the CHECK `CK_cleanup_rules_levels` lists `album` (rule 1), but `levels_allowed()` does not, so a rule naming it is a 400, and the built-in recommendations (`cleanup.md` rules 33-36) skip it.

## Model

7. `album_details("mediaId", kind = 'album', "primaryType", "secondaryTypes", "firstReleaseDate", "isCompilation", "targetEditionId", popularity, "originalLanguage", "orphanedAt")` is the release-group row, one per album, `kind` pinned by a composite foreign key (`media-details.md` rule 12). `"primaryType"` is `album`, `single`, `ep`, `broadcast`, `other` or NULL; `"secondaryTypes"` a set of `compilation`, `soundtrack`, `spokenword`, `interview`, `audiobook`, `audio drama`, `live`, `remix`, `dj-mix`, `mixtape/street`, `demo`, `field recording` (the `text[]` CHECK is `<@` that list, empty by default). `"firstReleaseDate"` is a date (a partial one is its first day). `"isCompilation"` is the Various Artists flag: an album with several artists is no person row named "Various Artists". `popularity` is `>= 0` (rule 24). `media_details_json` has a fifth arm for it: every video-only key NULL but `popularity` and `originalLanguage`.
8. The facts of a release are columns of `editions`, beside the ones books added: `country` (two upper-case letters), `status` (`official`, `promotion`, `bootleg`, `pseudo-release`, `withdrawn`, `expunged`, `cancelled`), `media` (`cd`, `vinyl`, `digital`, `cassette`, `other`), `barcode` (8 to 14 digits), `"catalogNumber"`, `"trackCount"` (`>= 0`), `"discCount"` (`>= 1`), `"albumGain"` (dB) and `"albumPeak"` (linear, `> 0`), `"orphanedAt"`. `publisher` is the label, `title` the release title when it differs from the album's, `format` the file format. The MusicBrainz release id is in `edition_external_ids` (rule 15), the release date a `media_release_dates` row of the edition.
9. **Target edition.** A want is `(mediaId, family, language)` and names no edition (`wants-follows.md` rule 1), while a track exists only per edition. Monitoring an album picks a target edition: the release that best fits the library's pressing preferences (country, media, track count, status). It is stored in `album_details."targetEditionId"` (`ON DELETE SET NULL ("targetEditionId")`: a removed edition leaves the album), and only its tracks are created; other releases become editions when files match them. A track want is `items.monitored` on the target edition. The `audio` want of an album is satisfied when every monitored track of the target edition has a part (`wants-follows.md` rule 2 gains this case with the acquisition batch). An import that matches another release better creates that edition and moves the target only while the album has no part yet. The columns exist since `1789000000880`; the picking is rule 51.
10. A track is an ungrouped item of its edition, `items."number"` NULL: a disc is never an `item_groups` row, because a grouped item is an episode for every series query (`items.md` rule 12) and groups are shared by every edition while the disc count differs per release. `track_details("itemId", "mediaId", "discNumber", "discTitle", position, "trackNumber", label, "recordingMbid", "releaseTrackMbid", isrc, "durationMs", explicit, gain, peak, popularity, "orphanedAt")` holds the facts, one row per item, `FOREIGN KEY ("itemId", "mediaId") REFERENCES items (id, "mediaId") ON DELETE CASCADE`. `"discNumber"` is 1 to 999 (default 1); `position` the rank in the release, disc after disc, from 1 (the sort key); `"trackNumber"` 0 to 9999 and `label` the number as printed (`A1`); the two MBIDs are `uuid`; `isrc` is twelve characters (`^[A-Z]{2}[A-Z0-9]{3}[0-9]{7}$`); `"durationMs"` is positive; `gain` (dB, at most 100 in absolute value) and `peak` (`> 0`) are the track ReplayGain. Indexes on `"mediaId"`, on `"recordingMbid"` and on `isrc` (the lookups of a track already owned through another album).
11. **A metadata miss never deletes.** An album refresh is its own apply path (`metadata/comics/apply.rs` is the pattern), never the video path of `media-write.md` rule 51: it deletes no edition, item or credit. A `not-found` sets `"orphanedAt"` on `album_details` (the album is gone), on `editions` (the release is gone) or on `track_details` (the track is gone from the release); a later hit clears it. Rows named by a merged MusicBrainz id are relinked through the redirect (rule 15). The apply path is rules 38 to 41.
12. Credits. An album artist is a `media_credits` row of role `artist` (`CK_media_credits_role` gains it), several, ordered by `position`. A track's credits are `item_credits("id", "itemId", "personId", role, position, "creditedName", "joinPhrase", instrument)` with `UNIQUE ("itemId", role, position)`, role `artist`, `composer`, `lyricist`, `performer`, `conductor`, `orchestra` or `ensemble`. `"creditedName"` is the text printed on the release when it differs from the person's name; `"joinPhrase"` follows the credit in a line of artists (`" feat. "`), not trimmed; `instrument` only for a performer. Deleting an item or a person deletes its credits.
13. Classical music. `works("id", mbid, title, "parentWorkId", "composerPersonId")`: a movement is a work with a parent, `mbid` is unique, a deleted parent or composer leaves the work (`ON DELETE SET NULL`), a work is never its own parent. `item_works("itemId", "workId", position)`, `PRIMARY KEY ("itemId", "workId")`, cascades on both. A track plays several works (a medley) and a work is played on many tracks.
14. Ratings and favourites. `item_ratings("userId", "itemId", rating, "createdAt", "updatedAt")`, `PRIMARY KEY ("userId", "itemId")`, `rating` 1 to 5 and no row for an unrated item, cascades on the user and the item. A favourite is the existing item-level `likes` row (`UQ_likes_item`).
15. Namespaces are the core's. `ExternalProvider` gains `musicbrainz` (a UUID, stored in lower case), `isrc` (twelve characters, hyphens dropped, upper case), `spotify` (22 base-62 characters), `deezer` (a positive integer of at most 18 digits) and `fanarttv` (images keyed by the MusicBrainz artist id: a UUID). `musicbrainz` is unique per kind: `UQ_media_external_ids_anchor` covers `("kind", provider, value)` for `tmdb`, `openlibrary` and `musicbrainz`, and `is_unique` is true for it. A MusicBrainz release group is a media id, a release an edition id (`EDITION_NAMESPACES`), an artist a person id; the CHECKs of `media_external_ids`, `edition_external_ids`, `person_external_ids` and `requests."externalId"` require a lower-case UUID for it. `isrc`, `spotify` and `deezer` are sources of `findBy` and are never stored as ids, nor a `preferredProvider`. A merged MusicBrainz id is kept in `media_external_id_aliases("mediaId", kind, provider, value)` (`PRIMARY KEY (kind, provider, value)`, cascade) or `person_external_id_aliases("personId", provider, value)` (`PRIMARY KEY (provider, value)`, cascade), because the id tables hold one id per provider and media. Every lookup of a MusicBrainz id reads the live id first, then the alias (`external_ids::find` and `holder`, the existing-media mark of a search hit, the ingest short-circuit, rule 33). The plugins declare these core namespaces, as an official plugin declares `openlibrary` (`provider-plugins.md` rule 20).
16. A follow of role `artist` joins `author` in `person_follows` (`CK_person_follows_role`); what a follow of an artist does is the acquisition batch's (`wants-follows.md` rules 5-14).
17. `fanarttv` has a default key in the source: `plugins/defaults.rs` holds `(ExternalProvider::FanartTv, "apiKey", "<key>")` beside the TMDB and TVDB ones (`provider-plugins.md` rules 34-36); a key in the plugin settings overrides it.

## Provider records

A music provider is a plugin that declares the kind `album`. `search work children edition person credits findBy` are its capabilities: `search` and `work` serve release groups, `children` lists the releases of a group, `fetch-edition` answers one release with its tracklist, `person` an artist and `credits` the discography of an artist. The checks are `fliks_domain::music::provider` (`album`, `albums`, `release`, `releases`, `edition`, `person`, `credit`), pure functions over the JSON. Every optional key out of its bounds is dropped from the record, not the record. Dates are `YYYY`, `YYYY-MM` or `YYYY-MM-DD`; a partial date is its first day.

18. A `search` hit, a `work` record and an entry of a discography are an album: `externalId` (1 to 128 characters, the MusicBrainz release group id) and `title` (1 to 500 characters after trim, no control character) are required; optional `overview` (at most 10 000 characters, line breaks and tabs allowed), `year` (1 to 9999, else the year of `firstReleaseDate`), `posterUrl` and `sourceUrl` (`https`), `primaryType` and `secondaryTypes` (the lists of rule 7, matched without case; an unknown secondary type is dropped, duplicates collapse), `firstReleaseDate`, `isCompilation` (absent: true when `secondaryTypes` holds `compilation` or an artist is Various Artists), `releaseCount` (`>= 0`), `popularity` (finite, `>= 0`), `genres` (at most 20 strings of 1 to 64 characters, without control characters, repeats without case collapsed: what fills `media.genres` when no tag gives any), `mediaType` (`"album"` when present) and `artists`. A record that fails a requirement is a malformed record (`provider-plugins.md` rule 14: `Upstream` 502, counted by the breaker). The search text goes in `query`, with `author` (the artist's name) and `author_id` (its MusicBrainz id) when the query has them.
19. A credit (`artists` of an album, an edition or a track, and the entries of a track's `credits`) is `{name, id?, sortName?, creditedName?, joinPhrase?, role?, instrument?}`: `name` (1 to 255 characters) is required; `id` is a MusicBrainz id (the Various Artists id names no person and is dropped); `joinPhrase` is 1 to 64 characters, kept as sent; `role` is one of rule 12's seven, absent meaning `artist` in `artists` and `performer` in `credits`, an unknown one drops the credit; `instrument` is kept for a performer only. Order is the order of the list.
20. `children` of an album is its releases, one object each: `externalId` and `title` (as rule 18), `country` (two upper-case letters), `status` and `media` (rule 8's lists, matched without case), `releaseDate`, `barcode` (8 to 14 digits), `catalogNumber`, `label`, `trackCount` (0 to 9999), `discCount` (1 to 999). A child that breaks a requirement is dropped and the host warns once per answer with the number dropped and the first reason, never a value; releases that share an `externalId` keep the first.
21. The tracklist is part of the edition record. `fetch-edition` of a `musicbrainz` id answers a release (rule 20's keys) plus `language` (at most 8 characters), `coverUrl` (`https`), `albumGain` and `albumPeak` (rule 8), `artists`, and `tracks`, a list of at most 2000 tracks: `title` (required), `discNumber` (1 to 999, default 1), `discTitle`, `position` (from 1, default the place in the list), `number`, `label`, `recordingId` and `releaseTrackId` (MusicBrainz ids), `isrc` (normalised by `ExternalProvider::Isrc`), `durationMs` (positive), `explicit`, `gain` and `peak` (rule 10), `popularity` (finite, `>= 0`, stored in `track_details.popularity`), `artists`, `credits` and `works`. A work is `{externalId?, title, parentId?, parentTitle?, composer?}`: a movement names its parent. A track that breaks a requirement is dropped, as is a track whose `position` an earlier one holds; a record whose `tracks` is not a list or holds more than 2000 is malformed.
22. A `person` record keeps the keys of the video persons the host reads (`name`, `biography`, `birthday`, `deathday`, `placeOfBirth`, `avatarUrl`) and adds `id` (the MusicBrainz id the provider holds the artist under now: another than the one asked is a merge, rule 40), `sortName`, `disambiguation` and `type` (`person`, `group`, `orchestra`, `choir`, `character`, `other`). The host stores `sortName` in `persons."sortName"` (and the person search vector), `disambiguation` in `persons.disambiguation` and `type` in `persons."artistType"`; the person routes do not show them yet. Every key is optional: a provider that only has images answers an `avatarUrl`. A partial `birthday` or `deathday` is its first day, so the row's date columns accept it; a record that is not an object is malformed.
23. `credits` of an artist is `{albums: [album]}`: its discography, each entry an album (rule 18); `cast` and `crew` are not read. An entry that breaks a requirement is dropped; more than 10 000 entries, or no `albums` list, is malformed. A provider is told from a video provider by declaring `credits` under `album`.
24. `PluginProvider` runs these checks on every `album` answer: `work` (rule 18), `children` (rule 20), `fetch-edition` of a `musicbrainz` id (rule 21), `person` of a provider that declares `person` under `album` (rule 22) and `credits` of one that declares it under `album` (rule 23). The ingest and the routes run the same functions again on what they read from a snapshot, so a record that does not come from a plugin is held to the same rules. `popularity` is a score of the provider (a listen count), only comparable inside one provider.

## Artists

25. A person with a `musicbrainz` id and no video id resolves to the provider keyed by `musicbrainz`: `GET /api/persons/:id` refreshes it (`persons.md` rule 10) by `fetch_person` of that provider, the record kept whole. `Metadata::person_providers(kind, ns)` lists the available providers of `kind` that describe the people of `ns`: the one keyed by `ns` first, then the others in `metadata.provider_order.<kind>` that declare `person` under `kind` and list `ns` in `findBy` (`MetadataProvider::serves_persons_of`). For `album` and `musicbrainz` they are asked the artist's MusicBrainz id, so an image provider is keyed by it (rule 15).
26. **Image and biography fill.** A MusicBrainz artist has no image. When the first provider's record lacks an `avatarUrl` or a `biography` (empty counts as missing), the next providers of rule 25 are asked in turn and fill only those two keys, never the others, until both are held. A filler that fails is logged and skipped: the artist is refreshed with what the first provider gave. The avatar is then stored like any person's (`persons.md` rule 12).

## Ingest

28. `MUSIC_EXTS` (`fliks_domain::media`) is `.m4b .m4a .mp3 .flac .ogg .opus .aac .wav .aiff .aif .ape .wv .dsf`, a superset of `AUDIO_EXTS`, which stays the books' own (`book-ingest.md` rule 1). A walk of a library that takes albums keeps these files, four folders deep (`Artist/Album/CD 1/track`), never through a link; where a scan reads albums and books together (a preview with no kind list) the shared extensions stay books. `collect` takes the kinds of the library, not a flag per kind.
29. **Grouping** (`fliks_domain::music::group`, pure). A file belongs to the folder it sits in, the disc folders (`CD 1`, `Disc 2`, `Disk 1`, `Disque 1`, any case, the space optional) taken off: one folder is one album, whatever its tags say. The files at the root of a library folder make one album per key, the release id of their tags, else the album and album artist, normalised. An album is anchored by its folder (`media."folderName"` is that folder, one or several components) when no other album sits in that folder or below it; otherwise its `folderName` is `''` and it owns its files by path. The scan answers one group per album with a file still unlinked: `group_key` `album:<dir>:<key>`, `folderName`, a title and year read from the tags of its first file (else the folder name), the album artist as `guessAuthors`, and the release group id of the tags as a `musicbrainz` file id.
30. **Tags.** The engine probe (`MediaTags`) is read by `TrackTags` (`ingest::music::tags`): artists, album artists and genres are cut again on the separators of the settings `music.artist_separators` (default `;` and ` / `) and `music.genre_separators` (default `;`, `,` and ` / `), JSON arrays of strings, so `AC/DC` and `Simon & Garfunkel` stay whole; the artist ids follow the names only while there are as many ids as names; Various Artists is no credit. A file with no title tag takes the title and number of its name (`07 - Title`). The lyrics (`tags.lyrics`, `tags.syncedLyrics`) are stripped before the probe answer is written to `media_files."streamInfo"`; the lyrics batch reads them from the file again.
31. **Registration** (`ingest::music::register`, the one writer of an album's files, every entry alike: relink, link in place, rescan, transfer). It inserts or updates the `media_files` row of each file (`quality` the extension, `streamInfo` the probe without lyrics, `probeVersion`), then, in one transaction under the item-versions lock (`items.md` rule 23), lays out every file of the album that has no part: its edition, one ungrouped monitored item (`items."number"` NULL), its `track_details` and its part (version 0, position 0). A conflict, one message per file, is a file another media owns or one the engine cannot read; it never stops the others. A file that has a part keeps its track: a changed file refreshes its probe and the duration and ReplayGain of its track, its tags again only on a forced rescan.
32. **Editions and tracks.** The edition of a file is the audio edition holding the `musicbrainz` release id of its tags, else the one no release names; a new edition takes the facts the tags give (label as `publisher`, status, medium, barcode, catalogue number) and the release id. A new track is the next `position` of its edition (the files of one batch go in disc then track order), with `discNumber`, `discTitle`, `trackNumber`, the recording and release track ids, the ISRC, the duration and the ReplayGain of its tags. A track of the edition that holds no part (a file that moved or was replaced) is taken again by the new file with the same recording id, else the same disc and number, so a rename makes no duplicate; the same pairing falls back to the title, case ignored. A file with no release id of an album that has a target edition (rule 51) joins that edition when it pairs with one of its tracks that holds no part, so a scene release with plain ID3 tags fills the target and satisfies the want; a file that pairs with none goes to the edition no release names. A track's credits are its artists (the album artists when the tags name none), composers, conductor and performers; its works are rule 35. The counts and the format of an edition fill when empty. While the album holds no id, `album_details` and the album artists are what the tags say: a compilation (the compilation tag, or no file with an album artist and several first track artists) has its tagged album artists, else the single album artist `Various Artists`, a name-only person (the MusicBrainz id of Various Artists names no person). A compilation a provider describes with no artist credit gets the same album artist.
33. **Identification** (`ingest::music::identify`), at the settle of an album that holds no MusicBrainz id and on a manual pick. The ids of the tags decide alone: the release group, else the release (resolved by the provider's search of its id). Otherwise the provider is searched for artist and album, with no year (the year of the tags is the pressing's, a reissue sits decades after the group's first release): the hits are ranked by the distance of album and artist to the tags (an edition qualifier after the title, `(Deluxe)` or ` - 20th Anniversary`, ignored on either side; a tag year later than the group's first release is no penalty), and each of the three best is looked at: its releases are ordered by the barcode of the tags, then by room for the files (a release with fewer tracks than files comes last), the gap of its year to the tags, the gap of its track count to the files, then the pressing preferences, and the three first are fetched with their tracks. The distance (`fliks_domain::music::matcher`) is the weighted mean of the penalties of the album (the closer of the full titles and the titles without their qualifier), artist, year, medium, disc count, barcode (2, when both name one), label, catalogue number and country, of every pair of tracks assigned by the Hungarian method (title 3, artist 2, length 2, number 1, recording id 10, a length gap of 10 s or more being the full penalty; a shared ISRC adds a perfect entry of weight 4, a different one says nothing; each pair adds its own entry of weight 2 for a track number that differs from the release's, the position naming the release), and of each local track left over (0.9, one entry per track) and each release track missing (0.6 times the share of the release's tracks the files hold, one entry per track). A pair further than 0.5 is no pair: its file is left over. Owning a few tracks of a long release therefore identifies it: the tracks the files hold decide, the tracks they lack weigh in step with how much of the release they cover, which ranks a complete edition above a longer one and a release that holds the tracks above one that does not, while a file the release does not hold keeps the album out of the automatic band (its worst track is 1). The best release applies when its similarity reaches `music.match.auto` (percent, default 90) and its worst pair of tracks is within 0.40 (no file left over); one between `music.match.review` (default 80) and that is offered for review (`Outcome::Review`) and changes nothing; the rest is dropped. Each identification logs one `info` line: the release group and release applied, the candidates offered for review, or no match with the closest release (or none found), with similarity and worst track. The pressing preferences are the settings `music.pressing.countries` and `music.pressing.media` (JSON arrays, best first); a release of a country or medium not listed takes the full penalty. A group already held by another album of the same library (as its id or as an alias of a merged id) absorbs the album instead (rule 40); one held by an album of another library is not taken: the album stays unidentified and a warning is logged. A release id in the tags is looked at only in its own group: a release id alone is resolved by search, and when the group found does not list that release the search by artist and album decides instead; a release id that its tagged group does not list is ignored. An album that no release matches stays an unidentified album built from its tags: it is a row of the library, never a set of unmapped files. `GET /api/media/:id/music/candidates` (`media.edit`, 400 for another kind) runs the same search and answers the releases that pass the review threshold, closest first, `[{group, release, title, artists, year, similarity}]`, applying none; the album is then identified by `POST /api/media/:id/identify` with the chosen `provider` and `externalId`.
34. **Covers**, in order: the embedded picture of the first file that has one (the engine `Cover` job at the post-import queue), then `cover.*`, `folder.*`, `front.*` or `album.*` in the album's folder or its parent (never the library root), at the settle, then the provider's: the poster of the identifying provider's record (the Cover Art Archive), and, when its download fails, the `posterUrl` alone of the next providers of `metadata.provider_order.album` that answer the group (never their title: an image provider answers the artist's name as `title`). A poster is only written when the album has none or the provider wrote the current one, and never over a locked field.
35. **Works and movements.** A track whose tags name a `movement` plays a work of that title (its `musicbrainz_work_id` as `mbid`) whose parent is the work named by `work`; a track with only a `work` plays that work; the composer tag is the work's composer. A provider's `works` list (rule 21) does the same, a movement naming its parent. A work is found by its `mbid`, else by title (case, accents and punctuation aside), parent and composer; two tracks of one work share its row. `GET /api/works?q=&limit=` searches works by title (prefix terms ANDed, 50 by default, 100 at most) and `GET /api/works/:id` reads one: `{id, mbid, title, parent: {id, title}|null, composer: {id, name}|null, trackCount}`, where `trackCount` counts the tracks of the libraries the caller can read that play the work or one of its movements, and a work with none is neither listed nor readable (404).
36. **Rescan.** The rescan of an album walks its own folder and, below it, only the disc folders (rule 29; an album with no folder name only the files it holds) and reads again the files whose size or mtime changed; a file found there that no media owns is registered, and none of this reads another album or the whole library. A manual import never starts a rescan.
37. Every writer of `item_parts` takes the item-versions lock of the media first: `register` (rule 31), the apply path (rule 39), the book and comic layouts, `attach` and `cover_ranges`.

## Apply path

38. A refresh of an album (`metadata::music::refresh`, the job and `POST /api/media/:id/refresh`) is its own path, never the video path of `media-write.md` rule 51. An album that holds no id merges its files alone. Otherwise it reads the release group and its releases, applies them (rule 39), then reads every release the album holds as an edition and the group still lists (the snapshots of 30 days answer most). It deletes no edition, item or credit.
39. **Writing a release group** (`write_album`): under the media's row lock and the versions lock, the fields not locked merged by `FieldOrder` (the provider first, then the files): title, overview, year, poster (rule 34) and genres, the provider's only when no file record has genres; `album_details` (types, first release date, compilation, popularity, `orphanedAt` cleared); the album artists replaced by the provider's, each a person found by its MusicBrainz id (live or alias), else by name; the facts of the releases the album holds as editions (`country`, `status`, `media`, `barcode`, `catalogNumber`, `publisher`, counts), their `orphanedAt` cleared. An edition the album holds whose release the provider no longer lists is flagged `orphanedAt`, unless the provider listed none at all. **Writing a release** (`write_edition`): the edition takes the release's facts, its album ReplayGain and its release date; each track of the edition is matched to a track of the release by release track id, then recording id, then by the distance of the rest (a pair nearer than 0.5), and takes the provider's title, disc, position, number, label, ids, ISRC, popularity, credits (by role, with the printed name and the join phrase) and works, its own duration and ReplayGain kept; a track of the edition that no track of the release matches is flagged `orphanedAt`, a matched one cleared. A track of the release that no file matches is created only when the caller asks (the target edition of a wanted album).
40. **Redirects and aliases.** A `work` record whose `externalId` differs from the id asked is a merge upstream: the album's live id becomes the new one and the old one an alias (`media_external_id_aliases`); when another album already holds the new id, the album is folded into it (`absorb`: its editions, tracks, parts, files and aliases move, its live id becomes an alias of the survivor; its `album_details` is dropped first, the survivor's stay), only when both albums are in the same library: otherwise nothing moves, the album keeps its id and a warning is logged. An alias that becomes a live id again is deleted; an alias is never added for an id another album holds as its live id. An artist whose record answers another `id` than the one asked keeps its row: the new id replaces the old, which becomes a `person_external_id_aliases` row, unless another person holds the new id, when nothing moves. A `404` of the release group flags `album_details."orphanedAt"` and the refresh succeeds; one of a release flags its edition; any other failure fails the refresh and changes nothing: the release group and every release the album holds are read before the first write.
41. `create_identified` and `POST /api/media/import` of an album read the release group, create the media in the library (folder from the naming scopes, `naming.md` rule 25; a taken folder takes the id suffix, 409 when that one is taken too) linked to the canonical id, and apply it (rule 39); a merged id the caller named becomes an alias. `POST /api/media/:id/identify` of an album needs `provider` and `externalId` and answers 409 when another album holds that id; it then runs the identification of rule 33 as a manual pick, applying that group whatever the distance, with the release of it the files match best, so the editions and tracks are matched at once.
## Acquisition

50. **Metadata profile.** `libraries."metadataProfile"` (jsonb object, NULL: the default) is `{primaryTypes, secondaryTypes, statuses}` (`fliks_domain::music::profile`). A release group is wanted when its `primaryType` is in `primaryTypes` (none counts as `other`) and each of its secondary types is in `secondaryTypes` (a studio release has none); a release is wanted when its `status` is in `statuses`, `unknown` standing for a release with none (Lidarr hides those, here they are selectable). The default is `album` and `ep`, no secondary type, `official`. `primaryTypes` is never empty. `GET /api/libraries` answers the effective profile of a library that holds `album`, `PATCH` and `POST` take `metadataProfile` (`null` clears it; any other value is read by `MetadataProfile::parse`, a bad one is a 400).
51. **Target edition.** `metadata::music::target::ensure` picks the target of a monitored album that holds an id and no file: the releases its group lists, those the profile allows (all of them when it allows none), ranked by the profile's status order, the pressing preferences (`music.pressing.countries`, `music.pressing.media`), the distance to the usual track count (the lower middle of the group's counts: the standard edition, not the deluxe one), the earliest date, then the id (`fliks_domain::music::target::pick_target`). The edition is created bare, `write_edition(create_missing = true)` makes its tracks, a track whose recording an item of another media already has a file for is left unmonitored, and `album_details."targetEditionId"` is set. An album that already has files targets the edition holding most of them; the target never moves once set (a file that fits none of its tracks gets an edition of its own, rule 32, never a new target). It runs when an album is created monitored (`POST /api/media/import`, a request, a follow, the Lidarr import) and when one is set monitored and `sweep` repeats it, 50 albums at a time, at each `FollowRefresh` for the albums a provider outage left without.
52. **Album wants.** The `audio` want of an album is satisfied when every monitored track of the target edition has a part, or a track of another edition of the same album with the same recording id has one; an album with no target is satisfied when it has a part (`wants-follows.md` rule 2). A track want is `items.monitored`: all the tracks are monitored for an album wanted as a whole, only some for a track wanted by `music-want-recording`. Approving a request for an album the library already holds picks its target when it has none, then monitors every track of the target edition again (a recording owned through another album stays out), so the request is not satisfied by the tracks monitored before.
53. **Acquisition reads** (`plugins/acquisition/album.rs`). `acquisitionContext` of an album is its target (`creators` are the album artists, `editionIds` the ids of the target edition, `runtimeMinutes` its tracks' duration); with `itemId` it is one track, the unit being `{group: disc, number: track number, label: title}`. `candidates` of kind `album` gives, for each monitored album released by `availableOn` that lacks a wanted track, one target when every track of the target edition is monitored, else one target per wanted track. `releases.match` names an album when the title holds its title and one of its album artists; a discography is `not-available`, an album with no wanted track `on-disk`, one not out yet or a release too fresh `too-fresh`, any other a `grab`. `releases.score` runs the music pipeline (`release.md` rules 71-72) over the audio want's profile.
54. **Library ingest of an album.** `library.ingest` of an album accepts the music files of `MUSIC_EXTS` (anything else is a 400 `is not a music file`), as many as it is given: a partial album or a single track is imported like a whole one, the want being satisfied by the tracks it names. A file is named by the track format of the naming settings (`naming.md` rule 25) from its tags, the multi-disc one when the disc total or the disc is above 1; a file with no track number keeps its own name, and a file whose tags name no disc keeps the `CD n` folder it came in, so two untagged discs never meet in one folder; an unreadable one answers `ERR_RETRY_LATER`. The sidecars of the file (`.lrc`, `.nfo`, images: `companion_file_extensions`) follow it, and the artwork of its folder (`cover`, `folder`, `front`, `back`, `albumart`, `disc`) goes once to the album's folder; nothing existing is replaced. A single-track want imports every music file of the downloaded release: the poller sends them all and each lands on the album's unmonitored tracks, the want being satisfied by the monitored one.
55. **Tag writing** is opt-in: with the setting `music.write_tags` set to `true`, the settle of an album writes the title, album, artists, album artists, track, disc, year and the MusicBrainz recording, track, release and release group ids into each file (lofty). A file whose tags already match is not rewritten, a symlink is skipped (never followed), and every write goes to a copy renamed over the file, so a hard link keeps its bytes; a file that fails is logged and left as it was, and a written file's row takes the new size and mtime.
56. **Follows.** A follow of role `artist` adds the release groups its artist's discography lists (`person-credits` of the music provider, a snapshot of the resource `credits`) that the library's profile allows and whose first release date is new (`wants-follows.md` rule 11), as monitored albums wished with the follow's wants; nothing of the back catalogue is added. A release group the library holds, holds as an alias or has been discovered (`discovered_works`) is not added again.
57. **Requests.** A request of `mediaType` `album` names a MusicBrainz release group by `externalId` and wishes it with `wants` (the `audio` family, with its quality profile), as a book request does (`requests.md` rule 57). Approving it creates the album in the request's library, or adds the want to the album the library holds (403 when that one sits in a library the requester cannot read), then picks the target edition (rule 51).
58. **Host calls for the import lists.** `media.resolveOrCreate` serves `album`: an entry naming a `spotify`, `deezer` or `isrc` id and no `musicbrainz` one is resolved through the music provider's `find-by` first (the plugin never calls MusicBrainz itself). `music.wantRecording {recording: {isrc} | {mbid}, libraryId?}` (scopes `media:create`, `media:read`) answers `{mediaId, itemId}`: an ISRC resolves to its album (created when missing, with only that track monitored, and refused with `ERR_NOT_FOUND` when its release group is outside the metadata profile of the library it would join), an MBID names a track an album of the library already holds (`ERR_NOT_FOUND` otherwise); the track and its album end up monitored. An album created for the call that gets no target edition (the provider failed) is left unmonitored and the call answers the retryable `unavailable`. `music.findRecording {recording}` (scope `media:read`) answers `{mediaId, itemId}` of the track of that recording that a library holds a file for, or null, and creates or monitors nothing: the plugin tells owned tracks from unknown ones with it. `playlist.sync {userId, name, itemIds[]}` (scope `playlists:write`) answers the id of the playlist `name` of that user that this plugin created (`playlists."pluginId"`, unique with the owner and the name), created when missing, holding the items that exist and sit in a library the user can read, in that order (at most 10 000). It never touches a playlist of the user's own, another plugin's, nor a smart one (`ERR_CONFLICT` when a playlist it made became smart); the rows another user added to it stay, only the owner's rows follow the list. A list that changes owner gets a new playlist for the new owner and leaves the old one with the old owner.

## Reads and playback (batch F4)

44. **List info.** Every list that attaches per-kind info (`GET /api/media`, recently added) gives each album `album: {artists, primaryType, secondaryTypes, firstReleaseDate, isCompilation, trackCount, discCount, durationSeconds, playCount}`: `artists` are the first three album artists by position (`{id, name, sortName, avatarUrl, creditedName, joinPhrase}`), the counts are over the tracks of editions the caller can read that hold a file, or, while none does, over the tracks of the target edition (`trackCount` then falls back to the edition's `"trackCount"`), `durationSeconds` sums `"durationMs"`, `playCount` counts the caller's history rows of the album's tracks.
45. **Detail.** `GET /api/media/:id` of an album adds `album: AlbumDetail`: the `album_details` facts, `targetEditionId`, `orphaned`, the album `artists`, the audio `editions` the caller can read (facts of rule 8, `label` is `publisher`, `releaseDate` the earliest date of the edition, `hasFiles`, `orphaned`) and the `tracks` of those editions ordered by edition, disc, position. A track is `{itemId, editionId, mediaFileId (the file of its highest version, first position), hasFile, orphaned, discNumber, discTitle, position, trackNumber, label, title, durationSeconds, explicit, gain, peak, artists, credits, works, favourite, rating, playCount, lastPlayedAt}`: `artists` are the track's `artist` credits, else the album's; `credits` the other roles with `instrument`; `works` the works it plays with their parent and composer; the last four are the caller's.
46. **Tracks.** `GET /api/tracks?libraryId&q&favourite=true&rated=true&sortBy=title|album|added|played|rating&sortOrder=asc|desc&page&limit` lists the tracks that hold a file in readable editions as the track of rule 45 plus `{mediaId, albumTitle, posterUrl}` (page 1, limit 50, at most 200; `q` matches the track or album title). `PUT /api/items/:itemId/rating` with `{rating}` (an integer 1 to 5, else 400) upserts `item_ratings` and answers `{itemId, rating}`; `DELETE` answers 204. Both answer 404 `Item #<id> not found` for an item that is no readable track. A favourite is `POST /api/likes` with `{mediaId: <album>, episodeId: <track itemId>}` (the key `itemId` is an alias of `episodeId`); `DELETE /api/likes` repeats the body. A like of an ungrouped item is accepted for an album only.
47. **Artists and composers.** `GET /api/persons?role=artist|composer` lists the people credited on owned music (artist: album artist or track `artist` credit, a track with no credit of its own counts for its album's artists; composer: track `composer` credit) with `workCount` (= `albumCount`), `albumCount` and `trackCount`; `sortBy=works` orders by albums. `GET /api/persons/:id/discography` refreshes the person like `GET /api/persons/:id`, then answers `{artist: {id, name, sortName, disambiguation, artistType, biography, imageUrl, avatarUrl, following}, albums}` with the readable albums credited to the artist and, when the artist has a MusicBrainz id, the `credits` of the first provider that answers (rule 23) merged by release-group id (live or alias): `{mediaId, externalId, title, year, primaryType, secondaryTypes, posterUrl, owned, monitored, trackCount, ownedTrackCount}`, a provider-only album has `mediaId` null, `owned` false. A provider failure leaves the owned albums. `GET /api/persons/:id` is unchanged.

## Lyrics (batch F5)

61. **Table.** `lyrics(id, "itemId" NOT NULL, "mediaFileId" NULL, kind, lang, sync, source, "sourceRef", "offsetMs", "audioDurationMs", doc, raw, reviewed, preferred, createdAt, updatedAt)`: `itemId` is the track item (`ON DELETE CASCADE`), `mediaFileId` the file the text was found in or timed on (`ON DELETE SET NULL`, so an upgrade that deletes the file keeps the row). `kind` is `main|translation|pronunciation`, `lang` an ISO 639 code or `und` (1 to 8 lower-case letters or digits; a region after `-` or `_` is dropped, so `en-US` is `en`), `sync` `none|line|word`, `source` `embedded|sidecar|user|generated|provider:<namespace>` (a core name or a plugin namespace, `provider-plugins.md` rule 22, at most 93 bytes in all), `offsetMs` in `[-60000, 60000]` (positive: the text shows sooner, as the OpenSubsonic `offset`), `audioDurationMs` the duration of the audio the timing was made on. One row per `(itemId, kind, lang, source)`. `raw` is the text as it was read, `doc` the parsed document (rule 62), `reviewed` is set by a user edit, `preferred` by an explicit pick: at most one row per `(itemId, kind, lang)` (a partial unique index; the pick locks the layer's rows).
62. **Document.** `doc` is `{agents: [{id, role, name?}], lines: [{start?, end?, text, agentId?, cues?: [{start, end, byteStart, byteEnd, agentId?, pitch?, golden?}]}], bg: [line]}`; times are milliseconds, `byteStart..byteEnd` is the cue's range in the UTF-8 bytes of its line's `text`, `pitch` (a MIDI note) is filled by the karaoke melody job (`karaoke.md` rule 19) or an UltraStar import, `golden` (absent when false) marks a golden note of an import. `agents` holds exactly one `main` agent (`main|voice|bg|group` roles); `bg` holds background-vocal lines. `sync` is `word` when any line has cues, `line` when every line has a `start`, else `none` (lines then carry no times). Lines are kept in start order; a line has at most 2000 characters, a document at most 5000 lines (blank ones too) and 200 000 cues in all, enforced while the document is read: a parser fails at the first limit it passes, before a line repeated by several tags is cloned, and a line over the character limit is dropped.
63. **Parsers** (`fliks_domain::lyrics`, pure; each answers the document, the `sync` it found, the `offset`, the `lang` and the title and artist its header names):
    - LRC: `[mm:ss.xx]` and `[mm:ss.xxx]` tags, several tags on one line repeat it, `[offset:]` (ms, as rule 61), `[ar:] [ti:] [al:] [by:] [length:] [lang:]`, other tags skipped, `[bg:text]` a background line of the previous line; a line with `<mm:ss.xx>` word tags is word-synced (a trailing tag closes the last word); a line end is the next line's start. A text with no line tag is plain.
    - SRT (line sync), plain text (no times, a blank line is an empty line), TTML (`itunes:timing`, `p` with `begin`/`end`/`ttm:agent`, `span` words, `ttm:role="x-bg"` background spans; clock values `h:mm:ss.fff`, `mm:ss.fff` and `12.5s`).
    - UltraStar `.txt` (a file with a `#BPM:` header, read through the plain format): `#BPM`, `#GAP` and the notes `:` `*` `F` `R` `G` become word cues, a syllable `~` extends the previous cue, `-` ends a line, `P1`/`P2` become the agents `v1` (main) and `v2` (voice); a cue's `pitch` is `60 + note` (none for `F` and `R`), `*` and `G` set `golden`; `#RELATIVE:YES` is refused.
    - SYLT arrives from the engine probe as LRC text (`tags.syncedLyrics`). Lyricsfile (YAML) is not read: the workspace has no YAML parser (Later).
    - A document that parses to no line is refused. Text is NFC, a trailing blank line trimmed, `\r\n` turned into `\n`.
64. **Discovery** (`lyrics::discover`, after the layout of `register` and `refresh`, and on `POST .../lyrics/fetch`). Sidecars: files of the track's folder with the track's base name (compared without case), then an optional `.<lang>` infix, then an extension of the setting `lyrics.sidecars` (a JSON array in order, default `["ttml","elrc","lrc","srt","txt"]`); each becomes a `kind main` row of source `sidecar` (`sourceRef` the file name). Embedded: the probe tags `syncedLyrics` then `lyrics`, a row of source `embedded`; a text read as plain whose lines carry LRC timestamps is parsed as LRC (an "unsynced" field is sniffed). A file is read when it is a regular file (a link is not followed) of at most 1 MiB; the folder is listed once for all its tracks. Rows of source `sidecar` and `embedded` of the track are replaced by what the file holds now, and those the file no longer holds are deleted; every other source is untouched. A row read again with the same text keeps its `offsetMs` and `reviewed`; a changed text replaces them. A nudge of the offset marks the row `reviewed`.
65. **Carry.** Lyrics belong to the track item, so an upgrade that gives the item a new file keeps them. When a new file takes a track that has rows, each row's `mediaFileId` becomes the new file and its `audioDurationMs` is compared with the file's duration: within 2 s the timing is kept, otherwise a `line` or `word` row drops to `sync none` (times and cues removed, text kept, `offsetMs` 0). A row with no stamp is stamped with the file's duration.
66. **Read.** `GET /api/items/:itemId/lyrics?enhanced=&kind=&lang=` answers `{structuredLyrics: [...]}` in the OpenSubsonic `songLyrics` v2 shape for a track the caller can read (404 for a non-track, 401 without a session; the routes take no stream credential and no other route embeds lyrics, so nothing reaches a public playlist or a party guest through them). An entry is `{id, kind, lang, synced, offset, displayArtist, displayTitle, source, sourceRef, reviewed, preferred, line: [{start?, value}]}`; `enhanced=true` adds `agents` and `cueLine: [{index, agentId?, start, end, value, cue: [{start, end, value, byteStart, byteEnd, pitch?, golden?}]}]`. A plain entry has `synced` false and lines without `start`. Order: `preferred`, then `main` before translation before pronunciation, then the source (`user`, `sidecar`, `embedded`, `provider`, `generated`), then the better `sync`. The list is empty (not 404) when the track has none; `instrumental` is true when a provider said so and no document exists.
67. **Write.** All need `media.edit`.
    - `PUT /api/items/:itemId/lyrics` `{kind?, lang?, format: lrc|elrc|ttml|srt|plain, body, offsetMs?}` or `{kind?, lang?, lines: [{start?, end?, text}], offsetMs?}` (the tap-sync editor) stores a row of source `user`, `reviewed` true, replacing the one of the same `(kind, lang)`; 400 on an unparsable body or a refused document (the body is bound by the 100 kB JSON limit, 413).
    - `PATCH /api/lyrics/:id` `{offsetMs?, preferred?, reviewed?}`; `DELETE /api/lyrics/:id`.
    - `POST /api/items/:itemId/lyrics/fetch` `{force?}` runs discovery and then the providers (rule 68), answering the list of rule 66.
68. **Providers.** A provider plugin that declares the capability `lyrics` under `album` exports `lyrics-provider` (`fetch-lyrics(query) -> result<option<lyrics-hit>, provider-error>`): the query is `{title, artist, album?, durationMs?, recordingId?, isrc?, language?}`, the hit `{format, document, instrumental, lang?, sourceRef?}` with `format` one of rule 67's, `document` empty when `instrumental`. `none` is a miss. The host asks the available providers in the order of the setting `lyrics.provider_order` (a JSON array of namespaces; default registration order) until one gives a document of `sync` `word` or `line`, keeping a plain one as a fallback, at `Priority::Background` (`Interactive` for `POST .../lyrics/fetch`), through the provider's own limiter. A hit is stored as `provider:<namespace>`; a document that fails to parse (inside the plugin call, so it counts) or an unknown format is a malformed record (502 of the provider breaker). `lyrics_lookups("itemId", provider, status, "checkedAt")` (`found|miss|instrumental`) is the negative cache: a track is not asked again of a provider for 30 days after a `miss` or `instrumental`, a hit that could not be stored counting as a `miss` (a `force` ignores it); a provider error caches nothing. A provider is not asked for a track that already holds a synced `main` row of source `user`, `sidecar` or `embedded`, or one of another provider.
69. **Auto-fetch** runs at the end of the settle of an album (`ingest::settle`) when the setting `lyrics.auto_fetch` is not `false`: every track of the media with a file, no synced `main` row and a provider with no lookup within 30 days is queued, and the settle goes on. One queue with two workers serves the whole server (rule 68 per track, `Priority::Background`), and a sweep every 6 hours (the first 5 minutes after boot) queues the same tracks of every album, so a provider error is retried. Nothing is queued while no provider declares `lyrics`. A `generated` row (`karaoke.md` rule 18) is not a synced `main` row for rules 68 and 69.
70. **Write-back** is opt-in (`lyrics.write_back` `true`): a `provider:*` or `user` row that is `line` or `word` synced is written next to its file as `<base>.lrc` (`.elrc` for a word-synced row), `<base>.<lang>.lrc` for a row of a language, never over an existing file (any sidecar extension of rule 64 of that language counts, and the file is created exclusively, so a file of any name or size, or a link, is never replaced); a plain row is written as `.txt`. A language that is not 2 or 3 letters is not written. Tags are not written.
71. `1789000000960_lyrics.sql` creates `lyrics` (an index led by each FK, the unique `(itemId, kind, lang, source)`, `set_updated_at`) and `lyrics_lookups`; `1789000000961_lyrics-source-namespace.sql` widens the `source` check to the namespace grammar and adds the unique `(itemId, kind, lang) WHERE preferred`.
72. **Search targets** (`GET /api/metadata/search/album?target=artist|recording`, `metadata.md` rule 52). A provider declaring `artistSearch` answers `search` with `extra.target = artist` an array of `{externalId, name, sortName?, disambiguation?, artistType?, country?}`; one declaring `recordingSearch`, with `extra.target = recording`, an array of `{externalId, title, durationMs?, artists: [{name, id?}], album: <the album record of rule 18>}`, the recording's release group. A record that fails these checks is dropped, not the answer.
73. **Want a track** (`POST /api/music/want-recording`, `media.create`). Body `{provider, externalId, albumExternalId, libraryId?, folderId?}`: `externalId` is a recording id, `albumExternalId` its release group, both of a provider serving albums (400 otherwise). The album is created like `POST /api/media/import` of an album (rule 41) when no library holds it; a held one is used as it is. The target edition is picked as rule 51 says; its tracks of that recording become monitored and, for an album this call created, every other track of it stops being monitored, so only that track is wanted. 201 `{mediaId, itemId}`, `itemId` null when the target edition has no track of the recording (the album then stays wanted whole); 403 for a library the caller cannot write to as for an import; 409 when the album is already held and the caller cannot read it.
