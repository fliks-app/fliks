# Spec: music in the catalogue

Scope: what the `album` kind adds to the data model: the kind and its family, an album, one MusicBrainz release, tracks, credits, works, the ids of music namespaces, the records a music provider answers, and the resolution of an artist. The ingest of music files (grouping, tags, identification, covers, the apply path of a provider) is batch F2; acquisition, the pages and the player are later work (`plans/music-library.plan.md`, batches F3 and F4); the metadata provider plugins are their own batches. The migration is `1789000000880_music.sql`.

## Kind and families

1. `MediaKind::Album`: wire name `album` (`media.type`, `requests."mediaType"`, `user_quotas.kind`, the `album` level of `cleanup_rules.levels`), `has_seasons` false, `families` `[Audio]`, `count_key` `albums`, `completed_stat_key` `albumsFinished`. Every exhaustive `match` on `MediaKind` has an `album` arm. The kind CHECKs list `MediaKind::ALL` (`items.md` rule 39); no family CHECK changes, `audio` is already listed. The test of that rule skips the column `primaryType`, whose vocabulary has an `album` of its own.
2. An album is one `media` row of type `album`: one MusicBrainz release (a pressing: its tracklist, its country, its label), with the title, overview, year and poster on `media`. The release group it belongs to is `album_details."releaseGroupMbid"` (rule 7); other releases of the group are other albums, never editions of this one (rule 9). A library accepts the type: `"album"` in `libraries."mediaTypes"`. **A library holds `album` or `book`, never both**: both own `.mp3`, `.m4a` and `.flac`, so `POST` and `PATCH /api/libraries` answer `400 mediaTypes cannot hold both album and book`. A library of albums owns the files of `MUSIC_EXTS` (rule 28) and no other.
3. `create_shell` for an album inserts one `audio` want (`language` NULL) and no edition and no item, like a book. The album's edition and tracks are made when a provider describes its release or a file lays it out (rule 9).
4. A media cannot become an album or stop being one: `PUT /api/media/:id` answers `400 An album cannot change type`. An album is requestable (rule 57) and the TMDB and TVDB imports refuse a kind that is not video. `POST /api/media/import` with `type: album`, a `provider` that serves albums and a release id (or a release group id, rule 41) as `externalId` creates the album, as `create_identified` does for an orphan relink.
5. An album counts in `GET /api/media/counts` and `GET /api/counts` under `albums`, in a user's `albumQuotaLimit` (read and written like `comicQuotaLimit`, `users.md` rule 19), and in the social stats as `albumsFinished` (the generic rule of `media-query.md` rule 20 until the music finish rule, `item-delivery.md` rule 22).
6. Cleanup excludes the album in v1: the CHECK `CK_cleanup_rules_levels` lists `album` (rule 1), but `levels_allowed()` does not, so a rule naming it is a 400, and the built-in recommendations (`cleanup.md` rules 33-36) skip it.

## Model

7. `album_details("mediaId", kind = 'album', "primaryType", "secondaryTypes", "firstReleaseDate", "isCompilation", "releaseGroupMbid", popularity, "originalLanguage", "orphanedAt")` is the row of the album's release group, one per album, `kind` pinned by a composite foreign key (`media-details.md` rule 12). `"releaseGroupMbid"` (`uuid`, indexed, not unique: several albums are releases of one group) is NULL while the album holds no provider id. `"primaryType"` is `album`, `single`, `ep`, `broadcast`, `other` or NULL; `"secondaryTypes"` a set of `compilation`, `soundtrack`, `spokenword`, `interview`, `audiobook`, `audio drama`, `live`, `remix`, `dj-mix`, `mixtape/street`, `demo`, `field recording` (the `text[]` CHECK is `<@` that list, empty by default). `"firstReleaseDate"` is a date (a partial one is its first day). `"isCompilation"` is the Various Artists flag: an album with several artists is no person row named "Various Artists". `popularity` is `>= 0` (rule 24). `media_details_json` has a fifth arm for it: every video-only key NULL but `popularity` and `originalLanguage`.
8. The facts of a release are columns of the album's edition, beside the ones books added: `country` (two upper-case letters), `status` (`official`, `promotion`, `bootleg`, `pseudo-release`, `withdrawn`, `expunged`, `cancelled`), `media` (`cd`, `vinyl`, `digital`, `cassette`, `other`), `barcode` (8 to 14 digits), `"catalogNumber"`, `"trackCount"` (`>= 0`), `"discCount"` (`>= 1`), `"albumGain"` (dB) and `"albumPeak"` (linear, `> 0`). `publisher` is the label, `title` the release title when it differs from the album's, `format` the file format, `disambiguation` the release's own (the provider's, NULL when it sends none). The release date is a `media_release_dates` row of the edition.
9. **One album, one release, one edition.** A want is `(mediaId, family, language)` and names no edition (`wants-follows.md` rule 1), while a track exists only per edition: an album holds exactly one audio edition, made with its first track (a provider's tracklist, or the first file laid out) and never shown. The album's MusicBrainz id (`media_external_ids`, rule 15) is its release id; a recording that sits on several releases is a track of each album that holds it, and a file satisfies all of them (rule 52). A track want is `items.monitored`: all the tracks for an album wanted as a whole, only some for a track wanted by rule 73; the unwanted tracks of a release stay in the album, unmonitored, so the page shows the full tracklist. The `audio` want of an album is satisfied when every monitored track has a file (rule 52). The items a file makes are monitored. Nothing is deleted by a refresh (rule 11).
10. A track is an ungrouped item of its edition, `items."number"` NULL: a disc is never an `item_groups` row, because a grouped item is an episode for every series query (`items.md` rule 12) and groups are shared by every edition while the disc count differs per release. `track_details("itemId", "mediaId", "discNumber", "discTitle", position, "trackNumber", label, "recordingMbid", "releaseTrackMbid", isrc, "durationMs", explicit, gain, peak, popularity, "orphanedAt")` holds the facts, one row per item, `FOREIGN KEY ("itemId", "mediaId") REFERENCES items (id, "mediaId") ON DELETE CASCADE`. `"discNumber"` is 1 to 999 (default 1); `position` the rank in the release, disc after disc, from 1 (the sort key); `"trackNumber"` 0 to 9999 and `label` the number as printed (`A1`); the two MBIDs are `uuid`; `isrc` is twelve characters (`^[A-Z]{2}[A-Z0-9]{3}[0-9]{7}$`); `"durationMs"` is positive; `gain` (dB, at most 100 in absolute value) and `peak` (`> 0`) are the track ReplayGain. Indexes on `"mediaId"`, on `"recordingMbid"` and on `isrc` (the lookups of a track already owned through another album).
11. **A metadata miss never deletes.** An album refresh is its own apply path (`metadata/comics/apply.rs` is the pattern), never the video path of `media-write.md` rule 51: it deletes no edition, item or credit. A `not-found` sets `"orphanedAt"` on `album_details` (the release or its group is gone) or on `track_details` (the track is gone from the release); a later hit clears it. Rows named by a merged MusicBrainz id are relinked through the redirect (rule 15). The apply path is rules 38 to 41.
12. Credits. An album artist is a `media_credits` row of role `artist` (`CK_media_credits_role` gains it), several, ordered by `position`. A track's credits are `item_credits("id", "itemId", "personId", role, position, "creditedName", "joinPhrase", instrument)` with `UNIQUE ("itemId", role, position)`, role `artist`, `composer`, `lyricist`, `performer`, `conductor`, `orchestra` or `ensemble`. `"creditedName"` is the text printed on the release when it differs from the person's name; `"joinPhrase"` follows the credit in a line of artists (`" feat. "`), not trimmed; `instrument` only for a performer. Deleting an item or a person deletes its credits.
13. Classical music. `works("id", mbid, title, "parentWorkId", "composerPersonId")`: a movement is a work with a parent, `mbid` is unique, a deleted parent or composer leaves the work (`ON DELETE SET NULL`), a work is never its own parent. `item_works("itemId", "workId", position)`, `PRIMARY KEY ("itemId", "workId")`, cascades on both. A track plays several works (a medley) and a work is played on many tracks.
14. Favourites. A track has no rating. A favourite is the existing item-level `likes` row (`UQ_likes_item`).
15. Namespaces are the core's. `ExternalProvider` gains `musicbrainz` (a UUID, stored in lower case), `isrc` (twelve characters, hyphens dropped, upper case), `spotify` (22 base-62 characters), `deezer` (a positive integer of at most 18 digits) and `fanarttv` (images keyed by the MusicBrainz artist id: a UUID). `musicbrainz` is unique per kind: `UQ_media_external_ids_anchor` covers `("kind", provider, value)` for `tmdb`, `openlibrary` and `musicbrainz`, and `is_unique` is true for it. A MusicBrainz release is a media id (an album, rule 2), its release group `album_details."releaseGroupMbid"`, an artist a person id; the CHECKs of `media_external_ids`, `edition_external_ids`, `person_external_ids` and `requests."externalId"` require a lower-case UUID for it. `isrc`, `spotify` and `deezer` are sources of `findBy` and are never stored as ids, nor a `preferredProvider`. A merged MusicBrainz id is kept in `media_external_id_aliases("mediaId", kind, provider, value)` (`PRIMARY KEY (kind, provider, value)`, cascade) or `person_external_id_aliases("personId", provider, value)` (`PRIMARY KEY (provider, value)`, cascade), because the id tables hold one id per provider and media. Every lookup of a MusicBrainz id reads the live id first, then the alias (`external_ids::find` and `holder`, the existing-media mark of a search hit, the ingest short-circuit, rule 33). The plugins declare these core namespaces, as an official plugin declares `openlibrary` (`provider-plugins.md` rule 20).
16. A follow of role `artist` joins `author` in `person_follows` (`CK_person_follows_role`); what a follow of an artist does is the acquisition batch's (`wants-follows.md` rules 5-14).
17. `fanarttv` has a default key in the source: `plugins/defaults.rs` holds `(ExternalProvider::FanartTv, "apiKey", "<key>")` beside the TMDB and TVDB ones (`provider-plugins.md` rules 34-36); a key in the plugin settings overrides it.

## Provider records

A music provider is a plugin that declares the kind `album`. `search work children edition person credits findBy` are its capabilities: `search` and `work` serve release groups, `children` lists the releases of a group, `fetch-edition` answers one release with its tracklist, `person` an artist and `credits` the discography of an artist. The checks are `fliks_domain::music::provider` (`album`, `albums`, `release`, `releases`, `edition`, `person`, `credit`), pure functions over the JSON. Every optional key out of its bounds is dropped from the record, not the record. Dates are `YYYY`, `YYYY-MM` or `YYYY-MM-DD`; a partial date is its first day.

18. A `search` hit, a `work` record and an entry of a discography are an album: `externalId` (1 to 128 characters, the MusicBrainz release group id) and `title` (1 to 500 characters after trim, no control character) are required; optional `overview` (at most 10 000 characters, line breaks and tabs allowed), `year` (1 to 9999, else the year of `firstReleaseDate`), `posterUrl` and `sourceUrl` (`https`), `primaryType` and `secondaryTypes` (the lists of rule 7, matched without case; an unknown secondary type is dropped, duplicates collapse), `firstReleaseDate`, `isCompilation` (absent: true when `secondaryTypes` holds `compilation` or an artist is Various Artists), `releaseCount` (`>= 0`), `popularity` (finite, `>= 0`), `genres` (at most 20 strings of 1 to 64 characters, without control characters, repeats without case collapsed: what fills `media.genres` when no tag gives any), `mediaType` (`"album"` when present) and `artists`. A record that fails a requirement is a malformed record (`provider-plugins.md` rule 14: `Upstream` 502, counted by the breaker). The search text goes in `query`, with `author` (the artist's name) and `author_id` (its MusicBrainz id) when the query has them.
19. A credit (`artists` of an album, an edition or a track, and the entries of a track's `credits`) is `{name, id?, sortName?, creditedName?, joinPhrase?, role?, instrument?}`: `name` (1 to 255 characters) is required; `id` is a MusicBrainz id (the Various Artists id names no person and is dropped); `joinPhrase` is 1 to 64 characters, kept as sent; `role` is one of rule 12's seven, absent meaning `artist` in `artists` and `performer` in `credits`, an unknown one drops the credit; `instrument` is kept for a performer only. Order is the order of the list.
20. `children` of an album is its releases, one object each: `externalId` and `title` (as rule 18), `disambiguation` (at most 255 characters, optional: a plugin that does not send it leaves the album's chip to the group's), `country` (two upper-case letters), `status` and `media` (rule 8's lists, matched without case), `releaseDate`, `barcode` (8 to 14 digits), `catalogNumber`, `label`, `trackCount` (0 to 9999), `discCount` (1 to 999). A child that breaks a requirement is dropped and the host warns once per answer with the number dropped and the first reason, never a value; releases that share an `externalId` keep the first.
21. The tracklist is part of the edition record. `fetch-edition` of a `musicbrainz` id answers a release (rule 20's keys) plus `releaseGroupId` (the MusicBrainz id of its group, required to create an album from a release id, rule 41), `language` (at most 8 characters), `coverUrl` (`https`), `albumGain` and `albumPeak` (rule 8), `artists`, and `tracks`, a list of at most 2000 tracks: `title` (required), `discNumber` (1 to 999, default 1), `discTitle`, `position` (from 1, default the place in the list), `number`, `label`, `recordingId` and `releaseTrackId` (MusicBrainz ids), `isrc` (normalised by `ExternalProvider::Isrc`), `durationMs` (positive), `explicit`, `gain` and `peak` (rule 10), `popularity` (finite, `>= 0`, stored in `track_details.popularity`), `artists`, `credits` and `works`. A work is `{externalId?, title, parentId?, parentTitle?, composer?}`: a movement names its parent. A track that breaks a requirement is dropped, as is a track whose `position` an earlier one holds; a record whose `tracks` is not a list or holds more than 2000 is malformed.
22. A `person` record keeps the keys of the video persons the host reads (`name`, `biography`, `birthday`, `deathday`, `placeOfBirth`, `avatarUrl`) and adds `id` (the MusicBrainz id the provider holds the artist under now: another than the one asked is a merge, rule 40), `sortName`, `disambiguation` and `type` (`person`, `group`, `orchestra`, `choir`, `character`, `other`). The host stores `sortName` in `persons."sortName"` (and the person search vector), `disambiguation` in `persons.disambiguation` and `type` in `persons."artistType"`; the person routes do not show them yet. Every key is optional: a provider that only has images answers an `avatarUrl`. A partial `birthday` or `deathday` is its first day, so the row's date columns accept it; a record that is not an object is malformed.
23. `credits` of an artist is `{albums: [album]}`: its discography, each entry an album (rule 18); `cast` and `crew` are not read. An entry that breaks a requirement is dropped; more than 10 000 entries, or no `albums` list, is malformed. `topRecordings` (optional): `[{recordingId, title, durationMs?, listenCount?, albumExternalId?, albumTitle?, coverUrl?}]`, at most 10 entries, an entry without a MusicBrainz `recordingId` or a title dropped. A provider is told from a video provider by declaring `credits` under `album`.
24. `PluginProvider` runs these checks on every `album` answer: `work` (rule 18), `children` (rule 20), `fetch-edition` of a `musicbrainz` id (rule 21), `person` of a provider that declares `person` under `album` (rule 22) and `credits` of one that declares it under `album` (rule 23). The ingest and the routes run the same functions again on what they read from a snapshot, so a record that does not come from a plugin is held to the same rules. `popularity` is a score of the provider (a listen count), only comparable inside one provider.

## Artists

25. A person with a `musicbrainz` id and no video id resolves to the provider keyed by `musicbrainz`: `GET /api/persons/:id` refreshes it (`persons.md` rule 10) by `fetch_person` of that provider, the record kept whole. `Metadata::person_providers(kind, ns)` lists the available providers of `kind` that describe the people of `ns`: the one keyed by `ns` first, then the others in `metadata.provider_order.<kind>` that declare `person` under `kind` and list `ns` in `findBy` (`MetadataProvider::serves_persons_of`). For `album` and `musicbrainz` they are asked the artist's MusicBrainz id, so an image provider is keyed by it (rule 15).
26. **Image and biography fill.** A MusicBrainz artist has no image. When the first provider's record lacks an `avatarUrl` or a `biography` (empty counts as missing), the next providers of rule 25 are asked in turn and fill only those two keys, never the others, until both are held. A filler that fails is logged and skipped: the artist is refreshed with what the first provider gave. The avatar is then stored like any person's (`persons.md` rule 12).

## Ingest

28. `MUSIC_EXTS` (`fliks_domain::media`) is `.m4b .m4a .mp3 .flac .ogg .opus .aac .wav .aiff .aif .ape .wv .dsf`, a superset of `AUDIO_EXTS`, which stays the books' own (`book-ingest.md` rule 1). A walk of a library that takes albums keeps these files, four folders deep (`Artist/Album/CD 1/track`), never through a link; where a scan reads albums and books together (a preview with no kind list) the shared extensions stay books. `collect` takes the kinds of the library, not a flag per kind.
29. **Grouping** (`fliks_domain::music::group`, pure). A file belongs to the folder it sits in, the disc folders (`CD 1`, `Disc 2`, `Disk 1`, `Disque 1`, any case, the space optional) taken off: one folder is one album, whatever its tags say. The files at the root of a library folder make one album per key, the release id of their tags, else the album and album artist, normalised. An album is anchored by its folder (`media."folderName"` is that folder, one or several components) when no other album sits in that folder or below it; otherwise its `folderName` is `''` and it owns its files by path. The scan answers one group per album with a file still unlinked: `group_key` `album:<dir>:<key>`, `folderName`, a title and year read from the tags of its first file (else the folder name), the album artist as `guessAuthors`, and the release group id of the tags as a `musicbrainz` file id.
30. **Tags.** The engine probe (`MediaTags`) is read by `TrackTags` (`ingest::music::tags`): artists, album artists and genres are cut again on the separators of the settings `music.artist_separators` (default `;` and ` / `) and `music.genre_separators` (default `;`, `,` and ` / `), JSON arrays of strings, so `AC/DC` and `Simon & Garfunkel` stay whole; the artist ids follow the names only while there are as many ids as names; Various Artists is no credit. A file with no title tag takes the title and number of its name (`07 - Title`). The lyrics (`tags.lyrics`, `tags.syncedLyrics`) are stripped before the probe answer is written to `media_files."streamInfo"`; the lyrics batch reads them from the file again.
31. **Registration** (`ingest::music::register`, the one writer of an album's files, every entry alike: relink, link in place, rescan, transfer). It inserts or updates the `media_files` row of each file (`quality` the extension, `streamInfo` the probe without lyrics, `probeVersion`), then, in one transaction under the item-versions lock (`items.md` rule 23), lays out every file of the album that has no part: its edition, one ungrouped monitored item (`items."number"` NULL), its `track_details` and its part (version 0, position 0). A conflict, one message per file, is a file another media owns or one the engine cannot read; it never stops the others. A file that has a part keeps its track: a changed file refreshes its probe and the duration and ReplayGain of its track, its tags again only on a forced rescan.
32. **The edition and its tracks.** A file joins the album's edition, made with the first file; a new edition takes the facts the tags give (label as `publisher`, status, medium, barcode, catalogue number). A new track is the next `position` of the edition (the files of one batch go in disc then track order), monitored, with `discNumber`, `discTitle`, `trackNumber`, the recording and release track ids, the ISRC, the duration and the ReplayGain of its tags. A track of the edition that holds no part (a file that moved or was replaced, or a track a provider listed) is taken again by the new file in ordered passes over the whole batch: the same recording id, then the same ISRC, then the same disc and number, then the title (case, punctuation and parenthesised parts ignored), so a rename makes no duplicate and a recording id wins over an earlier track of the same number. An id only confirms a pair, never refuses one (a recording has several ISRCs, a merged recording another id). A pairing by disc and number or by title is refused when the file and the track both have a duration and they differ by more than 3 s, so a live take never fills the studio track of the same title. One pairing function serves the layout and the merge of two editions (rule 40). In an album that holds a provider id, a file goes first to the one fileless track an `acquisition_queue` row (not `failed` or `removed`) targets by `itemIds` (`plugins.md` rule 69) when the pairing above leaves that track and exactly one file of the batch unpaired and their durations, when both are known, are within 3 s, otherwise to a free track by the pairing above; the tags never change the disc, disc title or number of a track of such an album (the provider is authoritative). A paired track takes the recording id and the ISRC of the file's tags when it holds none (the tags first when both name one). A track's credits are its artists (the album artists when the tags name none), composers, conductor and performers, each a person by the rule of 39 (a tag carries no MusicBrainz id, so it takes the person of that name, identified or not); its works are rule 35. The counts and the format of the edition fill when empty. While the album holds no id, `album_details` and the album artists are what the tags say: a compilation (the compilation tag, or no file with an album artist and several first track artists) has its tagged album artists, else the single album artist `Various Artists`, a name-only person (the MusicBrainz id of Various Artists names no person). A compilation a provider describes with no artist credit gets the same album artist.
33. **Identification** (`ingest::music::identify`), at the settle of an album that holds no MusicBrainz id and on a manual pick. The ids of the tags decide alone: the release when the provider's release lists it, else the release group, else the release resolved by the provider's search of its id. Otherwise the provider is searched for artist and album, with no year (the year of the tags is the pressing's, a reissue sits decades after the group's first release): the hits are ranked by the distance of album and artist to the tags (an edition qualifier after the title, one holding a word such as deluxe, remaster, expanded, anniversary, edition, bonus or special, as `(Deluxe)` or ` - 20th Anniversary`, ignored on either side; any other qualifier, `(Live)`, a conductor, a volume, stays; a tag year later than the group's first release is no penalty), and each of the three best is looked at: its releases are ordered by the barcode of the tags, then by room for the files (a release with fewer tracks than files comes last), the gap of its year to the tags, the gap of its track count to the files, then the pressing preferences, and the three first are fetched with their tracks. The distance (`fliks_domain::music::matcher`) is the weighted mean of the penalties of the album (the closer of the full titles and the titles without their qualifier), artist, year, medium, disc count, barcode (2, when both name one; compared by digits, without spaces, hyphens or leading zeros), label, catalogue number and country, of every pair of tracks assigned by the Hungarian method (title 3, artist 2, length 2, number 1, recording id 10, a length gap of 10 s or more being the full penalty; a shared ISRC adds a perfect entry of weight 4, a different one says nothing; each pair adds its own entry of weight 2 for a track number that differs from the release's, the position naming the release), and of each local track left over (0.9, one entry per track) and each release track missing (0.6 times the share of the release's tracks the files hold, one entry per track). A pair further than 0.5 is no pair: its file is left over. Owning a few tracks of a long release therefore identifies it: the tracks the files hold decide, the tracks they lack weigh in step with how much of the release they cover, which ranks a complete edition above a longer one and a release that holds the tracks above one that does not, while a file the release does not hold keeps the album out of the automatic band (its worst track is 1). The best release applies when its similarity reaches `music.match.auto` (percent, default 90) and its worst pair of tracks is within 0.40 (no file left over); one between `music.match.review` (default 80) and that is offered for review (`Outcome::Review`) and changes nothing; the rest is dropped. Each identification logs one `info` line: the release group and release applied, the candidates offered for review, or no match with the closest release (or none found), with similarity and worst track. The pressing preferences are the settings `music.pressing.countries` and `music.pressing.media` (JSON arrays, best first); a release of a country or medium not listed takes the full penalty. A release already held by another album of the same library (as its id or as an alias of a merged id) absorbs the album instead (rule 40); one held by an album of another library is not taken: the album stays unidentified and a warning is logged. A release id in the tags is looked at only in its own group: a release id alone is resolved by search, and when the group found does not list that release the search by artist and album decides instead; a release id that its tagged group does not list is ignored. The album becomes the best release (rule 39): its id is the release's, its group `album_details."releaseGroupMbid"`. An album that no release matches stays an unidentified album built from its tags: it is a row of the library, never a set of unmapped files. `GET /api/media/:id/music/candidates` (`media.edit`, 400 for another kind) runs the same search and answers the releases that pass the review threshold, closest first, `[{group, release, title, artists, year, similarity}]`, applying none; the album is then identified by `POST /api/media/:id/identify` with the chosen `provider` and `externalId`.
34. **Covers**, in order: the embedded picture of the first file that has one (the engine `Cover` job at the post-import queue), then `cover.*`, `folder.*`, `front.*` or `album.*` in the album's folder or its parent (never the library root), at the settle, then the provider's: the poster of the identifying provider's record (the Cover Art Archive), and, when its download fails, the `posterUrl` alone of the next providers of `metadata.provider_order.album` that answer the group (never their title: an image provider answers the artist's name as `title`). A poster is only written when the album has none or the provider wrote the current one, and never over a locked field.
35. **Works and movements.** A track whose tags name a `movement` plays a work of that title (its `musicbrainz_work_id` as `mbid`) whose parent is the work named by `work`; a track with only a `work` plays that work; the composer tag is the work's composer. A provider's `works` list (rule 21) does the same, a movement naming its parent. A work is found by its `mbid`, else by title (case, accents and punctuation aside), parent and composer; two tracks of one work share its row. `GET /api/works?q=&limit=` searches works by title (prefix terms ANDed, 50 by default, 100 at most) and `GET /api/works/:id` reads one: `{id, mbid, title, parent: {id, title}|null, composer: {id, name}|null, trackCount}`, where `trackCount` counts the tracks of the libraries the caller can read that play the work or one of its movements, and a work with none is neither listed nor readable (404).
36. **Rescan.** The rescan of an album walks its own folder and, below it, only the disc folders (rule 29; an album with no folder name only the files it holds) and reads again the files whose size or mtime changed (a file the engine cannot read is logged and skipped, the others go on); the sidecar lyrics of every file are read again (rule 64), the embedded ones of the changed files only; a file found there that no media owns is registered, and none of this reads another album or the whole library. A manual import never starts a rescan.
37. Every writer of `item_parts` takes the item-versions lock of the media first: `register` (rule 31), the apply path (rule 39), the book and comic layouts, `attach` and `cover_ranges`.

## Apply path

38. A refresh of an album (`metadata::music::refresh`, the job and `POST /api/media/:id/refresh`) is its own path, never the video path of `media-write.md` rule 51. An album that holds no id merges its files alone. Otherwise it reads the release the album is and the release group the release names by its own `releaseGroupId` (else `album_details."releaseGroupMbid"`), so a release the provider moved to another group follows it, applies them (rule 39), and creates the tracks of the release the album lacks, only for an album that holds no file (a file that fails to pair would otherwise get a bare twin): monitored as the album is. It deletes no edition, item or credit.
39. **Writing a release** (`write_album`): under the media's row lock and the versions lock, the fields not locked merged by `FieldOrder` (the provider first, then the files): title, overview, year, poster (rule 34) and genres, the provider's only when no file record has genres; `album_details` (release group id, types, first release date, compilation, popularity, `orphanedAt` cleared); the album artists replaced by the provider's, each a person found by its MusicBrainz id (live or alias), else by name. The name step keys on `name_key(name)`, lowest id first, and skips a person known only from films or series: a credit without a MusicBrainz id takes the person of its name whether or not that person holds an id, and a credit with an id never takes a person holding another one. A migration merges the persons made before this rule: a person with no id, no alias and no credit outside albums (a book author, a film or series credit) whose name is the name of exactly one person holding a MusicBrainz id is replaced by it in every credit, follow and work. The release (`write_edition`) is written onto the album's edition: its facts (country, status, medium, barcode, catalogue number, label, counts, `disambiguation`), its album ReplayGain and its release date; each track of the edition is matched to a track of the release by release track id, then recording id, then by the distance of the rest (a pair nearer than 0.5), and takes the provider's title, disc, position, number, label, ids, ISRC, popularity, credits (by role, with the printed name and the join phrase) and works, its own duration and ReplayGain kept; a track of the edition that no track of the release matches is flagged `orphanedAt`, a matched one cleared. A track of the release that no file matches is created only when the caller asks (`Create`): monitored as the album is, or unmonitored.
40. **Redirects and aliases.** An `edition` record whose `externalId` differs from the release id asked is a merge upstream: the album's live id becomes the new one and the old one an alias (`media_external_id_aliases`); when another album already holds the new id, the album is folded into it (`absorb`: its edition, tracks, parts, files and aliases move; a filed track that pairs (rule 32) with a fileless track of the survivor stays the track, with its plays, likes, lyrics and playlist entries, and takes that track's provider facts, ReplayGain and length kept from its file, the rows the fileless one held (playlist entries, likes, exclusions, annotations, party rows) moving to it unless it holds the same; one that pairs with a filed track of the survivor adds its files to it as older versions, so the survivor's file keeps playing, its rows moving the same way, its live id becomes an alias of the survivor; its `album_details` is dropped first, the survivor's stay), only when both albums are in the same library: otherwise nothing moves, the album keeps its id and a warning is logged. An alias that becomes a live id again is deleted; an alias is never added for an id another album holds as its live id. An artist whose record answers another `id` than the one asked keeps its row: the new id replaces the old, which becomes a `person_external_id_aliases` row, unless another person holds the new id, when nothing moves. A `404` of the release flags `album_details."orphanedAt"` and the refresh succeeds; one of the release group does the same; any other failure fails the refresh and changes nothing: the release and its group are read before the first write.
41. `create_identified` and `POST /api/media/import` of an album read a release (`metadata::music::resolve`): `externalId` is a release id, or a release group id, in which case `pick_target` (the profile and pressing preferences of the library, rule 51) chooses the release once, so the album is that release from then on. A release names its group by `releaseGroupId` of the provider's `edition` record (an album whose release does not is a malformed record, 502). The media is created in the library (folder from the naming scopes, `naming.md` rule 25; a taken folder takes the id suffix, 409 when that one is taken too) linked to the release id, with its edition and every track of the release, and applied (rule 39); a merged id the caller named becomes an alias. An album of the library that already is that release (its id or an alias), or that is a release of the same group with the same set of recordings, is the answer instead: 409 for an import. A provider that cannot read the release answers 503 and nothing is created. `POST /api/media/import` of an album also takes `wants` (audio wants, each naming a quality profile, replacing the default want that names none) and `monitoredRecordings` (a non-empty list of recording ids of that release: only those tracks are monitored, the others stay in the album unmonitored; a recording the release does not hold undoes the import and answers 404). `POST /api/media/:id/identify` of an album needs `provider` and `externalId` (a release id or a release group id; an album with no file takes, for a group, the release `pick_target` chooses in it for the library, rule 51) and answers 409 when another album holds that id; it stores no id itself: the identification of rule 33 runs as a manual pick, applying the release (the named one or the group's best for the files) whatever the distance and linking its id, so the edition and tracks are matched at once. When nothing applies the album keeps the id it had and the activity ends with `MetadataFailed`; when another album of the library holds the release the album is folded into it and the events carry the survivor.
## Acquisition

50. **Metadata profile.** `libraries."metadataProfile"` (jsonb object, NULL: the default) is `{primaryTypes, secondaryTypes, statuses}` (`fliks_domain::music::profile`). A release group is wanted when its `primaryType` is in `primaryTypes` (none counts as `other`) and each of its secondary types is in `secondaryTypes` (a studio release has none); a release is wanted when its `status` is in `statuses`, `unknown` standing for a release with none (Lidarr hides those, here they are selectable). The default is `album` and `ep`, no secondary type, `official`. `primaryTypes` is never empty. `GET /api/libraries` answers the effective profile of a library that holds `album`, `PATCH` and `POST` take `metadataProfile` (`null` clears it; any other value is read by `MetadataProfile::parse`, a bad one is a 400).
51. **Picking a release.** `fliks_domain::music::target::pick_target` chooses the release of a group when a caller names the group: the releases its group lists, those the profile allows (all of them when it allows none), ranked by the profile's status order, the pressing preferences (`music.pressing.countries`, `music.pressing.media`), the distance to the usual track count (the lower middle of the group's counts: the standard edition, not the deluxe one), the earliest date, then the id; `among` limits it to some release ids. It runs once, at creation: nothing moves an album from its release afterwards.
52. **Album wants and shared recordings.** A track has a file (`track_file(item)`, one SQL function, the one clause of `satisfied_sql`, the acquisition reads and the track rows) when it holds a part, else when a track of another album of the same library holds one for the same recording: the same `recordingMbid`, or the same ISRC only when either track holds no recording id. The shared track stays monitored, so deleting the album that owns the file reopens the want. The `audio` want of an album is satisfied when the album holds tracks and every monitored track has a file (`wants-follows.md` rule 2). Monitoring an album monitors every one of its tracks in one statement (a request approved for a whole album, `PUT /api/media` with `monitored` true). Approving a request for a release the library already holds monitors its tracks again, so the request is not satisfied by the tracks monitored before.
53. **Acquisition reads** (`plugins/acquisition/album.rs`). `acquisitionContext` of an album is the release (`creators` are the album artists, `editionIds` the release id, `runtimeMinutes` its tracks' duration); with `itemId` it is one track, the unit being `{group: disc, number: track number, label: title, isrc, duration-ms}` (`isrc` and `duration-ms` are the track's, none when unknown). `candidates` of kind `album` gives, for each monitored album released by `availableOn` that lacks a wanted track, one target when every track is monitored and one lacks a file (rule 52), else one target per wanted track without a file. `releases.match` names an album when the title holds its title and one of its album artists; a discography is `not-available`, an album with no wanted track `on-disk`, one not out yet or a release too fresh `too-fresh`, any other a `grab`. `releases.score` runs the music pipeline (`release.md` rules 71-72) over the audio want's profile.
54. **Library ingest of an album.** `library.ingest` of an album accepts the music files of `MUSIC_EXTS` (anything else is a 400 `is not a music file`), as many as it is given: a partial album or a single track is imported like a whole one, the want being satisfied by the tracks it names. A file is named by the track format of the naming settings (`naming.md` rule 25) from its tags, the multi-disc one when the disc total or the disc is above 1; a file with no track number keeps its own name, and a file whose tags name no disc keeps the `CD n` folder it came in, so two untagged discs never meet in one folder; an unreadable one answers `ERR_RETRY_LATER`. The sidecars of the file (`.lrc`, `.nfo`, images: `companion_file_extensions`) follow it, and the artwork of its folder (`cover`, `folder`, `front`, `back`, `albumart`, `disc`) goes once to the album's folder; nothing existing is replaced. A single-track want imports every music file of the downloaded release: the poller sends them all and each lands on the album's unmonitored tracks, the want being satisfied by the monitored one. The setting `music.unrequested_tracks` (`import_unmonitored`, the default, or `skip`; any other value is a 400 on `PUT /api/settings`) decides what becomes of the files that land on an unmonitored track: with `skip`, when the album has a monitored track, a file whose tags pair (rule 32) with an unmonitored track and with no monitored one is not placed and not registered, it is listed in the outcome's `skipped`, and a `move` download removes its staged copy with the rest. A file that pairs with no track still becomes a track; in an album that holds a provider id the track is flagged `orphanedAt` and listed apart.
55. **Tag writing** is opt-in: with the setting `music.write_tags` set to `true`, the settle of an album writes the title, album, artists, album artists, track, disc, year and the MusicBrainz recording, track, release and release group ids into each file (lofty). A file whose tags already match is not rewritten, a symlink is skipped (never followed), and every write goes to a copy renamed over the file, so a hard link keeps its bytes; a file that fails is logged and left as it was, and a written file's row takes the new size and mtime.
56. **Follows.** A follow of role `artist` adds the release groups its artist's discography lists (`person-credits` of the music provider, a snapshot of the resource `credits`) that the library's profile allows and whose first release date is new (`wants-follows.md` rule 11), as monitored albums (each the release rule 51 picks) wished with the follow's wants; nothing of the back catalogue is added. A release group the library holds, holds as an alias or has been discovered (`discovered_works`) is not added again.
57. **Requests.** A request of `mediaType` `album` names a MusicBrainz release (or a release group, rule 41) by `externalId` and wishes it with `wants` (the `audio` family, with its quality profile), as a book request does (`requests.md` rule 57). Approving it creates the album in the request's library, or adds the want to the album the library holds (403 when that one sits in a library the requester cannot read), then monitors every track (rule 52). A request may carry `recordings` (`requests.md` rule 52): approval then wants only those tracks of the release (`metadata::music::want::want_many`). A `TrackRow` carries `recordingId`, the MusicBrainz recording id of the track (null when it has none).
58. **Host calls for the import lists.** `media.resolveOrCreate` serves `album`: an entry naming a `spotify`, `deezer` or `isrc` id and no `musicbrainz` one is resolved through the music provider's `find-by` first (the plugin never calls MusicBrainz itself). `music.wantRecording {recording: {isrc} | {mbid}, libraryId?}` (scopes `media:create`, `media:read`) answers `{mediaId, itemId}`: the track of an album of the library that holds the recording (rule 73), else for an ISRC the album it resolves to (created when missing, with only that track monitored, and refused with `ERR_NOT_FOUND` when its release group is outside the metadata profile of the library it would join); an MBID no album of the library holds is `ERR_NOT_FOUND`; the track and its album end up monitored. A provider that cannot read the releases answers the retryable `unavailable` and creates nothing. `music.findRecording {recording}` (scope `media:read`) answers `{mediaId, itemId}` of the track of that recording that a library holds a file for, or null, and creates or monitors nothing: the plugin tells owned tracks from unknown ones with it. `playlist.sync {userId, name, itemIds[]}` (scope `playlists:write`) answers the id of the playlist `name` of that user that this plugin created (`playlists."pluginId"`, unique with the owner and the name), created when missing, holding the items that exist and sit in a library the user can read, in that order (at most 10 000). It never touches a playlist of the user's own, another plugin's, nor a smart one (`ERR_CONFLICT` when a playlist it made became smart); the rows another user added to it stay, only the owner's rows follow the list. A list that changes owner gets a new playlist for the new owner and leaves the old one with the old owner.

## Lyrics (batch F5)

61. **Table.** `lyrics(id, "itemId" NOT NULL, "mediaFileId" NULL, kind, lang, sync, source, "sourceRef", "offsetMs", "audioDurationMs", doc, raw, reviewed, preferred, createdAt, updatedAt)`: `itemId` is the track item (`ON DELETE CASCADE`), `mediaFileId` the file the text was found in or timed on (`ON DELETE SET NULL`, so an upgrade that deletes the file keeps the row). `kind` is `main|translation|pronunciation`, `lang` an ISO 639 code or `und` (1 to 8 lower-case letters or digits; a region after `-` or `_` is dropped, so `en-US` is `en`), `sync` `none|line|word`, `source` `embedded|sidecar|user|generated|provider:<namespace>` (a core name or a plugin namespace, `provider-plugins.md` rule 22, at most 93 bytes in all), `offsetMs` in `[-60000, 60000]` (positive: the text shows sooner, as the OpenSubsonic `offset`), `audioDurationMs` the duration of the audio the timing was made on. One row per `(itemId, kind, lang, source)`. `raw` is the text as it was read, `doc` the parsed document (rule 62), `reviewed` is set by a user edit, `preferred` by an explicit pick: at most one row per `(itemId, kind, lang)` (a partial unique index; the pick locks the layer's rows).
62. **Document.** `doc` is `{agents: [{id, role, name?}], lines: [{start?, end?, text, agentId?, cues?: [{start, end, byteStart, byteEnd, agentId?, pitch?, notes?, golden?}]}], bg: [line]}`; times are milliseconds, `byteStart..byteEnd` is the cue's range in the UTF-8 bytes of its line's `text`, `pitch` (a MIDI note) is the cue's main note and `notes` (`[{start, end, pitch}]`, absent for a single note over the whole cue) every note sung on it, both filled by the karaoke melody job (`karaoke.md` rule 19) or an UltraStar import (a held `~` syllable adds its note; `pitch` is the longest, as in `karaoke.md` rule 19), `golden` (absent when false) marks a golden note of an import. `agents` holds exactly one `main` agent (`main|voice|bg|group` roles); `bg` holds background-vocal lines. `sync` is `word` when any line has cues, `line` when every line has a `start`, else `none` (lines then carry no times). Lines are kept in start order; a line has at most 2000 characters, a document at most 5000 lines (blank ones too) and 200 000 cues in all, enforced while the document is read: a parser fails at the first limit it passes, before a line repeated by several tags is cloned, and a line over the character limit is dropped.
63. **Parsers** (`fliks_domain::lyrics`, pure; each answers the document, the `sync` it found, the `offset`, the `lang` and the title and artist its header names):
    - LRC: `[mm:ss.xx]` and `[mm:ss.xxx]` tags, several tags on one line repeat it, `[offset:]` (ms, as rule 61), `[ar:] [ti:] [al:] [by:] [length:] [lang:]`, other tags skipped, `[bg:text]` a background line of the previous line; a line with `<mm:ss.xx>` word tags is word-synced (a trailing tag closes the last word); a line end is the next line's start. A text with no line tag is plain.
    - SRT (line sync), plain text (no times, a blank line is an empty line), TTML (`itunes:timing`, `p` with `begin`/`end`/`ttm:agent`, `span` words, `ttm:role="x-bg"` background spans; a `ttm:agent` of `type="group"` gets the role `group`, not a duet side; clock values `h:mm:ss.fff`, `mm:ss.fff` and `12.5s`).
    - UltraStar `.txt` (a file with a `#BPM:` header, read through the plain format): `#BPM`, `#GAP` and the notes `:` `*` `F` `R` `G` become word cues, a syllable `~` extends the previous cue and adds its note to the cue's `notes`, `-` ends a line, `P1`/`P2` become the agents `v1` (main) and `v2` (voice), their lines merged in start order (a line both voices sing stays two overlapping copies, each with its own notes); a cue's `pitch` is `60 + note` (none for `F` and `R`), `*` and `G` set `golden`; `#RELATIVE:YES` is refused.
    - SYLT arrives from the engine probe as LRC text (`tags.syncedLyrics`). Lyricsfile (YAML) is not read: the workspace has no YAML parser (Later).
    - A document that parses to no line is refused. Text is NFC, a trailing blank line trimmed, `\r\n` turned into `\n`.
64. **Discovery** (`lyrics::discover`, after the layout of `register` and `refresh`, and on `POST .../lyrics/fetch`). Sidecars: files of the track's folder with the track's base name (compared without case), then an optional `.<lang>` infix, then an extension of the setting `lyrics.sidecars` (a JSON array in order, default `["ttml","elrc","lrc","srt","txt"]`); each becomes a `kind main` row of source `sidecar` (`sourceRef` the file name). Embedded: the probe tags `syncedLyrics` then `lyrics`, a row of source `embedded`; a text read as plain whose lines carry LRC timestamps is parsed as LRC (an "unsynced" field is sniffed). The sidecars are read for the file of the newest version of the track only. A file is read when it is a regular file (a link is not followed) of at most 1 MiB; the folder is listed once for all its tracks. Rows of source `sidecar` and `embedded` of the track are replaced by what the file holds now, and those the file no longer holds are deleted; every other source is untouched. A row read again with the same text keeps its `offsetMs` and `reviewed`; a changed text replaces them.
65. **Carry.** Lyrics belong to the track item, so an upgrade that gives the item a new file keeps them. When a new file takes a track that has rows, each row's `mediaFileId` becomes the new file and its `audioDurationMs` is compared with the file's duration: within 2 s the timing is kept, otherwise a `line` or `word` row drops to `sync none` (times and cues removed, text kept, `offsetMs` 0). A row with no stamp is stamped with the file's duration.
66. **Read.** `GET /api/items/:itemId/lyrics?enhanced=&kind=&lang=` answers `{structuredLyrics: [...]}` in the OpenSubsonic `songLyrics` v2 shape for a track the caller can read (404 for a non-track, 401 without a session; the routes take no stream credential and no other route embeds lyrics, so nothing reaches a public playlist or a party guest through them). An entry is `{id, kind, lang, synced, offset, displayArtist, displayTitle, source, sourceLabel?, sourceRef, reviewed, preferred, line: [{start?, value}]}`, `sourceLabel` the stored `label` of a `provider:` source's namespace; `enhanced=true` adds `agents` and `cueLine: [{index, agentId?, start, end, value, cue: [{start, end, value, byteStart, byteEnd, pitch?, notes?, golden?}]}]`. A plain entry has `synced` false and lines without `start`. Order: `preferred`, then `main` before translation before pronunciation, then the source (`user`, `sidecar`, `embedded`, `provider`, `generated`), then the better `sync`. The list is empty (not 404) when the track has none; `instrumental` is true when a provider said so and no document exists.
67. **Write.** All need `media.edit`.
    - `PUT /api/items/:itemId/lyrics` `{kind?, lang?, format: lrc|elrc|ttml|srt|plain, body, offsetMs?}` or `{kind?, lang?, lines: [{start?, end?, text}], offsetMs?}` (the tap-sync editor) stores a row of source `user`, `reviewed` true, replacing the one of the same `(kind, lang)`; 400 on an unparsable body or a refused document (the body is bound by the 100 kB JSON limit, 413).
    - `PATCH /api/lyrics/:id` `{preferred?, reviewed?}`; `DELETE /api/lyrics/:id`.
    - `POST /api/items/:itemId/lyrics/fetch` `{force?}` runs discovery and then the providers (rule 68), answering the list of rule 66.
68. **Providers.** A provider plugin that declares the capability `lyrics` under `album` exports `lyrics-provider` (`fetch-lyrics(query) -> result<option<lyrics-hit>, provider-error>`): the query is `{title, artist, album?, durationMs?, recordingId?, isrc?, language?}`, the hit `{format, document, instrumental, lang?, sourceRef?}` with `format` one of rule 67's, `document` empty when `instrumental`. `none` is a miss. The host asks the available providers in the order of the setting `lyrics.provider_order` (a JSON array of namespaces; default registration order), less those of `lyrics.disabled_providers` (a JSON array of namespaces), until one gives a document of `sync` `word` or `line`, keeping a plain one as a fallback, at `Priority::Background` (`Interactive` for `POST .../lyrics/fetch`), through the provider's own limiter. A hit is stored as `provider:<namespace>`; a document that fails to parse (inside the plugin call, so it counts) or an unknown format is a malformed record (502 of the provider breaker). `lyrics_lookups("itemId", provider, status, "checkedAt")` (`found|miss|instrumental`) is the negative cache: a track is not asked again of a provider for 30 days after a `miss` or `instrumental`, a hit that could not be stored counting as a `miss` (a `force` ignores it); a provider error caches nothing. A provider is not asked for a track that already holds a synced `main` row of source `user`, `sidecar` or `embedded`, or one of another provider.
69. **Auto-fetch** runs at the end of the settle of an album (`ingest::settle`) when the setting `lyrics.auto_fetch` is not `false`: every track of the media with a file, no synced `main` row and a provider with no lookup within 30 days is queued, and the settle goes on. One queue with two workers serves the whole server (rule 68 per track, `Priority::Background`), and a sweep every 6 hours (the first 5 minutes after boot) queues the same tracks of every album, so a provider error is retried. Nothing is queued while no provider declares `lyrics`. A `generated` row (`karaoke.md` rule 18) is not a synced `main` row for rules 68 and 69.
70. **Write-back** is opt-in (`lyrics.write_back` `true`): a `provider:*` or `user` row that is `line` or `word` synced is written next to its file as `<base>.lrc` (`.elrc` for a word-synced row), `<base>.<lang>.lrc` for a row of a language, never over an existing file (any sidecar extension of rule 64 of that language counts, and the file is created exclusively, so a file of any name or size, or a link, is never replaced); a plain row is written as `.txt`. A language that is not 2 or 3 letters is not written. Tags are not written.
71. `1789000000880_music.sql` creates `lyrics` (an index led by each FK, the unique `(itemId, kind, lang, source)`, the `source` check of the namespace grammar, the unique `(itemId, kind, lang) WHERE preferred`, `set_updated_at`) and `lyrics_lookups`.
72. **Search targets** (`GET /api/metadata/search/album?target=artist|recording`, `metadata.md` rule 52). A provider declaring `artistSearch` answers `search` with `extra.target = artist` an array of `{externalId, name, sortName?, disambiguation?, artistType?, country?}`; one declaring `recordingSearch`, with `extra.target = recording`, an array of `{externalId, title, durationMs?, artists: [{name, id?}], album: <the album record of rule 18>, release?: {externalId, title}}`, the recording's release group and, when the provider names one, the release the hit is on (optional: a hit without it opens the group). A record that fails these checks is dropped, not the answer.
73. **Want a track** (`POST /api/music/want-recording`, `media.create`). Body `{provider, externalId, albumExternalId, libraryId?, folderId?, wants?}` (`wants` as rule 41, applied to an album this call creates): `externalId` is a recording id, `albumExternalId` the release it names or its release group (rule 41), both of a provider serving albums (400 otherwise). The album is looked for in this order: an album of the library (`libraryId` when given, else the caller's readable libraries) that holds the recording, used as it is (the lowest id among those with a file, then monitored ones); else, for a release group, the provider's `recording-releases` kept to the group's releases, then `pick_target` among them (the library's profile, rule 51), else for a release that release; the album is created as `POST /api/media/import` does (rule 41) with every track unmonitored. The track of the recording is then monitored, and the album monitored; the other tracks of a created album stay unmonitored. A recording the release does not hold wants nothing: 404 `No release of the album holds recording(s) <ids>`, the album this call created is deleted. A provider that cannot read the releases answers 503 and creates nothing. 201 `{mediaId, itemId}`; 403 for a library the caller cannot write to as for an import; 409 when the album is already held and the caller cannot read it.
74. **Track picker** (`GET /api/music/albums/tracks?provider&externalId&libraryId`, `media.create`). The tracklist of the release rule 41 would create for that release or release group in that library: `[{recordingId, discNumber, position, number, title, durationMs}]`, empty when no release is allowed or the provider is not MusicBrainz; 400 for a missing parameter or a provider that does not serve albums, 404 for a library the caller cannot read. The add dialog shows it so the tracks to monitor can be picked, then sends them as `monitoredRecordings`.
75. **Album preview** (`GET /api/metadata/{provider}/album/{externalId}`, `media.read`, `metadata.md`). A provider serving albums, else 400; an id the provider refuses is a 400, an upstream 404 a 404. `externalId` is a release group or a release (rule 41). The album hit of rule 18 (of the group), `releaseGroupId`, `artists: [{name, creditedName, joinPhrase, externalId}]`, `release: {externalId, title, disambiguation, country, releaseDate}` (the release itself, or the one rule 51 picks with the default metadata profile, null when none) and its `tracks` as rule 74, `trackCount`, `durationMs` (the sum of the known durations) and `existingMediaId` (`metadata.md` rule 9: the album that is that release, or for a group the lowest album of the readable libraries that is a release of it). A namespace other than musicbrainz answers `tracks: []`.
