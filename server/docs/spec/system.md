# Spec: system

Auth, CASL and error-body rules are in `auth.md` (cited as "auth rule N"); jobs and the `commands` table are in `scheduler.md`.

Scope: the 11 routes of the system controller: health, restart, version, update, stats, backup create/list/restore/download/delete, logs. Specified elsewhere and not repeated: `/api/system/liveness`, `/api/system/events` and `/api/system/activity` (`events-hub.md`), `/api/system/streams*` and `/api/system/transcode-cache*` (`playback-info.md`), `/api/system/qoe/*` (`qoe.md`). The routers own disjoint paths, so no 405 can arise.

## Routes

Every route needs authentication (JWT or API key). The backup routes need `manage:all`; every other route except `version` is satisfied by `settings.access` or `manage:all` (auth rule 25: `Create`, `Read`, `Manage` on `Settings` all come from `settings.access`). Success statuses: 201 for `POST`, 200 otherwise.

| Method path | Auth (extractor + policy) | Request (fields, constraints) | Response (fields, types, nesting) | Errors (status, message/code) | Side effects |
|---|---|---|---|---|---|
| `GET /api/system/health` | `Read Settings` | none | 200 `{version: string, uptimeSeconds: int, database: {name:'PostgreSQL', ok: bool, message?: string}, installedPlugins: int, runningPlugins: int, restartSupervisor: string\|null}` | 401, 403; a database that is down is not an error (rule 4) | none |
| `POST /api/system/restart` | `Manage Settings` | none (body ignored) | 201 `{ok: true, supervisor: string}` | 400 `No process supervisor detected`; 401, 403 | process exits 300 ms later (rule 8) |

Client use: status page, restart, backups page, download link (an `<a href target=_blank>`, so cookie auth only), logs, dashboard, desktop updater. The error interceptor treats `/api/system/health` failures as "server down". Clients show `error.message` of a failed backup/restore, so the tool's last stderr line is part of the contract. The backups page is admin-only: other `settings.access` callers get 403.

## Rules

### A. Auth and shape

1. The restart policy is `settings.access` in effect; the five backup routes (create, list, download, restore, delete) need `manage:all`, because a dump holds every password hash, refresh-token hash and secret setting in clear (settings redaction would be bypassed by anyone with `settings.access`, and a restore can overwrite `users`). `GET /version` needs no permission but is still authenticated, and `scope:'stream'` tokens are refused (401).
2. Every handler's first line is its permission check (auth rule 27). 403 body is `{"message":"Forbidden resource","error":"Forbidden","statusCode":403}`. Error bodies of the 400/404/500 rows are `{statusCode, message, error}` (bootstrap rule 5): 500 `error` = `Internal Server Error`.

### B. Health and restart

3. `health` = `{version, uptimeSeconds: floor(uptime), database, installedPlugins, runningPlugins, restartSupervisor}`. `version` = the product version (rule 9). `uptimeSeconds` = seconds since the `fliks-server` process started.
4. `database`: `SELECT 1`; ok → `{name:'PostgreSQL', ok:true}`, failure → `{name:'PostgreSQL', ok:false, message:<driver error message>}` (`message` absent when ok). With the database down `health` still answers 200, with `ok:false` and both counts `0`.
5. `installedPlugins` = `SELECT count(*) FROM plugin_packages`; `runningPlugins` = same with `WHERE enabled = true` ("enabled", not necessarily reachable; capability health belongs to the plugin).
6. `restartSupervisor` (health) and `supervisor` (restart) come from one detector, first match wins: env `FLIKS_SUPERVISED` non-empty (the string `0` counts) → `'supervisor'`; env `pm_id` non-empty → `'pm2'`; env `INVOCATION_ID` non-empty → `'systemd'`; `/.dockerenv` exists → `'docker'`; none → `null`. Rust appends a fifth rung, env `FLIKS_ENGINE_TOKEN` non-empty (set only by `fliks_engine::supervise`) → `'supervisor'`, so a bare-metal install run under the engine can restart.
7. `POST /restart`: no supervisor → 400 `No process supervisor detected`, no side effect. Else warn `Restart requested (supervisor: <name>)` and answer 201 `{ok:true, supervisor}` before exiting.
8. Exit mechanics: 300 ms after the response (so it flushes), begin the normal graceful shutdown (drain), then exit with code 1 from `fliks-server` itself; the parent `fliks-engine --supervise` respawns it with its backoff (base 1 s). Never signal PID 1 (it is the engine, which must stay up to serve the 502 window and the resolver). The exit code is non-zero so a bare systemd `Restart=on-failure` also restarts.

### C. Version and update

9. `version` is `env!("CARGO_PKG_VERSION")` of the workspace; `.github/release-please-config.json` bumps `server/Cargo.toml` and `Cargo.lock`.
10. `UpdateStatus` = `{currentVersion: string, latestVersion: string|null, updateAvailable: bool, releaseUrl: string|null, releaseNotes: string|null, publishedAt: string|null}`, all keys always present. (a) Env `FLIKS_DISABLE_UPDATE_CHECK` trimmed + lower-cased in `1|true|yes` (read on every call): `latestVersion` and the other nullables `null`, `updateAvailable:false`, no outbound request. (b) A cached success younger than 6 h is returned as is. (c) Else `GET https://api.github.com/repos/<FLIKS_GITHUB_REPO, read once at start; unset → fliks-app/fliks, set-but-empty kept as is>/releases/latest` with `Accept: application/vnd.github+json`, `User-Agent: fliks-server`, 15 s timeout; non-2xx → warn `GitHub release lookup failed: HTTP <status>` and the all-null fallback; transport error or bad JSON → warn `GitHub release lookup error: <message>` and the fallback; `draft:true` → fallback. (d) Success: `latestVersion = tag_name ?? name ?? null` (raw, `v` prefix kept), `releaseUrl = html_url ?? null`, `releaseNotes = body ?? null`, `publishedAt = published_at ?? null`, `updateAvailable = isNewer(latestVersion, currentVersion)`. Only a result with a non-null `latestVersion` is cached (a failure retries on the next call); no single-flight. The fallback is still 200.
11. `isNewer`: parse each side as `v?` prefix stripped, cut at the first `-` or `+`, split on `.`, each part `parseInt(.,10)` (digit prefix: `3rc1` → 3); the side is trimmed and the `v` match is case-insensitive (`V1.2`); any part NaN or an empty side → not newer. Compare part by part, missing parts = 0; only a strictly greater part decides. Equal parts: newer only when `latest` has no `-` suffix and `current` has one (`5.1.0` vs `5.1.0-beta.1`); `+` build metadata is not a suffix. `1.2.x` is unparsable (false).

### D. Stats

12. `movies` and `series` = `SELECT type, count(*) FROM media GROUP BY type` folded through the kind registry, zero-filled (`media-details.md` rule 10), `pendingRequests` = `SELECT count(*) FROM requests WHERE status = 'pending'`.
13. `diskSpace`: libraries `ORDER BY name ASC` (+ `id ASC`) with a non-empty `path`; per library `{path: library.path as stored, label: label ?? name (an empty-string label stays empty), freeSpace: f_bfree * f_bsize, totalSpace: f_blocks * f_bsize}`; on a `statfs` error `freeSpace` and `totalSpace` are `-1` (JSON numbers; same semantics as `libraries.md` rule 6, run on the blocking pool). Absolute paths are exposed here by design: the route needs `settings.access`, the audience allowed to see server paths.

### E. Backups

14. Backup dir = `<data_dir>/backups` (`paths::data_dir()`, `FLIKS_DATA_DIR` with the writable-or-tmp fallback of `config.md`), created on first backup only. `GET /backups` lists regular entries ending `.sql` (case-sensitive), `{filename, size, date: mtime ISO}`, newest first by `date` string then `filename DESC`; a missing dir → `[]`.
15. Name validation (create-by-name routes: download, delete, restore): must match `^[A-Za-z0-9_.-]+\.sql$` (ASCII `\w`, so use the explicit class, not Rust's Unicode `\w`; `$` is end of input only) else 400 `Invalid backup name "<name>"`; then the file must exist in the backup dir else 404 `Backup "<name>" not found`. The check runs before any path join, so no separator or `..` segment can pass (`..sql` is a legal, harmless name).
16. Download: 200, `Content-Disposition: attachment; filename="<name>"`, `Content-Type: application/sql`, `Content-Length`, weak `ETag`, `Last-Modified`, `Accept-Ranges: bytes` and `Cache-Control: public, max-age=0`, `Range` supported; streamed, never buffered. The headers are pinned in the parity scenario.
17. Create: `filename = fliks-backup-<ISO-8601 UTC timestamp with milliseconds, every ':' and '.' replaced by '-'>.sql` (e.g. `fliks-backup-2026-10-16T02-00-00-123Z.sql`); mkdir -p the dir; run `pg_dump <connection args> --clean --if-exists --no-owner --no-privileges` with stdout = the new file, created mode `0600` in a `0700` directory; on any failure close and delete the partial file and rethrow; answer `{filename, size: bytes of the file}`. Log `Creating backup: <filename>` then `Backup created: <filename> (<size> bytes)`. `--clean --if-exists` so the restore works on a populated database; `--no-privileges` because grants name plugin roles a fresh cluster lacks.
18. Tool runner (`pg_dump`, `psql`): spawned without a shell, arguments as a vector, stdout to the file or discarded, stderr captured. `ENOENT` → 500 `<cmd> is not available on this server`; another spawn error → 500 `<cmd> failed: <message>`; exit code ≠ 0 → log `<cmd> exited with <code>: <full stderr>` and 500 with the last non-empty stderr line (else `<cmd> exited with code <n>`). No timeout applies (a dump of a large library takes minutes); the child is killed and the partial file removed when the server shuts down.
19. Connection args and secret: `-h <DB_HOST>`, `-p <DB_PORT>`, `-U <DB_USERNAME>`, `-d <DB_NAME>` (defaults `localhost`, 5432, `fliks`, `fliks`); the password travels in `PGPASSWORD`, never in argv; the child inherits the rest of the environment. All five values come from the one parsed `Config` the pool uses (default password `fliks`).
20. Retention (`Backup` job only, `scheduler.md` rule 22): keep the newest 7 of `list_backups()`, delete the rest, return the removed names; the direct `POST /backup` never prunes. The prune is shared with rule 33, whose `v<version>` dumps get one exception; for `fliks-backup-*` files nothing changes.
21. Delete: rule 15 validation (so a missing file is 404), `rm -f`, log `Backup deleted: <filename>`, answer `{ok:true}`.
22. Restore body: no DTO, the handler reads `body.filename` of a plain object. `{}` → 400 `Invalid backup name "undefined"`; any non-string `filename` (including a one-element string array) → 400 `Invalid backup name "<String(value)>"`; unknown extra keys are ignored. Flow: validate (rule 15), warn `Restoring backup: <filename>`, ensure plugin roles (rule 23), replay (rule 24), log `Backup restored: <filename>`, answer 201 empty. Rust also refuses a restore while the subtitle tick or a plugin job or scheduled call holds a `jobs::Running` claim (`subtitles.md` rule 55, `plugins.md` rules 50, 55), and stops every plugin before the replay and registers them again after it (`plugins.md` rule 44).
23. Plugin roles: read the file line by line; every line matching `^GRANT .+ TO (plugin_[a-z0-9_]{1,56}|fp_[0-9a-f]{8}_[a-z0-9_]{1,51});$` contributes its role (a set); when non-empty run `psql <connection args> -v ON_ERROR_STOP=1 -c "DO $$ BEGIN <one IF NOT EXISTS (SELECT FROM pg_roles WHERE rolname = '<role>') THEN CREATE ROLE \"<role>\" LOGIN; END IF; per role, joined by a space> END $$"`. The role charset is the only guard against SQL injection in that string, so the regex must stay exactly this tight and anchored. A missing role aborts the restore at its first `GRANT`, so the step is needed. The regex has two forms, `plugin_<id>` (dumps from 4.x) and `fp_<database oid>_<id>` (`plugins.md` SQL section), both equally tight and anchored.
24. Replay: `psql <connection args> --single-transaction -v ON_ERROR_STOP=1 -f <abs path>`: one transaction, rolled back on the first error (without `ON_ERROR_STOP` psql would report success after skipping failed statements). The command runs with `-X` (no `~/.psqlrc`) after the file is screened: a line outside a `COPY ... FROM stdin;` block that starts with a backslash (except `\restrict <key>`, `\unrestrict <key>`, `\.`) is 400 `Backup contains psql meta-commands`. The screen is best effort, not a SQL lexer: a meta-command after `;` on the same line, or text inside a multi-line string literal, is not seen; it reuses the pass of rule 23 and guards against a stray file in the directory, not a hostile one (no route uploads a file). Inside the replay's transaction, `public` and every `plugin_*` schema are dropped first and `public` is recreated, so the restore replaces the whole database content (also plugin schemas the dump lacks) and an older dump does not fail on objects a later migration added. The server keeps serving during the replay; `DROP TABLE` waits for in-flight queries and the pool's queries then wait on the lock.
25. Post-restore steps: refuse (409 `A command is running`) while any `commands` row is `queued`/`running` or this process runs a job, and hold a `Restore` claim in the in-process running set for the whole restore (no cron tick, manual trigger or second restore starts meanwhile); after a successful replay run the 4.x ledger adoption and the pending sqlx migrations so an older dump gets the current schema, and mark every `queued`/`running` row failed (a scheduled backup dumps its own `running` row). A migration failure (a dump newer than this binary) answers 500 with that error.

### F. Logs

26. Ring buffer: capacity 2 000 entries `{timestamp: ISO-8601 ms Z at push, level, context, message}`, oldest dropped first; `level` in `log|warn|error|debug`; `error(message, trace, context)` stores `message + "\n" + trace` when a trace is given. Memory only, lost on restart.
27. `GET /logs`: copy the buffer, filter `level` (exact, case-sensitive; an unknown value → `[]`; empty string = no filter), filter `q` (lower-cased substring of `message` or `context`; empty = none), reverse (newest first), then cut to `limit`: absent or empty → 200; else `parseInt(limit, 10)` (leading whitespace and sign, digit prefix); a result that is NaN, 0 or negative means no cut (up to 2 000). A `limit` that is not a canonical integer → 400 (shared with `scheduler.md` rule 20); `0` and negative integers keep "no cut".
28. Feed, `tracing`: a subscriber layer of `fliks-server` pushes every event at ERROR/WARN/INFO/DEBUG (`error`/`warn`/`log`/`debug`; TRACE is dropped) with `context` = the event target without the `fliks_server::` prefix and `message` = the `message` field followed by ` key=value` for each other field. Debug events exist only when `RUST_LOG` enables them (default INFO). The layer is installed beside the stderr writer of `main.rs`, which keeps printing.
29. Output of child processes (plugins) is not in the ring; it goes to the container's stdout/stderr, inherited through `fliks_engine::supervise`.
30. Hygiene: the ring is readable with `settings.access` and mirrored on stderr, so no entry may carry a credential. HTTP trace events log the method and path only, never the query string (stream tokens and API keys travel there); an error from `reqwest` is logged with its URL removed (`reqwest::Error::without_url`); the `Authorization`, cookie and `PGPASSWORD` values are never fields.

31. A `pg_dump` newer than the server major, or a server newer than the client tools, makes `pg_dump` abort; the Dockerfile installs PGDG `postgresql-client` and the tool's message surfaces as the 500 text.

### G. Pre-migration backup

31. At boot (`serve` and the `migrate` subcommand), before any migration runs, the server checks for pending migrations: some embedded sqlx migration is absent from `_sqlx_migrations` (or, on a 4.x database not yet adopted, from the TypeORM ledger). With none pending, or on an empty database (no table in `public`), nothing is dumped. Tests and `restore` call `db::migrate` directly and never dump.
32. A pending set triggers the rule 17 dump (same tool runner, arguments, modes) into `<data_dir>/backups/pre-migration/` as `fliks-pre-migration-v<version>-<ISO timestamp as rule 17>.sql`, `<version>` being the newest applied migration version (the newest TypeORM ledger timestamp before adoption, `0` when none). The folder is separate, so the rule 14 listing, the download and restore routes and the rule 20 prune never see these files. Log `Creating backup: <filename>` and `Backup created: <filename> (<size> bytes)`, with the folder path.
33. Retention: after a successful dump keep the newest 3 files of the folder and delete the rest (rule 20 logic), except the oldest file carrying the same `v<version>` as the newest file, which is never deleted: a migration that keeps failing writes a dump per restart, and the oldest of them is the only one holding the database as it was before the pending chain began (later ones may hold a half-migrated state). The folder therefore holds up to 4 files; dumps of older versions are pruned as usual, and the exception moves on once a later version is dumped.
34. A failed dump (rule 18 errors, including a missing `pg_dump`) aborts the boot with `pre-migration backup failed, migrations not applied: <message> (set FLIKS_SKIP_PRE_MIGRATION_BACKUP=1 to skip it)`; no migration runs and the partial file is removed.
35. Escape hatch: env `FLIKS_SKIP_PRE_MIGRATION_BACKUP` in `1|true|yes` (trimmed, case-insensitive) skips the step with a warning. It is an env var, not a setting, because it is read before the database is migrated, so the `settings` table may not exist or be readable. The parity runner sets it (no `pg_dump` guaranteed on the runner).

## SQL

- `SELECT 1` (health).
- `SELECT count(*) FROM plugin_packages` and `... WHERE enabled = true`.
- `SELECT count(*)::int FROM media WHERE type = 'movie'` (and `'series'`); `SELECT count(*)::int FROM requests WHERE status = 'pending'`.
- `SELECT id, name, label, path FROM libraries WHERE path IS NOT NULL AND path <> '' ORDER BY name ASC, id ASC`.
- Restore guard and sweep: `SELECT EXISTS (SELECT 1 FROM commands WHERE status IN ('running','queued'))`; `UPDATE commands SET status = 'failed', "endedOn" = now() WHERE status IN ('running','queued')`.
- External: `pg_dump`, `psql` (rules 17-24).

## Events

None emitted or consumed. (`restart` and `restore` send no SSE event; connected clients see the stream drop on restart and reconnect.)

## Settings keys

None in the `settings` table. Environment (`config.md`): `DB_HOST`, `DB_PORT`, `DB_USERNAME`, `DB_PASSWORD`, `DB_NAME` (rule 19), `FLIKS_DATA_DIR` / `FLIKS_IMAGES_DIR` (rule 14), `FLIKS_GITHUB_REPO`, `FLIKS_DISABLE_UPDATE_CHECK` (rule 10), `FLIKS_SKIP_PRE_MIGRATION_BACKUP` (rule 35), `FLIKS_SUPERVISED`, `pm_id`, `INVOCATION_ID`, `FLIKS_ENGINE_TOKEN` (rule 6), `RUST_LOG` (rule 28). `FLIKS_SUPERVISED` is set by the Windows tray `ServerManager`.

## Jobs/timers

- Backup 02:00 and the retention prune: `scheduler.md` rules 22, 26 (the file operations of this spec).
- Update-check cache TTL 6 h (in memory, lost on restart); restart delay 300 ms; log ring 2 000 entries. No other timer.

## Vectors/parity

No `server/fixtures` set: the Rust unit tests in `crates/server/src/system/{update,backup,supervisor}.rs` cover `isNewer` (rule 11: `1.2.3` vs `v1.2.4`, `1.10.0` vs `1.9.9`, `4.5.0-rc.1`, `5.1.0` vs `5.1.0-beta.1`, `4.5`, `4.5.0.1`, `1.2.x`, empty, `3rc1`), the backup-name table (rule 15 accept/reject incl. `é.sql`, `a/b.sql`, `..sql`, `a.sql\n`, `a.SQL`) and the supervisor detector (rule 6: each env/`/.dockerenv` combination, in order).

Backup and restore MUST run on a scratch database, never the dev or parity one: the integration test `server/crates/server/tests/it/backup_restore.rs` creates a random-named database from the migrated template, points `DB_NAME` and `FLIKS_DATA_DIR=/tmp/fliks-parity/data-<random>` at it and refuses to run when `DB_NAME` is `fliks`; it is skipped when `pg_dump`/`psql` are absent. Cases: create (name pattern, non-empty file, size matches the answer, file contains `CREATE TABLE`); round trip (insert a marker row in `settings`, backup, delete it, restore, row back); corrupt file (a statement error → 500 with the last stderr line, database unchanged: single transaction); restore of a dump with `GRANT ... TO plugin_x` on a cluster without the role (rule 23); pre-migration (rules 31-35, `backup.rs` and `db/migrate.rs` tests): a database behind by one migration gets a dump named `fliks-pre-migration-v<last>-<stamp>.sql` that is not listed by `GET /backups`; four runs against four behind-by-one databases keep 3 files; an up-to-date and an empty database dump nothing; an unreachable `pg_dump` leaves the ledger untouched and returns the rule 34 error; the skip variable bypasses it; a file with a `\!` meta-command or `\i` outside a COPY block → 400 (`\restrict`/`\unrestrict` lines accepted); restore while a `running` row exists → 409 and, when idle, no `running` row left after it; an older dump (taken before the last migration) restores into the newer database, a stale `plugin_*` schema is gone, and the ledger is at the current count; delete (404 on the second call); download bytes equal the file and a `Range` request answers 206; list order (newest first, ties by name); backup file mode `0600`. Never run against `docker-compose.yml`'s database.

Parity scenarios (`server/parity/scenarios/system/`): `health` (ignore `$..uptimeSeconds`; `restartSupervisor` pinned to the runner's env), `health-requires-auth` (401), `health-forbidden` (`noread` actor, no `settings.access`: 403), `version`, `version-requires-auth` (401), `version-any-user` (`readonly` 200), `update-disabled` (runner sets `FLIKS_DISABLE_UPDATE_CHECK=1`: all-null body, no network), `stats` (seed counts, `diskSpace` over `/tmp/fliks-parity/media`, ignore `freeSpace`/`totalSpace`), `logs-filters` (`level`, `q`, `limit`, unknown level `[]`), `logs-limit-malformed` (400), `backups-empty` (`[]`), `backup-create` (ignore `filename`, `size`), `backups-list-after-create`, `backup-download` (headers pinned: `expect.headers`), `backup-download-bad-name` (400), `backup-download-missing` (404), `backup-delete` (200, then 404), `restore-bad-body` (`{}` → 400 `Invalid backup name "undefined"`), `restore-array-filename` (`{filename:["a.sql"]}` → 400), `restore-missing` (404), `restart-unsupervised` (400 `No process supervisor detected`; the runner is not in a container and sets no supervisor env). The success path of `restart` is a topology test, not a parity scenario: under `fliks-engine --supervise ... -- fliks-server`, `POST /api/system/restart` answers 201 and a new `fliks-server` pid serves `/api/system/liveness` within 10 s. Backup/restore parity scenarios run only against the scratch database above.

## Open questions

- Does `restart` stay at `settings.access` (rule 8) or move to `manage:all` with the backups? Nothing in the specs argues for a change, so it stays until answered.
- Restart under the engine (rules 6, 8): the fifth detector rung reports `'supervisor'` instead of `null` on bare-metal engine installs, and Docker keeps `'docker'` because `/.dockerenv` is checked first. Confirm exiting `fliks-server` (not PID 1) is the intended restart in Docker, and that macOS (no `FLIKS_SUPERVISED`) should also report `'supervisor'`.
- `uptimeSeconds` is the `fliks-server` process uptime. Acceptable?
- After a restore, in-memory state (cached ACL / settings reads, engine config revision, SSE connections of deleted users) is stale: restart the process after a restore (`exit(1)` as in rule 8) instead of keeping the server running? It would change the restore UX (a 60 s outage) but remove a class of stale-cache bugs.
