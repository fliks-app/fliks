## Rules

### A. Auth and shape

1. The restart, backup, restore and delete policies are all `settings.access` in effect; `GET /version` has `() => true` (no permission, but still authenticated, `scope:'stream'` tokens refused, F8). Backups hold password hashes and every secret of the `settings` table, so the F5 redaction is bypassed by anyone with `settings.access`: F?1. `[ts:src/modules/scheduler/system.controller.ts:73]`–`[ts:src/modules/scheduler/system.controller.ts:216]`
2. Every handler's first line is its permission check (auth rule 27). 403 body is Nest's `{"message":"Forbidden resource","error":"Forbidden","statusCode":403}`. Error bodies of the 400/404/500 rows are Nest's `{statusCode, message, error}` (bootstrap rule 5): 500 `error` = `Internal Server Error`. `[ts:src/modules/scheduler/backup.service.ts:140]`–`[ts:src/modules/scheduler/backup.service.ts:149]`

### B. Health and restart

3. `health` = `{version, uptimeSeconds: floor(uptime), database, installedPlugins, runningPlugins, restartSupervisor}`. `version` = the product version (rule 9). `uptimeSeconds` = seconds since the `fliks-server` process started (Nest reported its own process; both reset on a restart, a Nest-only restart no longer resets it) `[assumed]`. `[ts:src/modules/scheduler/system.controller.ts:39]`–`[ts:src/modules/scheduler/system.controller.ts:49]`, `[ts:src/modules/scheduler/system.controller.ts:92]`–`[ts:src/modules/scheduler/system.controller.ts:103]`
4. `database`: `SELECT 1`; ok → `{name:'PostgreSQL', ok:true}`, failure → `{name:'PostgreSQL', ok:false, message:<driver error message>}` (`message` absent when ok). Nest then still awaits the plugin counts, which throw on a dead database, so `health` answers 500; Rust answers 200 with `ok:false` and both counts `0` (C?7). `[ts:src/modules/scheduler/system.controller.ts:133]`–`[ts:src/modules/scheduler/system.controller.ts:140]`
5. `installedPlugins` = `SELECT count(*) FROM plugin_packages`; `runningPlugins` = same with `WHERE enabled = true` ("enabled", not necessarily reachable; capability health belongs to the plugin). `[ts:src/modules/scheduler/system.controller.ts:97]`–`[ts:src/modules/scheduler/system.controller.ts:100]`
6. `restartSupervisor` (health) and `supervisor` (restart) come from one detector, first match wins: env `FLIKS_SUPERVISED` non-empty (the string `0` counts) → `'supervisor'`; env `pm_id` non-empty → `'pm2'`; env `INVOCATION_ID` non-empty → `'systemd'`; `/.dockerenv` exists → `'docker'`; none → `null`. Rust appends a fifth rung, env `FLIKS_ENGINE_TOKEN` non-empty (set only by `fliks_engine::supervise`) → `'supervisor'`, so a bare-metal install run under the engine can restart (Nest reported `null` and refused) `[new]`, Q2. `[ts:src/modules/scheduler/system.controller.ts:51]`–`[ts:src/modules/scheduler/system.controller.ts:57]`
7. `POST /restart`: no supervisor → 400 `No process supervisor detected`, no side effect. Else warn `Restart requested (supervisor: <name>)` and answer 201 `{ok:true, supervisor}` before exiting. `[ts:src/modules/scheduler/system.controller.ts:107]`–`[ts:src/modules/scheduler/system.controller.ts:118]`
8. Exit mechanics: Nest sets exit code 1 and sends `SIGTERM` after 300 ms (so the response flushes), to PID 1 when the supervisor is `docker` (the `npm run` wrapper would otherwise outlive it) else to itself. Rust, 300 ms after the response: begin the normal graceful shutdown (stop the Nest child through the supervise task, drain), then exit with code 1 from `fliks-server` itself; the parent `fliks-engine --supervise` respawns it with its backoff (base 1 s), `fliks-server` then respawns Nest. Never signal PID 1 (it is the engine, which must stay up to serve the 502 window and the resolver). The exit code is non-zero so a bare systemd `Restart=on-failure` also restarts. `[ts:src/modules/scheduler/system.controller.ts:114]`–`[ts:src/modules/scheduler/system.controller.ts:116]` `[assumed]` for the Rust half (plan §4.3 "supervised restart").

### C. Version and update

9. `version` = `CURRENT_FLIKS_VERSION`, read from the nearest `package.json` (4.5.0 today). Rust: `env!("CARGO_PKG_VERSION")` of the workspace; `.github/release-please-config.json` already bumps `server/Cargo.toml` and `Cargo.lock` with `backend/package.json`, so the three stay equal; a unit test compares them. `[ts:src/modules/plugins/plugin-version.ts:21]`–`[ts:src/modules/plugins/plugin-version.ts:27]`, `[ts:src/modules/scheduler/system.controller.ts:31]`
10. `UpdateStatus` = `{currentVersion: string, latestVersion: string|null, updateAvailable: bool, releaseUrl: string|null, releaseNotes: string|null, publishedAt: string|null}`, all keys always present. (a) Env `FLIKS_DISABLE_UPDATE_CHECK` trimmed + lower-cased in `1|true|yes` (read on every call): `latestVersion` and the other nullables `null`, `updateAvailable:false`, no outbound request. (b) A cached success younger than 6 h is returned as is. (c) Else `GET https://api.github.com/repos/<FLIKS_GITHUB_REPO or fliks-app/fliks>/releases/latest` with `Accept: application/vnd.github+json`, `User-Agent: fliks-server`, 15 s timeout; non-2xx → warn `GitHub release lookup failed: HTTP <status>` and the all-null fallback; transport error or bad JSON → warn `GitHub release lookup error: <message>` and the fallback; `draft:true` → fallback. (d) Success: `latestVersion = tag_name ?? name ?? null` (raw, `v` prefix kept), `releaseUrl = html_url ?? null`, `releaseNotes = body ?? null`, `publishedAt = published_at ?? null`, `updateAvailable = isNewer(latestVersion, currentVersion)`. Only a result with a non-null `latestVersion` is cached (a failure retries on the next call); no single-flight. The fallback is still 200. `[ts:src/modules/scheduler/update-check.service.ts:5]`–`[ts:src/modules/scheduler/update-check.service.ts:26]`, `[ts:src/modules/scheduler/update-check.service.ts:72]`–`[ts:src/modules/scheduler/update-check.service.ts:141]`
11. `isNewer`: parse each side as `v?` prefix stripped, cut at the first `-` or `+`, split on `.`, each part `parseInt(.,10)` (digit prefix: `3rc1` → 3); any part NaN or an empty side → not newer. Compare part by part, missing parts = 0; only a strictly greater part decides. `1.2.x` is unparsable (false). `[ts:src/modules/scheduler/update-check.service.ts:39]`–`[ts:src/modules/scheduler/update-check.service.ts:59]`

### D. Stats

12. `movies` = `SELECT count(*)::int FROM media WHERE type = 'movie'`, `series` the same with `'series'`, `pendingRequests` = `SELECT count(*) FROM requests WHERE status = 'pending'`. `[ts:src/modules/scheduler/system.controller.ts:145]`–`[ts:src/modules/scheduler/system.controller.ts:155]`
13. `diskSpace`: libraries `ORDER BY name ASC` (+ `id ASC`, C12) with a non-empty `path`; per library `{path: library.path as stored, label: label ?? name (an empty-string label stays empty), freeSpace: f_bfree * f_bsize, totalSpace: f_blocks * f_bsize}`; on a `statfs` error `freeSpace` and `totalSpace` are `-1` (JSON numbers; same semantics as `libraries.md` rule 6, run on the blocking pool). Absolute paths are exposed here by design: the route needs `settings.access`, i.e. the F22 audience. `[ts:src/modules/scheduler/system.controller.ts:157]`–`[ts:src/modules/scheduler/system.controller.ts:176]`

### E. Backups

14. Backup dir = `<data_dir>/backups` (`paths::data_dir()`, `FLIKS_DATA_DIR` with the writable-or-tmp fallback of `config.md`), created on first backup only. `GET /backups` lists regular entries ending `.sql` (case-sensitive), `{filename, size, date: mtime ISO}`, newest first by `date` string then `filename DESC` (C12); a missing dir → `[]`. `[ts:src/modules/scheduler/backup.service.ts:29]`, `[ts:src/modules/scheduler/backup.service.ts:67]`–`[ts:src/modules/scheduler/backup.service.ts:77]`
15. Name validation (create-by-name routes: download, delete, restore): must match `^[A-Za-z0-9_.-]+\.sql$` (ASCII `\w`: Rust's Unicode `\w` is wrong, use the explicit class; `$` is end of input only) else 400 `Invalid backup name "<name>"`; then the file must exist in the backup dir else 404 `Backup "<name>" not found`. The check runs before any path join, so no separator or `..` segment can pass (`..sql` is a legal, harmless name). `[ts:src/modules/scheduler/backup.service.ts:140]`–`[ts:src/modules/scheduler/backup.service.ts:149]`
16. Download: `res.download(path, name)`: 200, `Content-Disposition: attachment; filename="<name>"`, `Content-Type: application/sql`, `Content-Length`, weak `ETag`, `Last-Modified`, `Accept-Ranges: bytes` and `Cache-Control: public, max-age=0`, `Range` supported (Express `send`); streamed, never buffered `[assumed]` headers: record on Nest, pin in the scenario. `[ts:src/modules/scheduler/system.controller.ts:205]`–`[ts:src/modules/scheduler/system.controller.ts:209]`
17. Create: `filename = fliks-backup-<new Date().toISOString() with every ':' and '.' replaced by '-'>.sql` (e.g. `fliks-backup-2026-10-16T02-00-00-123Z.sql`); mkdir -p the dir; run `pg_dump <connection args> --clean --if-exists --no-owner --no-privileges` with stdout = the new file; on any failure close and delete the partial file and rethrow; answer `{filename, size: bytes of the file}`. Log `Creating backup: <filename>` then `Backup created: <filename> (<size> bytes)`. `--clean --if-exists` so the restore works on a populated database; `--no-privileges` because grants name plugin roles a fresh cluster lacks. `[ts:src/modules/scheduler/backup.service.ts:33]`–`[ts:src/modules/scheduler/backup.service.ts:65]`
18. Tool runner (`pg_dump`, `psql`): spawned without a shell, arguments as a vector, stdout to the file or discarded, stderr captured. `ENOENT` → 500 `<cmd> is not available on this server`; another spawn error → 500 `<cmd> failed: <message>`; exit code ≠ 0 → log `<cmd> exited with <code>: <full stderr>` and 500 with the last non-empty stderr line (else `<cmd> exited with code <n>`). No timeout in Nest; Rust adds none either (a dump of a large library takes minutes) but kills the child and removes the partial file when the server shuts down `[new]`. `[ts:src/modules/scheduler/backup.service.ts:166]`–`[ts:src/modules/scheduler/backup.service.ts:199]`
19. Connection args and secret: `-h <DB_HOST>`, `-p <DB_PORT>`, `-U <DB_USERNAME>`, `-d <DB_NAME>` (defaults `localhost`, 5432, `fliks`, `fliks`); the password travels in `PGPASSWORD`, never in argv; the child inherits the rest of the environment. Nest's `PGPASSWORD` default is `''` while the TypeORM pool defaults to `fliks`, so an install relying on the default password fails to back up; Rust derives all five values from the one `Config` the pool uses (C?8). `[ts:src/modules/scheduler/backup.service.ts:151]`–`[ts:src/modules/scheduler/backup.service.ts:173]`
20. Retention (`Backup` job only, `scheduler.md` rule 22): keep the newest 7 of `list_backups()`, delete the rest, return the removed names; the direct `POST /backup` never prunes. `[ts:src/modules/scheduler/backup.service.ts:26]`, `[ts:src/modules/scheduler/backup.service.ts:87]`–`[ts:src/modules/scheduler/backup.service.ts:93]`
21. Delete: rule 15 validation (so a missing file is 404), `rm -f`, log `Backup deleted: <filename>`, answer `{ok:true}`. `[ts:src/modules/scheduler/backup.service.ts:79]`–`[ts:src/modules/scheduler/backup.service.ts:83]`, `[ts:src/modules/scheduler/system.controller.ts:213]`–`[ts:src/modules/scheduler/system.controller.ts:216]`
22. Restore body: no DTO, the handler reads `body.filename` of a plain object. Absent or non-string values are stringified by the regex test, so `{}` → 400 `Invalid backup name "undefined"`; a one-element string array matches the regex and then makes `path.join` throw (500). Rust: any non-string `filename` → 400 `Invalid backup name "<JS String() of the value>"` (C?5); unknown extra keys are ignored. Flow: validate (rule 15), warn `Restoring backup: <filename>`, ensure plugin roles (rule 23), replay (rule 24), log `Backup restored: <filename>`, answer 201 empty. `[ts:src/modules/scheduler/system.controller.ts:200]`–`[ts:src/modules/scheduler/system.controller.ts:202]`, `[ts:src/modules/scheduler/backup.service.ts:95]`–`[ts:src/modules/scheduler/backup.service.ts:110]`
23. Plugin roles: read the file line by line; every line matching `^GRANT .+ TO (plugin_[a-z0-9_]{1,56});$` contributes its role (a set); when non-empty run `psql <connection args> -v ON_ERROR_STOP=1 -c "DO $$ BEGIN <one IF NOT EXISTS (SELECT FROM pg_roles WHERE rolname = '<role>') THEN CREATE ROLE \"<role>\" LOGIN; END IF; per role, joined by a space> END $$"`. The role charset is the only guard against SQL injection in that string, so the regex must stay exactly this tight and anchored. Older dumps granted to plugin roles; a missing one aborts the restore at its first `GRANT`. S8 removes the step if the WASM plugin data tier has no per-plugin roles. `[ts:src/modules/scheduler/backup.service.ts:113]`–`[ts:src/modules/scheduler/backup.service.ts:137]`
24. Replay: `psql <connection args> --single-transaction -v ON_ERROR_STOP=1 -f <abs path>`: one transaction, rolled back on the first error (without `ON_ERROR_STOP` psql would report success after skipping failed statements). Rust adds `-X` (no `~/.psqlrc`) and screens the file first (F?2). The server keeps serving during the replay; `DROP TABLE` waits for in-flight queries and the pool's queries then wait on the lock. `[ts:src/modules/scheduler/backup.service.ts:99]`–`[ts:src/modules/scheduler/backup.service.ts:108]`
25. Rust post-restore steps `[new]` (C?6, C?9): refuse (409) while any `commands` row is `queued`/`running`; after a successful replay run the legacy-ledger adoption and pending sqlx migrations (`bootstrap` step of plan §6.2) so an older dump gets today's schema, and mark every `queued`/`running` row failed (a scheduled backup dumps its own `running` row). A migration failure (a dump newer than this binary) answers 500 with that error. Nest did none of these and had one ledger (TypeORM's, inside the dump).

### F. Logs

26. Ring buffer: capacity 2 000 entries `{timestamp: ISO-8601 ms Z at push, level, context, message}`, oldest dropped first; `level` in `log|warn|error|debug` (Nest's `verbose` and `fatal` are not buffered); `error(message, trace, context)` stores `message + "\n" + trace` when a trace is given. Memory only, lost on restart. `[ts:src/modules/scheduler/log-buffer.service.ts:3]`–`[ts:src/modules/scheduler/log-buffer.service.ts:49]`
27. `GET /logs`: copy the buffer, filter `level` (exact, case-sensitive; an unknown value → `[]`; empty string = no filter), filter `q` (lower-cased substring of `message` or `context`; empty = none), reverse (newest first), then cut to `limit`: absent or empty → 200; else `parseInt(limit, 10)` (leading whitespace and sign, digit prefix); a result that is NaN, 0 or negative means no cut (up to 2 000). Rust: a `limit` that is not a canonical integer → 400 (C?1, shared with `scheduler.md` rule 20); `0` and negative integers keep "no cut". `[ts:src/modules/scheduler/system.controller.ts:220]`–`[ts:src/modules/scheduler/system.controller.ts:230]`, `[ts:src/modules/scheduler/log-buffer.service.ts:51]`–`[ts:src/modules/scheduler/log-buffer.service.ts:69]`
28. Rust feed 1, `tracing`: a subscriber layer of `fliks-server` pushes every event at ERROR/WARN/INFO/DEBUG (`error`/`warn`/`log`/`debug`; TRACE is dropped) with `context` = the event target without the `fliks_server::` prefix and `message` = the `message` field followed by ` key=value` for each other field `[assumed]`. Debug events exist only when `RUST_LOG` enables them (default INFO). The layer is installed beside the stderr writer of `main.rs`, which keeps printing. `[ts:src/main.ts:15]`–`[ts:src/main.ts:16]` (Nest's `app.useLogger(logBuffer)` is the equivalent)
29. Rust feed 2, Nest child output (strangler only, until S9): stdout and stderr of the Nest process are read line by line, passed through unchanged to `fliks-server`'s own stdout/stderr (container logs keep Nest's lines) and parsed: strip ANSI SGR sequences; a line matching `^\[Nest\] \d+\s+- .+? (LOG|WARN|ERROR|DEBUG|VERBOSE|FATAL)\s+(?:\[([^\]]*)\]\s+)?(.*)$` starts an entry `{timestamp: receipt time, level: lower-cased (LOG → log), context: group 2 or '', message: group 3}` (VERBOSE and FATAL dropped, as Nest never buffered them); a line that does not match is a continuation, appended with `\n` to the previous entry (stack traces, multi-line messages) and dropped when there is none. Nest's printed timestamp is locale-formatted (system locale) and is not parsed. Plugin child lines already arrive as `LOG [plugin:<id>] <line>` (`plugin-supervisor.ts`), so `context` = `plugin:<id>` as today. The line format is `[assumed]` from `ConsoleLogger` (no custom formatter in `main.ts`); the `nest-log-line` vectors pin it. Requires `fliks_engine::supervise::run` to expose the child's output (it inherits stdio today): engine-repo change and tag bump, Q1. `[ts:src/modules/scheduler/log-buffer.service.ts:15]`–`[ts:src/modules/scheduler/log-buffer.service.ts:37]`, `[ts:src/modules/plugins/supervisor/plugin-supervisor.ts:555]`–`[ts:src/modules/plugins/supervisor/plugin-supervisor.ts:560]`
30. Hygiene `[new]` (F?4): the ring is readable with `settings.access` and mirrored on stderr, so no entry may carry a credential. HTTP trace events log the method and path only, never the query string (stream tokens and API keys travel there); an error from `reqwest` is logged with its URL removed (`reqwest::Error::without_url`); the `Authorization`, cookie and `PGPASSWORD` values are never fields. Nest-origin lines are forwarded as they are (Nest's own F29-style rules apply there).

## SQL

- `SELECT 1` (health).
- `SELECT count(*) FROM plugin_packages` and `... WHERE enabled = true`.
- `SELECT count(*)::int FROM media WHERE type = 'movie'` (and `'series'`); `SELECT count(*)::int FROM requests WHERE status = 'pending'`.
- `SELECT id, name, label, path FROM libraries WHERE path IS NOT NULL AND path <> '' ORDER BY name ASC, id ASC` (Nest: `ORDER BY name ASC`, collation order: `README.md` "Frozen as is" order-insensitive parity applies).
- Restore guard and sweep: `SELECT EXISTS (SELECT 1 FROM commands WHERE status IN ('running','queued'))`; `UPDATE commands SET status = 'failed', "endedOn" = now() WHERE status IN ('running','queued')`.
- External: `pg_dump`, `psql` (rules 17-24).

## Events

None emitted or consumed. (`restart` and `restore` send no SSE event; connected clients see the stream drop on restart and reconnect.)

## Settings keys

None in the `settings` table. Environment (`config.md`): `DB_HOST`, `DB_PORT`, `DB_USERNAME`, `DB_PASSWORD`, `DB_NAME` (rule 19), `FLIKS_DATA_DIR` / `FLIKS_IMAGES_DIR` (rule 14), `FLIKS_GITHUB_REPO`, `FLIKS_DISABLE_UPDATE_CHECK` (rule 10), `FLIKS_SUPERVISED`, `pm_id`, `INVOCATION_ID`, `FLIKS_ENGINE_TOKEN` (rule 6), `RUST_LOG` (rule 28). `FLIKS_SUPERVISED` is set by the Windows tray `NodeManager` `[ts:windows/Fliks.Tray/Services/NodeManager.cs:28]` and must keep working.

## Jobs/timers

- Backup 02:00 and the retention prune: `scheduler.md` rules 22, 26 (the file operations of this spec).
- Update-check cache TTL 6 h (in memory, lost on restart); restart delay 300 ms; log ring 2 000 entries. No other timer.

## Bridges

None for these routes. Log capture is a process-supervision hook (rule 29), not an HTTP bridge. `fliks-server` health reads `plugin_packages` itself; Nest owns no state the routes need.

## Open questions

Security (proposed F rows, numbers continue after F34 in `README.md` Deviations; each lands in S5):

- F?1 Backup routes (create, list, download, restore, delete) require `manage:all` (admin) instead of `settings.access`. A dump holds every password hash, refresh-token hash and secret setting in clear, so `settings.access` bypasses F5 (read) and, through restore, can overwrite the `users` table to promote itself (write). Client impact: a non-admin `settings.access` user loses the backups page (403). Health, stats, update, logs keep `settings.access`. Also decide whether `restart` stays at `settings.access`.
- F?2 Restore replays only a screened file: psql executes meta-commands from `-f` files (`\!` runs a shell command, `\i`, `\copy ... PROGRAM`), and the file sits in a directory the data volume owner can edit. Rust runs `psql -X` and refuses (400 `Backup contains psql meta-commands`) any line outside a `COPY ... FROM stdin` data block that starts with a backslash, except `\restrict <key>` / `\unrestrict <key>` (pg_dump 17+) and `\.`; the screening reuses the pass that collects plugin roles (rule 23). No client impact.
- F?3 Backup files are created mode `0600` in a `0700` directory (Nest: `openSync(path,'w')`, umask default `0644`, readable by every local user of the host).
- F?4 No credential in logs (rule 30): HTTP trace logs path only, `reqwest` errors without URL. New Rust behaviour rather than a Nest fix, recorded because the ring is served to `settings.access`.

Correctness (proposed C rows, numbers continue after C20; `C?1` to `C?4` are in `scheduler.md`):

- C?5 `POST /restore` with a non-string `filename` → 400 `Invalid backup name "<String(value)>"` (Nest: a one-element string array passes the regex and ends in a 500).
- C?6 Restore answers 409 `A command is running` while a `commands` row is `queued`/`running`, and after a successful restore marks `queued`/`running` rows failed (the dump of a scheduled backup contains its own `running` row; a live job would also update ids that now belong to other rows).
- C?7 `GET /health` answers 200 with `database.ok:false` and zero plugin counts when the database is down (Nest: 500 from the plugin counts).
- C?8 `pg_dump` / `psql` take their connection values from the same parsed `Config` as the pool (default password `fliks`; Nest's `PGPASSWORD` default is empty).
- C?9 After a restore the server runs the legacy-ledger adoption and pending migrations so an older dump matches this binary's schema (Nest had one ledger; with sqlx a dump without `_sqlx_migrations`, or an older one, would leave the live ledger ahead of the restored schema).
