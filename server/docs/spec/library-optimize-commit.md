# Library optimizer: commit (server)

Module `server/crates/server/src/queue/` (`commit.rs`, `swap.rs`, `recover.rs`, `trash.rs`, `words.rs`, `ocr.rs`).

1. A `staged` job is probed by the local engine before any lock (streams and duration match the worker's `result`).
2. Busy file: an engine session, a `download` resolve under 10 minutes ago, or `listening()`. The job stays `staged`, `notBefore` +5 min, no failure.
3. Under `ingest.media.lock(media)` and `folder_moves` (read): the source must still be the job's snapshot (path, size, mtime, `dev:ino`), else `skipped` (`stale`).
4. Journal: `state = committing`, `result.journal` holds the paths, the `dev:ino`/size of source and staged, the policy and the companions. Written before the disk is touched.
5. Swap (`swap::perform`, idempotent): the original gets a second name (`trash`: `<root>/.fliks-trash/<job>.bak`; `keep`: `<source>.orig`, kept if present; `delete`: none) by hard link, or by a move to `.fliks-opt-<job>.old` on a filesystem without links; then the staged is renamed onto the target (`MoveFileEx` replace with retries on Windows, `busy` if still locked).
6. Rows: the forced rescan path (`ingest::rescan::refresh_content`, `content_changed`, `timeline_preserved`): streamInfo, quality, size, mtime, probeVersion, crop and `timestampBreakSeconds` recomputed, `osdbHash` kept; `subtitle_files."sourceStreamIndex"` set to NULL for image tracks that are gone (OCR SRTs stay); the OCR SRTs added by the job are deleted with their row; embedded rows recreated; `media.file_changed` SSE; `POST /v1/revoke {mediaFileIds}`; sprite requeued. Then `done`, `result.trashPath` for `trash`.
7. Renaming (library `allowRename`): only wrong technical words and the extension change; companions (`<stem>.<tail>`) follow in the journaled swap and `subtitle_files."filePath"` is updated, `hashMatched` kept.
8. Recovery of `committing` jobs at boot, every minute (rows idle for 2 minutes) and after a backup restore: the swap is run again from the journal; if nothing moved the job is `skipped`. An output already placed whose swap leaves leftovers (`.old`) still completes: the rows follow and the job is `done`, with a log line. A database error while reading the file row leaves the job as it is.
9. Restore (`recover::restore`): only while the file is still the produced one (`dev:ino`); the original comes back, the optimized file takes its slot (`trashPath` becomes the slot when `restoredAt` is written). The `restore` marker is written only if neither `trashPurgedAt` nor `restore` is set. A restore that moved nothing and cannot start (the file is not the produced one) is abandoned: `restore` is removed and the original keeps its recorded place.
10. Trash purge: after `trashRetentionDays`, and oldest first below `trashMinFreeGb`; `result.trashPurgedAt` is written (the lease space check counts the rest). The purge locks the job row (`FOR UPDATE`), rereads `trashPath` and `ocrTrash`, and skips a job with a restore in flight. OCR SRTs in the trash are purged under every policy; a job with only OCR SRTs (`keep`, `delete`) gets `ocrPurgedAt` and stays restorable, a restore skipping SRTs that are gone.

## Control (S5)

11. Queueing builds the engine's `OptimizePlan` from the diff (`Diff::plan`): video settings (quality, software, `tooSlow`, `maxSoftwareHours`, `minSavingsPct` unless the crop alone justifies the re-encode, raised to 20 for a recompress; `qualityCheck` from `guards.vmaf_sample`: `on` true, `off` false, `auto` unset for the engine's default), drops, tags, titles, defaults, playable audio (`encode`, `keepOriginal`), container, OCR subtitles (`extraSubtitles`, only for tracks whose OCR finished), `hvc1`, statistics tags. `Reorder`, `Flags` and a rename alone are not in the plan.
12. Selection capabilities come from the registered workers (`Shared::capabilities`): encodable codecs, AV1 hardware decode on a local device. No worker registered: nothing is encodable and the video is copied.
13. `POST /api/libraries/{id}/optimize/queue` runs one `select::analyze` pass and answers 202 `{files}`; the jobs are inserted in the background. `POST /api/optimize/jobs/{id}/restore` is `recover::restore`.
14. `GET /api/optimize/queue`: `paused`, `open` (time window), job counts per state, and the estimate: per level the jobs, playing seconds left and estimated seconds, `etaSeconds` (closed hours included) and `endsAt`; none while a level with jobs has no history. Speed = playing seconds over `encodedAt - startedAt` of the last 20 jobs per device and level, times the device's slots; a job the engine redid in software (`result.cpuFallback`) counts for the `cpu` device. The preview carries `estimateSeconds` per level from the same speeds.
14b. An optimize job keeps the diff it was queued from (`jobs.diff`: `changes`, `warnings`). `GET /api/optimize/jobs/{id}` answers `diff`, `source` (the probe at queueing), `output` (the output's probe, once encoded), `doneLevel`, `copyReason`, `cpuFallback`, `sampledSavingsPct`, `savingsPct` (video savings the samples predicted and the encode reached, also for an encode dropped for `low_savings`), `ssim` (lowest mean SSIM of the output's check windows) and `startedAt`/`encodedAt`/`finishedAt`; 404 outside the caller's libraries.
15. `POST /api/optimize/queue/pause|resume` (`paused` in the settings: no new lease), `POST /api/optimize/jobs/priority {ids}` (queued jobs run first, in the order given), `POST /api/optimize/jobs/cancel {ids}`.
16. SSE: `optimize.job_progress {jobId, progress, paused, runsOn}` on each heartbeat, `optimize.job_changed {jobId, state}` on a state change (a sweep woken by every job write that creates a job or moves its state; no periodic poll), `optimize.queue_changed` on queueing, reordering, pause and restore. Notifications `optimize.completed`, `optimize.failed`, `health.corrupt` (once per file) go out from the same sweep.
17. `hello` carries `cpuWeight` (default 2) and `gpuPlaybackBeforePause` (integer, 0 never) from the settings, applied at the next hello. `PUT /v1/config` sends `worker: true`.

## Automatic (S6)

18. `post_import::settled()` calls `queue::queue_new` for each file of the media: a library with `optimizeNewFiles` and a profile queues the optimize job at once with `notBefore = createdAt + eligible.min_age_days` (the age gate becomes the delay). A file that starts at once (`min_age_days = 0`) gets no sprites from `settled()`: the commit requeues them, and so does a job of the file that ends `failed`, `cancelled` or `skipped` (the job watcher, off the sweep). Otherwise sprites are generated as before. Markers are always detected.
19. Every hour the queue loop reviews the files created in the last 30 days in `optimizeNewFiles` libraries that never had a job, through the same `queue_new` (a hard-linked file becomes eligible once it stops being linked, or a pending OCR is done).
20. `POST /api/optimize/verify {mediaFileIds, priority?}` queues a `verify` job per file (full read, software decode counting the errors; `corrupt` and `damaged` failures raise `health.corrupt` once). Same answers as the optimize queueing.
21. Settings `verifyIntervalDays` (0 = no scheduled verification, default) and `verifyBatch` (default 20): each hourly pass queues, at priority -10, the video files whose last finished `verify` is older than the interval (never verified first), without an active job or a remembered `corrupt`/`damaged` failure of the same bytes.

A `separate` job (karaoke, `karaoke.md` rule 16) never reaches `staged` or `committing`: its stems are committed inside the worker's `result` and its row is deleted, so it leaves no entry in the optimize history.
