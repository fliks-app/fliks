# Spec: book ingest

Scope: how book files enter the library: grouping files into editions, archive reading, tags mapping, post-import work by family, covers, the KOReader hash, identification flow, naming at ingest. The parsers are `books-files.md`; the identification and linking seams are `book-metadata.md`; the data model is `books.md`. After the contract PR this file belongs to the ingest track, which writes the rules.

## Seams

- Ingest writes files, editions, items and parts, never external ids, facts, credits or series: those go through `metadata::books::link::attach(st, media, edition, &BookMatch, Priority)` (`book-metadata.md`).
- Identification starts from `BookHints` (ISBNs, ASIN, title, authors, narrators, language, series, year, family) read from the file (`books-files.md`) and the engine's `info.tags` and `info.cover`, and calls `metadata::books::identify::identify`.
- A book gets one edition per family found, each with one ungrouped item (`books.md` rules 3 and 4). The folder of a file comes from `folder_for(library, family)` of the library folders spec.
- No engine work is part of phase 1: the server reads `hello.jobFamilies`, runs the `Cover` job and keeps `info.tags`.

## Rules

### Files and grouping

1. A book file is a file whose lower-cased extension is in `fliks_domain::media::TEXT_EXTS` (`.epub .pdf .azw3 .mobi .fb2 .cbz`, family `text`) or `AUDIO_EXTS` (`.m4b .m4a .mp3 .flac .ogg .opus .aac`, family `audio`); its format is the extension without the dot. A library accepts them when its `mediaTypes` lists `book`; the video extensions and the two lists are disjoint. Every walk of a book (orphan scan, rescan, link in place, transfer) keeps book files and skips the rest; a book never walks for video files.
2. `ingest::books::group::group(paths) -> Vec<Work>` is pure: it takes `/`-separated paths relative to a folder root and answers the works they make, sorted by `(dir, name_path)`. A path that is not a book file is ignored. A work is `{ dir, name_path, versions }`: `dir` is the folder of its files with the disc folders (`CD1`, `Disc 2`, `Disk 1`, `Disque 1`, any case, space optional) taken off, `''` at the root; `name_path` is the path read by `filename::parse_path` for the hints (the first text file, else the first `m4b`, else the first file of the first audio version); `versions` are its alternatives in the order text, then audio, each by format then by first path.
3. Text files are one work per `(dir, normalised stem)`, the stem lower-cased with every character that is not a letter or a digit removed, so `Title.epub` and `Title.pdf` are the same work and two stems of one folder are two works. Audio files of a folder join the work of the one text work of that folder, or, with none or several, are one work of their own. At the root every audio file is its own work, joined to the text work of the same stem when there is one.
4. A text file is one version of one position. An `m4b` is one version of one position, each. The other audio files of a work are one version per format, ordered by `(disc, number, path)` of `filename::parse_path` (a file with no number after those with one, then by path in natural order), one position each; so `mp3` parts and an `m4b` of one folder are two versions, and `mp3` and `flac` parts are two.
5. `PARTS` writes (`ingest::books::parts::write_versions(tx, media, item, versions)`) the desired layout of an item in one transaction under the item-versions lock: a file keeps the version it has on the item when its desired version holds a file already there (the lowest such), else it gets the item's next version; the positions are `0..n` in version order. A file already at its desired `(version, position)` is not rewritten; the others are deleted and inserted again, which rebuilds their chapters (`items.md` rule 23). Chapters stay per part (`items.md` rule 37).

### Editions and rows

6. `ingest::books::register(st, media, files)` is the one writer of a book's files, whatever the entry (library ingest, link in place, rescan): it inserts or updates the `media_files` row of each file (`quality` = the format, `size`, `mtimeMs`, `probeVersion`, `streamInfo` = the engine probe for an audio file and `NULL` for a text file), then regroups every file of the media (rule 2) and writes the layout of each edition under the media's item-versions lock. An audio file is probed through the engine; a probe that fails stores the error blob and the file stays a part.
7. A media has at most one edition per family; `register` creates it when the first file of that family arrives, with one ungrouped, monitored item (`books.md` rule 4). The edition keeps what it has and takes, where a column is NULL: `format` when every version of the family has one format, `durationSeconds` (audio) the sum of the probed durations of the first version, `language` and `publisher` from the first file (`info.tags` or the OPF), never `title`. A later merge (`book-metadata.md` rule 8) overwrites them under its own locks.
8. The folder of a file is the folder of the media's want of its family (`wants."folderId"`, language NULL) when it belongs to the media's library, else the library's default folder (`books::folder_for`). A transferred file lands under `<folder root>/<folderName>`; the file name is `apply_book_format(formats.book, tokens)` plus, for a version of several files, ` - NN` (the 1-based index, two digits) before the extension; the folder name of an unnamed media is `apply_book_format(formats.book_folder, tokens)` (`pin_folder`, never `movie_folder`), validated as one component. The tokens are the title and year of the media, nothing else (`naming.md` rule 24).
9. A book is not a video: a transfer keeps every file of the request (no "largest file" selection), no companion files travel, no crop, no OpenSubtitles hash, no sprite, no keyframe scan, no subtitle search and no intro detection runs for it. The event is `MediaFilesImported` with the family of the first file.
10. A media of a book library is anchored by its folder when its work lies alone in one top-level folder of the scan root (`folderName` is that folder); otherwise (a loose file, a work nested below the top level, several works in one folder) its `folderName` is `''` and it owns its files by path, every work its own media. A media with no folder name owns files at any depth for a book (`ingest.md` rule 52 allows only the library root for a movie). Ceiling: a part added later to a work with no folder name is not found by a rescan; the orphan scan offers it again.

### Archive, tags, hashes, cover

11. `archive::read_epub(path)` opens the file as a zip and returns its `OpfMetadata` and its cover, or nothing: a file that is no zip, has no OPF or fails to read is a file with no package metadata, never an error. The OPF path comes from `META-INF/container.xml` (`opf::container_rootfile`), else the first entry ending in `.opf`. `container.xml` and the OPF are read through a cap of 2 MiB each (`books-files.md` rule 4), whatever the zip declares: a longer entry is no metadata. The cover is the entry of `cover_href` (`opf::resolve_href`), read through a cap of 16 MiB and kept only when it is a JPEG, a PNG, a WebP or a GIF by its header.
12. `tags::audio_hints(tags, guess)` maps the engine's `info.tags` of an audio file to `BookHints` (family `audio`): `title` the album, else the title; `authors` the artist, else the album artist, split on `;`, ` & ` and ` / `; `narrators` the narrator tag, split likewise; `language` through `normalize_language_code` (`und` is none); `series` the series with the part as `series_part` text; `year`; `isbns` the ISBN tag through `isbn::parse` (a bad one is dropped); `asin` through `ExternalProvider::Asin.normalize`. Every field the tags lack comes from `filename::parse_path(name_path)` (title, authors, narrators, series, year). `epub_hints(meta, guess)` does the same from the OPF: the title, the `aut` creators, the `nrt` creators, the language, the series, the year, every ISBN and the ASIN, with the name guess as the fallback of each. `*_record` builds the `file` record `attach_with` takes (`title`, `subtitle`, `authors`, `narrators`, `language`, `publisher`, `year`, `overview`, `subjects`, `series`, `isbn13`, `asin`, `releaseDate`, `format`, `durationSeconds`), omitting what is absent.
13. The KOReader partial MD5 of every text file is stored in `media_file_hashes("mediaFileId", kind = 'koreader', hash)` (`books-files.md` rule 40), refreshed when the file's size or mtime changes; the row goes with its file. A file that cannot be read has none.
14. The cover of the work comes from the EPUB archive or from the engine: for an audio file whose `info.cover` is set, the post-import queue submits a `Cover` job when `hello.jobFamilies` lists `Cover` for `audio`, reads the picture at `GET /v1/covers/{mediaFileId}` and stores it. The picture becomes `media."posterUrl"` through the image store only when the media has none; the edition cover is not written (`book-metadata.md` rule 13).
15. The post-import queue runs a job only when `hello.jobFamilies` lists its kind for the family of the file (`Engine::job_applies`); a kind the hello does not list applies to video only. `info.tags` and `info.cover` stay in `streamInfo` as the probe wrote them: the queue never re-probes an audio file.

### Identification

16. `ingest::books::identify_media(st, media)` runs when the media's post-import queue is idle (the settle timer): for each edition without an id it builds the hints of its first file (rule 12), calls `identify` at `Background` priority and, on a match, `attach_with` with that edition and the file record. When the work already holds an id and `identify` finds nothing, the stored match (`link::stored`) is attached to the edition. An edition that has an id is not identified again; a match that is not found leaves the work unmatched, and the next metadata refresh identifies it. No error of identification fails an import.
17. The ingest never writes external ids, facts, credits or series (`attach` does), and the metadata side never writes files, editions, items or parts. The ingest holds the media's lock and the `folder_moves` read lock across resolve, move and insert; identification holds neither.

## Tests

Golden: `fixtures/books-grouping` (a folder of parts, `CD1`/`CD2`, mixed formats, a single `m4b`, an ebook and an audiobook side by side, several ebooks in one folder, a nested work), `fixtures/books-tags` (the `info.tags` an `m4b`, an `mp3` and a `flac` carry), all synthetic. The EPUB reader runs on real zips built in the test (EPUB 2 and 3, a zip bomb, no OPF, no zip). `ingest/tests.rs` (`book_ingest`) runs a transfer, a link in place, a rescan and an identification against a throwaway database and a fake engine.
