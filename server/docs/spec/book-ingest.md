# Spec: book ingest

Scope: how book files enter the library: grouping files into editions, archive reading, tags mapping, post-import work by family, covers, the KOReader hash, identification flow, naming at ingest. The parsers are `books-files.md`; the identification and linking seams are `book-metadata.md`; the data model is `books.md`. After the contract PR this file belongs to the ingest track, which writes the rules.

## Seams

- Ingest writes files, editions, items and parts, never external ids, facts, credits or series: those go through `metadata::books::link::attach(st, media, edition, &BookMatch, Priority)` (`book-metadata.md`).
- Identification starts from `BookHints` (ISBNs, ASIN, title, authors, narrators, language, series, year, family) read from the file (`books-files.md`) and the engine's `info.tags` and `info.cover`, and calls `metadata::books::identify::identify`.
- A book gets one edition per family found, each with one ungrouped item (`books.md` rules 3 and 4). The folder of a file comes from `folder_for(library, family)` of the library folders spec.
- Adopting an existing library is the orphan scan and its relink (`ingest.md`); the classifier (`ingest::books::plan`, `ingest.md` rules 102-104) answers the work grouping and anchors of rules 2-4 and 10.
- No engine work is part of phase 1: the server reads `hello.jobFamilies`, runs the `Cover` job and keeps `info.tags`.

## Rules

### Files and grouping

1. A book file is a file whose lower-cased extension is in `fliks_domain::media::TEXT_EXTS` (`.epub .pdf .azw3 .mobi .fb2 .cbz`, family `text`) or `AUDIO_EXTS` (`.m4b .m4a .mp3 .flac .ogg .opus .aac`, family `audio`); its format is the extension without the dot. A library accepts them when its `mediaTypes` lists `book`; the video extensions and the two lists are disjoint. Every walk of a book (orphan scan, rescan, link in place, transfer) keeps book files and skips the rest; a book never walks for video files, and no walk follows a link: a symlink is neither a directory to enter nor a book file. The orphan scan reads a library folder four levels deep (`Author/Series/Title/CD1/part`), a book rescan the media folder three levels deep.
2. `ingest::books::group::group(paths) -> Vec<Work>` is pure: it takes `/`-separated paths relative to a folder root and answers the works they make, sorted by `(dir, name_path)`. A path that is not a book file is ignored. A work is `{ dir, name_path, versions }`: `dir` is the folder of its files with the disc folders (`CD1`, `Disc 2`, `Disk 1`, `Disque 1`, any case, space optional) taken off, `''` at the root; `name_path` is the path read by `filename::parse_path` for the hints (the first text file, else the first `m4b`, else the first file of the first audio version); `versions` are its alternatives in the order text, then audio, each by format then by first path.
3. Text files are one work per `(dir, normalised stem)`, the stem lower-cased with a trailing ` (xx)` or ` (xxx)` (lower-case letters, the language of a file named by rule 8) cut off and every character that is not a letter or a digit removed, so `Title.epub`, `Title (fr).epub` and `Title.pdf` are the same work and two stems of one folder are two works. Audio files of a folder join the work of the one text work of that folder, or, with none or several, go by title: an `.m4b` is keyed by its whole stem (none when that is the folder's name), another file by its stem before its last number (none for `01`, `Track 02`, `01 - Intro`, or a name with no number), the language tag ` (xx)` off. A folder is split only when it holds at least two different titles, one work per title and one more for the untitled files; otherwise it is one work. At the root every audio file is its own work, joined to the text work of the same stem when there is one.
4. A text file is one version of one position. An `m4b` is one version of one position, each. The other audio files of a work are one version per format, ordered by `(disc, number, path)` of `filename::parse_path` (a file with no number after those with one, then by path in natural order), one position each; so `mp3` parts and an `m4b` of one folder are two versions, and `mp3` and `flac` parts are two.
5. `PARTS` writes (`ingest::books::parts::write_versions(tx, media, item, versions)`) the desired layout of an item in one transaction under the item-versions lock: a file keeps the version it has on the item when its desired version holds a file already there (the lowest such), else it gets the item's next version; the positions are `0..n` in version order, with no gap: a rescan that removes a part lays the item out again even when it adds none, or when every file it adds is refused. A file already at its desired `(version, position)` is not rewritten; the others are deleted and inserted again, which rebuilds their chapters (`items.md` rule 23). Chapters stay per part (`items.md` rule 37).

### Editions and rows

6. `ingest::books::register(st, media, files)` is the one writer of a book's files, whatever the entry (library ingest, link in place, rescan): it inserts or updates the `media_files` row of each file (`quality` = the format, `size`, `mtimeMs`, `probeVersion`, `streamInfo` = the engine probe for an audio file and `NULL` for a text file), then regroups every file of the media (rule 2) and writes the layout of each edition under the media's item-versions lock. It answers the files it registered and the conflicts, one message per file it left alone: a file that another media owns, and, for a media anchored by its folder (rule 10), a file of a work other than the media's own. A conflict is never an error and never stops the other files; the facts (`language`, `publisher`) and the EPUB cover of a file refused or left alone are not kept, only those of a file whose row was written count; `lay_out` itself refuses (error, nothing written) the files of an anchored media that make more than one work. An audio file is probed through the engine; a probe that fails stores the error blob and the file stays a part.
7. A media has one edition per family and language that was asked for; `register` creates the first when a file of that family arrives, with one ungrouped, monitored item (`books.md` rule 4). A file already laid out keeps its edition; a new file joins the edition of the `language` of the request (`register_language`, from `library.ingest`): the one of that language, else an edition with no language and no part (it takes the language), else a new edition of that language. Without a language it joins the first edition of its family, no language first. A request with a language skips the anchored media's checks (rule 10) for its files: the caller names the media and the name is the host's own. The files of one family are laid out edition by edition, an anchored media's edition making one work: the files an edition already holds are grouped among themselves, the new files of the request among themselves with the files of the edition they join, so a version never spans two editions, whatever the format (several `mp3` of two languages in one folder stay two versions), and a relay or a rescan keeps each file where it is. The new files of a family without a request language join the edition of the one language they say (tags or OPF, else a trailing ` (xx)` of the name), the untagged ones with them; when they say several, each version goes by the first language one of its files says. That language picks the edition that has it, else an edition with no language and no part (it takes the language), else a new edition of that language when every edition has another language, else the first edition. An edition that has an external id or a publisher is never taken over by another language: a new edition is made. The edition keeps what it has and takes, where a column is NULL: `format` when every version of the family has one format, `durationSeconds` (audio) the sum of the probed durations of the first version, `language` and `publisher` from the first file (`info.tags` or the OPF), never `title`. A later merge (`book-metadata.md` rule 8) overwrites them under its own locks.
8. The folder of a file is the folder of the media's want of its family and the request's language (else the first want of the family, language NULL first; `wants."folderId"`) when it belongs to the media's library, else the library's default folder (`books::folder_for`). A transferred file lands under `<folder root>/<folderName>`; the file name is `apply_book_format(formats.book, tokens)`, then ` (<language>)` (the language of the request, as the edition holds it; none, no suffix), so two languages of one format never share a name, plus, for a version of several files, ` - NN` (the 1-based index, two digits) before the extension; the folder name of an unnamed media is `apply_book_format(formats.book_folder, tokens)` (`pin_folder`, never `movie_folder`), validated as one component. The tokens are the title and year of the media, nothing else (`naming.md` rule 24). A file is named when it is transferred and never renamed afterwards: an edition that learns its language later (a tag, a merge) keeps its file names. Before any transfer, a file whose destination (after the unique name of a collision) would be a file of another work of an anchored media (rule 10) is refused with an error and left at its source, counting the files the same request already placed; a move whose source is a file linked to another media is refused likewise, for a video as for a book.
9. A book is not a video: a transfer keeps every file of the request (no "largest file" selection), no companion files travel, no crop, no OpenSubtitles hash, no sprite, no keyframe scan, no subtitle search and no intro detection runs for it. The event is `MediaFilesImported` with the family of the first file.
10. The `folderName` of a book is `''` or a relative path under the library folder root, one or several components (`Title`, `Author/Title`, `Author/Series/Title`), each valid as `ingest.md` rule 3 says, never `.` or `..`; `M` is the folder root joined with it. A media is anchored by its folder (`folderName` is that path) when its work is the only one of its directory: `dir` of `group` (rule 2), where no other work, counting every book file there, linked or not and of any media, has the same `dir` or a `dir` below it, and every file of the work that is already linked belongs to a media of that same `folderName`. Otherwise (a loose file, several works in one folder, a work whose folder holds another) its `folderName` is `''` and it owns its files by path, every work its own media. A media with no folder name owns files at any depth for a book (`ingest.md` rule 52 allows only the library root for a movie). An anchored media owns what is under `M`: a rescan walks `M`, skips the files that another media owns, and never takes a file of another work. Ceiling: a part added later to a work with no folder name is not found by a rescan; the orphan scan offers it again, and offering it again to the same media (retry) finds the media by the paths its files hold. Deleting a book removes the files it owns and then every directory of them, up to its folder, that is left empty (`media-write.md` rule 70): a file it does not own, linked or not, and the directory holding it stay.

### Optional m4b merge

18. A library with `libraries."mergeM4b"` (default `false`) merges the first version of the first audio edition without an `m4b` that has a version of several files (a version never spans editions) into one `.m4b`, registered in that edition (the parts' edition, whatever the file's tags say), through the engine `Merge` job (`hello.jobFamilies` must list `Merge` for `audio`). The option read is the one of the library the audio edition lives in (`COALESCE(editions."libraryId", media."libraryId")`), and it is read again under the media lock before registering. Triggers: the settle of a book (rule 16) and turning the option on, which queues the books of that library (selected by that same `COALESCE`) in one background backfill per library: a repeated toggle or a concurrent PATCH starts none while one runs (it asks the running one for another round, which also forgets the failures anew), and a restart drops what is left of it (the next settle of a book resumes it). Turning the option on also deletes the library's `failed` and `retry` rows.
    - Candidate: in an audio edition with no `m4b` file, the first version of several files (an edition whose version is the one a recorded failure or a retry not yet due names is skipped for the next; editions whose library has the option off are not looked at) (at most 500), all probed with the current `probeVersion` and a positive duration, with no control character in a path, in one library folder and one work directory (rule 2, disc folders off). The output is `<work folder>/<name>.m4b` (`<name> (<language>).m4b` for an edition with a language when the media has another audio edition with files, rule 8), `name` being, for a media anchored to its folder (`media."folderName"` set), the nearest folder that is not a format name (`mp3`, `m4a`, `flac`, `ogg`, `opus`, `aac`, `audio`, `audiobook`, `parts`), else (and always for a media not anchored, which shares its folder) the title with path characters replaced. A version in which two parts end with the same number (two books interleaved) is never merged. The free space of the output directory must cover the parts' sizes plus 1 GiB, measured right before the job is submitted.
    - One merge runs at a time in the server (settle and backfill alike), and runs of one media are serialised. The job runs without holding the media lock or the `folder_moves` lock. Under both, once it ends: every part must still have its row, place, size and mtime in the database and on disk, and the probe of the output must match the result (audio stream, size, duration within the larger of 1% and 5 s, chapter count); then `register` (rule 6) must register exactly that file. The server never deletes a file it cannot prove the engine wrote for this run: after a failed check the output is removed only when no `media_files` row holds its `(folderId, relativePath)` (a rescan may have registered it first), its size is the job result's `bytes` and it was modified since the job was submitted; any other file is left and logged. The failure is returned. The server deletes no temporary file; the engine owns `.<output>.merge-*.tmp`. A resubmit after a restart is answered by the engine with the id of the identical job still open, and waits on it.
    - `book_merges("editionId", "mediaId", fingerprint, state, "folderId", output, "jobId", merge, error, attempts, "nextAttemptAt")` keeps one row per audio edition (another edition's merge never overwrites it), with the fingerprint (id, version, size, mtime, path of every part). `running`: a run is in flight. `replace`: the m4b is registered, the parts stay while someone listens and `merge` holds the job result; a later run of the media tries the replace again when the option is still on, the m4b is there and the parts are the ones of the recorded fingerprint, and ends the row once it is done or a proof fails (a changed or removed m4b included); a held replace schedules its own retry every 10 minutes while someone listens. `failed`: a failure the parts explain (the probe of the output does not match the result, registration refused it, the engine answered 400, a part has no contained path or no probe); it stops the merge while the fingerprint is the current one. `retry`: any other failure (engine or transport error, a job that failed, stalled or timed out, no disk space, a part that changed during the merge, the option turned off); a second ffmpeg failure of the job on the same fingerprint (`jobFailures`, kept apart from `attempts`; an ffmpeg killed by a signal does not count) turns it `failed`; the others wait until `"nextAttemptAt"` (a minute, doubling, at most an hour), `attempts` counts them, the first 5 are re-run by the server after the delay, then only the next settle or backfill tries again.
    - `"jobId"` is the engine job id, stored when the job is submitted and cleared when a run is recorded. A run that finds a `running` or `retry` row with a `jobId` asks the engine for that job (`GET /v1/jobs/{id}`): an open job for the same parts is waited for through the resubmit at the stored `output` (even when the title changed since), which the engine dedupes onto it; a `done` one whose `path` and `bytes` match an unregistered file at the stored `output`, for the same parts, is verified like a fresh result and registered under the media lock and the `folder_moves` read lock; a `failed` or `cancelled` one left nothing and the run starts over. A file the job does not vouch for, a job for other parts, or a job the engine lost leaves the file in place, logged, drops the job id and goes on as a fresh run (the engine then refuses the taken name, which is retried). Nothing is deleted there.
    - `libraries."mergeM4bReplace"` (default `false`, read with `mergeM4b`: it does nothing while that one is off, and is read again under the media lock) removes the parts once the merge is done; it is not applied to merges made before it was turned on. Under the media lock and the `folder_moves` read lock, after `register` committed the m4b: the parts and the output must still be at the paths the job used (a library folder re-pointed meanwhile moves no file), the m4b is probed again and must match the job result within `2 s + 0.1 s per part (not relative: a long book must not lose minutes)`, a tighter bound than the registration check (the path check also runs before `register`); then every part must still be what the merge read (row id, version, folder, path, size and mtime in the database and on disk, a non-null mtime, a regular file that is no symlink and whose realpath is itself, a `safe_rel` path), each part must be linked to exactly one item and the m4b to that same item, and no live session may name that item or one of the files and no playback state of the item may have been saved in the last 10 minutes. Any failed proof keeps all the parts (a version cut short would play a wrong timeline), logged, and the merge still succeeds. Otherwise, in one transaction under the versions lock: `item_version_aliases("itemId", version, "toVersion")` records the parts' version as replaced by the m4b's, and each `playback_states` row of the item that names a part (or that version) is pointed at the m4b (the `playback_states_version` trigger moves its saved version; `positionSeconds` stays, the item timeline being the same). The rows of all the parts are deleted in that same transaction (`item_parts` cascade, all or none). After the commit each file gets a contained unlink (no recycle bin exists); a failed unlink, or a crash after the commit, leaves an orphan part file, logged, never a missing one; a later scan may import it again as a new version of the item (no loss). Nothing is deleted outside the library root and no directory is removed. `item_version_aliases` rows are dropped with the last file of their `toVersion`.
    - A `?version=n` (item playback-info, chapters) naming a version that no `item_parts` row holds resolves to its alias when the aliased version exists (`item-delivery.md` rule 3, `books-api.md` A6); a delivery that names a removed file is refused as any file the item no longer has, while a heartbeat naming one is saved with a NULL `mediaFileId` (`heartbeat.md`).
    - Without `mergeM4bReplace` the parts are never deleted or moved. The m4b is one more version of the item (rules 4-5) and the highest one, so playback and chapters default to it (`item-delivery.md` rule 3, `books-api.md` A6) unless the caller's saved state or `?version=` names the parts; `watched` also picks the highest version. Deleting the m4b makes the next settle merge again.

### Archive, tags, hashes, cover

11. `archive::read_epub(path)` opens the file as a zip and returns its `OpfMetadata` and its cover, or nothing: a file that is no zip, has no OPF or fails to read is a file with no package metadata, never an error. The OPF path comes from `META-INF/container.xml` (`opf::container_rootfile`), else the first entry ending in `.opf`. `container.xml` and the OPF are read through a cap of 2 MiB each (`books-files.md` rule 4), whatever the zip declares: a longer entry is no metadata. The cover is the entry of `cover_href` (`opf::resolve_href`), read through a cap of 16 MiB and kept only when it is a JPEG, a PNG, a WebP or a GIF by its header.
12. `tags::audio_hints(tags, guess)` maps the engine's `info.tags` of an audio file to `BookHints` (family `audio`): `title` the album, else the title; `authors` the artist, else the album artist, split on `;`, ` & ` and ` / `; `narrators` the narrator tag, split likewise; `language` through `normalize_language_code` (`und` is none); `series` the series with the part as `series_part` text; `year`; `isbns` the ISBN tag through `isbn::parse` (a bad one is dropped); `asin` through `ExternalProvider::Asin.normalize`. Every field the tags lack comes from `filename::parse_path(name_path)` (title, authors, narrators, series, year). `epub_hints(meta, guess)` does the same from the OPF: the title, the `aut` creators, the `nrt` creators, the language, the series, the year, every ISBN and the ASIN, with the name guess as the fallback of each. `*_record` builds the `file` record `attach_with` takes (`title`, `subtitle`, `authors`, `narrators`, `language`, `publisher`, `year`, `overview`, `subjects`, `series`, `isbn13`, `asin`, `releaseDate`, `format`, `durationSeconds`), omitting what is absent.
13. The KOReader partial MD5 of every text file is stored in `media_file_hashes("mediaFileId", kind = 'koreader', hash)` (`books-files.md` rule 40), refreshed when the file's size or mtime changes; the row goes with its file. A file that cannot be read has none.
14. The cover of the work comes from the EPUB archive, from a CBZ's first page (`comics.md` rule 20, the same rendering as a comic volume's poster) or from the engine: for an audio file whose `info.cover` is set, the post-import queue submits a `Cover` job when `hello.jobFamilies` lists `Cover` for `audio`, reads the picture at `GET /v1/covers/{mediaFileId}` and stores it. The picture is read through a cap of 16 MiB (a longer answer is no cover) and becomes `media."posterUrl"` through the image store only when the media has none, written under one lock per media so two ingests of one book store it once; the edition cover is not written (`book-metadata.md` rule 13).
15. The post-import queue runs a job only when `hello.jobFamilies` lists its kind for the family of the file (`Engine::job_applies`); a kind the hello does not list, and every kind while no hello is held, applies to video only. `info.tags` and `info.cover` stay in `streamInfo` as the probe wrote them: the queue never re-probes an audio file.

### Identification

16. `ingest::books::identify_media(st, media)` runs when the media's post-import queue is idle (the settle timer): for each edition without an id it builds the hints of its first file (rule 12), calls `identify` at `Background` priority and, on a match, `attach_with` with that edition and the file record. When the work already holds an id, the stored match (`link::stored`) is attached to the edition whatever `identify` finds, and a match of the same work adds its edition ids. An edition that has an id is not identified again, unless the media holds no anchor work (an edition imported from an edition provider that no work answered for); a relink with a chosen work is therefore never moved by the settle; a match that is not found leaves the work unmatched but still merges the file record alone (`attach_with` without a match: no work or edition id is linked, the title, authors, overview and the other fields the file carries are written with `file` provenance, a locked field kept), and the next metadata refresh identifies it. A provider outage while identifying a book that holds no work still merges the file record, then reports the outage for the retry. A title typed in the scan panel that differs from the guess from the files is locked at the creation of the media, so the file title never replaces it. A disabled anchor provider or a failed provider call is an error of `identify_media`, not a missing match: only an outage (anchor disabled or unavailable, circuit open, transport failure, 429, 5xx) is retried, by the settle timer arming itself again; any other error is logged and ends the attempt. No error of identification fails an import. At startup, after migrations, a sweep settles one at a time every book that has a file, no external id and no `metadataRefreshedAt` (a book imported before the file record was merged); a settle stamps `metadataRefreshedAt`, so a book leaves the sweep once merged.
17. The ingest never writes external ids, facts, credits or series (`attach` does), and the metadata side never writes files, editions, items or parts. The ingest holds the media's lock and the `folder_moves` read lock across resolve, move and insert; identification holds neither.

## Tests

Golden: `fixtures/books-grouping` (a folder of parts, `CD1`/`CD2`, mixed formats, a single `m4b`, an ebook and an audiobook side by side, several ebooks in one folder, a nested work), `fixtures/books-tags` (the `info.tags` an `m4b`, an `mp3` and a `flac` carry), all synthetic. The EPUB reader runs on real zips built in the test (EPUB 2 and 3, a zip bomb, no OPF, no zip). `ingest/tests.rs` (`book_ingest`) runs a transfer, a link in place, a rescan and an identification against a throwaway database and a fake engine. It also covers the delete that keeps a loose book's files and the ones it does not own, the second work refused before its move, the positions closing up after a part goes, the rescan beside other books, an `Author/Title` anchor (rescan, delete), the scan anchors and the cover lock.

18. Hints are the file record's `title`, `authors`, `narrators`, `language`, `series`, `year`, `isbn13` and `asin` read back (`BookHints::of_record`): no parser fills a hints structure of its own.
