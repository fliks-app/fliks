# Spec: metadata (`/api/metadata/*` + TMDB / TVDB clients)

Scope: the `/api/metadata/*` routes and the TMDB / TVDB clients (circuit breaker: 3 failures open it for 30 s; stale fallback for lists; locale cache). Auth, error-body and validation rules are in `auth.md` ("auth rule N"); images the clients' URLs feed are `image-store.md`; the persons consumer is `persons.md`; library ACL is `libraries.md` rules 30-36. 4xx/5xx `Cache-Control: no-store` = `bootstrap.md` rule 7.

Everything that calls the clients (media import/refresh, requests, scheduler `RefreshMetadata*`, persons) shares one in-process Rust module, `metadata::{tmdb,tvdb,breaker,language}`; the providers sit behind one trait and a rate limiter (`metadata-orchestrator.md`).

## Routes

19 routes, all in the metadata controller. Class-level `JwtOrApiKeyGuard` only; **no policy check**: any authenticated user passes, whatever their permissions. Anonymous = 401 (auth rule 14); a `scope:'stream'` token is 401 (auth rule 12). No DTOs: query strings are read as bare strings, unknown keys are ignored, nothing else is validated. All GET = 200 on success.

Shapes. `Search` = `MetadataSearchResult` (rule 24); `Listed` = `Search & {existingMediaId: number|null, existingMediaType: 'movie'|'series'|null}` (rule 12; `Search` unchanged on an empty list). `Details` = `MetadataDetails` (rules 26-30). `Season` = `{seasonNumber:number, episodeCount:number, overview:string|null, airDate:string|null, posterUrl:string|null, episodes:{episodeNumber:number, title:string, overview:string|null, airDate:string|null, runtime:number|null, stillUrl:string|null}[]}`. `Stub` = `{seasonNumber:number, episodeCount:number}`. `Genre` = `{id:number, name:string}`.

## Rules

### A. Routing and input

1. Guards as above. `JwtOrApiKeyGuard` + no policy means `readonly` and a user without `media.read` can search and read details (no library data is exposed except rule 12).
2. Query parsing: a repeated key is an array (media-query rule 4), `a=` is `''`. `q` is trimmed; a repeated `q` is 400 with the standard validation body. `year`, `provider`, `mediaId`, `window`, `genres`, `sort`, `voteGte`, `yearGte`, `yearLte` are never validated.
3. Route overlap: the 2-segment routes (`search/*`, `trending/*`, `popular/*`, `upcoming/*`, `genres/*`, `discover/*`, `movie/:tmdbId`, `tv/:tmdbId`) and the 3/4-segment ones (`:provider/movie/:id`, `:provider/tv/:id[/seasons|/season-stubs]`, `tv/:tmdbId/seasons`) cannot match the same path except `/tv/tv/seasons`-style literals. The static-over-param router (matchit) routes `/tv/tv/seasons` to `tv/:tmdbId/seasons` (id `"tv"`); that id is non-canonical (rule 39), so it answers 400 (parity compares `statusCode` + `error`). Tests cover `GET /api/metadata/tv/tv/seasons` and `GET /api/metadata/movie/search` (the latter is `movie/:tmdbId`, id `"search"`, rule 15).
4. Search: `query = q?.trim()`; falsy (missing or blank) → 200 `[]` before any provider or DB call.
5. `year`: `year ? +year : undefined`; the provider adds the filter only when the number is truthy, so `year=abc` (NaN), `year=0` and `year=` are dropped silently (TMDB param `year` for movies, `first_air_date_year` for tv; TVDB `year` as `String(year)`).
6. Provider choice: `providerName ?? providerPreferredFor(mediaId)`, then `registry.resolve(name ?? null)`: the named provider is used **iff available**, i.e. its API key env var is truthy (rule 20); an unknown name (`foo`), or `tvdb` without `TVDB_API_KEY`, silently resolves to TMDB (the default, whether or not `TMDB_API_KEY` is set). `provider=` (empty string) is not nullish, so `mediaId` is not consulted and the result is TMDB. The registry and `resolve` are in `metadata-orchestrator.md` rules 8-9.
7. `providerPreferredFor(mediaId)`: `id = mediaId ? parseInt(mediaId, 10) : NaN`; not an integer (`Number.isInteger`) or `< 1` → no preference (`parseInt('12abc')` is 12, kept); an id beyond int4 → no preference. Unknown media → no preference. Otherwise `media.preferredProvider ?? media.library?.preferredProvider ?? undefined` (media override, then library, then none). One query (SQL Q1). The result only seeds `resolve`, it is not validated.
8. Empty-result fallback: when the chosen provider returns `[]`, `registry.getFallback(provider.name)` = the other provider **if available**; if so it is queried with the same arguments and its result (possibly `[]`) is returned; one `log` line. No fallback when the other provider has no key. The fallback is inside the same `try` (rule 10). `fallback` also requires the other provider to support the kind (`metadata-orchestrator.md` rule 9).
9. Results of the fallback keep their own `provider` field (`tvdb` results for a TMDB search); the client treats `provider` as authoritative.
10. Failure: any exception from the primary or the fallback (HTTP client error, breaker `CircuitOpenError`, TVDB `Error('TVDB API key not configured')`) → **503** `Metadata search failed on <provider.name>: <reason>` with `provider.name` the *primary* provider and `error: "Service Unavailable"`; the error is logged. `reason`: for an HTTP answer `HTTP <status>`, for a missing answer the error code name (`ECONNABORTED` timeout, `ECONNREFUSED`, `ENOTFOUND`, `ECONNRESET`) or `network error`, then ` — ` + `body.status_message ?? body.message ?? error message`; a non-HTTP error gives its message (`tmdb circuit open — upstream temporarily unreachable`). Parity compares only `statusCode` + `error`. The message **never contains the request URL** (rule 21: TMDB v3 puts the API key in the URL and `reqwest::Error`'s `Display` prints it; `without_url()` is used).
11. Search results are never cached or stale-served (no `withStaleFallback`); each call is one upstream request (two with the fallback).
12. `enrichWithExisting(results, type)` (every list route except genres): empty list → returned as is. Else `tmdbIds = results.map(tmdbId).filter(>0)`, `tvdbIds = results.map(tvdbId).filter(truthy && >0)`; one query over `media_external_ids` for the media of kind `$t` holding one of those ids (only the non-empty arms; none → no query) selecting `id, tmdbId, tvdbId` (SQL Q2); `type` is `'movie'` for movie routes and `'series'` for tv routes. Per result the match is the TMDB-keyed media first, else the TVDB-keyed one; output `{...result, existingMediaId: id|null, existingMediaType: type|null}`. `existingMediaType` is therefore the route's own type or `null`. A TMDB id and a TVDB id can name two different media, and a TVDB id can name several (it is not unique); the last row of the `ORDER BY id ASC` query is kept per arm. Only media in libraries the caller can read are matched (rule 38): others report `null`.
13. `window`: exactly `day` → `day`, anything else (missing, `DAY`, array) → `week`. It is part of the stale-cache key (rule 17).
14. Discover parsing: `genres` split on `,`, each `parseInt(_, 10)`, non-finite dropped (`'28,abc,12'` → `[28,12]`, `'28|12'` → `[28]`), empty → no filter; `sort || undefined` forwarded verbatim (no whitelist); `voteGte ? parseFloat : undefined`; `yearGte`/`yearLte ? parseInt(_, 10) : undefined`; the provider adds a filter only when the number is truthy (NaN and `0` are dropped). Movie params: `language, include_adult='false', sort_by=<sort or popularity.desc>, 'vote_count.gte'=50, with_genres='<ids joined ,>', 'vote_average.gte', 'primary_release_date.gte'='<Y>-01-01', 'primary_release_date.lte'='<Y>-12-31'`. TV params: same minus `include_adult`, dates are `first_air_date.gte/lte`, and the first `primary_release_date` in `sort` is rewritten to `first_air_date`. No stale fallback: an upstream error is a 503 (rule 39). All query values are URL-encoded by the HTTP client.
15. Detail routes: `registry.get(name)` (exact `tmdb` or `tvdb`, **availability not checked**) else 400 `Unknown provider: <name>`. The id (`externalId` / `tmdbId`) must be a canonical integer, else 400 (rule 39; auth rule 18); upstream 404 → 404 `not_found`; other upstream failures → 503 (rule 39). `tvdb` without key → `Error('TVDB API key not configured')` → 503.
16. `season-stubs` and the deprecated `tv/:tmdbId/seasons` are separate costs: stubs = one call (TMDB `GET /tv/{id}` seasons list, TVDB paged episode listing, rules 31, 32), `seasons` = every season with episodes (rules 31, 32). Season 0 (specials) is kept by both providers.

### B. Provider selection state, language, cache

17. Stale list fallback (TMDB only): `trending:<movie|tv>:<window>:<tmdbLocale>`, `popular:<movie|tv>:<tmdbLocale>`, `upcoming:movie:<tmdbLocale>:<region>`, `upcoming:tv:<tmdbLocale>`, `genres:<movie|tv>:<tmdbLocale>`. In-process `Map<string, mapped payload>`, no TTL, no size cap beyond the key space, lost on restart. Every successful live fetch overwrites the entry; a failure (any error, including breaker-open) with an entry returns the last copy and logs a warn; a failure without an entry (cold) propagates (route 503, rule 39). The cached payload is the provider-mapped array before `enrichWithExisting`, so `existingMediaId` is always fresh. Search, discover, details and seasons are never stale-served.
18. Circuit breaker (TMDB only): consecutive-failure counter `failures`, `openUntil`. A failure is transient when there is no response (timeout, DNS, refused, reset), HTTP 429 or `>= 500`; 4xx other than 429 is a real answer: it neither counts nor resets `failures`. On a transient failure `failures += 1`; when `failures >= 3` and now `>= openUntil`, `openUntil = now + 30 s` and a warn is logged. While `now < openUntil` every request is rejected **before sending** with `CircuitOpenError` (`<name> circuit open — upstream temporarily unreachable`); that rejection still runs the response error handler (no response = transient), so `failures += 1` for it too, without reopening (`now < openUntil`). Any successful response resets `failures` to 0 (logs "recovered" only if it was > 0). There is no half-open limit: after the cooldown all requests pass, and since `failures` is still `>= 3` the first transient failure reopens for another 30 s. This exact machine is pinned by the unit tests of `crates/domain/src/metadata/breaker.rs`. The request limiter sits before the breaker and the breaker records one outcome per call (`metadata-orchestrator.md` rules 17-20).
19. TVDB has the same breaker as TMDB (3 failures, 30 s), a single-flight login (concurrent first calls share one `POST /login`) with a 15 s timeout, and one re-login on a 401 (rule 40). The single-flight login stays inside the TVDB client (`metadata-orchestrator.md` rule 7).
20. API keys are **environment**, not settings: `TMDB_API_KEY`, `TVDB_API_KEY` (`config.md`; secrets stay out of `app_settings`). A provider is "available" iff its variable is non-blank after trim (`registry.isAvailable`, `getAvailable`); TMDB is always the default even when unavailable (its calls then fail with TMDB's 401 → rule 10 / 503). TMDB sends the key as query param `api_key` on every request, timeout 10 s; TVDB logs in with `POST https://api4.thetvdb.com/v4/login {apikey}` and sends `Authorization: Bearer <token>`, timeout 15 s (login: 15 s, rule 40). Both providers are always registered, available or not (`metadata-orchestrator.md` rule 8).
21. No URL, query string or header ever reaches a log line, an error body or `reason`: the TMDB key travels in the URL and `reqwest` errors embed it (`Error::without_url`).
22. TVDB token: kept in process memory with expiry now + 25 days (valid 30); refreshed lazily at the next call after expiry; a token the server revoked is replaced by the single re-login on a 401 (rule 40).
23. Language / region (`MetadataSettingsCache` + `resolveMetadataLanguage`): global `metadata_language` and `metadata_region` are read from `app_settings` once, concurrent first reads share one load, and the cache is dropped when either key changes; an in-flight load invalidated mid-flight does not commit its value (epoch). `resolve(override?)` merges per call: `override.language ?? global.language`, `override.region ?? global.region` (`??`: an empty string override wins over the global value). Pure resolution: `lang = (language ?? '').toLowerCase().split(/[-_]/)[0]`, found in the 12-row table (`en fr es de it pt nl pl ru ja ko zh`, with `tvdbCode eng fra spa deu ita por nld pol rus jpn kor zho` and `defaultRegion US FR ES DE IT PT NL PL RU JP KR CN`), unknown/empty → `en`; `region = (region ?? '').toUpperCase() || opt.defaultRegion` (any string, not checked against the 18-row region table: the table is client UI data); `tmdbLocale = <iso1>-<region>`; `includeImageLanguage = en → 'en,null'`, else `<iso1>,en,null`; `logoIso1 = iso1`; `tvdbCode`; `releaseDatePriority = region 'US' → ['US'] else [region,'US']`. Unknown language keeps the given region (`xx` + `FR` → `en-FR`). The cache is in-process and invalidated by the settings write path.

### C. Provider response mapping

24. `Search` (list and search results). TMDB movie, tv: `{tmdbId: id, provider:'tmdb', title (tv: name), originalTitle, overview, year, posterUrl, fanartUrl, rating, genres: [], genreIds, mediaType}`; `year = release_date ? parseInt(release_date) : null` (tv: `first_air_date`; `parseInt` of a date string = the year; NaN serialises as `null`), `posterUrl = https://image.tmdb.org/t/p/w500<poster_path>|null`, `fanartUrl = https://image.tmdb.org/t/p/original<backdrop_path>|null`, `rating = vote_average ?? 0`, `genreIds = genre_ids ?? []`, `mediaType` `movie`|`series`. TMDB results have **no** `tvdbId`/`imdbId` keys (absent, not null). TVDB: `{tmdbId, tvdbId, imdbId, provider:'tvdb', title, originalTitle, overview, year, posterUrl, rating: 0, genres, mediaType}`: `tmdbId = parseInt(<id of the first remote_ids entry with sourceName 'TheMovieDB.com'> ?? '0')` (0 when absent), `tvdbId = parseInt(r.tvdb_id ?? r.id)`, `imdbId = <same for sourceName 'IMDB'>|null`, `title = r.translations?.[tvdbCode] ?? r.name`, `originalTitle = r.name`, `overview = r.overviews?.[tvdbCode] ?? r.overview ?? ''`, `year = r.year ? parseInt : null`, `posterUrl = r.image_url ?? r.poster ?? null`, `genres = r.genres ?? []` (names); no `fanartUrl`/`genreIds` keys. Result order is the provider's.
25. `Details` keys always present for both providers (value `null`/`[]` when absent): `tmdbId, tvdbId, imdbId, provider, title, originalTitle, overview, year, posterUrl, fanartUrl, logoUrl, additionalFanartUrls, rating, genres, mediaType, runtime, seasonCount, episodeCount, releaseDate, inCinemas, digitalRelease, physicalRelease, status, budget, revenue, originalLanguage, productionCountries, productionCompanies, voteCount, popularity, tagline, cast, crew, videos, keywords, alternativeTitles, tmdbCollectionId, tmdbCollectionName`; plus `genreIds` on TMDB only (TVDB: absent). Items: `cast: {externalId, name, character, avatarUrl, order}`, `crew: {externalId, name, job, department, avatarUrl}`, `videos: {key, site, type, name}`.
26. TMDB movie details `GET /movie/{parseInt(id)}` with `language=<tmdbLocale>`, `include_image_language`, `append_to_response=external_ids,images,release_dates,credits,videos,keywords,alternative_titles`: `tvdbId/seasonCount/episodeCount = null`; `imdbId = external_ids.imdb_id ?? imdb_id ?? null`; `year` as rule 24; `posterUrl w500`, `fanartUrl original`; `logoUrl` (rule 28); `additionalFanartUrls` (rule 28); `rating = vote_average ?? 0`; `genres` names, `genreIds`; `runtime ?? null`; `releaseDate = release_date ?? null`; `inCinemas/digitalRelease/physicalRelease` from release dates (rule 29); `status = status?.toLowerCase() ?? 'unknown'`; `budget`/`revenue` `|| null` (0 becomes null); `originalLanguage ?? null`; `productionCountries` = country names; `productionCompanies` = company names; `voteCount`, `popularity` `?? null`; `tagline || null`; `cast`/`crew` from `credits` with `avatarUrl = https://image.tmdb.org/t/p/w185<profile_path>|null`; `videos` from `videos.results`; `keywords = keywords.keywords[].name`; `alternativeTitles` (rule 28); `tmdbCollectionId/Name = belongs_to_collection.id/name ?? null`.
27. TMDB tv details `GET /tv/{id}` (same params minus `release_dates`): `tvdbId = external_ids.tvdb_id ?? null`, `imdbId = external_ids.imdb_id ?? null`, `title = name`, `originalTitle = original_name`, `year` from `first_air_date`, `runtime = episode_run_time[0] ?? null`, `seasonCount = number_of_seasons ?? null`, `episodeCount = number_of_episodes ?? null`, `releaseDate = first_air_date ?? null`, `inCinemas/digitalRelease/physicalRelease = null`, `status` via `Returning Series→continuing, Ended→ended, Canceled→ended, In Production→announced, Planned→tba`, else `unknown`, `budget/revenue = null`, `productionCountries = origin_country ?? []`, `productionCompanies = networks names then production_companies names`, `keywords = keywords.results[].name`, `tmdbCollectionId/Name = null`.
28. TMDB artwork picks: `logoUrl` = best of `images.logos` (those with `file_path`) by `vote_average ?? 0` plus a language bonus (`+0.5` when `iso_639_1 == logoIso1`, else `+0.25` when `en`, else 0), highest score first (ties keep the provider order: the sort is stable), URL `…/original<file_path>`, `null` with no logo; `additionalFanartUrls` = `images.backdrops` with a `file_path` other than `backdrop_path`, sorted by `vote_average ?? 0` descending (stable), first 5 (`MAX_ADDITIONAL_FANARTS`), `…/original<file_path>`; `alternativeTitles` = movie `alternative_titles.titles[].title` / tv `alternative_titles.results[].name`, trimmed, empties dropped, de-duplicated case-insensitively against `title/name`, `original_title/original_name` and earlier entries, original casing kept.
29. TMDB release dates (movie): countries from `release_dates.results` sorted by index in `releaseDatePriority` (unlisted = 99, stable); the first country carrying a given `type` wins (`rd.release_date` non-empty, first 10 chars); `inCinemas = type3 ?? type2 ?? type1 ?? null`, `digitalRelease = type4`, `physicalRelease = type5`.
30. Cast: `Actor` and `Guest Star` characters sorted by `sort ?? 999`, `{externalId: peopleId, name: personName, character: name, avatarUrl: personImgURL ?? null, order: sort ?? index}`; crew: every other non-empty `peopleType`, `{externalId: peopleId, name: personName, job: peopleType, department: peopleType, avatarUrl}`.
31. TMDB seasons: stubs = `GET /tv/{id}?language=` → `seasons[] → {seasonNumber: season_number, episodeCount: episode_count ?? 0}` (season 0 kept); one season `GET /tv/{id}/season/{n}` (`episodeCount = episodes.length`, `overview || null`, `airDate || null`, `posterUrl` `w500`, episodes `{episodeNumber, title: name, overview || null, airDate || null, runtime ?? null, stillUrl w780 | null}`); full list = stubs then one request per stub with **at most 8 in flight** (`SEASON_FETCH_CONCURRENCY`), results in stub order, a season that fails (including breaker-open) is warned and dropped.
32. TVDB seasons: episodes via `GET /series/{id}/episodes/default?page=<n>` from page 0 while a page holds `>= 500` items (a page of exactly 500 triggers one more request); stubs = per-`seasonNumber` counts sorted ascending (no translation fetch, no season-extended call). Full list additionally calls `GET /series/{id}/extended?short=true` (official / "Aired Order" season bases give `posterUrl = image || null`, `airDate = base.year ?? first episode aired ?? null`), then fetches `GET /episodes/{id}/translations/{tvdbCode}` for each episode advertising `overviewTranslations` or `nameTranslations` containing the code, **8 in flight** (`EPISODE_TRANSLATION_CONCURRENCY`), a failed translation is skipped silently; episode `title = translation.name || ep.name`, `overview = translation.overview || ep.overview || null`; episodes sorted by `number`, seasons by `seasonNumber`, season `overview` always `null`.
33. External-id lookup (`findByExternalId`, not a route; called by media import / refresh): TMDB `GET /find/{id}?external_source=imdb_id|tvdb_id&language=` (any other source → `null` without a call): first `movie_results` → `{id: String(id), mediaType:'movie'}`, else first `tv_results` → `'series'`, else `null`; TVDB ignores `source` and calls `GET /search/remoteid/{id}`: first result with `series` then `movie`; an error of that call → `null` (swallowed), but `ensureAuth` runs outside the `try`, so a missing key or failed login propagates.
34. Person lookups used by `persons.md`: TMDB `GET /person/{id}?language=` (`avatarUrl` `w500`, `birthday/deathday/placeOfBirth ?? null`, `biography`/`knownForDepartment` raw) and `GET /person/{id}/combined_credits?language=` (`title = title ?? name ?? ''`, `media_type 'tv'` → `series` else `movie`, `posterUrl` `w500`, `fanartUrl` `original`, `releaseDate = release_date ?? first_air_date ?? null`, `rating = vote_average ?? 0`); TVDB `GET /people/{id}/extended?meta=translations` (biography in the configured language, else `eng`, else `''`; `knownForDepartment` inferred: `Actor`→`Acting`, else `Director`→`Directing`, else `Writer`→`Writing`, else first type, default `Acting`) and `GET /people/{id}/extended` for credits (cast = `Actor`/`Guest Star`, every other `peopleType` (empty included, unlike details crew) is crew with `job = department = peopleType`, `posterUrl = work.image ?? c.image ?? null`, `mediaType = movieId ? 'movie' : 'series'`, `externalId = seriesId ?? movieId ?? 0`, `releaseDate = work.year ? '<year>-01-01' : null`, `rating: 0`, no `fanartUrl`).

### D. Rust specifics

35. Clients are two `reqwest` clients with the same timeouts (rule 20), JSON bodies, no HTTP cache. Base URLs and the image host come from config with the real defaults (`https://api.themoviedb.org/3`, `https://api4.thetvdb.com/v4`, `https://image.tmdb.org/t/p`) so tests and parity can point them at a mock (rule 42, Vectors/parity).. Each client has one process-wide rate limiter (`metadata-orchestrator.md` rules 12-21).
36. The breaker is a pure state machine in `fliks_domain` (clock injected) so rule 18 is unit-testable; TMDB and TVDB wrap their clients with it (rule 40). The limiter is the same kind of pure state machine (`fliks_domain::metadata::limiter`).
37. Date and number strings: `year` is `parseInt` semantics on the leading digits (`"2020-05-01"` → 2020, `""` → `null`); date fields pass through as the provider sent them except rule 29 (first 10 chars).

### E. Access control and failure mapping

38. `existingMediaId` (rule 12), persons credits and `provider-credits.mediaId` expose only media in libraries the caller can read (`persons.md` rule 21); others report `null`.
39. Input and upstream-failure mapping for the routes that have none (rules 2, 7, 14, 15, 17): repeated `q` → 400; a `mediaId` beyond int4 → no preference; `externalId`/`tmdbId` must be canonical integers (auth rule 18) → 400; unknown provider is 400; upstream 404 on a detail route → 404 `not_found`; breaker open / timeout / 5xx / TMDB 401 on a detail, list or discover route → 503 `Metadata request failed on <provider>: <reason>` (the search wording of rule 10); a cold list with no stale copy → 503.
40. TVDB single-flight login with a 15 s timeout, one re-login on a 401, and the rule 18 breaker.
41. Every upstream failure on list, discover and detail routes maps to 503 and an unknown external id to 404 (the identify modal and the add-media page treat any non-2xx the same).
42. Test seam: three env vars carry the TMDB, TVDB and image base URLs (`FLIKS_TMDB_API_URL`, `FLIKS_TVDB_API_URL`, `FLIKS_TMDB_IMAGE_URL`); test-only configuration, documented in `config.md`, not in the user docs.
43. The language cache (rule 23) is dropped by the settings write path when `metadata_language` or `metadata_region` changes.
44. The stale list cache (rule 17) is in-memory only and lost on restart; after a restart during an upstream outage every list route answers 503 (rule 39). There is no persisted payload.

### F. Write side (media services in process, `media-write.md` rules 16, 17, 53-58)

45. `crate::metadata::service` is the media services' only door to the providers: `import(lookup)`, `for_media(id)`, `seasons_for_media(id)`, `episode(id)`, `persist_credits(id, details)`. A provider failure on these paths is a generic 500 (`Internal server error`, the reason only logged); a failed `persist_credits` or season application never undoes the rows already written. Each of them takes the `Priority` of its caller (`metadata-orchestrator.md` rules 10-11).
46. Provider and id of a media (`resolveProviderForMedia`): the season's `preferredProvider` (strict), the media's (strict), the library's (soft, a warning when unresolved), then `tmdbId` with TMDB available, `tvdbId` with TVDB available, `tmdbId` unchecked, an IMDB-only media cross-referenced through TMDB, else 400 `No provider ID available for this media`. A strict override that cannot be resolved is 400 `Season override "<p>" cannot be resolved for "<title>" (#<id>): no matching external ID available (check API key + cross-reference).` or `Media override "<p>" cannot be resolved for "<title>" (#<id>): no matching external ID available.`
47. Cross-reference to provider `p` when the media lacks its id: TVDB: an IMDB lookup, then the TMDB details' `tvdbId`; TMDB: an IMDB lookup, then a TVDB-id lookup. A found id is linked to the media (`external-ids.md` rule 8; a TMDB id another media of its kind holds is skipped with a `WARN`, rule 9) before use; none found answers `null` (the strict callers raise rule 46's 400).
48. Language: the library's `metadataLanguage` / `metadataRegion` override the global ones for every call of a media in that library (rule 23); the import uses the destination library's.
49. `import(lookup)` (`readForLibrary`): details from the provider that found the title (`provider ?? default`); a library preferring another available provider gets the details re-read from it by the id the first provider reports, else an IMDB lookup, ids the second lacks kept from the first; unavailable or no id: the finder's data with a warning. A series reads every season from the provider used; a missing `tmdbId` with a `tvdbId` is filled by a TMDB lookup (no key: the lookup fails).
50. Seasons of a series (`refreshSeriesEpisodes`): the media provider lists every season; a DB season whose `preferredProvider` differs is replaced by that provider's single season (TMDB: the season endpoint; TVDB: its list, cached per run), the media-level data when that provider cannot be resolved or has no such season.
51. `persist_credits` (`persistMediaMetadata`): the details row of the media's kind (`movie_details` or `series_details`, `media-details.md` rule 14) is updated (a provider `null` or absent scalar keeps the column; an absent list keeps it, a present one replaces it) or inserted; persons are matched by `(provider, value)` in `person_external_ids`, the missing ones inserted with their id row in one transaction under an advisory lock (`persons.md`), names and avatars (data dir, concurrency 8) updated; the cast and crew `media_credits` of the media replaced in one transaction (a null character or job is `''`, a null order 0, a crew row's `position` is its list index); departments merged with `Acting` and each crew department, sorted; person details (biography, birthday, department) are not fetched here: `GET /api/persons/:id` refreshes a person unseen for 7 days when its page opens. The `persons."searchVector"` is maintained by a database trigger.

## SQL

- **Q1 preferred provider** (rule 7): `SELECT m."preferredProvider" AS media_pref, l."preferredProvider" AS library_pref FROM media m LEFT JOIN libraries l ON l.id = m."libraryId" WHERE m.id = $1`.
- **Q2 existing media** (rule 12): `SELECT m.id, ids.tmdb, ids.tvdb FROM media m LEFT JOIN LATERAL (<rule 5 of external-ids.md>) ids ON true WHERE m.type = $kind AND m."libraryId" = ANY($libs) AND m.id IN (SELECT "mediaId" FROM media_external_ids WHERE kind = $kind AND ((provider = 'tmdb' AND value = ANY($tmdb)) OR (provider = 'tvdb' AND value = ANY($tvdb)))) ORDER BY m.id ASC`; no query when both id lists are empty. `type` is `text` under a `CHECK` (`movie|series`).
- **Q3 language settings** (rule 23): two point reads in parallel, `SELECT value FROM app_settings WHERE key = $1` for `metadata_language` and `metadata_region` (settings `get`, absent row → `null`); Rust may use one `key IN (…)` query.

No writes.

## Events

None emitted or consumed. The cache invalidation (rule 23) is the in-process settings change hook, not an SSE or domain event.

## Settings keys

| Key | Default | Parsing |
|---|---|---|
| `metadata_language` | absent → `null` → `en` | any stored string; lowercased, split on `-`/`_`, first part; unknown → `en` (rule 23); also accepted as per-library override (`libraries.metadataLanguage`, media spec) |
| `metadata_region` | absent → `null` → the language's default region | any stored string, uppercased; empty → default region (rule 23) |

Environment (not settings, `config.md`): `TMDB_API_KEY`, `TVDB_API_KEY` (rule 20). There are no secret settings keys in this domain (none appears in `secretsSet`).

## Jobs/timers

None. In-memory state owned by this module: breaker counters, stale list map, TVDB token and expiry, language cache. The scheduled `RefreshMetadata` / `RefreshMissingMetadata` jobs (04:00) belong to the media/scheduler specs and only call these clients.

## Vectors/parity

No golden vector set: the rules are covered by Rust tests, `crates/domain/src/metadata/{language,breaker,discover}.rs` (language table across every `language` x `region`, scripted breaker sequences of `{at, outcome: ok|transient|client4xx}` incl. 429/5xx/timeout and the post-cooldown reopen, discover query strings to TMDB params incl. `genres='28,abc,12'`, `voteGte=NaN`, tv date rewrite) and `crates/server/tests/it/metadata.rs` (mapping of recorded TMDB/TVDB JSON to `Search`/`Details`/`Season[]`: logo and fanart picks, alternative titles, release dates with US/FR priority and missing types, tv status, translation and artwork picks, aliases, trailer key extraction, cast/crew split, season grouping incl. the 500-page boundary).

External HTTP is always mocked. `server/parity/external/` holds one fixture file per upstream request (`tmdb/<method>_<path>_<sorted query>.json`, `tvdb/…`, `img/*.jpg`). Rust (unit tests and the parity run) points `FLIKS_TMDB_API_URL`, `FLIKS_TVDB_API_URL`, `FLIKS_TMDB_IMAGE_URL` (rule 42) at a loopback stub serving that directory, with scripted failure modes per path. Recorded responses are real payload shapes (captured once by hand with a real key, never committed with the key).
