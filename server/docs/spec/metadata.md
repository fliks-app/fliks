# Spec: metadata (`/api/metadata/*` + TMDB / TVDB clients)

Sources: `[ts:src/modules/metadata-providers/metadata-providers.controller.ts:1-362]` (controller), `[ts:src/modules/metadata-providers/providers/tmdb.provider.ts:1-843]`, `[ts:src/modules/metadata-providers/providers/tvdb.provider.ts:1-675]`, `[ts:src/modules/metadata-providers/http-circuit-breaker.ts:1-69]` (breaker), `[ts:src/modules/metadata-providers/metadata-settings-cache.service.ts:1-81]` (locale cache), `[ts:src/modules/metadata-providers/metadata-language.ts:1-102]`, `[ts:src/modules/metadata-providers/metadata-provider.registry.ts:1-63]`, `[ts:src/modules/metadata-providers/interfaces/metadata-provider.interface.ts:1-175]` (all under `src/modules/metadata-providers/`), specs `*.spec.ts` there. Milestone: S5 (plan §10 S5: "`/api/metadata/*` + TMDB/TVDB clients, circuit breaker 3 failures → 30 s, stale fallback for lists, locale cache"). Tag paths are relative to `backend/`. Auth, error-body and validation rules are in `auth.md` ("auth rule N"); images the clients' URLs feed are `image-store.md`; the persons consumer is `persons.md`; library ACL is `libraries.md` rules 30-36. 4xx/5xx `Cache-Control: no-store` = `bootstrap.md` rule 7.

Everything that calls the clients moves in the same milestone (media import/refresh, requests, scheduler `RefreshMetadata*`, persons), so the clients are an in-process Rust module (`metadata::{tmdb,tvdb,breaker,language}`) shared by those domains, not a service Nest talks to (see Bridges).

## Routes

19 routes in the manifest (filter `.[]|select(.path|test("^/api/metadata"))` = 19, all `MetadataProvidersController`). Class-level `@UseGuards(JwtOrApiKeyGuard)` only; **no `PoliciesGuard`, no `@CheckPolicies`**: any authenticated user passes, whatever their permissions `[ts:src/modules/metadata-providers/metadata-providers.controller.ts:39]`. Anonymous = 401 (auth rule 14); a `scope:'stream'` token is 401 in Rust (F8, auth rule 12). No DTOs: query strings are read as bare `@Query('x')` strings, unknown keys are ignored, nothing is validated by the pipe. No `httpCode`: all GET = 200. Declaration order = Nest match order (rule 3).

Shapes. `Search` = `MetadataSearchResult` (rule 24); `Listed` = `Search & {existingMediaId: number|null, existingMediaType: 'movie'|'series'|null}` (rule 12; `Search` unchanged on an empty list). `Details` = `MetadataDetails` (rules 26-30). `Season` = `{seasonNumber:number, episodeCount:number, overview:string|null, airDate:string|null, posterUrl:string|null, episodes:{episodeNumber:number, title:string, overview:string|null, airDate:string|null, runtime:number|null, stillUrl:string|null}[]}`. `Stub` = `{seasonNumber:number, episodeCount:number}`. `Genre` = `{id:number, name:string}`.

## Rules

### A. Routing and input

1. Guards as above. `JwtOrApiKeyGuard` + no policy means `readonly` and a user without `media.read` can search and read details (no library data is exposed except rule 12). `[ts:src/modules/metadata-providers/metadata-providers.controller.ts:38-39]`
2. Query parsing is Express `simple` (media-query rule 4): repeated key = array, `a=` = `''`. `q` is read as `q?.trim()`: a repeated `q` is an array and `.trim` throws, **500** today (C1 extension, proposed C?1: 400 standard validation body). `year`, `provider`, `mediaId`, `window`, `genres`, `sort`, `voteGte`, `yearGte`, `yearLte` are never validated. `[ts:src/modules/metadata-providers/metadata-providers.controller.ts:59]`
3. Route overlap (Express, declaration order): the 2-segment routes (`search/*`, `trending/*`, `popular/*`, `upcoming/*`, `genres/*`, `discover/*`, `movie/:tmdbId`, `tv/:tmdbId`) and the 3/4-segment ones (`:provider/movie/:id`, `:provider/tv/:id[/seasons|/season-stubs]`, `tv/:tmdbId/seasons`) cannot match the same path except `/tv/tv/seasons`-style literals (`provider = "tv"` wins in Nest and answers 400 `Unknown provider: tv`). A static-over-param router (matchit) differs on that one path: it routes `/tv/tv/seasons` to the legacy `tv/:tmdbId/seasons` (id `"tv"`); under C?1 that id is non-canonical, so both answer 400 (message differs, parity compares `statusCode` + `error`). The porter adds a test for `GET /api/metadata/tv/tv/seasons` and `GET /api/metadata/movie/search` (the latter is `movie/:tmdbId`, id `"search"`, rule 15). `[ts:src/modules/metadata-providers/metadata-providers.controller.ts:170-233]`
4. Search: `query = q?.trim()`; falsy (missing or blank) → 200 `[]` before any provider or DB call. `[ts:src/modules/metadata-providers/metadata-providers.controller.ts:59-60]`, `[ts:src/modules/metadata-providers/metadata-providers.controller.ts:76-77]`
5. `year`: `year ? +year : undefined`; the provider adds the filter only when the number is truthy, so `year=abc` (NaN), `year=0` and `year=` are dropped silently (TMDB param `year` for movies, `first_air_date_year` for tv; TVDB `year` as `String(year)`). `[ts:src/modules/metadata-providers/metadata-providers.controller.ts:63]`, `[ts:src/modules/metadata-providers/providers/tmdb.provider.ts:200]`, `[ts:src/modules/metadata-providers/providers/tmdb.provider.ts:218]`, `[ts:src/modules/metadata-providers/providers/tvdb.provider.ts:122]`
6. Provider choice: `providerName ?? providerPreferredFor(mediaId)`, then `registry.resolve(name ?? null)`: the named provider is used **iff available**, i.e. its API key env var is truthy (rule 20); an unknown name (`foo`), or `tvdb` without `TVDB_API_KEY`, silently resolves to TMDB (the default, whether or not `TMDB_API_KEY` is set). `provider=` (empty string) is not nullish, so `mediaId` is not consulted and the result is TMDB. `[ts:src/modules/metadata-providers/metadata-providers.controller.ts:62]`, `[ts:src/modules/metadata-providers/metadata-providers.controller.ts:286]`, `[ts:src/modules/metadata-providers/metadata-provider.registry.ts:56-62]`
7. `providerPreferredFor(mediaId)`: `id = mediaId ? parseInt(mediaId, 10) : NaN`; not an integer (`Number.isInteger`) or `< 1` → no preference (`parseInt('12abc')` is 12, kept); an id beyond int4 reaches the query and fails (500 today; Rust: no preference, C?1). Unknown media → no preference. Otherwise `media.preferredProvider ?? media.library?.preferredProvider ?? undefined` (media override, then library, then none). One query (SQL Q1). The result only seeds `resolve`, it is not validated. `[ts:src/modules/metadata-providers/metadata-providers.controller.ts:264-276]`
8. Empty-result fallback: when the chosen provider returns `[]`, `registry.getFallback(provider.name)` = the other provider **if available**; if so it is queried with the same arguments and its result (possibly `[]`) is returned; one `log` line. No fallback when the other provider has no key. The fallback is inside the same `try` (rule 10). `[ts:src/modules/metadata-providers/metadata-providers.controller.ts:290-300]`, `[ts:src/modules/metadata-providers/metadata-provider.registry.ts:51-54]`
9. Results of the fallback keep their own `provider` field (`tvdb` results for a TMDB search); the client treats `provider` as authoritative. `[ts:src/modules/metadata-providers/metadata-providers.controller.ts:297]`
10. Failure: any exception from the primary or the fallback (axios error, breaker `CircuitOpenError`, TVDB `Error('TVDB API key not configured')`) → **503** `Metadata search failed on <provider.name>: <reason>` with `provider.name` the *primary* provider and `error: "Service Unavailable"`; the error and stack are logged. `reason` (`upstreamReason`): for an HTTP answer `HTTP <status>`, for a missing answer the axios code (`ECONNABORTED` timeout, `ECONNREFUSED`, `ENOTFOUND`, `ECONNRESET`) or `network error`, then ` — ` + `body.status_message ?? body.message ?? error.message`; a non-axios error gives its message (`tmdb circuit open — upstream temporarily unreachable`). Parity compares only `statusCode` + `error`. Rust maps `reqwest` errors to the same code names; the message **never contains the request URL** (`[new]`, rule 21: TMDB v3 puts the API key in the URL and `reqwest::Error`'s `Display` prints it; use `without_url()`). `[ts:src/modules/metadata-providers/metadata-providers.controller.ts:20-36]`, `[ts:src/modules/metadata-providers/metadata-providers.controller.ts:301-312]`, spec `[ts:src/modules/metadata-providers/metadata-providers.search-failure.spec.ts:33-69]`
11. Search results are never cached or stale-served (no `withStaleFallback`); each call is one upstream request (two with the fallback). `[ts:src/modules/metadata-providers/providers/tmdb.provider.ts:191-225]`
12. `enrichWithExisting(results, type)` (every list route except genres): empty list → returned as is. Else `tmdbIds = results.map(tmdbId).filter(>0)`, `tvdbIds = results.map(tvdbId).filter(truthy && >0)`; one query `media WHERE (tmdbId IN tmdbIds AND type = $t) OR (tvdbId IN tvdbIds AND type = $t)` (only the non-empty arms; none → no query) selecting `id, tmdbId, tvdbId, type` (SQL Q2); `type` is `'movie'` for movie routes and `'series'` for tv routes. Per result the match is the TMDB-keyed media first, else the TVDB-keyed one; output `{...result, existingMediaId: id|null, existingMediaType: type|null}`. `existingMediaType` is therefore the route's own type or `null`. Duplicate `tvdbId` rows (no unique constraint on `tvdbId`) resolve to the last row in scan order; Rust orders by `id ASC` and keeps the last (`[assumed]`, same result as heap order, C12). No library ACL: an existing id is reported even for a library the caller cannot read (proposed F?1). `[ts:src/modules/metadata-providers/metadata-providers.controller.ts:315-361]`
13. `window`: exactly `day` → `day`, anything else (missing, `DAY`, array) → `week`. It is part of the stale-cache key (rule 17). `[ts:src/modules/metadata-providers/metadata-providers.controller.ts:88-92]`, `[ts:src/modules/metadata-providers/metadata-providers.controller.ts:108-112]`
14. Discover parsing: `genres` split on `,`, each `parseInt(_, 10)`, non-finite dropped (`'28,abc,12'` → `[28,12]`, `'28|12'` → `[28]`), empty → no filter; `sort || undefined` forwarded verbatim (no whitelist); `voteGte ? parseFloat : undefined`; `yearGte`/`yearLte ? parseInt(_, 10) : undefined`; the provider adds a filter only when the number is truthy (NaN and `0` are dropped). Movie params: `language, include_adult='false', sort_by=<sort or popularity.desc>, 'vote_count.gte'=50, with_genres='<ids joined ,>', 'vote_average.gte', 'primary_release_date.gte'='<Y>-01-01', 'primary_release_date.lte'='<Y>-12-31'`. TV params: same minus `include_adult`, dates are `first_air_date.gte/lte`, and the first `primary_release_date` in `sort` is rewritten to `first_air_date`. No stale fallback: an upstream error is a 500 (C?1). All query values are URL-encoded by the HTTP client. `[ts:src/modules/metadata-providers/metadata-providers.controller.ts:237-256]`, `[ts:src/modules/metadata-providers/providers/tmdb.provider.ts:615-660]`
15. Detail routes: `registry.get(name)` (exact `tmdb` or `tvdb`, **availability not checked**) else 400 `Unknown provider: <name>`. The id is `externalId` string passed through `parseInt(_, 10)` inside the client: `abc` becomes `NaN` and the upstream URL `/movie/NaN` (TMDB 404 → 500), `12abc` is 12. `tvdb` without key → `Error('TVDB API key not configured')` → 500. Proposed C?1: canonical integer ids (C20) → 400, upstream 404 → 404, other upstream failures → 503. `[ts:src/modules/metadata-providers/metadata-providers.controller.ts:170-190]`, `[ts:src/modules/metadata-providers/providers/tmdb.provider.ts:232]`, `[ts:src/modules/metadata-providers/providers/tvdb.provider.ts:96-97]`
16. `season-stubs` and the legacy `tv/:tmdbId/seasons` are separate costs: stubs = one call (TMDB `GET /tv/{id}` seasons list, TVDB paged episode listing, rule 31/35), `seasons` = every season with episodes (rule 32/36). Season 0 (specials) is kept by both providers. `[ts:src/modules/metadata-providers/metadata-providers.controller.ts:203-214]`, spec `[ts:src/modules/metadata-providers/providers/specials.spec.ts:5-67]`

### B. Provider selection state, language, cache

17. Stale list fallback (TMDB only): `trending:<movie|tv>:<window>:<tmdbLocale>`, `popular:<movie|tv>:<tmdbLocale>`, `upcoming:movie:<tmdbLocale>:<region>`, `upcoming:tv:<tmdbLocale>`, `genres:<movie|tv>:<tmdbLocale>`. In-process `Map<string, mapped payload>`, no TTL, no size cap beyond the key space, lost on restart. Every successful live fetch overwrites the entry; a failure (any error, including breaker-open) with an entry returns the last copy and logs a warn; a failure without an entry (cold) propagates (route 500, C?1). The cached payload is the provider-mapped array before `enrichWithExisting`, so `existingMediaId` is always fresh. Search, discover, details and seasons are never stale-served. `[ts:src/modules/metadata-providers/providers/tmdb.provider.ts:168-189]`, `[ts:src/modules/metadata-providers/providers/tmdb.provider.ts:506-613]`
18. Circuit breaker (TMDB only): consecutive-failure counter `failures`, `openUntil`. A failure is transient when there is no response (timeout, DNS, refused, reset), HTTP 429 or `>= 500`; 4xx other than 429 is a real answer: it neither counts nor resets `failures`. On a transient failure `failures += 1`; when `failures >= 3` and now `>= openUntil`, `openUntil = now + 30 s` and a warn is logged. While `now < openUntil` every request is rejected **before sending** with `CircuitOpenError` (`<name> circuit open — upstream temporarily unreachable`); that rejection still runs the response error handler (no response = transient), so `failures += 1` for it too, without reopening (`now < openUntil`). The vectors' `failures` column must show this. Any successful response resets `failures` to 0 (logs "recovered" only if it was > 0). There is no half-open limit: after the cooldown all requests pass, and since `failures` is still `>= 3` the first transient failure reopens for another 30 s. Keep this exact machine (vector set `metadata-breaker`). `[ts:src/modules/metadata-providers/http-circuit-breaker.ts:16-20]`, `[ts:src/modules/metadata-providers/http-circuit-breaker.ts:33-69]`, `[ts:src/modules/metadata-providers/providers/tmdb.provider.ts:161-165]`, spec `[ts:src/modules/metadata-providers/http-circuit-breaker.spec.ts:46-77]`
19. TVDB has **no** breaker today (`installCircuitBreaker` is only called for TMDB) and its token login (`axios.post` to `/login`) bypasses the client instance, has no timeout and is not de-duplicated (concurrent first calls each log in). Plan §10 lists the breaker for "the clients": open question Q1 (proposal: the same 3 / 30 s breaker on TVDB, login single-flight with a 15 s timeout, one re-login on a 401, C?2). Frozen default until answered: TVDB exactly as Nest. `[ts:src/modules/metadata-providers/providers/tvdb.provider.ts:85-111]`, `[ts:src/modules/metadata-providers/providers/tmdb.provider.ts:154-166]`
20. API keys are **environment**, not settings: `TMDB_API_KEY`, `TVDB_API_KEY` (`config.md`; secrets stay out of `app_settings`, F5 does not apply). A provider is "available" iff its variable is truthy (`registry.isAvailable`, `getAvailable`); TMDB is always the default even when unavailable (its calls then fail with TMDB's 401 → rule 10 / 500). TMDB sends the key as query param `api_key` on every request (axios `params`), timeout 10 s; TVDB logs in with `POST https://api4.thetvdb.com/v4/login {apikey}` and sends `Authorization: Bearer <token>`, timeout 15 s (login: none). `config.md` says a blank-after-trim `TMDB_API_KEY` is "not configured"; Nest's registry uses raw truthiness (`' '` is available): Rust trims first (`[assumed]`, difference only for whitespace keys). `[ts:src/modules/metadata-providers/metadata-provider.registry.ts:32-49]`, `[ts:src/modules/metadata-providers/providers/tmdb.provider.ts:154-158]`, `[ts:src/modules/metadata-providers/providers/tvdb.provider.ts:89]`, `[ts:src/modules/metadata-providers/providers/tvdb.provider.ts:94-111]`
21. `[new]` No URL, query string or header ever reaches a log line, an error body or `reason`: the TMDB key travels in the URL and `reqwest` errors embed it (`Error::without_url`). Nest never leaked it (axios messages carry no URL), so this keeps parity while avoiding a regression.
22. TVDB token: kept in process memory with expiry `now + 25 days` (valid 30); refreshed lazily at the next call after expiry; a token the server revoked is not detected until then (every call fails 401 → 500/503). `[ts:src/modules/metadata-providers/providers/tvdb.provider.ts:94-111]`
23. Language / region (`MetadataSettingsCache` + `resolveMetadataLanguage`): global `metadata_language` and `metadata_region` are read from `app_settings` once, concurrent first reads share one load, and the cache is dropped when either key changes; an in-flight load invalidated mid-flight does not commit its value (epoch). `resolve(override?)` merges per call: `override.language ?? global.language`, `override.region ?? global.region` (`??`: an empty string override wins over the global value). Pure resolution: `lang = (language ?? '').toLowerCase().split(/[-_]/)[0]`, found in the 12-row table (`en fr es de it pt nl pl ru ja ko zh`, with `tvdbCode eng fra spa deu ita por nld pol rus jpn kor zho` and `defaultRegion US FR ES DE IT PT NL PL RU JP KR CN`), unknown/empty → `en`; `region = (region ?? '').toUpperCase() || opt.defaultRegion` (any string, not checked against the 18-row region table: the table is client UI data); `tmdbLocale = <iso1>-<region>`; `includeImageLanguage = en → 'en,null'`, else `<iso1>,en,null`; `logoIso1 = iso1`; `tvdbCode`; `releaseDatePriority = region 'US' → ['US'] else [region,'US']`. Unknown language keeps the given region (`xx` + `FR` → `en-FR`). In Rust the cache is in-process and invalidated by the settings write path (settings route is Rust since S1), so no bridge is needed for it. `[ts:src/modules/metadata-providers/metadata-settings-cache.service.ts:25-81]`, `[ts:src/modules/metadata-providers/metadata-language.ts:21-102]`

### C. Provider response mapping

24. `Search` (list and search results). TMDB movie `[ts:src/modules/metadata-providers/providers/tmdb.provider.ts:752-771]`, tv `[ts:src/modules/metadata-providers/providers/tmdb.provider.ts:773-792]`: `{tmdbId: id, provider:'tmdb', title (tv: name), originalTitle, overview, year, posterUrl, fanartUrl, rating, genres: [], genreIds, mediaType}`; `year = release_date ? parseInt(release_date) : null` (tv: `first_air_date`; `parseInt` of a date string = the year; NaN serialises as `null`), `posterUrl = https://image.tmdb.org/t/p/w500<poster_path>|null`, `fanartUrl = https://image.tmdb.org/t/p/original<backdrop_path>|null`, `rating = vote_average ?? 0`, `genreIds = genre_ids ?? []`, `mediaType` `movie`|`series`. TMDB results have **no** `tvdbId`/`imdbId` keys (absent, not null). TVDB `[ts:src/modules/metadata-providers/providers/tvdb.provider.ts:513-538]`: `{tmdbId, tvdbId, imdbId, provider:'tvdb', title, originalTitle, overview, year, posterUrl, rating: 0, genres, mediaType}`: `tmdbId = parseInt(<id of the first remote_ids entry with sourceName 'TheMovieDB.com'> ?? '0')` (0 when absent), `tvdbId = parseInt(r.tvdb_id ?? r.id)`, `imdbId = <same for sourceName 'IMDB'>|null`, `title = r.translations?.[tvdbCode] ?? r.name`, `originalTitle = r.name`, `overview = r.overviews?.[tvdbCode] ?? r.overview ?? ''`, `year = r.year ? parseInt : null`, `posterUrl = r.image_url ?? r.poster ?? null`, `genres = r.genres ?? []` (names); no `fanartUrl`/`genreIds` keys. Result order is the provider's.
25. `Details` keys always present for both providers (value `null`/`[]` when absent): `tmdbId, tvdbId, imdbId, provider, title, originalTitle, overview, year, posterUrl, fanartUrl, logoUrl, additionalFanartUrls, rating, genres, mediaType, runtime, seasonCount, episodeCount, releaseDate, inCinemas, digitalRelease, physicalRelease, status, budget, revenue, originalLanguage, productionCountries, productionCompanies, voteCount, popularity, tagline, cast, crew, videos, keywords, alternativeTitles, tmdbCollectionId, tmdbCollectionName`; plus `genreIds` on TMDB only (TVDB: absent). Items: `cast: {externalId, name, character, avatarUrl, order}`, `crew: {externalId, name, job, department, avatarUrl}`, `videos: {key, site, type, name}`. `[ts:src/modules/metadata-providers/interfaces/metadata-provider.interface.ts:22-83]`
