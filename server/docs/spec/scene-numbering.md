# Spec: scene numbering

A release or file name carries the numbering its group uses (scene numbering), which some series do not share with the library's (aired) numbering: a show released by part names its fourth part `S04` while the library's season 3 holds it. TheXEM publishes the per-episode mapping from scene numbering to TVDB aired numbering. Library numbering never changes.

Code: `fliks_domain::release::scene` (pure), `server/src/scene.rs` (storage, refresh, loader), callers in `plugins/acquisition/release.rs` and `ingest/library.rs`.

## Rules

1. A series is in one of three states. Not mapped: TheXEM does not list its TVDB id, or the numbering guard (rule 4) fails; it behaves exactly as without this spec. Mapped: its mapping is stored and fits. Unknown: TheXEM lists it but no mapping is stored yet (added after the last refresh, a fresh deploy, a fetch that keeps failing); a provider answering none is not unknown, the series is not mapped. An unknown series never falls back to identity (rule 6).
2. Storage: table `scene_mappings` (`tvdbId` PK, `entries` jsonb null until fetched, `fetchedAt`). Every id the scene provider lists gets a row; a row is never deleted by a lookup. Each entry is `{sceneSeason, sceneEpisode, season, episode}` (aired side).
3. Refresh: the core does not call TheXEM. It asks the first available provider plugin that declares the `scene` capability for the `tvdb` origin (`provider-plugins.md` rule 18a; the official one is `fliks.thexem`), through the `scene-mapped-ids` and `scene-mapping` calls, so the limits, timeout and breaker are the provider's. With no such provider the core reads no scene numbers: a series with no stored mapping, or with a row but no mapping fetched, is not mapped (never unknown); a stored mapping that fits stays mapped. The `RefreshMetadata` job lists the ids, then fetches the mapping of every library series whose tvdb external id has a row (background priority). The same refresh runs once in the background when a scene provider turns ready and `scene_mappings` is empty. After a successful list the rows without a stored mapping whose id is no longer listed are deleted; a stored mapping is never deleted. A series in the unknown state is fetched on demand by the first read that needs it (interactive priority, one call per id at a time, the result stored as the job does; an id whose call failed is not asked again for 30 minutes, kept in memory). `media.acquisitionContext` reads it on demand, `acquisition.candidates` and targets never fetch, and `releases.match` fetches only for a title naming a season or episode. A failed call (transport error) keeps the stored row untouched and is logged. A provider that has no mapping for the id (none) is an answer: the row stores an empty mapping, replacing any earlier one, and the series is not mapped. A mapping with no pair is none.
4. Numbering guard: the mapping applies to a media only when, for every aired season above 0 that the mapping renumbers (some entry whose scene number differs from its aired number), the library has that season with the episode count the mapping lists. The last mapped season may hold more library episodes than the mapping lists. Otherwise the media is not mapped.
5. A scene number is translated per episode. A scene episode with no entry keeps its number (identity), so a new scene season TheXEM does not know is never extrapolated. Season 0 is never translated, and a season 0 reached by a scene season does not bound a season range that covers a season above 0. A scene episode mapped to consecutive episodes of one aired season (a double episode) is that aired range; a pack covers the union. A scene episode mapped to non-consecutive episodes, or to episodes of different seasons, is ambiguous: a name covering it (every episode of a range is checked) is not translated.
6. Unresolved: for a series in the unknown state (after the on-demand fetch failed), or a name covering an ambiguous scene number, a title naming a season or episode is refused, never read with identity: `releases.match` answers `skip` with `scene-unresolved`, `releases.score` adds the rejection `SCENE_UNRESOLVED`, import fails the file (rule 9).
7. Release side, one place: `releases.match` (RSS, automatic search, grab assignment) and `releases.score` (interactive and automatic search ranking) translate the parsed season/episode of a release title before anything reads it. The translated coverage is the one returned and scored. A parse: an episode (or episode range) maps to its aired season and episodes, keeping the range only when it stays in one aired season. A season pack covers the aired episodes its scene season maps to: when that is every aired episode of each aired season it touches, the result is a season pack (a range over several seasons); otherwise it is a partial pack, reported as one aired season with an episode range and never as a full season. A scene season with no entry is a full pack of the same number.
8. Search units (`SceneMap::scene_units`): aired season N lists the scene seasons mapping into it, an aired episode its scene episode; an aired unit with no entry, and aired season 0, search themselves. Every target the host hands a plugin (`media.acquisitionContext`, `acquisition.candidates`) carries them in `search-units` (`plugins.md` rule 31): the scene units when the stored mapping applies, the aired `ref` of the unit otherwise, `[]` for the whole work. Targets never fetch from TheXEM. A plugin queries from `search-units` only, one query per unit, and merges and deduplicates the results; matching stays in `releases.match` and `releases.score`.
9. Import: a downloaded file's parsed season and episode (and episode end) are translated for a mapped series, only when no valid explicit episode of the grab was found: an explicit episode wins and keeps the file's untranslated end. A series in the unknown state makes `library.ingest` answer `ERR_RETRY_LATER` (`plugins.md` rule 30), whatever the other files of the pack did: the files placed stay placed, a re-ingest finds them already present, and the caller retries until the mapping is known or its cap (the download plugin: 24 hours after the first refusal, then `import_failed`) runs out. The mapping is read once per pack, before the media's ingest lock is taken. An ambiguous number is not retryable: that file fails with the per-file error (`ingest.md` rule 20) and the plain `ERR` code.
10. Out of scope: labels such as `S03.Partie.4`, groups that disagree on numbering, anime absolute numbering.
