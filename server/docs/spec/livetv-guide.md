## Rules

### A. Guide source CRUD

1. `CreateGuideSource`: `name` string; `kind` in `xmltv|source`; optional `url` (`IsUrl({require_tld:false, require_protocol:true})`: `http`, `https`, `ftp` pass; a local path is 400 `[ts:src/modules/livetv/dto/create-livetv-guide-source.dto.spec.ts:22]–[ts:src/modules/livetv/dto/create-livetv-guide-source.dto.spec.ts:24]`); optional ints `sourceId`, `refreshIntervalHours`, `timezoneOffsetMinutes`, `priority`; optional string `language`; optional bool `enabled`. No minimum on any int; no rule ties `url` to `kind: xmltv` or `sourceId` to `kind: source` (C165 adds one, rule 6). `null` passes `IsOptional`. `[ts:src/modules/livetv/dto/create-livetv-guide-source.dto.ts:11]–[ts:src/modules/livetv/dto/create-livetv-guide-source.dto.ts:48]`
2. `UpdateGuideSource`: same fields all optional, with `url` only `IsString` (**no URL validation**: a local path or a non-URL is accepted and fails at sync); applied field by field on `!== undefined`; `sourceId: null` detaches. `null` on NOT NULL columns (`name, kind, refreshIntervalHours, timezoneOffsetMinutes, priority, enabled`) is a 500 today (C1: 400). `[ts:src/modules/livetv/dto/update-livetv-guide-source.dto.ts:10]–[ts:src/modules/livetv/dto/update-livetv-guide-source.dto.ts:46]`, `[ts:src/modules/livetv/services/livetv-guide.service.ts:126]–[ts:src/modules/livetv/services/livetv-guide.service.ts:142]`
3. Defaults: `kind xmltv`, `refreshIntervalHours 12`, `timezoneOffsetMinutes 0`, `priority 0`, `enabled true`, `lastSyncStatus never`, `programCount 0`. `language` is `varchar(16)`: longer → 500 today (C131). `[ts:src/modules/livetv/entities/livetv-guide-source.entity.ts:11]–[ts:src/modules/livetv/entities/livetv-guide-source.entity.ts:65]`
4. Create saves `{...dto, source: {id: sourceId} | null}`: an unknown `sourceId` violates the FK (500 today, C131); `sourceId` is a `@RelationId`, which `repo.create` does not copy and `save` does not refresh, so the create response carries **both** `source: {id}` or `null` and `sourceId` (the new value) `[recorded]`; update loads the row with `relations: ['source']`, so the PATCH response carries `source` = the full parent Source (shape of `livetv-sources.md` Routes, no password) or `null`, except that a PATCH sending `sourceId` answers `source: {id}` or `null`; `sourceId` is the value after the PATCH `[recorded]`. The web client ignores both responses (it reloads the list). List, create and PATCH differ; Rust reproduces each recorded shape, parity records them. `[ts:src/modules/livetv/services/livetv-guide.service.ts:117]–[ts:src/modules/livetv/services/livetv-guide.service.ts:142]`
5. Delete: 404 when missing, else delete the row; `livetv_programs` and `livetv_guide_channels` of that guide source cascade (FK `ON DELETE CASCADE`); deleting a Live TV source cascades to its guide sources of kind `source`. `[ts:src/modules/livetv/services/livetv-guide.service.ts:144]–[ts:src/modules/livetv/services/livetv-guide.service.ts:147]`, `[ts:src/modules/livetv/entities/livetv-guide-source.entity.ts:20]–[ts:src/modules/livetv/entities/livetv-guide-source.entity.ts:22]`
6. `[new]` Validation gaps answered with 400 (C131; create, and the merged row after update): a non-empty `url` must be `http(s)`; a `sourceId` that is not null must exist (FK violation: 500 today); `refreshIntervalHours >= 1`; `timezoneOffsetMinutes` within -1440..1440; `language` at most 16 chars (500 today); ints within int32 (500 today). Today a feed with `refreshIntervalHours <= 0` is due at every tick and an offset beyond JS Date range fails the insert at sync. Also 400 (C165): `url must be set when kind is xmltv` (`url` absent or null; on create an empty string is already refused by the URL rule, on PATCH it counts as missing) and `sourceId must be set when kind is source`. Create checks the row it builds. A PATCH checks a kind's requirement only when its payload sets `kind` or the field concerned (`url` for xmltv, `sourceId` for source), against the row as it would be after the save; a payload that touches neither never fails over a row already stored without them.
7. Retention settings (read at every sync, search and prune): `livetv_guide_days_past` default 2, `livetv_guide_days_future` default 7, parsed `parseInt(raw, 10)` (leading integer, NaN or absent → default; `0` and negatives are honoured). `[ts:src/modules/livetv/services/livetv-guide.service.ts:579]–[ts:src/modules/livetv/services/livetv-guide.service.ts:583]`, `[ts:src/modules/settings/entities/app-setting.entity.ts:35]`
8. A guide source can be synced by hand while `enabled = false`; the cron skips it. `[ts:src/modules/livetv/services/livetv-scheduler.service.ts:88]–[ts:src/modules/livetv/services/livetv-scheduler.service.ts:99]`

### B. Fetching the feed

9. Feed url: `kind xmltv` → `url` (none → `BadRequestException` `Guide source has no URL`); `kind source` → `sourceId` null → `Guide source has no parent Live TV source`, else `resolveGuideUrl(sourceId)`: Xtream parent → `<base>/xmltv.php?username=<enc>&password=<enc>` built from the **stored** credentials (`encodeURIComponent`, sources rule 18); M3U parent → the stored `guideUrls[0]`; none stored → fetch the playlist once (conditional validators not used) and take its first guide url, else throw `Source "<name>" playlist has no x-tvg-url header`. These throws are inside the sync `try` (rule 32). `[ts:src/modules/livetv/services/livetv-guide.service.ts:348]–[ts:src/modules/livetv/services/livetv-guide.service.ts:357]`, `[ts:src/modules/livetv/services/livetv-sources.service.ts:512]–[ts:src/modules/livetv/services/livetv-sources.service.ts:524]`
10. Request: UA and Referer of the **parent** source for `kind source` (default UA `VLC/3.0.20 LibVLC/3.0.20` otherwise, no Referer), `If-None-Match` / `If-Modified-Since` from the stored `etag` / `lastModified`, timeout **300 s** (idle, as the HTTP client's inactivity timeout), max 5 redirects, status 2xx or 304, `Content-Encoding` gzip, x-gzip, compress, deflate, br, zstd decoded by the client, body cap 512 MiB counted after that decoding and before the sniffed gunzip of rule 12 (F72), no URL guard (sources rule 14). `[ts:src/modules/livetv/services/livetv-guide.service.ts:232]–[ts:src/modules/livetv/services/livetv-guide.service.ts:245]`, `[ts:src/modules/livetv/livetv-http.ts:96]–[ts:src/modules/livetv/livetv-http.ts:115]`
11. 304: the body is dropped, row `lastSyncAt = now, lastSyncStatus 'ok', lastSyncError null`; response `{ok:true, programCount:<stored>, channelsTouched:0}`; nothing else changes. `[ts:src/modules/livetv/services/livetv-guide.service.ts:247]–[ts:src/modules/livetv/services/livetv-guide.service.ts:256]`
12. Gzip: the first two bytes are sniffed; `1f 8b` → gunzip (a `.gz` feed and a transport gzip read the same; concatenated members are decoded), anything else, an empty body included, is read as is. Decompressed bytes are capped at 1 GiB in Rust (F72). `[ts:src/modules/livetv/services/livetv-guide.service.ts:73]–[ts:src/modules/livetv/services/livetv-guide.service.ts:82]`, `[ts:src/modules/livetv/services/livetv-guide.service.ts:258]`
13. The body is parsed as a stream, never held whole: memory is bounded by one XML element (capped at 1 MiB in Rust, an oversize element is skipped), the feed's channel list, the chunk buffer (rule 38) and the touched set (rules 36-38), not by the file size (rule 40 measures it; the thresholds are rule 52). `[ts:src/modules/livetv/parsing/xmltv.parser.ts:251]–[ts:src/modules/livetv/parsing/xmltv.parser.ts:255]`
14. New validators `ETag` / `Last-Modified` (strings, else null) are stored only after the whole import commits. `[ts:src/modules/livetv/services/livetv-guide.service.ts:323]–[ts:src/modules/livetv/services/livetv-guide.service.ts:331]`

### C. XMLTV parsing (`parseXmltvStream`, pure over a chunked byte stream; vectors)

Rust: `quick-xml` `Reader` over the sniffed decoder (plan §10 S7), lenient (`check_end_names(false)`, no DTD processing, no entity expansion: `<!DOCTYPE>` and `<!ENTITY>` are ignored and `&custom;` stays literal, no billion-laughs surface), emitting the same `XmltvChannel` / `XmltvProgramme` values as the TS parser for the vector corpus, whatever the chunk boundaries. A malformed or truncated tail never fails the import: an element that does not close is dropped.

15. Recognised elements: `<channel …>` (only when the caller wants channels, as the sync does) and `<programme …>`, by the prefix `<channel` / `<programme` (the TS parser matches the open-tag text, so a `<channel\n  id=…>` with attributes on separate lines is recognised); self-closing forms end the element at once. Everything else (`<tv>`, `<credits>`, comments) is skipped. `[ts:src/modules/livetv/parsing/xmltv.parser.ts:256]–[ts:src/modules/livetv/parsing/xmltv.parser.ts:322]`
16. Attributes are read as `name = "value"` (double quotes, optional spaces around `=`), names lowercased, values entity-decoded (rule 19). Rust also accepts single-quoted values (superset, `[new]` C133, rule 49). `[ts:src/modules/livetv/parsing/xmltv.parser.ts:93]–[ts:src/modules/livetv/parsing/xmltv.parser.ts:99]`
17. `<channel id>`: `id` required (else the element is dropped); `displayNames` = every non-empty decoded `<display-name>` text in order; `iconUrl` = the `src` of the **first** `<icon>` in the element (`src=""` gives `''`), else `null` (also when that `<icon>` has no `src`). `[ts:src/modules/livetv/parsing/xmltv.parser.ts:226]–[ts:src/modules/livetv/parsing/xmltv.parser.ts:235]`, `[ts:src/modules/livetv/parsing/xmltv.parser.ts:119]–[ts:src/modules/livetv/parsing/xmltv.parser.ts:128]`
18. `<programme start stop channel>`: dropped when `start` does not parse, `channel` is missing, or there is no non-empty `<title>`. `endsAt` = parsed `stop` or `null`. Children: `title`, `sub-title`, `desc` chosen by language (below); `category` = all non-empty texts in order; `icon` first `src`; `date` = the `<date>` text chosen as rule 20 with no language, first 4 chars parsed with JS `parseInt` (leading integer, so `19ab` = 19; NaN → null); `rating` = the `<value>` inside the first `<rating>` block chosen the same way (a `<star-rating>` is ignored); `icon` = the first `<icon>`'s `src` as in rule 17; `<new/>` or `<new>` and `<live/>` or `<live>` (never `<new-x>`) set `isNew` / `isLive`. Tag names match case-insensitively. `[ts:src/modules/livetv/parsing/xmltv.parser.ts:188]–[ts:src/modules/livetv/parsing/xmltv.parser.ts:224]`, `[ts:src/modules/livetv/parsing/xmltv.parser.ts:130]–[ts:src/modules/livetv/parsing/xmltv.parser.ts:133]`
19. Text decoding (`decodeXmlText`), in this order: unwrap `<![CDATA[…]]>` (its content is then entity-decoded too, non-standard but kept), `&#x…;`, `&#…;` (a code point above U+10FFFF or negative is left as written), `&amp; &lt; &gt; &quot; &apos;`, `&nbsp;` as an ASCII space, any other named entity left as written; each step is one pass, in that order: `&amp;lt;` becomes `&lt;`, but a numeric reference that yields `&` is decoded again by the named step (`&#38;lt;` becomes `<`); then JS `trim()`. U+0000 is stripped (C128). A reference to a surrogate (`&#xD800;`-`&#xDFFF;`) yields a lone UTF-16 surrogate that Node writes to Postgres as U+FFFD: Rust emits U+FFFD (vectors compare the stored text, not the JS string). `[ts:src/modules/livetv/parsing/xmltv.parser.ts:35]–[ts:src/modules/livetv/parsing/xmltv.parser.ts:59]`
20. Language choice (`title`, `sub-title`, `desc`): among non-empty values, the one whose `lang` equals the configured `language` case-insensitively and exactly (`fr` does not match `fr-FR`), else the first without `lang`, else the first. No configured language: untagged first, else first. `rating`'s `value` uses no language. `[ts:src/modules/livetv/parsing/xmltv.parser.ts:101]–[ts:src/modules/livetv/parsing/xmltv.parser.ts:117]`
21. `parseXmltvDate(raw, fallbackOffsetMinutes)`: `^(\d{4})(\d{2})(\d{2})(\d{2})(\d{2})(\d{2})?\s*([+-]\d{4})?` on the trimmed text (seconds optional, trailing text ignored); instant = UTC fields minus the offset (the stamp's own offset, else the guide source's `timezoneOffsetMinutes`); no match → null. Rust rejects impossible fields (month 13, day 31 of a 30-day month, hour 24 and above, minute or second above 59, year before 1970) with null instead of rolling over as `Date.UTC` does (C128). `[ts:src/modules/livetv/parsing/xmltv.parser.ts:62]–[ts:src/modules/livetv/parsing/xmltv.parser.ts:91]`
22. Episode numbers, over every `<episode-num system>` (system lowercased, default `onscreen`; empty values skipped), first non-null wins per field: `xmltv_ns` = `season.episode.part`, each part's text before `/` parsed with `parseInt`, **plus 1** (zero based), NaN → null; `onscreen` = first match of `S?\s*(\d{1,3})\s*[EXx]\s*(\d{1,4})` (uppercase `S`, letters `E`, `X`, `x` only: `s01e05` does **not** match) giving season and episode, else `^E?(\d{1,4})$` on the trimmed value gives the episode only; any other system → `seriesId = "<system>:<value>"` (first wins). `[ts:src/modules/livetv/parsing/xmltv.parser.ts:135]–[ts:src/modules/livetv/parsing/xmltv.parser.ts:186]`
23. Memory-safe element framing: the unmatched tail kept between chunks is bounded (the TS parser keeps 16 chars when nothing matches); a CDATA section containing the closing tag does not end the element. Chunk boundaries anywhere (also inside a multibyte character, a tag, an entity) give identical output. `[ts:src/modules/livetv/parsing/xmltv.parser.ts:237]–[ts:src/modules/livetv/parsing/xmltv.parser.ts:249]`, `[ts:src/modules/livetv/parsing/xmltv.parser.ts:265]–[ts:src/modules/livetv/parsing/xmltv.parser.ts:321]`
24. Encoding: the TS parser reads every stream as UTF-8 and ignores the XML declaration (a `ISO-8859-1` feed gives mojibake). Rust honours a declared encoding through `encoding_rs` (C133); invalid UTF-8 bytes become U+FFFD. `[ts:src/modules/livetv/parsing/xmltv.parser.ts:316]`
25. Output limits at the database: `rating` is `varchar(32)`, longer values truncated to 32 chars in Rust (today the insert fails and the whole sync errors, C128); other text columns are unbounded. `[ts:src/modules/livetv/entities/livetv-program.entity.ts:73]–[ts:src/modules/livetv/entities/livetv-program.entity.ts:74]`
26. Handlers are awaited per element (backpressure): a slow database slows the read; Rust uses a bounded channel between the reader and the writer, so memory stays bounded when the database is slower than the network. `[ts:src/modules/livetv/parsing/xmltv.parser.ts:27]–[ts:src/modules/livetv/parsing/xmltv.parser.ts:33]`, `[ts:src/modules/livetv/parsing/xmltv.parser.ts:306]–[ts:src/modules/livetv/parsing/xmltv.parser.ts:312]`

### D. Sync (`POST …/guide-sources/:id/sync` and the job)

27. One request, one streamed pass (the DTD puts every `<channel>` before any `<programme>`): the first programme seen triggers the **match pass** (rules 33-34); a feed with no programme triggers it once at the end. `[ts:src/modules/livetv/services/livetv-guide.service.ts:153]–[ts:src/modules/livetv/services/livetv-guide.service.ts:160]`, `[ts:src/modules/livetv/services/livetv-guide.service.ts:264]–[ts:src/modules/livetv/services/livetv-guide.service.ts:265]`, `[ts:src/modules/livetv/services/livetv-guide.service.ts:302]–[ts:src/modules/livetv/services/livetv-guide.service.ts:304]`
28. Window: `windowStart = now - livetv_guide_days_past d`, `windowEnd = now + livetv_guide_days_future d`, both from rule 7. `[ts:src/modules/livetv/services/livetv-guide.service.ts:165]–[ts:src/modules/livetv/services/livetv-guide.service.ts:169]`
29. Match report (`GET …/guide/match-report`): `total` = count of all channels; `byKind` = `{id, name, fuzzy, manual}` counts over channels by `guideMatchKind`; `unmatched` = channels with `guideMatchKind` null, `[{channelId, name}]` (a channel with a provider `tvg-id` but no match kind is unmatched), order by channel id `[new]`; `candidates` = rows of `livetv_guide_channels` (optionally only `guideSourceId`), ordered by `"channelId"` then id, `[{id: channelId, displayName: displayNames[0] ?? channelId, guideSourceId}]`. ## SQL

- insert / patch / delete as the source CRUD (sources spec SQL), table `livetv_guide_sources`; FK `sourceId` `ON DELETE CASCADE` to `livetv_sources`.
- sync: `SELECT … FROM livetv_channels ORDER BY id` (id, name, enabled, "guideChannelId", "guideMatchKind", "guideShiftMinutes"); `UPDATE livetv_channels SET "guideChannelId" = $1, "guideMatchKind" = $2 WHERE id = ANY($3)` per `(kind, guideChannelId)` group; `DELETE FROM livetv_guide_channels WHERE "guideSourceId" = $1` + `INSERT INTO livetv_guide_channels ("guideSourceId", "channelId", "displayNames", "iconUrl") SELECT … FROM UNNEST(…)` in one tx; programmes: `SELECT coalesce(max(id), 0) FROM livetv_programs`, `INSERT INTO livetv_programs ("guideSourceId", "guideChannelId", "startsAt", "endsAt", title, subtitle, description, categories, "iconUrl", "seasonNumber", "episodeNumber", "seriesId", "isNew", "isLive", rating, year) SELECT … FROM UNNEST(…)`, then the rule 38 delete, `UPDATE livetv_guide_sources SET …`.
- indexes used: `IDX_livetv_programs_source_channel_start ("guideSourceId", "guideChannelId", "startsAt")` (the replace delete), `IDX_livetv_programs_channel_start ("guideChannelId", "startsAt")` (reads), `IDX_livetv_programs_window ("startsAt", "endsAt")` (prune); `UQ_livetv_guide_channel_source_id ("guideSourceId", "channelId")`. `livetv_programs` has no unique key.
- match report: `SELECT id, name, "guideMatchKind" FROM livetv_channels`; `SELECT * FROM livetv_guide_channels [WHERE "guideSourceId" = $1] ORDER BY "channelId" COLLATE "C", id`.
- priority map: `SELECT id, priority FROM livetv_guide_sources`.
- programmes window: `SELECT * FROM livetv_programs p WHERE p."guideChannelId" = ANY($1) AND p."startsAt" < $to AND p."endsAt" > $from ORDER BY p."startsAt", p.id`.
- search: `SELECT * FROM livetv_programs p WHERE p.title ILIKE $1 ESCAPE '\' AND p."startsAt" < $to AND p."endsAt" > $from AND EXISTS (SELECT 1 FROM livetv_channels c LEFT JOIN livetv_user_channel_prefs pref ON pref."channelId" = c.id AND pref."userId" = $uid WHERE c."guideChannelId" = p."guideChannelId" AND c.enabled AND (pref.hidden IS NULL OR pref.hidden = false) [AND (c."groupName" IS NULL OR lower(btrim(c."groupName")) <> ALL($denied))]) ORDER BY p."startsAt", p.id LIMIT 50`.
- program by id: `SELECT * FROM livetv_programs WHERE id = $1`.
- prune: `DELETE FROM livetv_programs WHERE "endsAt" < $pastCutoff OR "startsAt" > $futureCutoff`.
