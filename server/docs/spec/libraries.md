## Routes

8 routes in the manifest (filter: `.[]|select(.path|test("^/api/libraries"))` = 8; all from `LibrariesController`); 7 are ported in S3, `DELETE /api/libraries/:id` stays in Nest until S5 (rule 18, method fallback forwards it). Class-level guards `JwtOrApiKeyGuard, PoliciesGuard` on all of them `[ts:src/modules/libraries/libraries.controller.ts:27]`; no `SessionTokenGuard` (a `scope:'stream'` token passes the guard but holds no `Settings`/`Library` ability for non-admins; F8 makes the Rust extractor reject it with 401 on these routes, none is stream-allowed). 401 for missing/invalid credentials on every route (auth rule 14). `Library` here = the library JSON of rule 2 (`LibraryWithDetails`); `Summary` = rule 5. Route order matters in Nest: `mine` is declared before `:id`; in Rust the static segment must win over `:id` (`GET /api/libraries/mine` must never reach the integer parser).

## Rules

### A. Shape and reads

1. Policies: `Read Settings` and `Manage Settings` are both granted by `settings.access`; `Read Library` by `media.read`, `settings.access` (as `manage Library`) or `manage:all`; admins/`manage:all` satisfy everything (auth rules 20, 25). `[ts:src/modules/auth/casl/casl-ability.factory.ts:84]`–`[ts:src/modules/auth/casl/casl-ability.factory.ts:91]`, `[ts:src/modules/auth/casl/casl-ability.factory.ts:132]`–`[ts:src/modules/auth/casl/casl-ability.factory.ts:140]`
2. `Library` JSON (entity serialised as is; `libraries` has no `@Exclude`/`@Expose`): `id int`, `createdAt`/`updatedAt` ISO strings, `name string` (unique), `icon string|null` (varchar 48), `color string|null` (varchar 32), `mediaTypes ('movie'|'series')[]` (jsonb, default `["movie","series"]`), `preferredProvider string|null`, `metadataLanguage string|null` (varchar 8), `metadataRegion string|null` (varchar 8), `defaultQualityProfileId int|null`, `defaultLanguageProfileId int|null` (the `@RelationId` virtuals; the relation objects are NOT loaded, so no `defaultQualityProfile` key), `path string|null`, `label string|null` (no DTO writes it: always `null` unless set in SQL), plus `userIds int[]` and `disk`. `disk` = `null` when `path` is null, else `{freeSpace: number, totalSpace: number, accessible: bool}`; `statfs` failure (any error) = `{freeSpace: -1, totalSpace: -1, accessible: false}`. `[ts:src/modules/libraries/entities/library.entity.ts:19]`–`[ts:src/modules/libraries/entities/library.entity.ts:69]`, `[ts:src/modules/libraries/libraries.service.ts:383]`–`[ts:src/modules/libraries/libraries.service.ts:396]`
3. `GET /libraries` scope: ids = `getAccessibleLibraryIds(caller)` (rule 30); `[]` is queried as `id IN (-1)` (empty result); then `ORDER BY name ASC, id ASC` (C12, rule 39; database collation: README "Frozen as is" order-insensitive parity rule applies, Rust sorts by name in byte order `[assumed]`: same treatment as `/api/settings`, the README paragraph names only two routes, Q1). `[ts:src/modules/libraries/libraries.service.ts:116]`–`[ts:src/modules/libraries/libraries.service.ts:128]`
4. Nest: `GET /libraries/:id` and `GET /libraries/:id/access` do NOT apply the library ACL (any `Read`/`Manage Settings` caller reads any library and its `userIds`). Rust does (F20, rule 40). `[ts:src/modules/libraries/libraries.service.ts:130]`–`[ts:src/modules/libraries/libraries.service.ts:137]`, `[ts:src/modules/libraries/libraries.service.ts:253]`–`[ts:src/modules/libraries/libraries.service.ts:258]`
5. `GET /libraries/mine` `Summary` = exactly `{id, name, icon, color, mediaTypes, defaultQualityProfileId, defaultLanguageProfileId}` (no dates, `path`, `label`, `disk`, `userIds`; the two profile ids are `int|null`), scoped like rule 3, `ORDER BY name ASC, id ASC` (C12). Any authenticated user with `media.read` (the sidebar). `[ts:src/modules/libraries/libraries.service.ts:80]`–`[ts:src/modules/libraries/libraries.service.ts:114]`
6. `statfs` semantics (Rust must reproduce on Linux with `statvfs`, run off the async runtime so a slow mount does not stall requests): `freeSpace = f_bfree * f_bsize` (free blocks including root-reserved, NOT `f_bavail`), `totalSpace = f_blocks * f_bsize`; JSON numbers; `accessible = (freeSpace !== -1)`. `[ts:src/modules/libraries/libraries.service.ts:367]`–`[ts:src/modules/libraries/libraries.service.ts:381]`, `[ts:src/modules/libraries/libraries.service.ts:388]`–`[ts:src/modules/libraries/libraries.service.ts:394]`
7. `userIds` of a library = `library_user_access.userId` of that library, no `ORDER BY` in Nest; Rust uses `ORDER BY lua.id` (C12 stable tie-break; insertion order is what Postgres returns in practice, same reasoning as `users.md` rule 3). Admins appear only if they hold a row. `[ts:src/modules/libraries/libraries.service.ts:253]`–`[ts:src/modules/libraries/libraries.service.ts:258]`

### B. Create and update (writes disk)

8. `CreateLibraryDto`: `name` string (required, empty string allowed, unique); optional (`IsOptional` = absent or `null` passes): `icon` string|null, `color` string|null, `mediaTypes` array of `'movie'|'series'` (`[]` allowed), `preferredProvider` string|null, `metadataLanguage` string|null, `metadataRegion` string|null, `defaultQualityProfileId` int|null, `defaultLanguageProfileId` int|null, `path` string, `userIds` int[]. Unknown keys 400 (auth rule 16). `[ts:src/modules/libraries/dto/create-library.dto.ts:10]`–`[ts:src/modules/libraries/dto/create-library.dto.ts:61]`
9. `UpdateLibraryDto`: same fields minus `userIds`, all optional, `path` included. Unknown keys (`userIds` too) 400. `null` passes validation for `name`/`mediaTypes` and then hits a NOT NULL violation = 500 in Nest; Rust answers 400 (C1, rule 38). `[ts:src/modules/libraries/dto/update-library.dto.ts:14]`–`[ts:src/modules/libraries/dto/update-library.dto.ts:58]`
10. `AssignLibraryAccessDto`: `userIds` required int array (`[]` allowed). `[ts:src/modules/libraries/dto/assign-library-access.dto.ts:3]`–`[ts:src/modules/libraries/dto/assign-library-access.dto.ts:7]`
11. `create`, in ONE transaction: INSERT the row with `name`, `icon ?? null`, `color ?? null`, `mediaTypes ?? ['movie','series']`, `preferredProvider ?? null`, `metadataLanguage || null`, `metadataRegion || null` (empty string stores `null`), `defaultQualityProfileId`/`defaultLanguageProfileId` = id when truthy else `null` (so `0` and `null` both store `null`); then `assignPath` if `dto.path` is truthy (rule 13); then `replaceUserAccess` if `dto.userIds` is non-empty (rule 21); commit; then respond with `findOne(id)` read after commit (rule 2). `[ts:src/modules/libraries/libraries.service.ts:139]`–`[ts:src/modules/libraries/libraries.service.ts:178]`
12. `update`, in ONE transaction: library missing → 404 `Library #<id> not found`; build a patch from the fields that are `!== undefined` (`name`, `icon`, `color`, `mediaTypes`, `preferredProvider` as given, `null` stays `null`; `metadataLanguage`/`metadataRegion` `|| null`; profile ids truthy-or-`null`); `UPDATE libraries SET <patch>, "updatedAt" = now()` only when the patch is non-empty; then `assignPath` when `dto.path !== undefined`; respond `findOne(id)` after commit. An update that changes nothing writes nothing and does not bump `updatedAt`. `[ts:src/modules/libraries/libraries.service.ts:180]`–`[ts:src/modules/libraries/libraries.service.ts:217]`
13. `assignPath(libraryId, rawPath)` (the only code that touches the disk), in this order:
    1. library row re-read inside the tx, missing → 404 `Library #<id> not found`;
    2. `trimmed = sanitizeFsPath(rawPath)`: remove code points U+200B-U+200F, U+202A-U+202E, U+2066-U+2069, U+FEFF, then `trim()` (JS whitespace trim);
    3. `trimmed === ''` (empty or whitespace-only): current `path` null → no-op; else `SELECT count(*) FROM media WHERE "libraryId" = $1` > 0 → 400 `Path "<current>" still contains <n> media item(s).`; else `UPDATE libraries SET path = NULL`; done (nothing on disk);
    4. `current path === trimmed` → no-op, nothing checked on disk (not even existence);
    5. path does not exist (`existsSync` false, a file counts as existing, a dangling symlink does not) → `mkdir -p <trimmed>` (`fs.promises.mkdir(..., {recursive: true})`, default mode `0o777` & umask, intermediate directories created); failure → 400 `Path "<trimmed>" could not be created on the server: <os error message>` (Node's `EACCES: permission denied, mkdir '<p>'` form; free text);
    6. another library row with the same `path` (`SELECT ... FROM libraries WHERE path = $1`, exact case-sensitive string compare, no DB unique index, so racy) → 400 `Path "<trimmed>" is already attached to another library`;
    7. current `path` non-null and different, and the library has media → 400 `Path "<current>" still contains <n> media item(s) — cannot change the library's root path.`;
    8. `UPDATE libraries SET path = <trimmed>, "updatedAt" = now()`.
    Nest has no absolute-path check, no canonicalisation (`..`, trailing slash, symlinks kept verbatim), no directory or root check: a relative `trimmed` is created under the process cwd. Rust changes the order and adds the absolute check (F19, rule 37): steps 6-7 run BEFORE step 5 and step 5 is the last step before step 8. `[ts:src/modules/libraries/libraries.service.ts:291]`–`[ts:src/modules/libraries/libraries.service.ts:349]`, `[ts:src/common/utils/fs-path.util.ts:6]`–`[ts:src/common/utils/fs-path.util.ts:21]`
14. Nest: disk side effects are not transactional: step 5 runs BEFORE the conflict and in-use checks of steps 6-7, so a request that ends 400 (path taken, media present) or a later failure (create: `replaceUserAccess` fails) rolls the database back but leaves the newly created directories on disk. The `mkdir` is the only write: no file is created, moved or deleted, real media is never touched (plan §0.10). Rust does not keep this order (F19, rule 37). `[ts:src/modules/libraries/libraries.service.ts:321]`–`[ts:src/modules/libraries/libraries.service.ts:337]`
15. Rust test obligation (plan §10 S5 states it for the write side; applies here to the single `mkdir -p`): the path write is exercised only on temp dirs under `/tmp/fliks-parity/`; a unit test asserts `assignPath` never creates anything for the no-op/clear branches (rule 13.3, 13.4). `[assumed]`: derived from plan §0.10, no Nest test covers it.
16. `name` uniqueness and the profile/user foreign keys are enforced only by the database; Nest returns 500 on a duplicate `name`, an unknown profile id, an over-long `icon`/`color`/`metadataLanguage`/`metadataRegion`, or `null` for a NOT NULL column; Rust: rule 38 (C1). `[ts:src/modules/libraries/entities/library.entity.ts:21]`–`[ts:src/modules/libraries/entities/library.entity.ts:46]`
17. The library row's FK `defaultQualityProfileId`/`defaultLanguageProfileId` are `ON DELETE SET NULL`; `library_user_access.libraryId` is `ON DELETE CASCADE`; DDL is S0's. `[ts:src/modules/libraries/entities/library.entity.ts:48]`–`[ts:src/modules/libraries/entities/library.entity.ts:57]`, `[ts:src/modules/libraries/entities/library-user-access.entity.ts:18]`

### C. Delete (stays in Nest until S5, plan §15.3)

Rules 18-20 document the Nest behaviour that is NOT ported in S3: the route needs `MediaService.remove` (S5). The Rust router does not register it; the method fallback forwards it to Nest, which keeps `libraries.service.ts` `remove` until S5.

18. `DELETE /libraries/:id`: library missing → 404 `Library #<id> not found`; list the library's media ids (`SELECT id FROM media WHERE "libraryId" = $1`, no order); for each, sequentially, call `MediaService.remove(id)`; then delete the library row (cascade removes its `library_user_access` rows); log `Library #<id> deleted - <n> media row(s) removed, files kept`; 200 empty body. `[ts:src/modules/libraries/libraries.service.ts:230]`–`[ts:src/modules/libraries/libraries.service.ts:247]`
19. Not transactional: a failure on the k-th media leaves the first k-1 removed and the library in place. The disk path returned by `MediaService.remove` is deliberately ignored (files and folders are kept). `[ts:src/modules/libraries/libraries.service.ts:225]`–`[ts:src/modules/libraries/libraries.service.ts:243]`
20. `MediaService.remove(id)` is S5 media write code (not specified here, it moves with `media`): loads the media with files, `requestLifecycle.onMediaRemoved(media)`, `DELETE FROM media` (FK cascades), fire-and-forget `thumbnails.deleteForFile(fileId)` per file, domain event `media.removed {mediaId, tmdbId|null, mediaType}`, fire-and-forget `mediaServers.dispatch('media.deleted', {title, path})`. Hence the route stays in Nest until S5 (plan §15.3; no bridge). The S5 port reproduces rule 18 with in-process calls. `[ts:src/modules/media/media-service/media-mutation.service.ts:217]`–`[ts:src/modules/media/media-service/media-mutation.service.ts:247]`

### D. Access assignment

21. `replaceUserAccess(libraryId, userIds)` (inside a transaction): `DELETE FROM library_user_access WHERE "libraryId" = $1`; when `userIds` is non-empty, bulk INSERT one row per id (`userId`, `libraryId`). Only this library's rows are deleted (other libraries of the same users are untouched; `libraries.service.user-access.spec.ts` guards this). Duplicate ids in the body violate the `(libraryId, userId)` unique constraint = 500 today; an unknown user id violates the FK = 500 in Nest; Rust answers 400 (C1, rule 38). `[ts:src/modules/libraries/libraries.service.ts:351]`–`[ts:src/modules/libraries/libraries.service.ts:365]`, `[ts:src/modules/libraries/libraries.service.user-access.spec.ts:10]`
22. `PUT /libraries/:id/access` (`setUserAccess`): `before` = current `userId`s of the library read OUTSIDE the transaction; run rule 21 in one transaction; after commit, for each id in `before` that is not in `userIds` call `engine.revokeOwner(id)` fire-and-forget (never awaited, never changes the response, no-op when the engine client is absent or lacks the `revoke` feature, failures logged as warnings). Users newly added or kept are NOT revoked. Nest does not check the library: an unknown `:id` with `userIds: []` answers 200, with ids it fails the FK = 500; Rust answers 404 `Library #<id> not found` in both cases (F20, C1, rule 38). Revocation also does not run on library delete (rule 18) or on `create`. `[ts:src/modules/libraries/libraries.service.ts:260]`–`[ts:src/modules/libraries/libraries.service.ts:268]`, `[ts:src/modules/engine/engine.service.ts:476]`–`[ts:src/modules/engine/engine.service.ts:487]`, `[ts:src/modules/libraries/libraries.service.revoke.spec.ts:4]`
23. In Rust the revoke is the S1 minimal engine client called directly (same as `users.md` rules 26-27), not a bridge; body `POST /v1/revoke {"ownerId": "<userId>"}`. Library ACL is read live from the database on every request by both processes (rule 31), so no cache invalidation or SSE drop is needed after an access change. `[ts:src/modules/engine/engine.service.ts:477]`–`[ts:src/modules/engine/engine.service.ts:487]`
24. `library_user_access` is also written by `users.md` (create user, `PUT /users/:id libraryIds`) and read by `sse-audience` (events-hub); the table is owned here, DDL by S0. `[ts:src/modules/users/users.service.ts:190]`–`[ts:src/modules/users/users.service.ts:203]`

### E. Library ACL helpers (used by many modules)

30. `getAccessibleLibraryIds(user): Promise<number[]>`: when `user.isAdmin` or `user.permissions` contains `manage:all` (auth rule 19: `isAdmin` implies it) return every `libraries.id` (`SELECT id FROM libraries`, no order, resolved at call time so a new library is visible immediately); otherwise the `libraryId` of every `library_user_access` row of `user.id` (no order). The result is always a concrete array; `[]` = no access and every caller short-circuits to an empty result before further SQL. ### F. Deviations decided for the port (plan §15.3)

37. [new] F19: a library `path` (create, update) must be absolute (starts with `/` after `sanitizeFsPath`), else 400 (standard validation body, message free text). Order in `assignPath` becomes: 1-4 as rule 13, then conflict (13.6), in-use (13.7), then `mkdir -p` (13.5), then `UPDATE` (13.8): `mkdir -p` is the last step before the UPDATE, so a rejected request leaves no directory behind.
38.
