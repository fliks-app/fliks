# Spec: subtitle providers (opensubtitles, subdl, subsynchro, supersubtitles, yify, gestdown)

Out of scope here: the search orchestration (blacklist, language/flag filter, dedup, scorer, sidecar write), the `/api/media/:id/subtitles*` routes, scheduler jobs, OCR/sync, the moviehash (`subtitle-files.md` rule 37, rule 44 here). Rule 43 states only the contract the orchestrator relies on. Translation engines and the translation-provider CRUD: `translation.md`.

## Routes

9 routes under `/api/subtitles/providers`, class guards `JwtOrApiKeyGuard, PoliciesGuard`; `scope:'stream'` tokens are rejected (401). Declaration order matters: `GET rate-limits` and `POST test-connection` come before `:id` routes. This spec owns all 9, `:id/stats` included; `subtitles.md` rule 31 points here.

`ProviderJSON` = `{id, createdAt, updatedAt, name, type, enabled, settings, priority}` with `settings` redacted (rule 38): credential keys removed, `secretsSet: string[]` added. `type` in the 15 enum values of rule 37.

## Rules

### A. Provider contract and factory

1. Interface: `search(params) -> SubtitleSearchResult[]`, `download(result) -> bytes`, `testConnection(settings) -> {ok, detail?}`. Providers expose raw metadata and set `score: 0`; the orchestrator rescores everything.
2. `SubtitleSearchParams`: `imdbId?` (string), `tmdbId?`, `title`, `year?`, `season?`, `episode?`, `language` (ISO 639-1), `filePath?`, `moviehash?`, `moviebytesize?`, `videoReleaseName?`, `hearingImpairedMode?`, `forced?`. Providers read only `imdbId, tmdbId, title, year, season, episode, language, moviehash`; the rest is for the orchestrator.
3. `SubtitleSearchResult` JSON (camelCase, also the body of `GET /api/media/:id/subtitles/search` and the client's `POST.../download` `searchResult`): `providerFileId: string`, `title: string`, `releaseName?`, `imdbId?` (string, no `tt`), `hashMatched?: bool`, `language: string`, `forced: bool`, `hearingImpaired: bool`, `score: number`, `downloadCount?`, `providerName: string` (display), `providerType: string`.
4. Factory: a provider object is built per call from `(type, settings)`; no instance state survives (process-wide state lives in rules 5-9 and 12). Supported types: `opensubtitles, subdl, subsynchro, supersubtitles, yify, gestdown`; any other value throws `Unsupported subtitle provider type: <type>`. `yify` and `gestdown` ignore settings.
5. Every `search` and `download` starts with `isRateLimited(type)` (`testConnection` never does): `search` returns `[]`, `download` throws `<Name> is rate-limited, try again later` with the display name `OpenSubtitles`, `Subdl`, `Subsynchro`, `Supersubtitles`, `YIFY`, `Gestdown`. Subsynchro's download runs `providerUrl` first, so a bad path throws rule 15's message even while limited. When `rateLimitedFetch` itself returns `null` mid-download, the failure messages print `res?.status`, i.e. the literal `undefined` (`Subsynchro download failed: undefined`, same for Supersubtitles, YIFY page/download, Gestdown); only Subdl and OpenSubtitles print `rate-limited`. These strings reach the client in 400 `Download failed (<name>): <msg>` and the stats `errorMessage`.

### B. Rate limiter and circuit breaker

6. State is in memory, one record per provider TYPE string (two rows of the same type share it, a restart clears it): `{retryAfter ms, remaining|null, consecutiveFailures, circuit: closed|open|half-open, circuitResetAt ms}`.
7. `rateLimitedFetch(type, url, init?, {maxRetries=2, defaultBackoffSec=60})`: returns `null` at once when `isRateLimited(type)` (cooldown active or circuit open). Otherwise up to `maxRetries+1` attempts; each fetch has `AbortSignal.timeout(30000)` (a caller `init.signal` would override it, none passes one).
8. Outcomes per attempt: (a) throw (DNS, TLS, reset, timeout) -> `recordFailure('network: <message>')`, return `null`, no retry; (b) status 429 or 423 -> `markRateLimited`, then if attempts remain sleep `min(delaySec, 10)` s and retry, else return `null`; (c) status >= 500 -> `recordFailure('http <status>')` and return the response (the caller sees a non-ok response); (d) any other status (2xx, 3xx, 4xx) -> `recordSuccess` (closes the circuit, zeroes failures) and `trackQuota`, return the response.
9. Breaker: `recordFailure` in `closed` increments; at 3 consecutive failures -> `open` for 5 min (`circuitResetAt = now + 300000`); a failure in `half-open` re-opens for 5 min at once. `circuitOpen` flips `open -> half-open` lazily when `now >= circuitResetAt`; half-open admits one in-flight probe per type and the other callers skip the type (`null`, as open) until it resolves (rule 50). 429/423 never count as failures. Only a network error or 5xx (re-open) or any other status (close) ends half-open.
10. `markRateLimited(type, response|null, defaultBackoffSec)`: backoff = `Retry-After` when numeric (seconds, including 0), else when a parseable HTTP date `max(1, ceil((date-now)/1000))`, else the default, capped at 1 h (rule 51); `retryAfter = now + backoff*1000`. When `x-ratelimit-remaining-second` (else `ratelimit-remaining`) is present `remaining = Number(header)`. `getRateLimitDelay` = `ceil((retryAfter-now)/1000)` or 0 (and clears `retryAfter` once passed).
11. `trackQuota` after every non-429/423 non-5xx response: `remaining = Number(first present of x-ratelimit-remaining-second, ratelimit-remaining, x-ratelimit-remaining)`. `remaining` is informational (exposed by rule 12), it gates nothing.
12. `GET /providers/rate-limits` = `getAllCooldowns()`: one entry per type with `rateLimited || circuit != closed || consecutiveFailures > 0`, in Map insertion order (first time the type was touched): `{providerType, retryAfter (ms epoch), remaining (number|null), delaySec (ceil remaining cooldown, 0 when none), circuit, circuitResetAt (ms epoch), circuitResetInSec (ceil, 0 unless the circuit is not closed and still in the future), consecutiveFailures}`. A type that never failed or limited is absent. It does not run the lazy flip of rule 9: an open circuit past `circuitResetAt` still reads `circuit: "open"` with `circuitResetInSec: 0` until a provider call touches it.
13. The breaker applies only through `rateLimitedFetch`; there is no per-call circuit wrapper.
14. Not routed through `rateLimitedFetch` (no breaker, no cooldown): every `testConnection` (30 s timeout) and the OpenSubtitles CDN file fetch (60 s timeout, rule 24). Every outbound request has an explicit timeout.

### C. Download targets and archives

15. `providerUrl(base, candidate)`: `new URL(candidate, base)` (resolve, never concatenate); invalid -> `Invalid download path: <candidate>`; `resolved.origin !== new URL(base).origin` -> `Refusing to download from <origin>`; returns the resolved string. `@attacker.tld/x` resolves to a path on the provider; `https://attacker.tld/x`, `//attacker.tld/x`, `file:///etc/passwd` throw; an absolute URL on the same origin is kept. Applies to subdl (`https://dl.subdl.com`), subsynchro (`https://www.subsynchro.com`), yify (`https://yifysubtitles.ch`, also to the scraped link), gestdown (`https://api.gestdown.info`). spec
16. The origin check covers the first URL; redirects are followed only within the scheme, host and port of the request (the OpenSubtitles CDN link: `https` only, any host, no redirect off it). The redirect client is the shared `outbound::client()` (at most 5 hops, an off-origin hop stops and its 3xx is a non-ok answer; its check compares scheme, host and port, which also holds for the importers and media servers); timeouts stay per request (rule 14); yify search keeps `redirect: manual` (rule 33).
17. `extractSubtitleFromZip(buf)` (subdl, yify): walk local file headers from offset 0 while the signature is `PK\x03\x04`; the first entry whose name matches `/\.(srt|ass|ssa|sub|vtt)$/i` is returned (stored: `uncompSize` bytes; deflate: raw inflate of `compSize` bytes; any other method is skipped); else throws `No subtitle file found in ZIP archive`. Sizes come from the local header, so an entry written with a data descriptor (sizes 0) cannot be read.
18. Subsynchro has its own variant: only when the body starts with `PK`; entries collected (skip directories and `compressedSize = 0`, deflate or stored only, parse stops on a truncated entry); first entry whose lower-cased name ends in `.srt.ass.ssa.sub.vtt`; else the FIRST entry of any name; none -> `No subtitle file found in ZIP archive`. A non-zip body is returned as is.
19. The downloaded body is capped at 10 MiB and the extracted subtitle at `SUBTITLE_UPLOAD_MAX_BYTES` (5 MiB); over the cap is a download error (a legitimate file above 5 MiB, none known, fails). Rules 17 and 18 share one `zip` crate reader (central directory) with a `fallback_first` flag for Subsynchro.

### D. OpenSubtitles (`opensubtitles`, JSON REST `https://api.opensubtitles.com/api/v1`)

Settings `{apiKey?, username, password}` (`apiKey`, `password` secrets). Header set `Api-Key`, `Content-Type: application/json`, `User-Agent: Fliks v1.0`, plus `Authorization: Bearer <token>` when a token is cached.

20. Effective key: `settings.apiKey` trimmed, else the built-in consumer key constant `DEFAULT_API_KEY` (rule 47).
21. Token cache: process-wide map keyed `"<apiKey>:<username>"`, TTL 23 h, evicted lazily on read; never evicted on a 401 from search/download (kept, rule 48). `ensureToken` (before search and download): skip when a token is cached, or username or password is empty, or rate-limited; else `POST /login` `{username, password}` through `rateLimitedFetch` (default backoff 60 s); on 2xx cache `body.token`; on a non-2xx log WARN `OpenSubtitles login failed: <status> <body>` and continue unauthenticated.
22. Search request: `GET /subtitles?<query>` with `URLSearchParams` in this order: `moviehash` (if set), `imdb_id` (if set), `tmdb_id` (if truthy), then ONLY when none of hash, imdb, tmdb is present `query=<title>` and `year` (if truthy); then `languages=<language>`; `season_number` / `episode_number` when `!= null`. `rateLimitedFetch` with `defaultBackoffSec: 5`. `null` response -> `[]`; non-ok -> WARN `OpenSubtitles search failed: <status> <body>` and `[]`. `imdb_id` is sent as stored (callers pass the `tt…` string; the provider sends it unchanged).
23. Search mapping, per `data[]` item: `providerFileId = String(attributes.files[0]?.file_id ?? item.id)`, `title = releaseName = attributes.release`, `imdbId = String(attributes.feature_details.imdb_id)` when `!= null` (a number, no `tt`), `hashMatched = attributes.moviehash_match`, `language = attributes.language`, `forced = attributes.foreign_parts_only`, `hearingImpaired = attributes.hearing_impaired`, `downloadCount = attributes.download_count`, `providerName 'OpenSubtitles'`, `providerType 'opensubtitles'`. A body without `data`, or an item without a `files` array, throws a `TypeError` (caught by the orchestrator, rule 43); an empty `files` falls back to `item.id`.
24. Download: `POST /download` `{file_id: Number(providerFileId)}` (default backoff 60 s). `null` or non-ok -> throw `OpenSubtitles download failed: <body | 'rate-limited'>` (the upstream body verbatim). Response `{link, remaining}`: when `remaining != null && remaining <= 0` WARN and `markRateLimited(type, null, 3600)` (1 h cooldown, the current download still proceeds). `link` must parse as a URL with scheme `https:` else throw `OpenSubtitles returned a non-https link (<protocol>)`; no host allowlist (CDN hosts vary). Fetch it with a 60 s timeout, redirects followed; non-ok -> `Failed to fetch subtitle file: <status>`; return the bytes raw (no archive handling).
25. `testConnection(settings)`: `apiKey = settings.apiKey.trim() || effective key`, `username/password = settings.* || stored`; either empty -> `{ok:false, detail:'missing username or password'}` with no request; else `POST /login` directly (no rate limiter, no cache write) and `testResultFromResponse`.

### E. Subdl (`subdl`, JSON `https://api.subdl.com/api/v1/subtitles`, files on `https://dl.subdl.com`)

Settings `{apiKey}` (secret). User-Agent `Fliks/1.0`.

26. Search: `GET ?api_key=<key>` (a missing key is sent as the string `undefined`) then `imdb_id`, `tmdb_id` (if set), `film_name` + `year` only when neither imdb nor tmdb is present (a moviehash does NOT suppress it: Subdl has no hash search), `languages`, `type=tv` when `season != null` else `movie`, `season_number`, `episode_number` when `!= null`, `subs_per_page=30`. Default `rateLimitedFetch` options (60 s backoff). non-ok -> WARN `Subdl search failed: <status> — <text>` and `[]`. Body `{status:false, error}` -> `[]` (debug log when `error` matches `/can't find/i`, else WARN `Subdl API error: <error>`). Mapping of `subtitles[]`: `providerFileId = url` (a path like `/subtitle/123.zip`), `title = releaseName = release_name`, `language`, `forced false`, `hearingImpaired = hi`, `providerName 'Subdl'`.
27. Download: `providerUrl('https://dl.subdl.com', providerFileId)`, GET, non-ok -> `Subdl download failed: <status | 'rate-limited'>`; the body is a ZIP -> rule 17. Test probe: GET `?api_key=<settings.apiKey || stored>&imdb_id=tt0111161`.

### F. Subsynchro, Supersubtitles, Yify, Gestdown

28. Subsynchro (`https://www.subsynchro.com`, no settings, headers `User-Agent: Fliks`, `Referer: https://www.subsynchro.com`). Search: movie only, `season != null || episode != null` -> `[]`; `GET /include/ajax/subMarin.php?title=<title>[&year=<year>]`; non-ok -> WARN and `[]`; body must be `{status: 200, data: []}` else `[]`. Mapping per item: `providerFileId = telechargement`, `title = release || filename || titre_original || titre`, `releaseName = release || filename || undefined`, `language 'fr'` always (no gate on the requested language; the orchestrator drops it), `forced false`, `hearingImpaired false`. A 2xx non-JSON body throws (`res.json()`). Download: `providerUrl(base, providerFileId)` (before the rate-limit check, rule 5), non-ok -> `Subsynchro download failed: <status>`, rule 18. Probe: `GET …subMarin.php?title=test`. This is a JSON endpoint, not a scraper.
29. Supersubtitles = feliratok.eu (`https://www.feliratok.eu`, no settings). Headers: `Referer: https://www.feliratok.eu/index.php` and a `User-Agent` drawn at random from 4 browser strings per request (a fixed first entry is acceptable, nothing depends on it). Download: `GET /index.php?action=letolt&felirat=<encodeURIComponent(providerFileId)>`, raw bytes returned, except that a body starting with `PK\x03\x04` is extracted (rule 52). Probe: `GET /index.php?term=test&nyelv=0&action=autoname`.
30. Supersubtitles search: `season != null && episode != null` -> episode path, else movie path (so a series with a missing episode searches films by title). Language codes: only Hungarian and English are mapped (`mapLanguage`: lower-cased text containing `magyar|hungarian` or equal `hu` -> `hu`; containing `angol|english` or equal `en` -> `en`; anything else the lower-cased text).
31. Supersubtitles episode path: (1) series id: `GET /index.php?term=<enc title>&nyelv=0&action=autoname`, non-ok or null -> no result; body parsed with `parseJson` (empty body or non-JSON -> null, never throws); needs a non-empty array; pick the row whose `name.toLowerCase().trim()` equals the title lower-cased and trimmed, else the first row; its `ID` must match `^\d+$` (a miss is one row with a non-numeric sentinel such as `-100x`) else no result and NO second request; (2) `GET /index.php?action=xbmc&sid=<id>&ev=<season>&rtol=<episode>`; non-ok -> WARN and `[]`; body (an object or an array of `EpisodeSubtitle`, the recorded sample is an array; may be empty/`null`/plain text `Nincs SorozatID!`) -> `[]` when not an object; `Object.values` walks either. Per value: skip when `felirat` falsy or `evadpakk === '1'` (season pack); `lang = mapLanguage(language)`; skip when a language is requested and differs; `providerFileId = String(felirat)`, `title = fnev || nev || "S<evad>E<ep> - <title>"`, `releaseName = fnev || nev || undefined`, `forced = nev.toLowerCase().includes('forced')`, `hearingImpaired false`.
32. Supersubtitles movie path: `GET /index.php?search=<enc title>&soriSorszam=&nyelv=&tab=film`; non-ok -> WARN and `[]`; the HTML is parsed (regexes verbatim): split on `/<tr[^>]*>/i`; per row link `/action=letolt[^"']*?[&?](?:amp;)?felirat=(\d+)/` (no match skips the row), language cell `/class="lang"[^>]*>\s*<small>([^<]+)<\/small>/i` (absent -> `hu`; else `mapLanguage(trim)`), skip when a language is requested and differs, release `/class="eredeti"[^>]*>([^<]*)</i` trimmed (empty -> `Movie subtitle #<id>`), `forced = row.toLowerCase().includes('forced') || row.includes('szinkronoshoz')`, label decoded for `&amp; &lt; &gt; &quot; &#039; &#39;` only; `title = releaseName = decoded label`. The id is the LAST query parameter, after the filename; the CSS class `magyar` on the Hungarian-title div must never be read as a language.
33. Yify (`https://yifysubtitles.ch`, no settings, desktop Chrome `User-Agent`). Search: needs `imdbId` and no season (`season != null` -> `[]`); `GET /movie-imdb/<imdbId>` (`imdbId` interpolated unencoded) with `redirect: 'manual'`: every status `>= 300` (redirects, 404, 5xx) -> `[]` silently; the WARN branch after it is unreachable. `targetLang = LANG_MAP[language].toLowerCase()` (31 ISO codes -> English names: the same table as Gestdown); an unmapped language leaves `targetLang` undefined, which accepts EVERY language row (labelled with the requested code).
34. Yify results page (regexes verbatim): `<table[^>]*class="[^"]*other-subs[^"]*"[^>]*>[\s\S]*?<tbody>([\s\S]*?)</tbody>` (absent -> `[]`); rows `/<tr[^>]*>([\s\S]*?)<\/tr>/gi`; cells `/<td[^>]*>([\s\S]*?)<\/td>/gi`, rows with fewer than 5 cells skipped; cell 1 language `/class="sub-lang"[^>]*>([\s\S]*?)<\/span>/i` -> tags stripped, trimmed, lower-cased, must equal `targetLang` when set; cell 2 link `/href="([^"]+)"/` (none: skip), trimmed, = `providerFileId` (page path), anchor text `/<a[^>]*>([\s\S]*?)<\/a>/i` with tags stripped and a leading `subtitle` word removed = release (empty: skip); cell 3 `/hi-subtitle/i` -> `hearingImpaired`; cell 0 rating is parsed and unused. `title = releaseName`, `language` = the requested code, `forced false`.
35. Yify download: `providerUrl(base, providerFileId)` -> GET page (non-ok -> `YIFY subtitle page failed: <status>`); link `/class="download-subtitle"[^>]*href="([^"]+)"/` else `YIFY: download link not found on subtitle page`; the link goes through `providerUrl` again, GET (non-ok -> `YIFY download failed: <status>`), ZIP -> rule 17. Probe: `GET /movie-imdb/tt0111161` (`redirect: manual`, a 3xx makes `res.ok` false so the probe reads `HTTP 30x`).
36. Gestdown (`https://api.gestdown.info`, `User-Agent: Fliks/1.0`, default backoff 5 s on every call). Search: TV only (`season` or `episode` null -> `[]`); the language must be in `LANG_MAP` else `[]`; show id: `GET /shows/search/<enc title>` (non-ok -> `[]`, WARN when a response came back), `shows[]` empty -> `[]`, prefer `shows.find(s => s.tmdbId === params.tmdbId)` when `tmdbId` set, else `shows[0].id`; then `GET /subtitles/get/<showId>/<season>/<episode>/<LanguageName>` (non-ok -> `[]`). Keep `matchingSubtitles` with `completed` true; mapping: `providerFileId = downloadUri`, `title = [params.title, version, release].filter(Boolean).join(' - ')`, `releaseName = release ?? version ?? undefined`, `language` = requested code, `forced false`, `hearingImpaired`, `downloadCount`. Download: `providerUrl(base, downloadUri)`, raw bytes (no archive handling), non-ok -> `Gestdown download failed: <status>`. Probe: `GET /shows/search/test`.

### G. Settings, CRUD, test, stats

37. Entity `subtitle_providers`: `name` varchar, `type` pg enum `subtitle_providers_type_enum` (15 values: `opensubtitles, subscene, sous_titres_eu, subdl, subsynchro, supersubtitles, whisper, yify, gestdown, embedded, radarr, sonarr, disk, ocr, translated`), `enabled` bool default true, `settings` jsonb default `{}`, `priority` int default 25; `subtitle_provider_stats`: `id`, `providerId` FK cascade, `queryDate` (default now), `queryType` default `search`, `responseTimeMs`, `resultCount`, `errorMessage` text null. The DTOs accept all 15 values; only 6 have an implementation (rule 4).
38. Secret fields (redact/merge convention of `settings.md`): `password`, `apiKey`; `username` is not secret. Responses: `redactSecretFields`: those keys removed, `secretsSet` = the secret keys with a truthy stored value, in the order `password, apiKey`; always present (`[]` when none). Redaction happens in the controller; the service reads the real values.
39. Writes: `create`: `settings = mergeSecretFields(undefined, dto.settings ?? {})` (a `null` secret is dropped; a blank one becomes `undefined`, i.e. absent; the `secretsSet` key is stripped), `enabled ?? true`, `priority ?? 25`. `update` (404 first): `name`, `type`, `enabled`, `priority` assigned only when `!== undefined`; `settings` (when defined) = `mergeSecretFields(stored, incoming)`: incoming blank/absent secret keeps the stored value, explicit `null` erases it, a non-empty value replaces it. A `type` change drops the stored secrets (as `test-connection` and the translation providers do), so a stored OpenSubtitles key is never sent to another provider's host.
40. Test probe (`test-connection`, `:id/test`): `settings = resolveStoredSecrets(repo, id, settings, secret fields, stored.type === type)`: with an `id`, blank secrets are filled from the stored row only when the stored `type` equals the requested one; an unknown id gives no fill. `POST:id/test` uses the stored `(type, settings)` and needs `settings.access` (rule 53). Then `factory.create(type, settings).testConnection(settings)`; a thrown error (including `Unsupported subtitle provider type: <t>`) becomes `{ok:false, detail:<message>}`. Logs: LOG on success, WARN with `detail` on a verdict failure, ERROR on a throw.
41. `testResultFromResponse(res)`: ok -> `{ok:true}`; else the JSON body's first non-blank string among `message, error, detail, error_description` (trimmed, first 200 chars) gives `detail = "HTTP <status>: <reason>"`; no usable reason (HTML, non-JSON, unreadable) gives `detail = "HTTP <status>"` + `" <statusText>"` when the status text is non-empty.
42. Stats (read side): `GET:id/stats`, owned here only (`subtitles.md` rule 31), runs the query in SQL below over the last 30 local days; `date` is the instant of server-local midnight, not `YYYY-MM-DDT00:00:00.000Z` (right only under UTC). The write side (one `search` row per provider per search, one `download` row per download, `errorMessage` = exception message) belongs to the orchestrator and is fire-and-forget (`void save`).
43. Contract relied on by the orchestrator: providers run sequentially in priority order (`findEnabled`: `enabled = true ORDER BY priority ASC, id ASC`); a provider that throws contributes nothing and is logged WARN `Search failed for provider <name>: <err>`; a provider returning `[]` through a skip (rate limit, open circuit, wrong media kind) is indistinguishable from "no result". Download resolves the provider row by `String(type) === searchResult.providerType`, 404 `No matching provider found`, and the client-supplied `searchResult` is NOT validated (`providerFileId` is attacker-controlled: rule 15 and the `Number()`/`encodeURIComponent` of rules 24/29 are the only guards; OpenSubtitles sends `file_id: NaN -> null` upstream for a non-number).

### H. Moviehash

44. Owned by `subtitle-files.md` rule 37 (the hash is the engine probe's; stored values are recomputed on re-enrich). Providers only forward `params.moviehash` (rules 2, 22), read by the orchestrator from `media_files.osdbHash`.

### I. Outbound HTTP in tests and parity

45. Every provider struct takes its base URL(s) as constructor fields defaulting to the constants above (`api.opensubtitles.com`, `api.subdl.com`, `dl.subdl.com`, `www.subsynchro.com`, `www.feliratok.eu`, `yifysubtitles.ch`, `api.gestdown.info`). `providerUrl` checks the origin against the configured base, so a stub on `http://127.0.0.1:<port>` works unchanged. Unit and integration tests start an axum stub per test and point the structs at it; no production env switch exists (a base-URL env var would let a config change redirect credentials). The OpenSubtitles `link` rule (https only, rule 24) is relaxed to `http` by a constructor field (`allow_http_link`, false in the production wiring): `cfg(test)` would not reach the `tests/` integration tests, which link the non-test build.
46. Parity (black box over HTTP, `PARITY_TARGET`): a release binary cannot be repointed (provider bases are constants); only a build with the `parity` cargo feature reads `FLIKS_SUBTITLE_PROVIDERS_URL` (`config.md`), which `subtitles-provider/` scenarios use against a Subdl stub. Parity covers CRUD, redaction, validation, rate-limits (empty), and test-connection with an unsupported type (`ok:false`, no network). Network behaviour is covered by Rust integration tests against stubs and by the fixtures below.

### J. Settled behaviours

47. `DEFAULT_API_KEY` is the app's OpenSubtitles consumer key, not a leaked secret: the client form has no `apiKey` field for OpenSubtitles (only username and password), so every install relies on it. It identifies the application; user auth is the login token. The constant stays (an env var would break installs that set none: contract change).
48. The cached OpenSubtitles token is not dropped on a 401 and the login is not retried (rule 21).
49. Error strings, logs and the `detail` / `error` bodies of providers and translation engines never carry a URL or a secret (shared with `translation.md`; the errors, logs and SSE of notification senders, importers and media servers never contain the request URL or its userinfo either). The Gemini key travels in `x-goog-api-key`. reqwest's `Display` includes the request URL, which holds `api_key=` (Subdl) or `key=` (Gemini): Rust strips URLs from every error (`without_url`), never logs a request URL, and redacts the configured secret values from upstream bodies echoed in `detail`, the stat `errorMessage`, `subtitle_files.errorMessage` and SSE.
50. Half-open admits one in-flight probe per type and the other callers skip it (`null`, as open) until it resolves: a network error or 5xx re-opens, any other status closes, a 429/423 leaves half-open plus the cooldown.
51. The cooldown from `Retry-After` is capped at 1 h, the OpenSubtitles quota cooldown value, so a header of `86400` or a huge number cannot block the type until restart (rule 10).
52. Supersubtitles `letolt` may answer a ZIP (the episode sample names `placeholder.s1.zip`); the body is sniffed for `PK\x03\x04` and extracted like Subsynchro (rule 18). A raw SRT never starts with those bytes, so the sniff is safe whatever the site answers and ships without a live check.
53. `POST:id/test` needs `settings.access`, the policy of `test-connection`, because it triggers a login with the stored credentials; `GET /api/subtitles/health` needs `subtitles.manage` for the same reason (shared with `subtitles.md` rule 23). The client has no caller of `:id/test`.

## SQL

Provider rows: `SELECT * FROM subtitle_providers ORDER BY priority ASC, name ASC` (list); `WHERE id = $1` (get); `WHERE enabled = true ORDER BY priority ASC, id ASC` (orchestrator); `INSERT/UPDATE/DELETE` by id (rules 37-39). Column names are the camelCase quoted ones of the baseline migration.

Stats (`GET:id/stats`, parameters `$1` id, `$2` = now minus 30 days (`setDate(getDate()-30)`), server local time):

```sql
SELECT DATE(s."queryDate") AS date, COUNT(*) AS queries,
       AVG(s."responseTimeMs")::int AS "avgResponseMs",
       SUM(s."resultCount")::int AS "totalResults",
       SUM(CASE WHEN s."errorMessage" IS NOT NULL THEN 1 ELSE 0 END)::int AS errors
FROM subtitle_provider_stats s
WHERE s."providerId" = $1 AND s."queryDate" >= $2
GROUP BY DATE(s."queryDate") ORDER BY date DESC
```

Types: `date` is the instant of server-local midnight, serialised as UTC ISO (`2026-10-14T22:00:00.000Z` under UTC+2; `T00:00:00.000Z` only when TZ is UTC; `subtitles.md` rule 53), `queries` is a numeric STRING (pg `bigint` count), the three `::int` columns are numbers (`null` for an all-null group is impossible: `avg`/`sum` of non-null columns). Pin it in parity (`providers-stats`, recorded under TZ=UTC and Europe/Paris). Insert of stats rows: `INSERT INTO subtitle_provider_stats ("providerId","queryType","responseTimeMs","resultCount","errorMessage")`.

none emitted by providers. (The orchestrator's `subtitle.*` events and notifications dispatch are in the orchestration spec.)

No app-setting keys. ## Jobs/timers

none in this spec. Timeouts and limits: fetch 30 s (via `rateLimitedFetch`), OpenSubtitles CDN file 60 s, 429/423 retry sleep `min(delay, 10)` s with 2 retries, breaker 3 failures / 5 min, token TTL 23 h, OpenSubtitles quota-zero cooldown 1 h, default cooldown 60 s (5 s for OpenSubtitles search and Gestdown). Body cap 10 MiB, extracted subtitle 5 MiB (rule 19).

## Vectors/parity

No vector set: the provider classes are tested in Rust (`crates/server/src/subtitles/tests/providers.rs`) against loopback stubs and the saved provider pages of `server/fixtures/subtitle-providers/`: `html/supersubtitles-movie.html`, `html/yify-movie.html`, `html/yify-subtitle.html`, `json/subsynchro-search.json`, `json/supersubtitles-{hit,miss,episode}.json`. Each case records `{url, method, headers (secret values masked), body}` of the calls and the result or error text; the limiter state and the OpenSubtitles token cache live in the per-test `Shared`, and the 10 s retry sleeps and the 5 min breaker run on a paused tokio clock.
- `provider-url-*`: relative path, same-origin absolute URL, other origin, `file:` scheme, plus `//host`, `\\host`, `http://` same host different scheme, empty candidate, query-only.
- `rate-limiter-*`: fake clock for threshold (2 failures stay closed, 3rd opens), open -> half-open at 300 s with a single probe, half-open failure re-opens, 429 with `Retry-After` seconds / HTTP date / garbage / `0`, 423, retry count (3 attempts), sleep cap 10 s, `getAllCooldowns` shape and filtering, `trackQuota` header precedence.
- `os-search-*`: free-text query with year; tmdb id suppresses title; moviehash suppresses title; imdb + season/episode params; mapping of a recorded `data[]` item incl. empty `files` (falls back to `id`), missing `files` (throws), `feature_details` absent, `imdb_id` numeric.
- `os-download-*`: `remaining 0` -> 1 h cooldown, non-https link refused, `file_id` from `providerFileId`, login token cached and reused (call counts), login failure continues.
- `subdl-search-*`: hash does not suppress `film_name`, `status:false` with/without `can't find`, tv type, `subs_per_page`.
- `supersubtitles-*`: a real hit, the no-match sentinel, empty/plain-text/`null` bodies, entry without id, the two-row movie page, CSS-class language trap, language filter, no link, season pack skipped, `forced` from name, entity decoding, `fnev` fallback label.
- `yify-*`, `subsynchro-*`, `gestdown-*`: cases written against the recorded shapes of rules 28, 33-36.
- `zip-*`: stored entry, deflated entry, no subtitle entry (throws), non-first entry, data-descriptor entry (documented limitation), Subsynchro fallback-first-entry variant, directory entries.
- `provider-test-*`: `testResultFromResponse` (200-char truncation, `error_description`, whitespace-only message), `missing username or password`.

Rust integration tests (axum stub servers, no external network): breaker over real 5xx/closed-port/timeout (paused clock), `Retry-After` handling, redirect to another origin refused (rule 16), oversized and zip-bomb bodies refused (rule 19), error text and logs carry no URL and no key (rule 49), probes with a 30 s timeout.
