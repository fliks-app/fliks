## Rules

### A. Provider contract and factory

1. Interface: `search(params) -> SubtitleSearchResult[]`, `download(result) -> bytes`, `testConnection(settings) -> {ok, detail?}`. Providers expose raw metadata and set `score: 0`; the orchestrator rescores everything. `[ts:src/modules/subtitles/providers/subtitle-provider.interface.ts:1]`-`[ts:src/modules/subtitles/providers/subtitle-provider.interface.ts:107]`
2. `SubtitleSearchParams`: `imdbId?` (string), `tmdbId?`, `title`, `year?`, `season?`, `episode?`, `language` (ISO 639-1), `filePath?`, `moviehash?`, `moviebytesize?`, `videoReleaseName?`, `hearingImpairedMode?`, `forced?`. Providers read only `imdbId, tmdbId, title, year, season, episode, language, moviehash`; the rest is for the orchestrator. `[ts:src/modules/subtitles/providers/subtitle-provider.interface.ts:1]`-`[ts:src/modules/subtitles/providers/subtitle-provider.interface.ts:26]`
3. `SubtitleSearchResult` JSON (camelCase, also the body of `GET /api/media/:id/subtitles/search` and the client's `POST .../download` `searchResult`): `providerFileId: string`, `title: string`, `releaseName?`, `imdbId?` (string, no `tt`), `hashMatched?: bool`, `language: string`, `forced: bool`, `hearingImpaired: bool`, `score: number`, `downloadCount?`, `providerName: string` (display), `providerType: string`. `[ts:src/modules/subtitles/providers/subtitle-provider.interface.ts:34]`-`[ts:src/modules/subtitles/providers/subtitle-provider.interface.ts:61]`
4. Factory: a provider object is built per call from `(type, settings)`; no instance state survives (process-wide state lives in rules 5-9 and 12). Supported types: `opensubtitles, subdl, subsynchro, supersubtitles, yify, gestdown`; any other value throws `Unsupported subtitle provider type: <type>`. `yify` and `gestdown` ignore settings. `[ts:src/modules/subtitles/providers/subtitle-provider.factory.ts:13]`-`[ts:src/modules/subtitles/providers/subtitle-provider.factory.ts:33]`
5. Every `search` and `download` starts with `isRateLimited(type)` (`testConnection` never does): `search` returns `[]`, `download` throws `<Name> is rate-limited, try again later` with the display name `OpenSubtitles`, `Subdl`, `Subsynchro`, `Supersubtitles`, `YIFY`, `Gestdown`. Subsynchro's download runs `providerUrl` first, so a bad path throws rule 15's message even while limited. When `rateLimitedFetch` itself returns `null` mid-download, the failure messages print `res?.status`, i.e. the literal `undefined` (`Subsynchro download failed: undefined`, same for Supersubtitles, YIFY page/download, Gestdown); only Subdl and OpenSubtitles print `rate-limited`. These strings reach the client in 400 `Download failed (<name>): <msg>` and the stats `errorMessage`. `[ts:src/modules/subtitles/providers/subdl.provider.ts:38]`, `[ts:src/modules/subtitles/providers/subdl.provider.ts:95]`

### B. Rate limiter and circuit breaker (`rate-limiter.ts`)

6. State is in memory, one record per provider TYPE string (two rows of the same type share it, a restart clears it): `{retryAfter ms, remaining|null, consecutiveFailures, circuit: closed|open|half-open, circuitResetAt ms}`. `[ts:src/modules/subtitles/providers/rate-limiter.ts:16]`-`[ts:src/modules/subtitles/providers/rate-limiter.ts:45]`
7. `rateLimitedFetch(type, url, init?, {maxRetries=2, defaultBackoffSec=60})`: returns `null` at once when `isRateLimited(type)` (cooldown active or circuit open). Otherwise up to `maxRetries+1` attempts; each fetch has `AbortSignal.timeout(30000)` (a caller `init.signal` would override it, none passes one). `[ts:src/modules/subtitles/providers/rate-limiter.ts:233]`-`[ts:src/modules/subtitles/providers/rate-limiter.ts:259]`
8. Outcomes per attempt: (a) throw (DNS, TLS, reset, timeout) -> `recordFailure('network: <message>')`, return `null`, no retry; (b) status 429 or 423 -> `markRateLimited`, then if attempts remain sleep `min(delaySec, 10)` s and retry, else return `null`; (c) status >= 500 -> `recordFailure('http <status>')` and return the response (the caller sees a non-ok response); (d) any other status (2xx, 3xx, 4xx) -> `recordSuccess` (closes the circuit, zeroes failures) and `trackQuota`, return the response. `[ts:src/modules/subtitles/providers/rate-limiter.ts:246]`-`[ts:src/modules/subtitles/providers/rate-limiter.ts:287]`
9. Breaker: `recordFailure` in `closed` increments; at 3 consecutive failures -> `open` for 5 min (`circuitResetAt = now + 300000`); a failure in `half-open` re-opens for 5 min at once. `circuitOpen` flips `open -> half-open` lazily when `now >= circuitResetAt` and then reports "not open", so EVERY caller passes while half-open (the comment says one probe; nothing enforces it). 429/423 never count as failures. Only a network error or 5xx (re-open) or any other status (close) ends half-open. [new] C70: rule 50. `[ts:src/modules/subtitles/providers/rate-limiter.ts:5]`-`[ts:src/modules/subtitles/providers/rate-limiter.ts:93]`
10. `markRateLimited(type, response|null, defaultBackoffSec)`: backoff = `Retry-After` when numeric (seconds, any value including 0 or huge, no cap), else when a parseable HTTP date `max(1, ceil((date-now)/1000))`, else the default; `retryAfter = now + backoff*1000`. When `x-ratelimit-remaining-second` (else `ratelimit-remaining`) is present `remaining = Number(header)`. `getRateLimitDelay` = `ceil((retryAfter-now)/1000)` or 0 (and clears `retryAfter` once passed). [new] C71: rule 51. `[ts:src/modules/subtitles/providers/rate-limiter.ts:99]`-`[ts:src/modules/subtitles/providers/rate-limiter.ts:158]`
11. `trackQuota` after every non-429/423 non-5xx response: `remaining = Number(first present of x-ratelimit-remaining-second, ratelimit-remaining, x-ratelimit-remaining)`. `remaining` is informational (exposed by rule 12), it gates nothing. `[ts:src/modules/subtitles/providers/rate-limiter.ts:164]`-`[ts:src/modules/subtitles/providers/rate-limiter.ts:172]`
12. `GET /providers/rate-limits` = `getAllCooldowns()`: one entry per type with `rateLimited || circuit != closed || consecutiveFailures > 0`, in Map insertion order (first time the type was touched): `{providerType, retryAfter (ms epoch), remaining (number|null), delaySec (ceil remaining cooldown, 0 when none), circuit, circuitResetAt (ms epoch), circuitResetInSec (ceil, 0 unless the circuit is not closed and still in the future), consecutiveFailures}`. A type that never failed or limited is absent. It does not run the lazy flip of rule 9: an open circuit past `circuitResetAt` still reads `circuit: "open"` with `circuitResetInSec: 0` until a provider call touches it. `[ts:src/modules/subtitles/providers/rate-limiter.ts:181]`-`[ts:src/modules/subtitles/providers/rate-limiter.ts:221]`, `[ts:src/modules/subtitles/subtitles.controller.ts:35]`-`[ts:src/modules/subtitles/subtitles.controller.ts:39]`, spec `[ts:src/modules/subtitles/providers/rate-limiter.spec.ts:11]`-`[ts:src/modules/subtitles/providers/rate-limiter.spec.ts:60]`
13. `withCircuitBreaker` is exported and unused: not ported. `[ts:src/modules/subtitles/providers/rate-limiter.ts:298]`-`[ts:src/modules/subtitles/providers/rate-limiter.ts:311]`
14. Not routed through `rateLimitedFetch` (no breaker, no cooldown, no 30 s cap; Node's fetch default of 300 s applies): every `testConnection`, and the OpenSubtitles CDN file fetch (60 s cap, rule 24). [new] Rust: every outbound request has an explicit timeout; probes 30 s (C68).

### C. Download targets and archives

15. `providerUrl(base, candidate)`: `new URL(candidate, base)` (resolve, never concatenate); invalid -> `Invalid download path: <candidate>`; `resolved.origin !== new URL(base).origin` -> `Refusing to download from <origin>`; returns the resolved string. `@attacker.tld/x` resolves to a path on the provider; `https://attacker.tld/x`, `//attacker.tld/x`, `file:///etc/passwd` throw; an absolute URL on the same origin is kept. Applies to subdl (`https://dl.subdl.com`), subsynchro (`https://www.subsynchro.com`), yify (`https://yifysubtitles.ch`, also to the scraped link), gestdown (`https://api.gestdown.info`). `[ts:src/modules/subtitles/providers/provider-url.ts:11]`-`[ts:src/modules/subtitles/providers/provider-url.ts:22]`, spec `[ts:src/modules/subtitles/providers/provider-url.spec.ts:5]`-`[ts:src/modules/subtitles/providers/provider-url.spec.ts:27]`
16. The origin check covers the first URL only: the fetch follows redirects (fetch default) to any host or scheme the provider answers with, and the body is written as a sidecar. [new] Rust: redirects followed only within the original origin (F55; the OpenSubtitles CDN link: `https` only, any host, no redirect off it). The redirect client is S5's `outbound::client()` (at most 5 hops, an off-origin hop stops and its 3xx is a non-ok answer); its check compares scheme and host only, so S6 adds the port (`port_or_known_default`) in that shared policy, which tightens the importers and media servers the same way; timeouts stay per request (C68); yify search keeps `redirect: manual` (rule 33).
17. `extractSubtitleFromZip(buf)` (subdl, yify): walk local file headers from offset 0 while the signature is `PK\x03\x04`; the first entry whose name matches `/\.(srt|ass|ssa|sub|vtt)$/i` is returned (stored: `uncompSize` bytes; deflate: raw inflate of `compSize` bytes; any other method is skipped); else throws `No subtitle file found in ZIP archive`. Sizes come from the local header, so an entry written with a data descriptor (sizes 0) cannot be read. `[ts:src/modules/subtitles/providers/zip-utils.ts:7]`-`[ts:src/modules/subtitles/providers/zip-utils.ts:38]`
18. Subsynchro has its own variant: only when the body starts with `PK`; entries collected (skip directories and `compressedSize = 0`, deflate or stored only, parse stops on a truncated entry); first entry whose lower-cased name ends in `.srt .ass .ssa .sub .vtt`; else the FIRST entry of any name; none -> `No subtitle file found in ZIP archive`. A non-zip body is returned as is. `[ts:src/modules/subtitles/providers/subsynchro.provider.ts:98]`-`[ts:src/modules/subtitles/providers/subsynchro.provider.ts:202]`
19. No size limit: bodies are read whole (`arrayBuffer()`), inflate has no output cap. [new] Rust caps the downloaded body at 10 MiB and the extracted subtitle at `SUBTITLE_UPLOAD_MAX_BYTES` (5 MiB), over the cap is a download error (F56; a legitimate file above 5 MiB, none known, fails); unify rule 17/18 on the `zip` crate central directory with a `fallback_first` flag for Subsynchro.

## SQL

Provider rows: `SELECT * FROM subtitle_providers ORDER BY priority ASC, name ASC` (list); `WHERE id = $1` (get); `WHERE enabled = true ORDER BY priority ASC, id ASC` (orchestrator); `INSERT/UPDATE/DELETE` by id (rules 37-39). Column names are the camelCase quoted ones of the baseline migration.

Stats (`GET :id/stats`, parameters `$1` id, `$2` now minus 30 days via `setDate(getDate()-30)`, server local time):

```sql
SELECT DATE(s."queryDate") AS date, COUNT(*) AS queries,
       AVG(s."responseTimeMs")::int AS "avgResponseMs",
       SUM(s."resultCount")::int AS "totalResults",
       SUM(CASE WHEN s."errorMessage" IS NOT NULL THEN 1 ELSE 0 END)::int AS errors
FROM subtitle_provider_stats s
WHERE s."providerId" = $1 AND s."queryDate" >= $2
GROUP BY DATE(s."queryDate") ORDER BY date DESC
```

`getRawMany` types: `date` is the pg `date` parsed by node-pg into a JS `Date` at server-local midnight, serialised as UTC ISO (`2026-10-14T22:00:00.000Z` under UTC+2; `T00:00:00.000Z` only when TZ is UTC; `subtitles.md` rule 53), `queries` is a numeric STRING (pg `bigint` count), the three `::int` columns are numbers (`null` for an all-null group is impossible: `avg`/`sum` of non-null columns). Pin it in parity (`providers-stats`, recorded under TZ=UTC and Europe/Paris). Insert of stats rows: `INSERT INTO subtitle_provider_stats ("providerId","queryType","responseTimeMs","resultCount","errorMessage")`.
