## Routes

3 routes (manifest filter `.[]|select(.path|test("^/api/persons"))` = 3, all `PersonsController`). **No guard of any kind today**: no `@UseGuards`, no policy, so anonymous callers get data and `GET /api/persons/:id` can make the server call TMDB/TVDB and write to disk for them `[ts:src/modules/persons/persons.controller.ts:4-6]`. **F4** `[new]`: Rust authenticates them (`Authed`, no policy, like `AnyAuthenticatedUser`): anonymous 401 (auth rule 14), `scope:'stream'` token 401 (F8). No `httpCode` (GET = 200). `search` is declared before `:id`, so `search` is never read as an id (axum static-over-param gives the same).

`Person` = the `persons` row without `searchVector` (`select: false`): `{id, createdAt, updatedAt, provider: string, tmdbId: number, name: string, avatarUrl: string|null, biography: string|null, birthday: string|null ('YYYY-MM-DD'), deathday: string|null, placeOfBirth: string|null, knownForDepartment: string|null, departments: string[], metadataRefreshedAt: string|null (ISO)}`; timestamps in the `%Y-%m-%dT%H:%M:%S%.3fZ` form (media-query rule 30). `MediaRow` = `Media` as `media-query.md` rule 30 (all columns, `path`, joined `library`, `qualityProfile`, `languageProfile`) plus `metadata` (rule 31, `media_metadata` row, bigints as strings); no `files`, `seasons`, `cast`, `crew`, `addedBy`, `episodeStats`, `watched`, `progressPercent` (rule 17).

| Method path | Auth | Request | Response | Errors | Side effects |
|---|---|---|---|---|---|

`CastRow` = `{id, createdAt, updatedAt, character: string, order: number, media: MediaRow, person: Person}`; `CrewRow` = `{id, createdAt, updatedAt, job: string, department: string, media: MediaRow, person: Person}` (`person` is an eager relation, so every row repeats the full person, including its refreshed fields). `Credit` = `{externalId: number, title: string, mediaType: 'movie'|'series', character?: string, job?: string, department?: string, posterUrl: string|null, fanartUrl?: string|null, releaseDate: string|null, rating: number, mediaId: number|null}` (`character` on cast items, `job` + `department` on crew items; absent keys are absent, see meta rule 34).

## Rules

### A. Search

1. F4 `[new]`: authentication required on all three routes (README F4). The client already sends a credential (`client-audit.md` F4); Apple TV, Cast and Electron main do not call these routes.
2. `q` is a bare `@Query('q')`: missing → `undefined`; `q?.trim()` falsy (missing, empty, whitespace) lists persons (rule 3); a repeated `q` is an array and `.trim` throws → 500 today (C28: 400 standard validation body). `[ts:src/modules/persons/persons.service.ts:47-50]`
3. Empty `q`: `personRepo.find({order:{name:'ASC'}})`: all rows, no limit, no pagination; ties by name unordered, Rust adds `, id ASC` (C12). C171 `[new]`: the first 1000 by name, so a large catalog no longer ships every biography in one response (a person past it is still found by name). `[ts:src/modules/persons/persons.service.ts:48-50]`
4. Non-empty `q`: `tsQuery = q.trim().split(/\s+/).map(w => w + ':*').join(' & ')` then `p."searchVector" @@ to_tsquery('simple', $1)`: every whitespace-separated word is a prefix term, all words ANDed, config `simple` (no stemming, no stop words, lowercase). `[ts:src/modules/persons/persons.service.ts:51-60]`
5. Words are not escaped, so `to_tsquery` parses them as tsquery syntax (checked on PG 18): `a&`, `x!`, `(`, `a)`, `a<b`, `a:b`, a lone `'` or `:` → `syntax error in tsquery` → **500**; `a&b`, `a|b`, `!a` are silently read as operators (AND / OR / NOT); `o'brien` parses as the phrase `'o':* <-> 'brien':*` and does match "O'Brien"; `jean-luc` → `'jean-luc':* <-> 'jean':* <-> 'luc':*`; `a\b` → `'ab':*`; a word with no lexeme (`-`) gives an empty query (NOTICE) that matches nothing → `[]`. C30 `[new]`: Rust builds the query from sanitised words (each word reduced to its letter/digit/`-`/`_` runs, empties dropped, quoted as a lexeme with `:*`), so `o'brien` and `jean-luc` still match as today, operators are never interpreted, and a `q` with no usable word answers `[]`.
6. Order and size: `ORDER BY ts_rank(p."searchVector", to_tsquery('simple', $1)) DESC LIMIT 50` (`getMany`); ties unordered, Rust adds `, p.name ASC, p.id ASC` (C12). `searchVector` is NULL for a person never indexed (rule 22), which never matches. `[ts:src/modules/persons/persons.service.ts:57-62]`
7. Result = `Person[]` (`searchVector` never selected). Empty result `[]`. `[ts:src/modules/media/entities/person.entity.ts:42-47]`

### B. Detail (`GET :id`)

8. `ParseIntPipe` on `:id` (auth rule 18): Nest accepts any numeric-looking string and `parseInt`s it (`007` → 7, `1e1` → 10, ` 7 ` → 7); Rust accepts canonical integers within `i32` only, else 400 (C20). `[ts:src/modules/persons/persons.controller.ts:14]`
9. `findOne(id)`: `SELECT … FROM persons WHERE id = $1`; missing → `NotFoundException("Person #<id> not found")`. Then `ensureDetailsLoaded` runs **inside the request** before the cast/crew queries (latency = provider call, up to 10 s TMDB / 15 s TVDB, plus the avatar download up to 15 s after waiting for a slot of the image store's download semaphore). `[ts:src/modules/persons/persons.service.ts:65-73]`
10. Refresh condition: `metadataRefreshedAt` is `null` or older than **7 days** (`Date.now() - t > 7 * 86400000`); otherwise nothing is fetched and the stored row is returned as is. Persons created by a media import therefore have no biography until the first `GET :id`. `[ts:src/modules/persons/persons.service.ts:26-27]`, `[ts:src/modules/persons/persons.service.ts:121-126]`
11. Provider routing (`callProvider`, shared with `provider-credits`): the person's `provider` column names the provider that issued `tmdbId` (`tmdb` default, `tvdb` for TVDB credits, unique on `(provider, tmdbId)`); `registry.resolve(person.provider)` picks it iff its key is configured, else TMDB (meta rule 6, so a `tvdb` person with no `TVDB_API_KEY` is asked of TMDB). The id sent is `String(person.tmdbId)`. When the call fails with an **HTTP 404** (axios error with `response.status === 404`: the id belongs to the other provider) and another provider is available (`getFallback`), the same call is made there; on success the row is pinned to it (`UPDATE persons SET provider = <fallback>` and the in-memory person), one log line. Any other error (timeout, 5xx, 429, breaker open, non-404 4xx, fallback also failing) is rethrown. If the pin violates `UNIQUE(provider, tmdbId)` (another row already holds that pair) the UPDATE throws; see rule 13 and C31. `[ts:src/modules/persons/persons.service.ts:158-179]`, spec `[ts:src/modules/persons/persons.provider-credits.spec.ts:51-70]`
12. Avatar: when `details.avatarUrl` is set, `downloadAndStore(url, 'person', person.id)` (img rules 1-15) stores `<dataDir>/persons/<id>.jpg` (+ `-thumb`, no `-medium`, `person: {thumb: w45, full: original}`); the returned `/api/images/person/<id>?v=<hash>` becomes `avatarUrl`; a `null` result (download or decode failed) leaves the existing `avatarUrl` untouched and the provider's URL is **never stored**. `[ts:src/modules/persons/persons.service.ts:132-140]`
13. Whole refresh is wrapped in `try { … } catch { /* serve stale */ }`: provider failure, image failure, a failing UPDATE and the unique violation of rule 11 are all swallowed, nothing is logged by this code, `metadataRefreshedAt` stays old, and the stored row is served. Consequence: while the provider is unreachable **every** `GET :id` of a stale person pays the full timeout (TMDB's breaker, meta rule 18, makes it fast after 3 failures; TVDB has none). `[ts:src/modules/persons/persons.service.ts:128-155]`
14. Update set (`personRepo.update(person.id, updates)`): `name: details.name`, `avatarUrl` only when rule 12 produced a local path, `biography: details.biography` (string, `''` allowed), `birthday`, `deathday`, `placeOfBirth` as `details.x ?? undefined` (TypeORM skips `undefined`, so a provider that now answers `null` **never clears** a stored value), `knownForDepartment: details.knownForDepartment`, `metadataRefreshedAt: new Date()`; `updatedAt` is set by the entity's `@UpdateDateColumn` (and C8's trigger). `departments` is not touched. `name` changes do **not** refresh `searchVector` (rule 22; C31). `[ts:src/modules/persons/persons.service.ts:141-151]`
15. Response of the refreshing request: the in-memory entity after `Object.assign(person, updates)`, not a re-read: `birthday`/`deathday`/`placeOfBirth` that the provider returned as `null` are assigned `undefined`, so those keys are **absent** from the JSON of that one response (they are `null` on the next, DB-read response) and `updatedAt` is the pre-update value; `avatarUrl` keeps its old value without a local download. C31 `[new]`: re-read the row after the update (keys `null`, fresh `updatedAt`); the client reads `string|null` and treats absent as `null` (`persons-api.service.ts:5-17`). `[ts:src/modules/persons/persons.service.ts:151-152]`
16. Concurrent `GET :id` of one stale person: each request runs its own provider call; only the image store de-duplicates (img rule 2), the later UPDATE wins. No lock (frozen).
17. Cast/crew (after the refresh): `castRepo.find({where:{person:{id}}, relations:['media'], order:{order:'ASC'}})` and `crewRepo.find({where:{person:{id}}, relations:['media']})` run concurrently (SQL Q3/Q4). `relations: ['media']` also joins `media`'s eager relations (`library`, `qualityProfile`, `languageProfile`, `metadata`; TypeORM 0.3.31 `SelectQueryBuilder.js:1797` `buildEagerRelations`), so each `media` is the entity of media-query rule 30 + `metadata` (rule 31), serialised with the `path` getter. Cast order is `order ASC` (ties unordered, Rust `, id ASC`); crew has no order (Rust `id ASC`, C12). No library ACL: every credit's media is returned, including libraries the caller cannot read, with absolute `path` and `library.path` (see F40, F22). `[ts:src/modules/persons/persons.service.ts:75-87]`, `[ts:src/modules/media/entities/media.entity.ts:85-91]`, `[ts:src/modules/media/entities/media.entity.ts:196-200]`
18. A person with no credits answers `cast: []`, `crew: []`. A person row with `provider` other than `tmdb`/`tvdb` is not constrained by the schema; it resolves like an unavailable provider (rule 11).

### C. Provider credits (`GET :id/provider-credits`)

19. `findOne` (no `ensureDetailsLoaded`: no avatar, no row refresh, 404 as above), then `callProvider(person, p => p.getPersonCredits(String(person.tmdbId)))` (rule 11, including the 404 fallback and provider pin). Provider payload: meta rule 34 (TMDB `combined_credits`: `title = title ?? name ?? ''`, `mediaType = media_type === 'tv' ? 'series' : 'movie'`, `releaseDate = release_date ?? first_air_date ?? null`, `rating = vote_average ?? 0`, `posterUrl w500`, `fanartUrl original`). `[ts:src/modules/persons/persons.service.ts:90-100]`
20. Credits are mapped to `{...item, mediaId: null}` then linked to owned media (SQL Q5): ids = distinct truthy `externalId`s of cast + crew; none → no query; `column = person.provider === 'tvdb' ? 'tvdbId' : 'tmdbId'` (the **pinned** provider, after rule 11); `SELECT id, <column> FROM media WHERE <column> = ANY(ids)`; `mediaId = byExternalId.get(externalId) ?? null`. The match ignores `mediaType`: a TMDB movie and series that share a numeric id are both `media` rows (`UNIQUE(type, tmdbId)`) and the last row wins, so a credit can link to the wrong media; C31 `[new]` match `(type, id)` using the credit's `mediaType`. No library ACL (F40). `[ts:src/modules/persons/persons.service.ts:102-119]`
21. `[new]` F40: `mediaId` in provider credits, and `media` in `CastRow`/`CrewRow` (rule 17), only for media in libraries the caller can read (library ACL, `libraries.md` rules 30-36; admin and `manage:all` see all); credits for other media keep `mediaId: null`, cast/crew rows for other media are omitted, and `media.path` / `media.library.path` are omitted for callers who cannot manage libraries (F22, same predicate as `media-query.md` rule 73).
22. `searchVector` maintenance: today only the media metadata import writes it (`UPDATE persons SET "searchVector" = to_tsvector('simple', name) WHERE id = ANY($1)` for every person of the media's credits, after their insert or `name` update, `[ts:src/modules/media/media-service/media-metadata.service.ts:1181-1186]`); it is the only path that creates persons, and it re-indexes the persons it renames. The gap is rule 14: a name changed by `GET :id` stays indexed under the old name until the next import of one of that person's media (and a row whose import failed between its insert and this UPDATE stays NULL). Decided (S3 `media.searchVector` pattern, plan §15.3; part of C31): a `BEFORE INSERT OR UPDATE OF name` trigger sets `"searchVector" = to_tsvector('simple', name)` with a backfill (and the media-metadata UPDATE is not ported), plus `CREATE INDEX idx_persons_search_vector ON persons USING gin ("searchVector")` (no such index exists, search is a sequential scan).

### D. Deviations

23. Summary of the `[new]` rows above: **F4** (rule 1, already in README); **F40** library ACL on credits media and `mediaId` (rules 17, 20, 21); **C28** (shared with `metadata.md` rule 39): a repeated `q` is 400, `provider-credits` upstream failure is 503 `Metadata request failed on <provider>: <reason>` instead of 500; **C30** tsquery sanitisation (rule 5); **C171** blank `q` capped at 1000 rows (rule 3); **C31** (rules 11, 15, 20, 22): a provider pin that violates `UNIQUE(provider, tmdbId)` keeps the row's provider and still returns the credits instead of a 500 / silent no-refresh, the refreshing response is the re-read row, credits link media by `(type, id)`, `searchVector` follows `name` (rule 22).
24. `[new]` Decided (reviewer recommendations, kept): F40 applies the library-ACL filtering of rule 21 to credits (same decision as `metadata.md` rule 38); the `persons.searchVector` trigger, backfill and GIN index of rule 22 ship in S5 and the media-metadata UPDATE is not ported.
25. Frozen (reviewer recommendations, kept): `GET :id` refreshes synchronously (rules 9, 13) and an unreachable provider costs the full timeout on every request; the persons page keeps one unpaged list (rule 3, capped by C171; paging would be a client change).

## SQL

- **Q1 search all** (rule 3): `SELECT id, "createdAt", "updatedAt", provider, "tmdbId", name, "avatarUrl", biography, birthday, deathday, "placeOfBirth", "knownForDepartment", departments, "metadataRefreshedAt" FROM persons ORDER BY name ASC, id ASC LIMIT 1000` (C171).
- **Q1b search** (rules 4-6): same columns `FROM persons p WHERE p."searchVector" @@ to_tsquery('simple', $1) ORDER BY ts_rank(p."searchVector", to_tsquery('simple', $1)) DESC, p.name ASC, p.id ASC LIMIT 50`.
- **Q2 one person** (rule 9): `SELECT <columns> FROM persons WHERE id = $1`; refresh write: `UPDATE persons SET name=$, "avatarUrl"=$, biography=$, birthday=$, deathday=$, "placeOfBirth"=$, "knownForDepartment"=$, "metadataRefreshedAt"=$, "updatedAt"=now() WHERE id = $` with the `undefined` columns left out (rule 14); provider pin: `UPDATE persons SET provider = $2 WHERE id = $1`.
- **Q3 cast** (rule 17): `SELECT mc.id, mc."createdAt", mc."updatedAt", mc.character, mc."order", <media row + library + qualityProfile + languageProfile + metadata>, <person row> FROM media_cast mc JOIN media m ON m.id = mc."mediaId" LEFT JOIN libraries l … LEFT JOIN media_metadata mm … JOIN persons p ON p.id = mc."personId" WHERE mc."personId" = $1 ORDER BY mc."order" ASC, mc.id ASC`. TypeORM uses LEFT JOINs throughout. `mediaId` and `personId` are **nullable** in the schema (baseline; FKs ON DELETE CASCADE): `personId = $1` makes the person join exact, but `media` must stay a LEFT JOIN, serialised `media: null` for a row with NULL `mediaId` (the import never writes one).
- **Q4 crew** (rule 17): same on `media_crew mc` selecting `job, department`, `ORDER BY mc.id ASC`.
- **Q5 owned media** (rule 20): `SELECT id, "tmdbId" FROM media WHERE "tmdbId" = ANY($1) ORDER BY id ASC` (or `"tvdbId"`; Nest has no ORDER BY, the last row per id wins, C12); with C31: `SELECT id, type, "<col>" FROM media WHERE "<col>" = ANY($1)` keyed `(type, <col>)`.
