### B. Formatting

4. Substitution mechanics: the format is rewritten by successive global replacements, in the order below, each replacing every occurrence of one exact, case-sensitive token (`{Movie Title}` is not `{movie title}`) by the value; the next replacement therefore also sees tokens that a previous value injected (a title that contains `{Release Year}` is expanded by a later step); finally `sanitize` (rule 7). Order: movie file: `{Movie Title}`, `{Original Title}`, `{Release Year}`, `{Quality Full}`, `{Quality Title}`, `{Release Group}`, `{TMDB Id}`, `{MediaInfo AudioCodec}`, `{MediaInfo VideoCodec}`. Series file: `{Series Title}`, `{season:00}`, `{episode:00}`, `{Episode Title}`, `{Quality Full}`, `{Quality Title}`, `{Release Group}`, `{Air Date}`, `{MediaInfo AudioCodec}`, `{MediaInfo VideoCodec}`. Movie folder: `{Movie Title}`, `{Original Title}`, `{Release Year}`, `{TMDB Id}`. Series folder: `{Series Title}`, `{Original Title}`, `{Release Year}`, `{TMDB Id}`. Season folder: `{season:00}`, `{season}`. `[ts:src/modules/scheduler/naming.service.ts:87]`–`[ts:src/modules/scheduler/naming.service.ts:197]`
5. Values: `title`/`seriesTitle` `?? ''`; `{Original Title}` = `originalTitle || title` (series folder: `originalTitle || seriesTitle`), so an empty original falls back; `{Release Year}` = the year as a decimal string when truthy, else `''` (year `0` and null both empty); `{TMDB Id}` likewise (`0` empty); `{Quality Full}` and `{Quality Title}` both = `quality ?? ''`; `{Release Group}` = `releaseGroup ?? ''`; `{Episode Title}` = `episodeTitle ?? ''`; `{Air Date}` = `airDate ?? ''` (a string, no reformatting); `{season:00}` / `{episode:00}` = decimal string left-padded with `0` to width 2 and never truncated (`100` stays `100`, `-1` stays `-1`); `{season}` = the plain decimal string; both media-info tokens always `''`. A token not in the list for that function stays in the string until `sanitize` deletes it. `[ts:src/modules/scheduler/naming.service.ts:98]`–`[ts:src/modules/scheduler/naming.service.ts:197]`
6. Movie and series FILE formats take the quality and release group; FOLDER formats do not (a `{Quality Full}` in a folder format is deleted by `sanitize`).
7. `sanitize(name)`, in this order: (1) delete every `{...}` (`\{[^}]*\}`, so a lone `{` or `}` survives); (2) delete the literal text `undefined` (case-sensitive, anywhere: `Undefined Behavior` keeps its capital, `undefinedx` loses it); (3) delete each of `< > : " / \ | ? *` and the code points U+0000-U+001F; (4) collapse runs of 2+ whitespace chars (`\s{2,}`) to one space; (5) delete `(` + optional whitespace + `)` and `[` + optional whitespace + `]` (empty groups only, one pass); (6) collapse 2+ whitespace again; (7) trim (JS whitespace, `js::trim`). One pass each: `((  ))` leaves `()`. A name that ends in `.` or contains a stray ` - ` is returned as is (the spec pins both as "invalid on Windows" and a leftover separator). `[ts:src/modules/scheduler/naming.service.ts:407]`–`[ts:src/modules/scheduler/naming.service.ts:420]`
8. Pinned by the spec (each is a vector): year null drops the empty parentheses; empty quality trims the trailing space; empty episode title leaves ` - ` before the quality; a colon in a title is deleted (`Nova Skyline: Requiem` -> `Nova Skyline Requiem`); a slash is deleted and the double space it leaves is collapsed (`Nova / Skyline` -> `Nova Skyline`); a trailing dot stays; `undefined` after a token is stripped. `[ts:src/modules/scheduler/naming.service.spec.ts:95]`–`[ts:src/modules/scheduler/naming.service.spec.ts:111]`, `[ts:src/modules/scheduler/naming.service.spec.ts:209]`–`[ts:src/modules/scheduler/naming.service.spec.ts:238]`, `[ts:src/modules/scheduler/naming.service.spec.ts:254]`–`[ts:src/modules/scheduler/naming.service.spec.ts:262]`
9. [new] C46: values are substituted LITERALLY. Nest passes the value as the replacement STRING of `String.prototype.replace`, so `$$` becomes `$`, `$&` inserts the token itself, `` $` `` and `$'` insert the text around it, `$1` stays: a title like `Money $$$` is named `Money $$` and `Cash $& Carry` embeds the token `{Movie Title}` (verified in Node; and then step 4 may expand it). Rust uses plain string replacement; a title is never rewritten. Deviation: rename of titles containing `$`; visible only for those titles, new imports only (existing folders keep their names). The `naming` vectors exclude `$` from generated values; a Rust unit test pins the new behaviour (`Money $$$` -> `Money $$$`, `A $& B` unchanged).
10. [new] F44 (one row with `ingest.md` rule 3 and `importers.md` rule 36): `apply_movie_folder_format` / `apply_series_folder_format` return the sanitized string as is and never map `.`, `..` or an empty result to `''`: `''` makes `Media.path` fall back to the bare library root (`[ts:src/modules/media/entities/media.entity.ts:109]`–`[ts:src/modules/media/entities/media.entity.ts:113]`), so a series or a movie named `''` would own the whole library folder (rescan, delete). Every `folderName` writer (TMDB import, importers, relink, `createUnmatched`, the `confirmImport` pin) passes the result through the one `fliks_domain::naming` folder-name validator (`ingest.md` rule 3), which REJECTS a name that is empty, `.`, `..` or contains a separator or NUL (400 on a route, an `errors` entry in a batch); a title such as `..` or `???` therefore cannot be imported. The only empty name accepted is the explicit root-level movie of the relink and `createUnmatched` paths (the client sends `''` for a root-level group). The season folder needs no rule: `.` already joins to the show folder and `..` is refused by the ingest confinement (`relativePathUnderMediaRoot`, file skipped with an error). FILE formats always get an extension appended.

### C. Parsing

11. `extract_release_group(sourceTitle)`: first match of `-([A-Za-z0-9]+)(?:\.[a-z0-9]{2,4})?$` (case-insensitive, so the extension class also takes upper case) on the raw title: group 1, else `''`. Underscores are not group characters here (unlike the attribute parser, `release.md` rule 15). Pinned: `...WEBDL-1080p.mkv` yields `1080p`; no dash yields `''`; the group keeps its case. `[ts:src/modules/scheduler/naming.service.ts:226]`–`[ts:src/modules/scheduler/naming.service.ts:229]`, `[ts:src/modules/scheduler/naming.service.spec.ts:486]`–`[ts:src/modules/scheduler/naming.service.spec.ts:518]`
12. `parse_episode_numbers(sourceTitle, filePath?)` normalises first: `normalized = sourceTitle` with every `_` replaced by a space, then every `.` that is not followed by four ASCII digits replaced by a space (so a `.2023` stays). Each pattern below is tried on `normalized` first, then on the raw `sourceTitle` (`normalized.match(re) ?? sourceTitle.match(re)`), which is why `S01E05_06` loses its range end (the `_` is gone before the multi-episode pattern sees it). `[ts:src/modules/scheduler/naming.service.ts:244]`–`[ts:src/modules/scheduler/naming.service.ts:246]`, `[ts:src/modules/scheduler/naming.service.ts:324]`, `[ts:src/modules/scheduler/naming.service.spec.ts:582]`–`[ts:src/modules/scheduler/naming.service.spec.ts:589]`
13. The cascade (index of the season group, of the episode group; `E` = explicit: the name states both numbers), first usable hit wins: (1) `[Ss](\d{1,2})[Ee](\d{1,3})(?:[_\-Ee]+(\d{1,3}))*` season 1, episode 2, end 3, E (the repeated group keeps its LAST iteration: `S01E01-E03` end 3, `S01E01E02E04` end 4); (2) `[Ss](\d{1,2})\s*[Ee](\d{1,3})` 1/2 E; (3) `[Ss](\d{1,2})\s*[.\- _][Ee](\d{1,3})` 1/2 E; (4) `(\d{1,2})[xX](\d{2,3})` 1/2 E; (5) `(?:^|[\s.])(\d)(\d{2})(?:[\s.]|$)` 1/2 (`Title 103` is S1E03); (6) `(?:Part|Pt)\s*\.?\s*(\d{1,3})` case-insensitive, no season, episode 1; (7) `(?:Episode|Ep)\s*\.?\s*(\d{1,3})` case-insensitive, no season; (8) `(?:^|[\s.])- (\d{2,4})(?:[\s.]|$)` no season (anime ` - 03`); (9) `[Ee](\d{2,3})(?:[^a-zA-Z\d]|$)` no season. A pattern without a season group gives season 1. Regex semantics for rules 11-16 (`release.md` rule 7 applies): all are non-`u` JS patterns, so `\d` is `[0-9]` (Rust's Unicode `\d` would hand Arabic-Indic or fullwidth digits to `parse`, where JS never matches them), `\s` is `js::is_ws`, and the `i` patterns (11, 6, 7, `NUMBERED_SPECIAL`, `SPECIAL_TOKEN`, `SPECIALS_FOLDER`) must not fold U+212A or U+017F (`(?i)` in Rust matches `k`/`s` with them: use `(?i-u)` or ASCII classes); the lookaheads (`\.(?!\d{4})`, `(?![0-9])`) need `fancy_regex` or a manual check; every pattern is non-global, so no `lastIndex` state. A repeated group reports its last iteration in Rust too. `[ts:src/modules/scheduler/naming.service.ts:248]`–`[ts:src/modules/scheduler/naming.service.ts:307]`
14. Per hit, in this order: `episode = parseInt(group)`; an `E` pattern with `episode === 0` returns `None` (a `SxxE00` special states no number; no later pattern may guess); `episode < 1` continues to the next pattern; when the name is special (rule 15) and the pattern is not `E` returns `None`; `episodeEnd` is set only by pattern 1 and only when the end group matched and is greater than `episode` (else absent); no-season patterns return `{season: 1, episode, episodeEnd}`; otherwise `season = parseInt(season group)` and a negative season continues (impossible with these groups). No hit: `None`. A season-only pack (`S02`) is `None`. `[ts:src/modules/scheduler/naming.service.ts:317]`–`[ts:src/modules/scheduler/naming.service.ts:349]`, `[ts:src/modules/scheduler/naming.service.spec.ts:654]`–`[ts:src/modules/scheduler/naming.service.spec.ts:676]`
15. Specials before the cascade: `NUMBERED_SPECIAL` = `(?:^|[^a-z0-9])(?:specials?|ova|oav|ovd|sp|ncop|nced)[ ._-]*(\d{1,2})(?![0-9])` (case-insensitive) on the RAW `sourceTitle`; when it matches and the number is at least 1 the answer is `{season: 0, episode}` at once (`Show - OVA - 01` is S00E01); a number 0 falls through. `special = is_special_file(filePath ?? sourceTitle)` (so a `Specials` folder in the full path counts only when the caller passes the path). `[ts:src/modules/scheduler/naming.service.ts:22]`–`[ts:src/modules/scheduler/naming.service.ts:24]`, `[ts:src/modules/scheduler/naming.service.ts:309]`–`[ts:src/modules/scheduler/naming.service.ts:315]`, `[ts:src/modules/scheduler/naming.service.spec.ts:678]`–`[ts:src/modules/scheduler/naming.service.spec.ts:734]`
16. `is_special_file(pathOrName)` = any of: `SPECIALS_FOLDER` `(?:^|[\\/])(?:specials?|(?:season|saison)[ ._-]*0+)(?:[\\/])` (a `Specials` or `Season 00` folder, case-insensitive); `SPECIAL_TOKEN` `(?:^|[^a-z0-9])(?:specials?|ova|oav|ovd|ncop|nced)(?:[^a-z0-9]|$)` (no `sp`: too short); `NUMBERED_SPECIAL`; `DECIMAL_EPISODE` `(?:^|[^0-9])\d{1,3}\.5(?:[^0-9]|$)` (case-sensitive: `12.5`); `EPISODE_ZERO` `(?:[Ss](\d{1,2})[ ._-]*[Ee]|(\d{1,2})[xX])0+(?![0-9])` (`S01E00`, `1x00`). `[ts:src/modules/scheduler/naming.service.ts:28]`–`[ts:src/modules/scheduler/naming.service.ts:39]`, `[ts:src/modules/scheduler/naming.service.ts:356]`–`[ts:src/modules/scheduler/naming.service.ts:364]`, `[ts:src/modules/scheduler/naming.service.spec.ts:736]`–`[ts:src/modules/scheduler/naming.service.spec.ts:752]`
17. `match_special_by_title(filename, specials)` (returns the index of the winning element): `haystack = normalize_title(basename(filename) minus its extension)`; for each special in order, `needle = normalize_title(title ?? '')`; skip a needle shorter than 4 characters (ASCII after rule 18, so byte length = JS length); skip when `haystack` does not contain it; the winner is the earliest position, ties on position go to the LONGER needle, and a still-tied later special does not replace the first; none -> `None` (no guessing). Nest's callers pass `season.episodes` in unspecified relation order, so a full tie is non-deterministic today; Rust callers pass the specials `ORDER BY "episodeNumber" ASC, id ASC` (C12). `[ts:src/modules/scheduler/naming.service.ts:374]`–`[ts:src/modules/scheduler/naming.service.ts:397]`, `[ts:src/modules/scheduler/naming.service.spec.ts:754]`–`[ts:src/modules/scheduler/naming.service.spec.ts:795]`
18. `normalize_title(s)`: NFD, delete every `\p{Diacritic}` code point (this includes ASCII `^` and `` ` `` and U+00B7, which then do NOT become spaces), lower-case, replace each run of `[^a-z0-9]+` by one space, trim. Needs `unicode-normalization` (`release.md` rule 54). `[ts:src/modules/scheduler/naming.service.ts:42]`–`[ts:src/modules/scheduler/naming.service.ts:49]`
19. `basename(filename)` minus `extname`: Node `path` semantics, POSIX flavour (`/` only; trailing separators ignored): `extname` = from the last `.` of the last segment to its end, `''` when the dot is the first character of the segment, absent, or the segment is `..`; `basename(p, ext)` removes `ext` only when the segment is longer than it and ends with it (`.mkv` alone keeps its name; `a.` has extname `.`). On a Windows host Node uses the win32 flavour (`\` also separates): Rust uses `cfg!(windows)` for that and the vectors are generated on POSIX; the win32 cases are Rust unit tests. Verified in Node 24: `extname` of `a.mkv`/`.mkv`/`a.`/`..`/`a..`/`a.mkv/` = `.mkv`/`''`/`.`/`''`/`.`/`.mkv`, basename minus it `a`/`.mkv`/`a`/`..`/`a.`/`a`. Every caller already passes a basename (`path.basename(absPath)`, `sourceBase`), so only the extension strip matters in practice.

Not ported (no caller outside the file and its spec): `parseQuality` (`naming.service.ts:199`, spec `:446`-`:484`) and `parseSeasonNumber` (`naming.service.ts:402`): the quality of a file comes from `parse_release_quality` / `quality_from_resolution` (`release.md`). ### D. Consistency and safety

21. Inconsistent default, frozen: `media-import.service.ts` reads `naming_movie_folder_format` itself and falls back to `{Original Title} ({Release Year})` when the key is absent, while `getFormats` (disk import) falls back to `{Movie Title} ({Release Year})`; series folders agree (`{Series Title}`).
