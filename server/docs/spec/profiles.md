## Rules

### A. Common

1. Policies, from the CASL factory: `Read QualityProfile` / `Read LanguageProfile` are granted by `media.read`; `Manage` of both (every action: create, update, delete included) by `settings.access`; `manage:all` everything. The custom-format and quality-definition routes use the string subject `'Settings'`, granted only by `settings.access` (`Read` and `Manage` both; `Action.Update` is covered by `Manage`) or `manage:all`. So the default `User` and `Readonly` roles (`media.read`) read quality/language profiles and language definitions, and cannot read custom formats or quality definitions. `[ts:src/modules/auth/casl/casl-ability.factory.ts:84]`–`[ts:src/modules/auth/casl/casl-ability.factory.ts:87]`, `[ts:src/modules/auth/casl/casl-ability.factory.ts:132]`–`[ts:src/modules/auth/casl/casl-ability.factory.ts:136]`
2. Validation is the global pipe (auth rule 16): body whitelisted, unknown keys 400 `property <k> should not exist`, including inside nested items (`items.0.x`, `specs.0.x`, `audioLanguages.0.x`); JSON types are strict (`IsNumber` accepts non-integers, rejects strings; `IsBoolean` rejects `"true"`; `IsOptional` lets `null` through). Rust: `#[serde(deny_unknown_fields)]` on every DTO and nested item. `[ts:src/main.ts:76]`–`[ts:src/main.ts:80]`
3. `:id` params: `ParseIntPipe` (auth rule 18); in Rust C20 applies (canonical integers only, ` 7 `/`1e1`/`0x10` are 400) and an id outside the `int4` range is 400 `Validation failed (numeric string is expected)` (Nest reaches Postgres and answers 500; C1).
4. Timestamps `createdAt`/`updatedAt` serialise as ISO-8601 with milliseconds (`timestamptz`); `updatedAt` is maintained by the `set_updated_at` trigger (C8, migration `1786500000000_updated_at_trigger.sql`), so Rust issues the UPDATE every time. A PUT that changes nothing leaves `updatedAt` untouched in Nest (TypeORM `save` skips an unchanged row) and bumps it in Rust; parity ignores `$..updatedAt`. `[assumed]` (invisible to clients).
5. Lists end with `id ASC` as final tie-break (C12): `ORDER BY name ASC, id ASC` in SQL. The sort runs in Postgres with the same collation as Nest, so no ordering deviation (unlike `libraries.md` rule 3: nothing is sorted in Rust). Quality definitions order by the unique `"qualityId"`. `[ts:src/modules/profiles/profiles.service.ts:147]`–`[ts:src/modules/profiles/profiles.service.ts:149]`, `[ts:src/modules/profiles/profiles.service.ts:200]`–`[ts:src/modules/profiles/profiles.service.ts:202]`, `[ts:src/modules/profiles/custom-formats.service.ts:41]`–`[ts:src/modules/profiles/custom-formats.service.ts:43]`, `[ts:src/modules/profiles/quality-definitions.service.ts:101]`–`[ts:src/modules/profiles/quality-definitions.service.ts:104]`
6. Write routes answer the saved row as TypeORM materialises it: every column is set explicitly on create, so the body equals a re-read (`id`, `createdAt`, `updatedAt` from the INSERT). Rust answers `INSERT/UPDATE ... RETURNING *` (one statement; Nest does SELECT then save). `QP` JSON = `{id: number, createdAt, updatedAt, name: string, cutoff: number, items: QPItem[], upgradeAllowed: boolean, resolutionUpgradeOnly: boolean, minCustomFormatScore: number}`; `QPItem` = `{quality: {id: number, name: string, resolution: number, source: string}, allowed: boolean, sortOrder: number, groupId?: number}` (`groupId` key absent when none). `[ts:src/modules/profiles/entities/quality-profile.entity.ts:4]`–`[ts:src/modules/profiles/entities/quality-profile.entity.ts:42]`

### B. Quality profiles

7. `CreateQualityProfileDto`: `name` string (required, empty allowed); `cutoff` number (required); `upgradeAllowed?`, `resolutionUpgradeOnly?` boolean; `minCustomFormatScore?` number; `items` array (required, may be empty) of `QualityItemDto` = `qualityId` number, `qualityName` string, `resolution` number, `source` string, `allowed` boolean, `sortOrder` number (all required), `groupId?` number. `null` passes `IsOptional` on every optional field. `[ts:src/modules/profiles/dto/create-quality-profile.dto.ts:11]`–`[ts:src/modules/profiles/dto/create-quality-profile.dto.ts:58]`
8. Create: row = `name`, `cutoff`, `upgradeAllowed ?? false`, `resolutionUpgradeOnly ?? false`, `minCustomFormatScore ?? 0` (so `null` stores the default), `items` mapped 1:1: DTO `{qualityId, qualityName, resolution, source}` becomes `quality: {id, name, resolution, source}`, `allowed`, `sortOrder`, `groupId: groupId ?? undefined` (null and absent both drop the key). Stored as jsonb; numbers keep whatever the client sent (a non-integer `sortOrder` is stored as is). `[ts:src/modules/profiles/profiles.service.ts:123]`–`[ts:src/modules/profiles/profiles.service.ts:145]`
9. Update (PUT, full replace): load or 404; `name`, `cutoff` replaced; the three optionals KEEP the stored value when absent or `null` (`dto.x ?? profile.x`: differs from create's reset to defaults); `items` replaced wholesale with the rule 8 mapping. `[ts:src/modules/profiles/profiles.service.ts:158]`–`[ts:src/modules/profiles/profiles.service.ts:182]`
10. Get one: `QualityProfile #<id> not found` 404 (`{message, error:"Not Found", statusCode:404}`). `[ts:src/modules/profiles/profiles.service.ts:151]`–`[ts:src/modules/profiles/profiles.service.ts:156]`
11. Delete: 404 when missing, else `DELETE`; no usage check. The FKs `libraries.defaultQualityProfileId`, `media.qualityProfileId`, `requests.qualityProfileId` are `ON DELETE SET NULL` (baseline DDL), so a profile in use disappears silently and its titles become unprofiled (frozen, rule 40). Rust: `DELETE ... WHERE id = $1 RETURNING id`, no row = 404 (no SELECT-then-DELETE race). `[ts:src/modules/profiles/profiles.service.ts:184]`–`[ts:src/modules/profiles/profiles.service.ts:187]`
12. Frozen as is (no validation exists): `cutoff` need not be the id of an item; item `quality` ids need not exist in `APP_QUALITIES`; names are not unique; `groupId` semantics are the scorer's (`release.md` rule 27). A cutoff that matches no item resolves to resolution 0 in `cutoffResolution` (rule 34); frozen, rule 40.
13. `items` order is the client's; the server never sorts or re-numbers it.

### E. Quality definitions

24. `QD` JSON = `{id, createdAt, updatedAt, qualityId: number (unique), title: string, minSize: number, preferredSize: number, maxSize: number}`; sizes are `double precision` in MB per hour of content, `0` on min/max = no limit. `[ts:src/modules/profiles/entities/quality-definition.entity.ts:4]`–`[ts:src/modules/profiles/entities/quality-definition.entity.ts:24]`
25. Seeding (`ensureDefaults`): when `SELECT count(*) FROM quality_definitions` is 0, insert one row per `APP_QUALITIES` entry (24 rows, `title` = quality name, sizes from rule 26). Nest runs it at module init AND at the start of every `findAll` / `updateAll` (so `GET`, `POST /reset` through `getDefaults`, `PUT`, and `getSizeLimitsMap`). Nest's `save` has no `ON CONFLICT`: two concurrent first calls can 500 on the unique key. Rust: `profiles::seed_quality_definitions(pool)` at boot after migrations and BEFORE Nest is spawned (like `roles::seed`, `roles.md` rule 11), and again at the start of `GET` / `POST /reset` / `PUT` (idempotent: `INSERT ... ON CONFLICT ("qualityId") DO NOTHING` guarded by the empty check). `[ts:src/modules/profiles/quality-definitions.service.ts:68]`–`[ts:src/modules/profiles/quality-definitions.service.ts:84]`, `[ts:src/modules/profiles/profiles.module.ts:39]`–`[ts:src/modules/profiles/profiles.module.ts:41]`
26. Default sizes (`min`/`preferred`/`max`, MB/h) by key `"<resolution>-<source>"` then `"<resolution>"` then `"0"`: `0`: 0/700/1500; `480`: 0/800/1500; `720-hdtv` 150/1200/2500; `720-web` 150/1500/3000; `720-bluray` 250/2500/5000; `720` 150/1500/3500; `1080-hdtv` 250/2000/4000; `1080-web` 250/3000/5000; `1080-bluray` 400/5000/10000; `1080-remux` 8000/18000/30000; `1080` 250/3000/6000; `2160-hdtv` 600/4000/8000; `2160-web` 600/6000/12000; `2160-bluray` 1000/12000/25000; `2160-remux` 15000/35000/60000; `2160` 600/8000/20000. Consequences pinned by the vector `quality-definition-defaults`: resolution-0 qualities (ids 1-4) and an unknown id get `0`; `480p` qualities (ids 5-10, incl. DVD and Bluray-480p) all get `480`; `720p` sources `web`/`hdtv`/`bluray` hit their own key. `[ts:src/modules/profiles/quality-definitions.service.ts:21]`–`[ts:src/modules/profiles/quality-definitions.service.ts:57]`

### G. Deviations

36. [new] C1 (extended to these routes): no 500 on input the DTOs let through. `cutoff`, `minCustomFormatScore`, `score` (custom format) must be integers within `int4`; `qualityId` of a definition item within `int4` and integral (the size fields are already finite and `>= 0` in Nest: `IsNumber` + `Min(0)`); non-integer or out-of-range values, `title: null` on a definition item, and an out-of-range `:id` answer 400 with the standard validation body (today Postgres says `invalid input syntax for type integer` or `out of range` and Nest answers 500).
37. `title_regex` has no evaluation budget (Nest has none; only an admin can write a pattern): see rule 39.
38. [new] C2 applies: `PUT /quality-definitions` is one transaction (rule 29); the other writes are single statements.
39. [new] Decided (reviewer recommendation, kept): `title_regex` compiles with `regress` (`icase`), so every stored pattern keeps the meaning it had under `new RegExp(v, 'i')` on Node (lookbehind, backreferences, named groups, ES case folding); a pattern it rejects is 400 at write and logged at boot when already stored. The internal fixed patterns stay on `regex` / `fancy-regex` as S3 did (the vectors prove each). `regress` has no backtracking budget, so no step-budget row exists (`release.md` rule 50).
40. Frozen (reviewer recommendations, kept): `POST /api/quality-definitions/reset` only computes defaults (the client then saves with PUT); `cutoff` is not required to be among the items, duplicate names are allowed, an absent `score` on custom-format PUT resets to 0 while an absent optional on quality-profile PUT keeps the stored value, an absent language-profile array resets; deleting a profile that libraries, media or requests reference silently nulls them (titles become `unprofiled`); a definition `qualityId` that does not exist is ignored by PUT. An integral `f64` sent as `1.0` is serialised as `1.0` where Nest echoes `1`: parity compares numerically and clients parse both alike.
41. Decided (user): no Nest copy of the profile code survives S5; the plugin host's profile and scoring reads are a known gap until S8 (Bridges).
