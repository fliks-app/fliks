# Spec: live TV sessions (play, leave, heartbeat, capacity, failover, resolver, engine coupling)

Engine side: `fliks-engine/PROTOCOL.md` (`POST/GET /v1/live`, resolver, `LiveAttempt`, `LiveReleased`) and `fliks-engine/docs/spec/live.md`, cited `[engine:...]`; wire types come from `fliks_engine_core::api` (`OpenLiveRequest`, `OpenLiveResponse`, `LiveSnapshot`, `LiveMode`, `LiveTvConfig`, `EngineEvent`), never redeclared.

Scope: the host's control plane of live TV: the three session routes, the capacity policy, the viewer and hold registry, the reactions to the engine's live events, the resolver `live` purpose, the config the engine receives. The data plane (`GET|HEAD /api/livetv/sessions/:sid/{index.m3u8,direct.ts,:segment}`, failover itself, ffmpeg, idle teardown) is the engine's and is reached through the engine front door, which answers those paths before fliks-server's routes (`[engine:PROTOCOL.md:76]`); fliks-server must not register a `GET`/`HEAD` there. Catalog visibility, groups and grants: `livetv-access.md`. Sources and sync: `livetv-sources.md` (other author).

## Routes

Every route here is `SessionAuthed` (a stream-scope token gets 403 `{"statusCode":403,"message":"session_token_required","error":"Forbidden"}`) with policy Read LiveTvChannel (`livetv.read`).

| Method path | Request | Response | Errors | Side effects |
|---|---|---|---|---|
| `POST /api/livetv/channels/:id/play` | path `id` canonical int; body `{directPlay?: bool, maxBitrateBps?: int >= 1, useTs?: bool}`; unknown keys 400; an empty or absent body is fine | **201** `{sessionId: string, channelId: int, channelName: string, url: string, mode: "direct"\|"remux"\|"transcode", isLive: true, dvrWindowSeconds: number, segmentSeconds: number}`; `url` = engine `playPath` + `?token=` + `encodeURIComponent(streamToken)` (`/api/livetv/sessions/<sid>/index.m3u8`, `direct.ts` for direct) | 400 validation; 401; 403 `session_token_required` or no `livetv.read`; 404 `{statusCode:404,message:"Live TV channel #<id> not found",error:"Not Found"}` (absent, disabled, denied group: `livetv-access.md` rule 12); 409 `{code:"livetv_source_at_capacity", sourceName, limit}`; 409 `{code:"livetv_user_at_capacity", limit}` (rule 39); 503 `{code:"livetv_channel_unavailable", channelName}` (also when every stream is on a disabled source); 503 `{code:"livetv_account_expired", channelName, sourceName}`; 503 `{statusCode:503,message:"The engine has no live TV runtime",error:"Service Unavailable"}`; 503 `... "The streaming engine is not running"`; other engine refusals 502 `{statusCode:502,message:"Bad Gateway"}`, a transport failure 503 (rule 12) | rules 5-17: engine session, viewer, hold, QoE tracker, activity row |
| `DELETE /api/livetv/sessions/:sessionId` | path `sessionId` any string | 200 `{ok: true}` (also for an unknown sid) | 401, 403; engine non-2xx on the delete: 502 | engine `DELETE /v1/sessions/{sid}`, viewer dropped (rule 20); ownership check (rule 18) |
| `PUT /api/livetv/sessions/:sessionId/state` | path any string; body any JSON (not validated; an absent or non-object body is read as no sample) `{qoe?: unknown, state?: unknown}` | 200 `{ok: true}` | 404 `Live TV session not found`; 403 `Not your session`; 401 | when `body.qoe != null`: QoE sample (rule 21) |

Not routes of this module but part of the live contract: the engine's data plane above; `GET /api/system/streams` live rows (`playback-info.md` rule 34); the engine's resolver callback `POST /engine/resolve` (`engine-glue.md` rule 39) with `purpose: "live"`.

Status codes: a 409 or 503 refusal with an object body sends that object verbatim (no `statusCode`, `message`, `error` keys), a string body gets `{statusCode, message, error}`. Parity pins the 409 and the two 503 object bodies byte for byte.

## Rules

### State

1. Process-wide state in Rust, one `std::sync::Mutex` (never held across an `.await`): `viewers: sid -> Viewer{channelId, channelName, userId: Option<i32>, device: Option<String>, startedAt: ms, capacityToken}`, `holds: capacityToken -> Hold{sourceId, channelId, streams: Vec<Stream+Source>, fed: Option<u32>, pending: bool, mode: Option<LiveMode>}`, `recentReleases: sourceId -> Vec<Instant>`, `segmentSeconds: i32` (2 until the first config read). All except `recentReleases` are rebuilt from `GET /v1/live` after a restart (rule 24).
2. `recentReleases` uses a monotonic clock; entries older than the grace are pruned on insert as well as on read.
3. A hold is a session's reservation of one provider connection, keyed by the `capacityToken` (a UUID v4 minted per open). Viewers of a shared upstream share one token (the joined session's).

### Opening a channel (`play`)

4. Order of checks: path id and body validation, `findPlayable(id, user)` (`livetv-access.md` rule 12), `open`, then the stream token.
5. Stream order: `priority ASC`, then a stream without `lastError` before one with, then `lastOkAt DESC` (null counts 0); stable sort. No stream (none, or only streams of disabled sources, dropped by `findPlayable`): 503 `livetv_channel_unavailable` (no engine call, no hold).
6. Grace = `livetv_slot_release_seconds`, `parseInt(raw,10)` if finite else 15 (read per open; 0 and negative accepted).
7. Capacity verdict and hold with no `.await` between them (the mutex is held for both): verdict = `assertBelowLimit(primary.source, grace, holdsOn(primary.sourceId))` where `primary` = `streams[0]` and `holdsOn` counts holds whose `sourceId` is the primary's (pending ones included, the new one not yet inserted); the same section computes every stream's own verdict (rule 8); then `holds[token] = {sourceId: the first unvetoed stream's source (the engine's order[0] after filtering, so the primary's when it is free; the primary's when none is), channelId, streams, fed: None, pending: true, mode: None}`. Two concurrent opens on one source cannot both pass.
8. Capacity: `source.maxStreams` null or 0 means unlimited. `inUse = holdsOn + (releases of that source younger than grace)`; at `inUse >= maxStreams` the verdict is the 409 body `{code:"livetv_source_at_capacity", sourceName: source.name, limit: source.maxStreams}`. A closed upstream still counts for `grace` seconds because the provider does. The verdict is taken per stream for its own source (counting only holds of other tokens: a source already holding this open's token is free), so a failover never lands on a source at its limit when the open was sent; the 409 body, when every stream is vetoed, is the primary's.
9. The verdict is not thrown: no request-level `atCapacity` is sent (`false`); each upstream carries `LiveUpstream.atCapacity` from its own source's verdict (engine 0.4: a vetoed upstream never feeds the session, so a full primary with a free secondary plays on the secondary; an all-vetoed open answers 409 `live_at_capacity`, whose body the host builds from the primary's verdict). The engine answers that 409 only when it must open a new upstream (a session of the same channel, mode, container and bitrate is joined for free). `[engine:docs/spec/live.md:14-15]`
10. Engine request `POST /v1/live` (`Engine::open_live`, 503 + `Retry-After` retried up to 15 s, no `live` feature: `NoLive`): `channelId = String(channel.id)`; `upstreams` = every sorted stream `{url, priority, headers, probedContainer, probedVideoCodec, probedAudioCodec}` (null probe values omitted); `headers` = `User-Agent` plus `Referer` when non-empty; each value is the stream's own `userAgent`/`referer` (from `#EXTVLCOPT`/KODIPROP) else the source's, the agent then defaulting to `VLC/3.0.20 LibVLC/3.0.20`; the engine takes any header map per upstream and passes `User-Agent`/`Referer` to ffprobe, ffmpeg and the direct GET (`[engine:docs/spec/live.md:21-24]`), so no engine change; `caps = {directPlay, maxBitrateBps, useTs}` from the DTO (`directPlay` default false, `useTs` default false, `maxBitrateBps` omitted when absent); `ownerId = String(user.id)`; `capacityToken = token`; `atCapacity`; `tags = {channelName: channel.name, username: user.username ?? "", device: <User-Agent request header or "">}`.
11. Answer handling: if `res.capacityToken != token` the open joined a running session: the new hold is deleted at once, **no** release grace, the viewer carries the session's token; else `hold.pending = false`, `hold.mode = res.mode`. Then `viewers[res.sessionId] = {channelId, channelName, userId, device: <User-Agent header or null>, startedAt: the open time in ms, capacityToken: res.capacityToken}`, activity row (rule 29), QoE `register(ref)` + `set_pipeline(ref, res.qoePipeline)` (the engine's own pipeline; `qoe.md` rule 41 and `playback-info.md` rule 16 own the null defaults), and the response of the route table. `dvrWindowSeconds` and `segmentSeconds` are the engine's numbers as sent.
12. Failure mapping (`openFailed`): (a) not an engine HTTP error (no runtime, not running, transport): hold deleted, error rethrown as is (the two 503 strings above; a transport failure is 503); (b) engine `code = live_unavailable` (503): `release(token, "failed")` (rule 26: grace starts, channel failure counted) then 503 `livetv_account_expired{channelName, sourceName}` for the first sorted stream whose source account is `expired` (`liveTvAccountStateOf(source.expiresAt, source.accountStatus)` of the sources spec), else 503 `livetv_channel_unavailable{channelName}`; (c) any other engine refusal: hold deleted; `live_at_capacity` with a verdict becomes the 409 body, anything else (400 no config, bad URL scheme, 503 without code after the retry window) is 502 `{statusCode:502,message:"Bad Gateway"}` (the client treats every 5xx alike, a retry overlay, `live-player.ts` `handlePlayError`).
13. The hold is created before the engine call and deleted on every non-success path except `live_unavailable` (released, not deleted) so a refused open never leaks a slot. A `LiveReleased` that arrives before the HTTP answer already removed the hold: `release` is idempotent (rule 26).
14. `lastPlayedAt` of the channel and of the pref is not written (`livetv-access.md` rule 19). `mode` in the answer is the engine's effective mode (a remux of a non-H.264 upstream is `transcode`, `[engine:docs/spec/live.md:15]`).
15. Zap: there is no server-side zap. Changing channel is `play` on the new channel, optionally followed by `DELETE` of the previous session; the host never ends the previous viewer, so a client that forgets holds a viewer (and possibly a provider connection) until the engine's idle expiry (`liveSessionTtlMs`, 30 s without data-plane requests). A user may hold several viewers unless the admin sets the per-user cap (rule 39).
16. Failover is the engine's: it tries the upstreams in the order sent, skips an upstream after 2 failures, restarts in place on stall or exit, and ends the session when all failed (`[engine:docs/spec/live.md:22-23]`). The host's part is: the order at open (rule 5), persisting each attempt (rule 23), moving the capacity hold to the source that feeds (rule 22) and counting a dead channel (rule 26). It never re-opens.
17. Stream token: minted in-process as `sign_live(user, sid)` for the sid the engine answered: a `StreamAuthed`-class token (claims `sub`, `username`, `scope:"stream"`, `STREAM_TOKEN_TTL` default 12 h, `auth.md` rule 5) carrying a `live: <sid>` claim (rule 40). A mint failure is a 500.

### Leaving and heartbeat

18. `leave(sid)`: engine `DELETE /v1/sessions/{sid}` (idempotent, 204), then `dropViewer(sid)`. Owner = the viewer's `userId`, else (viewer unknown, e.g. just after a restart) the engine's `GET /v1/live/{sid}` `ownerId`; a caller that is neither the owner nor holds Manage Settings gets 403 `Not your session`; a sid that is not a live viewer (engine 404) answers `{ok:true}` without calling the engine, so this route can never end an on-demand session.
19. Heartbeat: `viewer = viewers[sid]` else 404 `Live TV session not found`; `viewer.userId != caller.id` 403 `Not your session`; `body.qoe != null` -> `record_sample(ref{state: body.state == "paused" ? paused: playing}, parseSample(body.qoe))` (an unparsable sample is dropped, `qoe.md` rule 41); always `{ok:true}`. It does not touch the engine (the engine's `lastSeenMs` moves on data-plane requests) and does not extend any hold.
20. `dropViewer(sid)`: unknown sid is a no-op; else delete it, finalise the QoE tracker once (`Qoe::end_session(sid).await` on the leave route so a following admin read sees the row, as the stop routes do; `Qoe::session_ended(sid)` on the event and resync paths), recompute the activity row of its token (rule 29). Called by leave, `SessionEnded`, resync.
21. QoE ref of a viewer (built on demand, `lastBeat` = the current time each time): `{sessionId, userId, mediaFileId: null, mediaTitle: channelName, startedAt, lastBeat, deviceLabel: device, systemName: null, appVersion: null, kind: "live", quality: null, transcodeReasons: [], state: "playing", attributedUserId: null}`. Live TV calls `Qoe` in-process (`register`, `set_pipeline`, `record_sample`, `observe_served`, `session_ended`, `set_live_transcodes`).

### Engine events (the consumer)

22. Source of events: the events consumer (`Engine::subscribe()` feed, `engine-glue.md` rules 49-54: subscribe, then resync, 45 s idle watchdog, backoff 0.5 to 15 s); live TV is one more subscriber next to presence and QoE. On `Feed::Resync` it runs its own `list_live` (the feed's `GET /v1/sessions` snapshot carries no live viewers); on `Lagged` it asks `resync_events()`.
23. `LiveAttempt{capacityToken, upstream, upstreamUrl, upstreamPriority, error?, probe?}`: hold by token and stream = the hold's stream with equal `url` and `priority` (neither found: ignore). Patch of that stream row: `probedVideoCodec`/`probedAudioCodec`/`probedContainer` set when the event's probe member is non-empty; on success (no `error`): `hold.sourceId = stream.sourceId`, `hold.fed = ev.upstream`, if `!hold.pending` refresh modes (rule 27), patch `lastOkAt = now()`, `lastError = NULL`; on failure: `lastError = "account expired"` when the stream's source account is `expired`, else `ev.error`; when `hold.fed == ev.upstream` the source of that stream gets `recordRelease` (its provider connection lingers) and `hold.fed = None`. The patch is written even with no other change.
24. Capacity follows the feeding upstream: a failover to a stream of another source moves the hold to that source (rule 23 success); the new source was vetoed at open if it was full (rule 8), so only a source that filled since can be exceeded, by one stream (rule 36). Resync (below) restores `fed` from `LiveSnapshot.upstream`.
25. `SessionEnded{sessionId}`: `dropViewer`. `SegmentServed{sessionId, cmcdRaw?, waitedMs}` for a known viewer: `observe_served(ref, read_cmcd_raw(cmcdRaw), segmentSeconds, waitedMs)` (QoE treats `waitedMs < 20` as already on disk, `qoe.md` rule 35); an unknown sid is ignored. Presence ignores live sids and the reverse (disjoint ids).
26. `LiveReleased{capacityToken, reason: idle|failed|shutdown}` and the internal `release(token, reason)`: no hold: nothing. Else delete the hold, `recordRelease(hold.sourceId)` (grace starts, wherever the token had moved), remove activity `livetv:<token>`; when `reason == "failed"`: `UPDATE livetv_channels SET "lastErrorAt" = now(), "consecutiveFailures" = "consecutiveFailures" + 1 WHERE id = $channelId` and a warn log `Live TV channel #<id> ended: every stream failed`. `lastErrorAt` and `consecutiveFailures` are written and returned by the admin list but never read or reset (kept).
27. Mode bookkeeping: `refreshModes` = `GET /v1/live`, `hold.mode = s.mode` for each known token (errors swallowed). `activeTranscodes` = number of holds with `mode == transcode` (one per session: viewers share an encoder); pushed with `qoe.set_live_transcodes(n)` after every hold mutation (open, attempt, release, resync).
28. Resync (after every events (re)connect and at boot once the engine answers): `listedAt` = the time of the listing; `snaps = GET /v1/live` (an error aborts the resync with state untouched, is logged and calls `resync_events()`, so the feed reconnects with its backoff); `restoreHolds`: for a snapshot whose token has a hold only `mode ??= s.mode`; else load the channel's streams with sources, `fed` = the stream equal to `(upstreamUrl, upstreamPriority)` (none: skip) and insert a hold `{sourceId: fed.sourceId, channelId, streams, fed: s.upstream, pending: false, mode: s.mode}` (re-check the map after the `.await`); then viewers: every snapshot unknown to the map is added (`channelName = tags.channelName ?? ""`, `userId = ownerId` parsed or null, `device = tags.device` or null, `startedAt = openedAtMs`, token); every known viewer absent from the snapshot and with `startedAt < listedAt` is dropped (one opened after the listing is newer, not stale); every hold absent from the snapshot's tokens and not `pending` is `release(token, "shutdown")` (grace starts, no failure count). Restored viewers get no QoE register, but their activity row is reported (the registry is empty after a restart).
29. Activity (admin `GET /api/system/activity`, in-process registry of `events-hub.md`): after open and after `dropViewer`, for the viewer's token: no viewers left -> `remove("livetv:<token>")`; else `upsert_running("livetv:<token>", "livetv.viewing", subject {title: <first viewer's channelName>}, current = viewers on that token)` (no `total`).

### Resolver `live` and config

30. Resolver `live` is an in-process call: in `engine/resolve.rs` the `ResolveMediaId::Live` arm calls `livetv::resolve_live(st, sid, user)`. Input: the viewer's sid and the user already resolved from the credential by the resolver (any token scope accepted, `engine-glue.md` rule 38). Output: unknown sid -> `{allow:false, ttlS:60}`; user not `enabled` -> same (already denied by the resolver's own user check); `findPlayable(viewer.channelId, user)` fails with a not-found, or keeps no stream (every stream on a disabled source) -> same; else `{allow:true, ownerId:String(user.id), ttlS:0}` (no path; re-checked on every data-plane request, so revoking a group, disabling a channel, a source or a user ends an HLS viewer at its next request; a `direct.ts` viewer is one long response, resolved only when it connects: grant changes end it through `livetv-access.md` rule 29). A non-HTTP failure (DB down) is a 5xx, never a denial. A sid missing from the registry is looked up with `GET /v1/live/{sid}` (viewer rebuilt from the snapshot as in rule 28; engine 404 is the denial), because the engine only asks for sids it holds and ends the viewer on a denial, so a request racing the boot resync would otherwise end it. `[engine:PROTOCOL.md:56]`
31. The engine, not the host, enforces the owner: it answers 403 when the returned `ownerId` is not the viewer's, and it **ends the viewer (`SessionEnded{revoked}`) on a denial for the viewer's owner**. So the host never denies because of an owner mismatch: when `viewer.userId != user.id` it answers `{allow:true, ownerId:String(user.id), ttlS:0}` (engine 403s, viewer untouched), and the group check is evaluated for the viewer's owner, not the caller. `[engine:docs/spec/live.md:41]` `[engine:crates/engine/src/serve.rs:1241-1248]` Engine 0.4 ends a viewer only on a denial whose `ownerId` equals the viewer's owner, so a live denial for a credential that resolves to a known user carries `ownerId: String(user.id)` and any other denial (absent, garbage, expired credential: no user to name) is bare and ends nothing.
32. Config owner: the host builds `LiveTvConfig {segmentSeconds: max(1, intOr(livetv_segment_seconds, 2)), timeshiftMinutes: max(1, intOr(livetv_timeshift_minutes, 15)), probeSeconds: intOr(livetv_probe_seconds, 3), channelIdleSeconds: intOr(livetv_channel_idle_seconds, 30), fastZap: "true"->true, "false"->false, else absent}` (`intOr` = `parseInt(raw,10)` if finite else default; the engine floors `probeSeconds` at 3) from `app_settings` and includes it in every `PUT /v1/config` (`engine-glue.md` rules 15-23). It reloads when a settings write touches one of the 5 keys (the settings-change hook of `engine/config.rs`, `settings_changed`) and at boot; it also caches `segmentSeconds` for rule 25.
33. `livetv_slot_release_seconds` is read by the host only (rule 6); `livetv_stale_stream_days` is `livetv-access.md`.

### Admin and activity views

34. `GET /api/system/streams` live rows (`stream/system.rs::live_tv_rows`): one row per `LiveSnapshot` of `GET /v1/live` (`[]` on engine failure), `mediaType "livetv"`, `quality "Live"`, QoE `live_summary(sid)` joined.
35. No admin route ends a live viewer: `POST /api/system/streams/:sid/command` needs a presence entry and answers 400 `Session not found` for a live sid; only the owner (rule 18) or the engine's idle expiry ends it.

### Per-user cap and the live token

39. `livetv_max_viewers_per_user` (default 0 = unlimited, read per open; a value below 1 is unlimited). `open` counts the viewers whose `userId` is the caller's plus the caller's pending holds, in the critical section of rule 7 (two concurrent opens cannot both pass); `count >= cap` answers 409 `{code:"livetv_user_at_capacity", limit: cap}` before any hold or engine call. A viewer that joined a shared session counts, a zap releases the previous viewer first (`DELETE`) so a capped user can still zap.
40. A live token binds one viewer session: `Claims.live = <sid>`. Every host extractor (`Authed`, `StreamAuthed`, `SessionAuthed`, `OptionalAuthed`) answers 401 to it. The resolver (`POST /engine/resolve`) allows it only for `purpose: live` with `mediaId` equal to that sid; any other purpose or sid is a bare denial (no `ownerId`, so it ends nobody's viewer), and the sid's own lookup is rule 30, so the token stops working as soon as the viewer is gone. It keeps the 12 h `exp` because released clients never refresh it: they load the play `url` once for the whole session.

### Decisions settled in review

36. Accepted ceiling (engine 0.4): verdicts are taken at open and a failover does not re-ask, so a failover onto a source that filled after the open can exceed its `maxStreams` by one stream; closing it needs a host callback before every attempt, adding latency to each failover. A down primary still counts against its own source until the first attempt event. `[engine:docs/spec/live.md:51]`
37. Closed by engine 0.4: the engine ends a live viewer only on a denial for its owner (rule 31).
38. `consecutiveFailures` and `lastErrorAt` stay written and returned by the admin list but never read or reset (rule 26).

## SQL

- Streams of a channel with their source (open, restore): `SELECT s.*, src.* FROM livetv_channel_streams s JOIN livetv_sources src ON src.id = s."sourceId" WHERE s."channelId" = $1` (the source `password` column is not selected).
- Stream health patch: `UPDATE livetv_channel_streams SET "lastOkAt" = now(), "lastError" = NULL [, "probedVideoCodec" = $2] [, "probedAudioCodec" = $3] [, "probedContainer" = $4] WHERE id = $1` (success) / `SET "lastError" = $2 [, probes] WHERE id = $1` (failure); `updatedAt` by the `updatedAt` trigger.
- Channel failure: `UPDATE livetv_channels SET "lastErrorAt" = now(), "consecutiveFailures" = "consecutiveFailures" + 1 WHERE id = $1`.
- Settings reads: `SELECT value FROM app_settings WHERE key = $1` per key (`livetv_*`).
- Play-path channel and denial queries: `livetv-access.md` SQL.

## Events

- Engine events consumed (camelCase, tag `type`): `LiveAttempt{capacityToken, upstream: int, upstreamUrl, upstreamPriority: int, error?: string, probe?: {videoCodec?, audioCodec?, container?}}`, `LiveReleased{capacityToken, reason: "idle"|"failed"|"shutdown"}`, `SessionEnded{sessionId, reason}`, `SegmentServed{sessionId, track, rung, index, waitedMs, cacheHit, cmcdRaw?}`. No `SessionOpened` exists for live viewers. `[engine:PROTOCOL.md:39]`
- SSE events emitted: none (no live TV event reaches clients; the client learns a viewer ended from the data plane's 403/404/410). Domain events: none.
- Activity rows: rule 29. QoE: rules 11, 19, 25. Settings consumed: the 5 keys of rule 32 through the settings-change hook.

## Jobs/timers

None owned here. Timers that matter: the engine's viewer idle expiry (`liveSessionTtlMs` 30 s, GC 5 s), `channelIdleSeconds` teardown (then `LiveReleased{idle}`), and the host's lazy release grace (`livetv_slot_release_seconds`, evaluated on read, no timer). The events consumer task and its resync are `engine-glue.md` rules 49-54.

## Vectors/parity
