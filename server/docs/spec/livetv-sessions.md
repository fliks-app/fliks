## Rules

### State

1. Process-wide state in Rust, one `std::sync::Mutex` (never held across an `.await`): `viewers: sid -> Viewer{channelId, channelName, userId: Option<i32>, device: Option<String>, startedAt: ms, capacityToken}`, `holds: capacityToken -> Hold{sourceId, channelId, streams: Vec<Stream+Source>, fed: Option<u32>, pending: bool, mode: Option<LiveMode>}`, `recentReleases: sourceId -> Vec<Instant>`, `segmentSeconds: i32` (2 until the first config read). All except `recentReleases` are rebuilt from `GET /v1/live` after a restart (rule 24). `[ts:src/modules/livetv/services/livetv-session.service.ts:72-93]` `[ts:src/modules/livetv/services/livetv-session.service.ts:111-116]` `[ts:src/modules/livetv/services/livetv-capacity.service.ts:11]`
2. `recentReleases` uses a monotonic clock (Nest used `Date.now()`); entries older than the grace are pruned on insert as well as on read (Nest pruned only when that source was queried again). `[ts:src/modules/livetv/services/livetv-capacity.service.ts:25-33]`
3. A hold is a session's reservation of one provider connection, keyed by the `capacityToken` (a UUID v4 minted per open). Viewers of a shared upstream share one token (the joined session's).

### Opening a channel (`play`)

4. Order of checks: path id and body validation, `findPlayable(id, user)` (`livetv-access.md` rule 12), `open`, then the stream token. `[ts:src/modules/livetv/controllers/livetv.controller.ts:147-157]`
5. Stream order: `priority ASC`, then a stream without `lastError` before one with, then `lastOkAt DESC` (null counts 0); stable sort. No stream (none, or C136: only streams of disabled sources, dropped by `findPlayable`): 503 `livetv_channel_unavailable` (no engine call, no hold). `[ts:src/modules/livetv/services/livetv-session.service.ts:171-179]` `[ts:src/modules/livetv/services/livetv-session.service.ts:324-332]`
6. Grace = `livetv_slot_release_seconds`, `parseInt(raw,10)` if finite else 15 (read per open; 0 and negative accepted). `[ts:src/modules/livetv/services/livetv-session.service.ts:181-184]`
7. Capacity verdict and hold with no `.await` between them (the mutex is held for both): verdict = `assertBelowLimit(primary.source, grace, holdsOn(primary.sourceId))` where `primary` = `streams[0]` and `holdsOn` counts holds whose `sourceId` is the primary's (pending ones included, the new one not yet inserted); then `holds[token] = {sourceId: primary.sourceId, channelId, streams, fed: None, pending: true, mode: None}`. Two concurrent opens on one source cannot both pass. `[ts:src/modules/livetv/services/livetv-session.service.ts:186-196]` `[ts:src/modules/livetv/services/livetv-session.service.ts:297-320]`
8. Capacity: `source.maxStreams` null or 0 means unlimited. `inUse = holdsOn + (releases of that source younger than grace)`; at `inUse >= maxStreams` the verdict is the 409 body `{code:"livetv_source_at_capacity", sourceName: source.name, limit: source.maxStreams}`. A closed upstream still counts for `grace` seconds because the provider does. Only the primary stream's source is checked (known gap, engine follow-up: rule 36). `[ts:src/modules/livetv/services/livetv-capacity.service.ts:13-48]`
9. The verdict is not thrown yet: it is sent as `atCapacity: verdict.is_some()`; the engine answers 409 `live_at_capacity` only when it must open a new upstream (a session of the same channel, mode, container and bitrate is joined for free). `[ts:src/modules/livetv/services/livetv-session.service.ts:187-221]` `[engine:docs/spec/live.md:14-15]`
10. Engine request `POST /v1/live` (`Engine::open_live`, already ported in S2, 503 + `Retry-After` retried up to 15 s, no `live` feature: `NoLive`): `channelId = String(channel.id)`; `upstreams` = every sorted stream `{url, priority, headers, probedContainer, probedVideoCodec, probedAudioCodec}` (null probe values omitted); `headers` = `User-Agent` plus `Referer` when non-empty; Nest builds them from the stream's **source** only (`source.userAgent || "VLC/3.0.20 LibVLC/3.0.20"`, `source.referer`), ignoring the per-entry `userAgent`/`referer` columns of the stream (from `#EXTVLCOPT`/KODIPROP, documented as winning over the source's). Rust `[new]` (C140): each value is `stream.x || source.x`, the agent then the VLC default; the engine takes any header map per upstream and passes `User-Agent`/`Referer` to ffprobe, ffmpeg and the direct GET (`[engine:docs/spec/live.md:21-24]`), so no engine change; `caps = {directPlay, maxBitrateBps, useTs}` from the DTO (`directPlay` default false, `useTs` default false, `maxBitrateBps` omitted when absent); `ownerId = String(user.id)`; `capacityToken = token`; `atCapacity`; `tags = {channelName: channel.name, username: user.username ?? "", device: <User-Agent request header or "">}`. `[ts:src/modules/livetv/services/livetv-session.service.ts:198-226]` `[ts:src/modules/livetv/livetv-http.ts:36-61]` `[ts:src/modules/engine/engine.service.ts:405-423]`
11. Answer handling: if `res.capacityToken != token` the open joined a running session: the new hold is deleted at once, **no** release grace, the viewer carries the session's token; else `hold.pending = false`, `hold.mode = res.mode`. Then `viewers[res.sessionId] = {channelId, channelName, userId, device: <User-Agent header or null>, startedAt: now ms, capacityToken: res.capacityToken}`, activity row (rule 29), QoE `register(ref)` + `set_pipeline(ref, res.qoePipeline)` (the engine's own pipeline; `qoe.md` rule 41 and `playback-info.md` rule 16 own the null defaults), and the response of the route table. `dvrWindowSeconds` and `segmentSeconds` are the engine's numbers as sent. `[ts:src/modules/livetv/services/livetv-session.service.ts:231-259]`
12. Failure mapping (`openFailed`): (a) not an engine HTTP error (no runtime, not running, transport): hold deleted, error rethrown as is (the two 503 strings above; a transport failure is a plain `Error`, 500 today, 503 in Rust per C139); (b) engine `code = live_unavailable` (503): `release(token, "failed")` (rule 26: grace starts, channel failure counted) then 503 `livetv_account_expired{channelName, sourceName}` for the first sorted stream whose source account is `expired` (`liveTvAccountStateOf(source.expiresAt, source.accountStatus)` of the sources spec), else 503 `livetv_channel_unavailable{channelName}`; (c) any other engine refusal: hold deleted; `live_at_capacity` with a verdict becomes the 409 body, anything else (400 no config, bad URL scheme, 503 without code after the retry window) is rethrown: 500 today. `[ts:src/modules/livetv/services/livetv-session.service.ts:263-294]` Rust: (c) other is 502 `{statusCode:502,message:"Bad Gateway"}` `[new]` (C139; the client treats every 5xx alike, a retry overlay, `live-player.ts` `handlePlayError`).
13. The hold is created before the engine call and deleted on every non-success path except `live_unavailable` (released, not deleted) so a refused open never leaks a slot. A `LiveReleased` that arrives before the HTTP answer already removed the hold: `release` is idempotent (rule 26).
14. `lastPlayedAt` of the channel and of the pref is not written (`livetv-access.md` rule 19). `mode` in the answer is the engine's effective mode (a remux of a non-H.264 upstream is `transcode`, `[engine:docs/spec/live.md:15]`).
15. Zap: there is no server-side zap. Changing channel is `play` on the new channel, optionally followed by `DELETE` of the old session; the host never ends the previous viewer, so a client that forgets holds a viewer (and possibly a provider connection) until the engine's idle expiry (`liveSessionTtlMs`, 30 s without data-plane requests). A user may hold several viewers; the host sets no per-user cap (deferred: fliks-app/fliks#1728).
16. Failover is the engine's: it tries the upstreams in the order sent, skips an upstream after 2 failures, restarts in place on stall or exit, and ends the session when all failed (`[engine:docs/spec/live.md:22-23]`). The host's part is: the order at open (rule 5), persisting each attempt (rule 23), moving the capacity hold to the source that feeds (rule 22) and counting a dead channel (rule 26). It never re-opens.
17. Stream token: `streamToken = mint_stream_token(user)` in-process (`StreamAuthed`-class token, claims `sub`, `username`, `scope:"stream"`, `STREAM_TOKEN_TTL` default 12 h, `auth.md` rule 5); the S1 bridge `POST /internal/auth/stream-token` is deleted. A mint failure is a 500. Token scope and lifetime unchanged (a live-only token is deferred: fliks-app/fliks#1728). `[ts:src/modules/bridge/stream-token.client.ts:6-18]` `[ts:src/modules/livetv/controllers/livetv.controller.ts:152-156]`

### Leaving and heartbeat

18. `leave(sid)`: engine `DELETE /v1/sessions/{sid}` (idempotent, 204), then `dropViewer(sid)`. `[ts:src/modules/livetv/services/livetv-session.service.ts:334-337]` Rust `[new]` (F74): owner = the viewer's `userId`, else (viewer unknown, e.g. just after a restart) the engine's `GET /v1/live/{sid}` `ownerId`; a caller that is neither the owner nor holds Manage Settings gets 403 `Not your session`; a sid that is not a live viewer (engine 404) answers `{ok:true}` without calling the engine, so this route can never end an on-demand session (today it can: the engine delete is generic).
19. Heartbeat: `viewer = viewers[sid]` else 404 `Live TV session not found`; `viewer.userId != caller.id` 403 `Not your session`; `body.qoe != null` -> `record_sample(ref{state: body.state == "paused" ? paused : playing}, parseSample(body.qoe))` (an unparsable sample is dropped, `qoe.md` rule 41); always `{ok:true}`. It does not touch the engine (the engine's `lastSeenMs` moves on data-plane requests) and does not extend any hold. `[ts:src/modules/livetv/controllers/livetv.controller.ts:176-184]`
20. `dropViewer(sid)`: unknown sid is a no-op; else delete it, finalise the QoE tracker once (`Qoe::end_session(sid).await` on the leave route so a following admin read sees the row, as the S2 stop routes do; `Qoe::session_ended(sid)` on the event and resync paths), recompute the activity row of its token (rule 29). Called by leave, `SessionEnded`, resync. `[ts:src/modules/livetv/services/livetv-session.service.ts:398-404]`
21. QoE ref of a viewer (built on demand, `lastBeat = now` each time): `{sessionId, userId, mediaFileId: null, mediaTitle: channelName, startedAt, lastBeat, deviceLabel: device, systemName: null, appVersion: null, kind: "live", quality: null, transcodeReasons: [], state: "playing", attributedUserId: null}`. Direct calls into `Qoe` (`register`, `set_pipeline`, `record_sample`, `observe_served`, `session_ended`, `set_live_transcodes`) replace the S2 QoE bridges. `[ts:src/modules/livetv/services/livetv-session.service.ts:373-396]`

### Engine events (the consumer)

22. Source of events: the S2 events consumer (`Engine::subscribe()` feed, `engine-glue.md` rules 49-54: subscribe, then resync, 45 s idle watchdog, backoff 0.5 to 15 s); live TV is one more subscriber next to presence and QoE. On `Feed::Resync` it runs its own `list_live` (the feed's `GET /v1/sessions` snapshot carries no live viewers); on `Lagged` it asks `resync_events()`. The Nest follower (`EngineEventsService` live listeners `onEvent`/`onResync`) is deleted at S7. `[ts:src/modules/livetv/services/livetv-session.service.ts:132-135]` `[ts:src/modules/livetv/services/livetv-session.service.ts:406-433]`
23. `LiveAttempt{capacityToken, upstream, upstreamUrl, upstreamPriority, error?, probe?}`: hold by token and stream = the hold's stream with equal `url` and `priority` (neither found: ignore). Patch of that stream row: `probedVideoCodec`/`probedAudioCodec`/`probedContainer` set when the event's probe member is non-empty; on success (no `error`): `hold.sourceId = stream.sourceId`, `hold.fed = ev.upstream`, if `!hold.pending` refresh modes (rule 27), patch `lastOkAt = now()`, `lastError = NULL`; on failure: `lastError = "account expired"` when the stream's source account is `expired`, else `ev.error`; when `hold.fed == ev.upstream` the source of that stream gets `recordRelease` (its provider connection lingers) and `hold.fed = None`. The patch is written even with no other change. `[ts:src/modules/livetv/services/livetv-session.service.ts:436-467]`
24. Capacity follows the feeding upstream: a failover to a stream of another source moves the hold to that source (rule 23 success) without a capacity check of the new source (rule 36). Resync (below) restores `fed` from `LiveSnapshot.upstream`.
25. `SessionEnded{sessionId}`: `dropViewer`. `SegmentServed{sessionId, cmcdRaw?, waitedMs}` for a known viewer: `observe_served(ref, read_cmcd_raw(cmcdRaw), segmentSeconds, waitedMs)` (QoE treats `waitedMs < 20` as already on disk, `qoe.md` rule 35); an unknown sid is ignored. Presence ignores live sids and the reverse (disjoint ids). `[ts:src/modules/livetv/services/livetv-session.service.ts:418-431]`
26. `LiveReleased{capacityToken, reason: idle|failed|shutdown}` and the internal `release(token, reason)`: no hold: nothing. Else delete the hold, `recordRelease(hold.sourceId)` (grace starts, wherever the token had moved), remove activity `livetv:<token>`; when `reason == "failed"`: `UPDATE livetv_channels SET "lastErrorAt" = now(), "consecutiveFailures" = "consecutiveFailures" + 1 WHERE id = $channelId` and a warn log `Live TV channel #<id> ended: every stream failed`. `lastErrorAt` and `consecutiveFailures` are written and returned by the admin list but never read or reset (kept). `[ts:src/modules/livetv/services/livetv-session.service.ts:470-489]`
27. Mode bookkeeping: `refreshModes` = `GET /v1/live`, `hold.mode = s.mode` for each known token (errors swallowed). `activeTranscodes` = number of holds with `mode == transcode` (one per session: viewers share an encoder); pushed with `qoe.set_live_transcodes(n)` after every hold mutation (open, attempt, release, resync) instead of Nest's pull probe. `[ts:src/modules/livetv/services/livetv-session.service.ts:556-567]`
28. Resync (after every events (re)connect and at boot once the engine answers): `listedAt = now`; `snaps = GET /v1/live` (an error aborts the resync with state untouched, is logged and calls `resync_events()`: Nest's follower drops the connection and reconnects with its backoff when a resync listener throws `[ts:src/modules/streaming/services/engine-events.service.ts:113-131]`); `restoreHolds`: for a snapshot whose token has a hold only `mode ??= s.mode`; else load the channel's streams with sources, `fed` = the stream equal to `(upstreamUrl, upstreamPriority)` (none: skip) and insert a hold `{sourceId: fed.sourceId, channelId, streams, fed: s.upstream, pending: false, mode: s.mode}` (re-check the map after the `.await`); then viewers: every snapshot unknown to the map is added (`channelName = tags.channelName ?? ""`, `userId = ownerId` parsed or null, `device = tags.device` or null, `startedAt = openedAtMs`, token); every known viewer absent from the snapshot and with `startedAt < listedAt` is dropped (one opened after the listing is newer, not stale); every hold absent from the snapshot's tokens and not `pending` is `release(token, "shutdown")` (grace starts, no failure count). Restored viewers get no QoE register; Rust also reports their activity row (the registry is empty after a restart) `[new]` (C141, no contract change). `[ts:src/modules/livetv/services/livetv-session.service.ts:492-554]`
29. Activity (admin `GET /api/system/activity`, in-process registry of `events-hub.md`): after open and after `dropViewer`, for the viewer's token: no viewers left -> `remove("livetv:<token>")`; else `upsert_running("livetv:<token>", "livetv.viewing", subject {title: <first viewer's channelName>}, current = viewers on that token)` (no `total`). `[ts:src/modules/livetv/services/livetv-session.service.ts:569-582]` The S2 bridge `POST /internal/activity` carries these today.

### Resolver `live` and config

30. Resolver `live` is a function call, not a bridge: in `engine/resolve.rs` the `ResolveMediaId::Live` arm calls `livetv::resolve_live(st, sid, user)` instead of `nest_live`, so the 5 s HTTP call, the 502 path and `POST /engine/resolve` on Nest disappear. Input: the viewer's sid and the user already resolved from the credential by the resolver (any token scope accepted, `engine-glue.md` rule 38). Output: unknown sid -> `{allow:false, ttlS:60}`; user not `enabled` -> same (already denied by the resolver's own user check); `findPlayable(viewer.channelId, user)` fails with a not-found, or (C136) keeps no stream -> same; else `{allow:true, ownerId:String(user.id), ttlS:0}` (no path; re-checked on every data-plane request, so revoking a group, disabling a channel, a source or a user ends an HLS viewer at its next request; a `direct.ts` viewer is one long response, resolved only when it connects: grant changes end it through `livetv-access.md` rule 29). A non-HTTP failure (DB down) is a 5xx, never a denial. Rust `[new]`: a sid missing from the registry is looked up with `GET /v1/live/{sid}` (viewer rebuilt from the snapshot as in rule 28; engine 404 is the denial), because the engine only asks for sids it holds and ends the viewer on a denial, so a request racing the boot resync would otherwise end it. `[ts:src/modules/engine/engine-resolver.service.ts:41-56]` `[engine:PROTOCOL.md:56]`
31. The engine, not the host, enforces the owner: it answers 403 when the returned `ownerId` is not the viewer's, and it **ends the viewer (`SessionEnded{revoked}`) on any denial**. So the host must never deny because of an owner mismatch, and today a denial computed with the *caller's* group access ends *someone else's* viewer (F75). Rust `[new]`: when `viewer.userId != user.id` answer `{allow:true, ownerId:String(user.id), ttlS:0}` (engine 403s, viewer untouched); evaluate the group check for the viewer's owner, not the caller. `[engine:docs/spec/live.md:41]` `[engine:crates/engine/src/serve.rs:1241-1248]` Not covered: a credential that resolves to no user (absent, garbage, expired) is denied before the `live` arm and still ends the viewer; the host cannot attribute it, so this needs an engine change (end a live viewer only on a denial for its owner) and is a known gap (engine issue).
32. Config owner: Rust builds `LiveTvConfig {segmentSeconds: max(1, intOr(livetv_segment_seconds, 2)), timeshiftMinutes: max(1, intOr(livetv_timeshift_minutes, 15)), probeSeconds: intOr(livetv_probe_seconds, 3), channelIdleSeconds: intOr(livetv_channel_idle_seconds, 30), fastZap: "true"->true, "false"->false, else absent}` (`intOr` = `parseInt(raw,10)` if finite else default; the engine floors `probeSeconds` at 3) from `app_settings` and includes it in every `PUT /v1/config` (`engine-glue.md` rules 15-23). It reloads when a settings write touches one of the 5 keys (the settings-change hook of `engine/config.rs`, `settings_changed`) and at boot; it also caches `segmentSeconds` for rule 25. Replaces Nest's listener L3 `pushConfig`, `PUT /internal/engine/livetv-config` and `set_livetv`. `[ts:src/modules/livetv/services/livetv-session.service.ts:95-160]`
33. `livetv_slot_release_seconds` is read by the host only (rule 6); `livetv_stale_stream_days` is `livetv-access.md`.

### Admin and activity views

34. `GET /api/system/streams` live rows (S2, already in Rust `stream/system.rs::live_tv_rows`): one row per `LiveSnapshot` of `GET /v1/live` (`[]` on engine failure), `mediaType "livetv"`, `quality "Live"` (C19), QoE `live_summary(sid)` joined. At S7 nothing changes: Nest's `listForActivity` has no caller left (its `system.controller.ts` consumer went in S2) and is deleted with the service. `[ts:src/modules/livetv/services/livetv-session.service.ts:346-370]`
35. No admin route ends a live viewer: `POST /api/system/streams/:sid/command` needs a presence entry and answers 400 `Session not found` for a live sid; only the owner (rule 18) or the engine's idle expiry ends it. Kept.

### Decisions settled in review

36. Known gap, engine follow-up (no bridge, `bridge.md`): capacity is checked only for the primary stream's source and the hold then follows the feeding upstream (rules 8, 24), so a failover onto another source's stream can exceed that source's `maxStreams`, and a down primary counts against the wrong source until the first attempt event. The fix needs an engine change, a per-upstream capacity veto (`LiveUpstream.atCapacity`, or a host callback before an attempt on another source); parity with Nest until then.
37. Known gap, engine follow-up (no bridge, `bridge.md`): the engine ends a live viewer on any resolver denial, including a credential that resolves to no user (rule 31, residual of F75). The fix needs an engine change: end a live viewer only on a denial for its owner.
38. `consecutiveFailures` and `lastErrorAt` stay written and returned by the admin list but never read or reset (rule 26), as in Nest; resetting them on success or dropping the columns is decided at S9.
