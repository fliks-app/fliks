# Store listing assets

Everything a store asks for **around** the app package: listing icons,
screenshots and the description documents. One directory per store.

In-app assets are **not** here — they are build inputs and stay next to the
code that packages them:

| What | Where |
|---|---|
| Tizen home icon (1024×1024) | `client/tizen/icon.png` |
| webOS icon (400×400) + splash (1920×1080) | `client/webos/icon.png`, `splash.png` |
| tvOS App Icon layers + Top Shelf | `appletv/Sources/Resources/Assets.xcassets/` |
| iOS app + marketing icon (1024×1024) | `client/ios/App/App/Assets.xcassets/AppIcon.appiconset/` |
| Android launcher icon | `client/android/app/src/main/res/mipmap-*/` |
| Brand logo / icon sources (SVG) | `client/public/fliks-logo*.svg`, `fliks-icon.svg` |

Signed packages are never committed — CI produces them (`tizen-publish.yml`
keeps the store-signed widget as a build artifact, deliberately not a public
release asset, because a signature embeds the author certificate).

## samsung/ — Samsung Apps TV Seller Office

| Slot | File | Requirement |
|---|---|---|
| Logo Asset With Transparency | `icons/logo-1920x1080.png` | 1920×1080, 32-bit PNG (RGBA), ≤ 300 KB |
| Background Image | `icons/background-1920x1080.jpg` | 1920×1080, 24-bit PNG or JPG, ≤ 300 KB |
| 512×423 Full Color Asset | `icons/fullcolor-512x423.png` | exactly 512×423 PNG, ≤ 300 KB |
| Screenshots | `screenshots/*.jpg` | 1920×1080, shown in file-name order |
| App Description | `app-description.pptx` | mandatory document; missing sections get the app rejected |

The 16:9 and 1:1 assets are generated by Seller Office from the logo and the
background; the 512×423 one is not, it must be uploaded separately.

### Getting the signed package for a submission

`tizen-publish.yml` signs on every release tag. The signed widget is a build
artifact rather than a release asset, so fetch it from the tag's run:

```bash
run=$(gh run list --workflow=tizen-publish.yml --branch v2.1.0 --limit 1 \
        --json databaseId -q '.[0].databaseId')
gh run download "$run" -n tizen-wgt -D /tmp/fliks-wgt
# → /tmp/fliks-wgt/store/Fliks-2.1.0-store.wgt   the file to upload
# → /tmp/fliks-wgt/Fliks-2.1.0.wgt               unsigned, same as the release asset
```

Artifacts expire after 7 days. Past that, re-run the workflow on the tag
(`gh workflow run tizen-publish.yml --ref v2.1.0`) — or sign locally from the
same staged bundle, see `client/tizen/README.md` §3.

`app-description.pptx` fills Samsung's own `App_Description_template_eng`
(v1.42) — UI structure, usage scenario including log-in, menu descriptions,
key policy, languages. It carries the demo-server credentials testers need,
since the app is useless without a server to pair with.

## lg/ — LG Content Store (Seller Lounge)

| Slot | Requirement |
|---|---|
| Store icon | 400×400 PNG, uploaded in Seller Lounge and auto-resized there |
| Screenshots | 1 primary + up to 5 secondary; LG recommends 960×540 or 1280×720 |

LG documents that most rejections come from images at the wrong size, so check
each one before submitting. The packaged icon (`client/webos/icon.png`) already
is 400×400 and can be reused as the store icon; `appinfo.json` points both
`icon` and `largeIcon` at it, where webOS docs describe 80×80 and 130×130
in-package icons — worth revisiting only if LG ever flags it.

## android/ — Google Play Console

| Slot | File | Requirement |
|---|---|---|
| App icon | `icon-512x512.png` | 512×512, 32-bit PNG, ≤ 1 MB |
| Feature graphic | `feature-graphic-1024x500.png` | exactly 1024×500, JPG or 24-bit PNG, **no alpha** |
| TV banner | `banner-tv-1280x720.png` | 1280×720, no alpha — mandatory for the Android TV listing |
| Screenshots | `screenshots/<locale>/<slot>/NN-*.jpg` | 2 to 8 per slot, 320–3840 px per side, max 2:1 |

Android TV submissions get rejected for a missing full-size banner, so it is not
optional here even though the phone listing does not use it.

### Screenshots

One directory per Play locale, then one per device slot — Play uploads and
stores them per locale, and a slot left empty falls back to the phone set.

```
screenshots/en-US/{phone,tablet-7,tablet-10,tv}/
screenshots/fr-FR/{phone,tablet-7,tablet-10,tv}/
```

The `NN-` prefix is the upload order, and the rest names the screen
(`04-movie-detail-wing-it-landscape.jpg`). Tablet slots hold both orientations,
landscape first. Captured on the emulators — `fliks_tablet7`, `fliks_tablet10`,
`fliks_androidtv` — except the phone set, which comes from a device.

Tablet and TV captures are JPEG q92 4:4:4: as PNG the set weighed 109 MB, which
does not belong in git history for assets Play re-encodes anyway. The phone
files are the original JPEGs, copied untouched rather than re-encoded.

## ios/ — App Store Connect

| Slot | File | Requirement |
|---|---|---|
| iPhone 6.9" screenshots | `screenshots/<locale>/iphone-69/NN-*.jpg` | exactly 1320×2868 or 2868×1320, 1 to 10 |
| iPhone 6.5" screenshots | `screenshots/<locale>/iphone-65/NN-*.jpg` | exactly 1242×2688 or 2688×1242, 1 to 10 |
| iPad 13" screenshots | `screenshots/<locale>/ipad-13/NN-*.jpg` | exactly 2064×2752 or 2752×2064, 1 to 10 |

PNG or JPEG, RGB, **no alpha**, and the pixel dimensions are exact — there is no
tolerance. 6.9" is the only required iPhone size and Apple scales it down for the
rest; 6.5" is optional and only worth filling when the framing deserves its own
capture. No icon here: App Store Connect reads the 1024×1024 marketing icon from
the app bundle's asset catalog.

### Screenshots

Same layout as `android/` — one directory per App Store locale, then one per
device slot, with the `NN-` prefix carrying the upload order:

```
screenshots/en-US/{iphone-69,iphone-65}/
screenshots/fr-FR/{iphone-69,iphone-65}/
```

Both sets show the same six screens, so the `NN-` order matches across slots and
locales. Captured on two simulators — the 6.5" one being the last device type of
that size still shipping a bootable runtime:

```bash
xcrun simctl create "iPhone 16 Pro Max (6.9in)" \
  com.apple.CoreSimulator.SimDeviceType.iPhone-16-Pro-Max \
  com.apple.CoreSimulator.SimRuntime.iOS-26-4
xcrun simctl create "iPhone 11 Pro Max (6.5in)" \
  com.apple.CoreSimulator.SimDeviceType.iPhone-11-Pro-Max \
  com.apple.CoreSimulator.SimRuntime.iOS-26-4
```

`⌘S` in the Simulator writes PNGs **with an alpha channel**, which App Store
Connect rejects — flatten them on the way in (JPEG q92 4:4:4, same recipe as the
Android tablet set).

## Regenerating

Both generators are reproducible and take the brand SVGs as their only input:

```bash
store/tools/samsung-icons.sh              # → samsung/icons/
store/tools/android-banner.sh             # → android/banner-tv-1280x720.png
uv run --with python-pptx python store/tools/samsung-app-description.py
```

The TV banner reuses the tvOS App Store icon's background layer, so the two TV
stores share one gradient — replacing it in `appletv/` reflows into the banner.

The description document embeds the screenshots from `samsung/screenshots/`, so
regenerate it after replacing them.
